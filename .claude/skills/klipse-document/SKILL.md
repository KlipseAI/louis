# Klipse 문서

**모양은 정해져 있다. 남는 일은 무엇을 먼저 말할지 정하고 문장을 쓰는 것이다.** 규범은
`design/patterns/document.md` 가 갖고, 이 스킬은 그 규범으로 문서 한 편을 끝까지 내는 순서와 검사를 갖는다.
규범의 값(크기 · 간격 · 색)을 여기에 옮겨 적지 않는다 — 옮긴 값은 조용히 낡는다.

## 0. 문서가 맞는가

| 이런 것이면 | 쓰는 것 |

| 발표 장표(1920×1080, 한 장에 주장 하나) | klipse-deck-kit(`/new-deck`) |

| Linear 이슈에 붙이는 진행 문서(마크다운) | 이슈 문서 형식 — 이 스킬이 아니다 |

문서 안에서 버튼 · 입력이 필요해지면 그것은 화면이다. 링크는 괜찮다.

## 2. 순서

### 2.1 내용 확보

사용자가 준 자료(메모 · 수치 · 캡처 · 이전 문서)를 먼저 모은다. 모자라면 **넷만** 묻는다 — 그 이상 묻지 않는다.

1. 제목과 발행 주체
2. 다 읽은 사람이 무엇을 알거나 정하기를 바라는가(한 문장)
3. 승인 · 확인이 필요한 것(있으면)
4. 다룰 내용과 수치의 출처

내용이 충분하면 묻지 않고 바로 짠다. 긴 작업이면 `BRIEF.md`(뼈대가 문서 폴더에 복사한다)를 채워 달라고 한다.
**수치를 지어내지 않는다.** 모르는 값은 `〔채울 자리: …〕` 로 두고 끝에 물을 목록으로 모은다 — 검사가 남은 자리를 오류로 센다.

### 2.2 설계 — 마크업보다 먼저

**결론이 먼저다.** 아래를 정하지 않고 마크업을 쓰지 않는다.

| 정할 것 | 기준 |
| --- | --- |
| 리드(결론 한 문장) | 무엇을 했고 무엇을 정해야 하는지. 제목을 되풀이하지 않는다 |
| 결정 요청 | 머리 바로 아래. 항목마다 명사구 라벨(「… 승인」 · 「… 착수」) + 조건 한 줄(기한 · 비용 · 범위). 없으면 두지 않는다 |
| 절 목록 | 절마다 키커 · 제목(그 절의 주장 한 문장) · 출처 줄(기준 시점과 출처) · 블록 |
| 블록 순서 | 주장 → 근거 → 해석. 수치 격자 → 비교 → 표 → 해석 카드 |
| 맺음 절 | 결정 요청을 근거와 함께 다시 한 번 말한다 |

키커는 `요약` · `01` · `02` … · `판단 기준` · `정할 내용` · `부록` 처럼 짧게. 절이 다섯을 넘을 때만 목차를 둔다.

### 2.3 부품 고르기

부품 선택표(`document.md`)가 정본이다. 자주 쓰는 것만 줄였다 — 마크업은 예시에서 클래스 이름으로 찾아 옮긴다
(`grep -n 'louis-document-bars' packages/css/examples/document-report.html`).

| 말하려는 것 | 부품(클래스 뿌리) | 한도 · 주의 |
| --- | --- | --- |
| 정할 것 | `louis-document-decision` | 머리 바로 아래 |
| 주장 풀어 쓰기 | `louis-document-prose` | 강조는 `strong` 만 |
| 나란한 항목 셋 · 넷 | `louis-document-grid` + `-card` | 번호가 있으면 `ol` + 표식 |
| 지표 | `louis-document-grid[data-columns="4"]` + `-stat` | 한 행 넷까지 |
| 두세 대상 비교 | 카드 안 `louis-document-bars` + `-verdict` | 앞선 쪽만 `data-lead`, 막대는 0 에서 |
| 세 시점 이상의 흐름 | 카드 안 `louis-document-trend` | 계열 하나. 두 시점이면 비교 막대 |
| 전체 수치 | `.louis-document-table > table.louis-table` | 앱과 같은 기본 표. `caption` · `scope` |
| 부분과 전체 | 카드 안 `louis-document-stack` | 조각 셋까지, 합 100% |
| 화면 캡처 · 견주기 · 짚기 | `louis-document-media` · `-compare` · `-shot` + `-pin` | 늘이지 않는다, 사각형 · 화살표 금지, 핀 넷까지 |
| 순서 · 일정 | `louis-document-flow` · `-timeline` | 칩 다섯 · 항목 넷까지 |
| 결론 한 줄 · 비용 주의 | `louis-document-callout`(`data-tone="caution"`) | 절마다 하나. 노랑은 비용 · 되돌리기 어려움에만 |
| 소유자 · 고객의 말 | `louis-document-quote` | 절마다 하나. 누가 언제 |
| 근거 | `louis-document-footnote` + `-sources` | 번호는 링크, 출처는 「본문으로」로 되돌아간다 |
| 경로 · 명령 | 본문 `code` · `louis-document-codeblock` | |

**앱 부품을 얹지 않는다** — Alert 를 강조로, StatTile 을 수치 카드로, Badge 를 칩으로 쓰지 않는다(DS-D-0067 · 첫 시안이
거절된 이유). 맞는 부품이 없으면 새 CSS 를 쓰지 말고 가장 가까운 부품으로 쓴 뒤 **부록 절에 모자란 자리를 적는다** —
다음 작업에서 `document.md` 「남은 것」으로 옮겨 부품을 세운다.

### 2.4 뼈대

```bash
node .claude/skills/klipse-document/scripts/new-document.mjs <슬러그> "<제목>" [--publisher "Klipse 마케팅"]
```

`documents/<슬러그>/`(git 이 추적하지 않는다)에 `index.html` · `BRIEF.md` · `media/` 가 생긴다. 머리 · 결정 요청 ·
요약 절 · 번호 절 · 맺음 절 · 맺음 줄이 채울 자리와 함께 선다. 슬러그는 영문 소문자 · 숫자 · 하이픈, 날짜를 앞에 두면
정렬이 좋다(`2026-09-meta-ads`). 캡처는 `media/` 에 두고 `media/파일` 로 참조한다.

### 2.5 작성

**마크업**

- LOUIS 클래스만 쓴다. `<style>` · 인라인 색 · 새 클래스를 만들지 않는다. 인라인 `style` 은 부품이 읽는
  `--louis-document-*` 변수(막대 길이 · 핀 자리 · 추이 좌표)에만 쓴다.
- 목록 부품(`ol` · `ul`)은 `role="list"` 를 단다. 번호 표식은 `aria-hidden="true"`.
- 절은 `section aria-labelledby` + 안의 `h2`. 문서 제목 `h1` 은 하나.
- 캡처 `img` 는 `alt`(보이는 것과 짚는 점 한두 문장) · `width` · `height`.
- 제목에 `<br>` 을 넣지 않는다. 두 줄이 더 좋으면 구마다 `.louis-document__title-line` 으로 감싼다.

**색과 강조** — 강조색은 파랑 하나. 초록은 앞선 값에만, 노랑은 비용이 드는 지점에만. 카드 레일 · 테두리 · 그림자 ·
라벨 앞 점 · 대문자 라벨 · 이모지를 쓰지 않는다. 한도를 넘으면 글자를 줄이지 말고 절을 나눈다.

**문장** — 승인본(`document.html`)의 호흡을 따른다.

- 문서체는 공식 콘텐츠 문체다 — [Voice & Tone](../../../design/content/voice-tone.md)의 공식 톤을 따른다. 합니다체로 쓰고
  (「연장하고, 함께 검토합니다」), 구어 동사 대신 공식 표현(「추가되었습니다」 · 「확인할 수 있습니다」)을 쓴다.
  한다체로 쓰지 않는다(2026-10-07 소유자 지시 — 예전 「문서체는 한다체」 규칙을 걷었다).
- 절 제목은 그 절의 주장이다 — 「생성기는 검사를 통과한 채 틀린 보드를 생성했습니다」. 「현황」 · 「배경」 같은 목차형 라벨로 도망가지 않는다.
- 쓰지 않는 넷: 세는 제목(「세 가지 이유」) · 안심 어미(「~면 됩니다」 · 「~뿐입니다」) · 「A가 아니라 B」 대구 · 번역체(「주인공은 ~입니다」).
  진짜 대조(나쁜 예와 좋은 예를 나란히)는 남긴다.
- 제목들을 세로로 훑어 마지막 어절이 같은 제목이 셋 이상이면 흩는다(검사기도 마지막 어절을 견준다 — 「~니다」 어미가 겹치는 것은 반복이 아니다).
- 수치 절은 출처 줄에 기준 시점과 출처를 둔다. 숫자와 단위는 붙인다(`514회`), 금액은 기호를 앞에(`₩110,539`).
- 칸이 있다고 채우지 않는다 — 제목이 다 말했으면 카드 설명을 줄인다.

### 2.7 캡처를 본다

통과해도 끝이 아니다. `documents/<슬러그>/check/` 의 `desktop.png` · `mobile.png` · `dark.png` 를 열어 본다 —
기계가 못 재는 것: 절 제목이 구 경계에서 끊기는가, 면이 겹쳐 한 단 짙은 상자가 생겼는가, 캡처가 읽히는가, 다크에서
표식 · 막대가 보이는가, 좁은 화면에서 수치가 카드를 넘는가(`document.md` Known deviations 6).

CSS 라 밖에서 열리지 않는다.

## 3. 고칠 때

기존 문서를 고쳐 달라는 요청도 같은 순서다 — 먼저 결론 · 결정 요청이 머리 아래 있는지, 절 제목이 주장인지 본다.
원본 순서를 두고 부품만 갈아 끼우는 것은 고친 것이 아니다(첫 시안이 거절된 이유). 고친 뒤 2.6 · 2.7 을 다시 돈다.
