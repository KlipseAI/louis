# Canvas Edge

노드 캔버스의 **연결선**. 실선 한 겹 위에 흐르는 쉬머 한 겹이 얹히고, 쉬머에는 톤마다 반경이
다른 번짐이 걸린다.

**정본은 제품이고, 그 정본의 형태는 CSS 가 아니라 톤 표다.** `V2EdgeLayers.tsx` 가 구현이고
LOUIS 에는 표면이 없다 — `packages/css/src/component` 에도 `packages/react/src` 에도 이 이름의
파일이 없다. **그것이 결함이 아니라 판정이라는 것이 이 문서의 요지다**(DS-D-0061 · 아래 절).
그리고 톤 어휘의 **실행 가능한 SSOT** 는 같은 폴더의 `lib/edgeTone.ts` 다. 그 파일이
「핸들 id → 채널」을 정하고, 핸들 원반의 색과 거기 꽂힌 전선의 색이 같다는 불변식을 유지한다.

**video 채널은 없다.** 비디오는 매체이지 채널이 아니다 — 편집 입력에 도착한 비디오는 edit
채널이고, 퍼블리시 노드로 나가는 비디오는 youtube·instagram 채널이다. 새 톤을 만들고 싶어지면
먼저 `edgeTone.ts` 의 그 주석을 읽어라. 원반만 새 색이 되고 전선은 그대로 남아 불변식이 깨진다.

## Availability

| Surface | 상태 | 근거 |
| --- | --- | --- |
| Web | `not-planned` | **레시피를 세우지 않는 것이 판정이다**(DS-D-0061). 정본은 CSS 가 아니라 톤 표다 — 아래 「왜 CSS 레시피가 없는가」. LOUIS 가 소유하는 것은 그 표가 부르는 이름이고, `canvas-edge.browser.test.tsx` 가 그것을 잰다 |
| Figma | `partial` | `CanvasEdge` 14 variant(`Tone` × `State`). 그린 것은 **실선뿐**이다 — 쉬머와 번짐은 아래 「Figma 가 담지 못하는 것」 |
| Documentation | `done` | 이 문서 |
| Maturity | `experimental` | 되읽기·계약·문서가 방금 처음 섰다. 승격은 LOUIS recipe 가 아니라 **Figma 가 담지 못하는 셋을 어떻게 다룰지**와 아래 Accessibility 의 결손 셋이 정한다 |

## When to use

- 노드 캔버스에서 두 핸들을 잇는 선을 그릴 때. 캔버스의 **모든** 연결선이 이것이다 —
  `DeletableEdge` 가 React Flow 의 엣지 타입으로 등록돼 있고, 드래그 중 미리보기 선
  (`PreviewConnectionLine`)과 워크스루 연결 시연도 같은 조형을 쓴다.
- 쓰지 않는 자리:
  - **일반 구분선** — [Pane Divider](./pane-divider.md) 이거나 메뉴 구분자다. 저쪽은 미는 것이고
    이쪽은 잇는 것이다.
  - **정렬 스냅 가이드** — 아래 「이 문서가 다루지 않는 것」.

## Anatomy

1. **Base** — 실선. 두께 2, 끝은 둥글다. 색이 채널을 말한다.
2. **Shimmer** — 같은 경로 위에 겹치는 두 번째 획. 채널 램프의 밝은 칸을 심으로 하는
   좁은 그라디언트가 선을 따라 무한히 흐른다.
3. **Glow** — 쉬머에 걸리는 번짐. 반경이 톤마다 다르다.
4. **히트 영역** — 그 위에 겹치는 투명 획. 보이는 선이 2 라 그것만으로는 잡히지 않는다.
   트랙은 얇고 히트 영역은 넓다 — [Pane Divider](./pane-divider.md) 와 같은 문법이다.
5. **삭제 버튼** — 호버할 때 선 한가운데에 뜬다. **이 컴포넌트에 없다**(아래).

## Tone — 이 컴포넌트의 내용

| Tone | 실선 | 쉬머 하이라이트 | hover |
| --- | --- | --- | --- |
| `default` | `color-palette-gray-000` | 베이스와 같은 색 | 바뀌지 않는다 |
| `image` | `color-node-handle-icon-image` | `color-green-200` | 바뀌지 않는다 |
| `text` | `color-node-handle-icon-text` | `color-yellow-200` | 바뀌지 않는다 |
| `youtube` | `color-node-handle-icon-youtube` | `color-red-200` | 흰 잉크 한 겹 |
| `instagram` | `color-node-handle-icon-instagram` | `color-red-200` | 흰 잉크 한 겹 |
| `edit` | `color-node-handle-icon-edit` | `color-violet-200` | 흰 잉크 한 겹 |
| `audio` | `color-node-handle-icon-audio` | `color-pink-200` | 흰 잉크 한 겹 |

**실선을 채널 토큰으로 정한 것이 이 회차의 판정이다.** 제품 `V2EdgeLayers` 는 accent 램프를
직접 읽고, 같은 채널의 핸들 원반은 채널 토큰을 읽는다. 두 곳이 지금은 같은 값으로 끝나지만
참조가 갈려 있어 한쪽만 움직이면 조용히 어긋난다. 정본을 채널 토큰 쪽으로 두면
`edgeTone.ts` 가 지키려는 불변식(원반 색 = 전선 색)을 토큰이 대신 지킨다.

**쉬머 하이라이트를 채널 램프의 200 칸으로 정한 것도 판정이다.** 여섯 톤 중 edit·audio 두 톤은
제품 리터럴이 이미 그 칸과 바이트로 같다. image·text·youtube 세 톤만 램프 밖 리터럴이다. 규칙이
이미 두 번 맞은 자리라, 새 색을 셋 만드는 대신 램프를 정본으로 삼고 세 리터럴을 어긋남으로
적었다.

**hover 는 색을 갈아 끼우지 않는다.** 획 위에 `color-static-white-alpha-12` 를 한 겹 얹는다 —
합성 결과가 제품의 `color-mix` 와 같다. **일곱 톤 중 넷만 그렇게 한다.** default·image·text 는
제품이 hover 에서 색을 바꾸지 않고, 왜 그 셋만 예외인지는 코드에 적혀 있지 않다. 접지 않고
기록에 `null` 로 적어 그 사실을 고정했다.

## Figma 가 담지 못하는 것

**흐르는 쉬머.** 그라디언트를 무한 반복으로 이동시키는 애니메이션이다. Skeleton 이 스윕을 담지
못하는 것과 같은 한계이며, 정지 상태로 접어 그리면 「멈춘 그라디언트」라는 없는 상태를 정본으로
만든다. 그래서 Figma 변형에는 실선만 있다.

**번짐(glow).** 반경이 톤마다 다른데(밝은 채널이 덜 번지고 짙은 채널이 더 번진다) 되읽기의
effect 역할은 자손 이름 하나에 값 하나다. 한 값으로 적으면 일곱 톤 중 여섯을 거짓으로 고정하므로
Figma 에 두지 않았고 계약도 비웠다. 값은 `figma/components.measured.json` 의
`canvas-edge.$glowNote` 가 갖는다.

**삭제 버튼.** 호버할 때 뜨는 원형 버튼은 엣지가 아니라 엣지 위에 뜨는 컨트롤이다. 지금 제품은
그것을 [Icon Button](./icon-button.md) 이 아니라 자기 클래스로 그리고 있고, 흡수할지 별 부품으로
세울지는 아직 판정하지 않았다.

## 왜 CSS 레시피가 없는가 — 판정 (DS-D-0061)

이 자리를 열어 보는 사람은 「생성 CSS 에 `louis-canvas-edge` 가 0 건」을 먼저 본다. 그것은
**빠진 것이 아니라 정해진 것이다.** 같은 질문을 다시 하지 않도록 사유를 여기 둔다.

**CSS 가 담을 수 있는 것은 넷뿐이다** — 실선 색 · stop 색 · stop 불투명도 · 번짐 필터.
나머지는 원리적으로 담기지 않는다.

1. **쉬머의 페인트가 인스턴스 기하다.** 쉬머는 `gradientUnits="userSpaceOnUse"` 인
   `<linearGradient>` 이고 그 좌표 넷은 **두 핸들의 런타임 좌표**에서 나온다. 획은 엣지마다
   다른 `url(#…)` 를 물어야 한다. CSS 클래스는 paint server 를 만들지도, 그 좌표를 정하지도,
   인스턴스마다 다른 id 를 붙이지도 못한다.
2. **주기는 SMIL 이지 CSS 가 아니다.** 1.45초는 `<animateTransform>` 의 `dur` 이며 그것을
   정하는 CSS property 는 존재하지 않는다. 계약의 `shimmerPeriodMs` 는 **어떤 레시피로도**
   옮겨가지 못한다. 쉬머를 CSS 로 애니메이트할 수 있게 다시 설계하는 것은 출시된 제품 시각을
   바꾸는 일이고, 그 순간 「정본은 제품」이라는 이 문서의 전제가 뒤집힌다.
3. **그래서 레시피는 한 표를 두 집에 살게 한다.** 넷은 CSS 로, 나머지는 JS 로 갈린다.

세 번째가 결정적이다. **이 컴포넌트를 기록할 값어치가 정확히 그 반대편에 있기 때문이다** —
위 「손으로 복제된 사본 일곱 벌」이 적듯 이 조형은 이미 일곱 벌이고 그중 넷이 주기 · 번짐 색 ·
image 하이라이트에서 갈렸다. 제품 `V2_EDGE_TONE` 의 주석이 그 교훈을 적는다: 주석은 동일함을
지켜 주지 않으며, 값을 한 곳에 두어야 갈릴 자리가 사라진다. **LOUIS 레시피는 여덟 번째 사본이
되고, 통째로 소비될 수 없는 첫 사본이 된다.**

### 그러면 LOUIS 는 무엇을 소유하는가

**이름이다.** 표가 부르는 채널 토큰과 accent 램프가 LOUIS 토큰 생성물에 있고, 제품의 표는 그
이름을 읽는다. 검사가 빠진 것이 아니라 CSS 가 아닌 근거 위에 서 있다 —
`packages/react/test/canvas-edge.browser.test.tsx` 가 그 이름이 두 테마에서 실재하는지와
톤마다 옳은 칸(실선 500 · 쉬머 200)을 무는지를 실브라우저에서 잰다.

### 게이트가 이 사실을 안다

계약(`figma/components.measured.json`)의 최상위 `$noRecipe` 가 이 이름과 사유를 갖고,
`scripts/verify-recipe-record.mjs` 가 **세 방향**을 문다.

- `$noRecipe` 에 있는 이름은 manifest 의 `web` 이 `not-planned` 여야 한다.
- 그 이름으로 `packages/css/src/component/<id>.css` 가 **생기면 실패한다** — 판정을 뒤집는
  일이므로 Decision · 문서 · manifest 를 같은 회차에서 함께 옮기라고 말한다.
- 거꾸로 `web` 이 `not-planned` 인데 `$noRecipe` 에 사유가 없으면 실패한다 — 사유 없이
  상태만 내려 두는 길을 막는다.

### 닫지 않은 것

**LOUIS 가 톤 표를 TS export 로 소유하는 길**은 남아 있다. 그러면 제품의 사본 일곱이 하나로
접히고 위 「사본 넷의 어긋남」이 구조적으로 사라진다. 오늘 하지 않는 이유는 하나다 — **소비처가
없다.** 제품이 그것을 물어야 이득이 생기고, 무는 것은 제품 회차의 일이다. 수요가 서면 Decision
으로 이 판정을 다시 연다(`select` 가 DS-D-0053 에서 그렇게 열렸다). **CSS 는 그 길의 대체재가
아니다** — 위 1·2 가 CSS 에서는 성립하지 않기 때문이다.

## 손으로 복제된 사본 일곱 벌

제품 앵커에서 이 조형은 일곱 자리에 있다 — `V2EdgeLayers` 를 부르는 셋(엣지 타입 등록 ·
`DeletableEdge` · `PreviewConnectionLine`)과, 「V2EdgeLayers 와 동일」이라 주석을 달고 값을
베낀 워크스루 연결 오버레이 네 파일이다.

**네 사본은 원본과 세 자리에서 이미 어긋나 있다.**

| 축 | 정본 | 사본 넷 |
| --- | --- | --- |
| 쉬머 주기 | 1.45초 | 1.85초 |
| 번짐 색 | 톤마다 다르다 | 톤과 무관하게 노랑 계열 하나 |
| image 하이라이트 | 램프 밖 리터럴 하나 | **또 다른** 리터럴 |

주석으로 「동일」이라 적은 것이 동일함을 지켜 주지 않는다는 증거다. 정본을 세우는 일의 값은
여기에 있다.

## 이 문서가 다루지 않는 것

**바닥의 점 격자.** 간격 24 · 점 2 이고 색은 `color-node-canvas-dot` 이 이미 갖는다.
컴포넌트가 아니라 **패턴 채움**이라 component set 으로 세우지 않는다. 다만 그 변수의 라이트 값이
제품과 다르다 — 자세한 것은 `design/updates/README.md` 의 이 회차 항목.

**정렬 스냅 가이드.** 제품이 아직 이름 없는 색 리터럴 하나로 그린다. 이름을 정하는 일은 새
프리미티브를 세우는 일이고, 그것은 토큰 파이프라인과 Figma 변수 컬렉션을 함께 움직이는 별건이다.

## Properties

정본은 제품 `V2EdgeLayers` 의 prop 이다. 좌표 넷은 두 핸들이 정하는 **데이터**이므로 Figma 축이
되지 않는다.

| prop | 값 | 기본 | 뜻 |
| --- | --- | --- | --- |
| `edgeTone` | 채널 일곱 중 하나 | `default` | 실선·쉬머·번짐의 색을 함께 정한다 |
| `edgePath` | SVG path | 없음 | React Flow 가 두 핸들에서 만든 베지에 |
| `sourceX`/`sourceY`/`targetX`/`targetY` | 수 | 없음 | 쉬머 그라디언트의 이동 축을 정한다 |
| `hovered` | boolean | `false` | 실선 색과 쉬머 한가운데 stop 의 불투명도를 올린다 |
| `strokeWidth` | 수 | 2 | 흐름 좌표계 두께. 변환 밖에서 그릴 때만 줌을 곱해 넘긴다 |
| `shimmerEnabled` | boolean | `true` | 끄면 실선만 남는다. 성능 스위치다 |

| Figma | 타입 | 코드 대응 |
| --- | --- | --- |
| `Tone` | variant 7 | `edgeTone` |
| `State` | variant 2 | `hovered` |

`edgePath` 와 좌표 넷은 Figma 에 대응이 없다. 변형이 그리는 곡선은 시편이며 프레임 좌우에 8 씩
여백을 남겨 획이 프레임 밖으로 새지 않게 잡아 둔 것이다.

## States

| 상태 | 무엇이 바뀌나 |
| --- | --- |
| Default | 채널 색 실선. 쉬머 한가운데 stop 이 낮은 값 |
| Hover | 네 톤은 획 위에 흰 잉크 한 겹이 얹히고, **일곱 톤 모두** 쉬머 한가운데 stop 이 올라간다 |
| Preview(연결 드래그 중) | 같은 레이어를 그대로 쓴다. 톤은 도착 핸들이, 없으면 출발 핸들이 정한다 |
| Invalid(꽂을 수 없는 자리) | 선 자체는 그대로고 감싸는 그룹이 흐려지며 채도가 낮아진다 |
| Shimmer off | 캔버스의 엣지가 많아지면 쉬머가 통째로 꺼지고 실선만 남는다 |

**Figma 에 있는 것은 앞의 둘뿐이다.** 뒤의 셋은 엣지가 아니라 엣지를 감싸는 층이 바꾸는 것이라
이 component set 의 축이 아니다.

## Content

- **보이는 글자가 없다.** 선 하나이며 라벨도 툴팁도 붙지 않는다.
- 호버할 때 뜨는 삭제 버튼만 문구를 갖는다. 그 문구는 이 컴포넌트가 아니라 그 버튼의 것이고,
  제품에서 i18n 메시지로 `aria-label` 에 실린다.

## Accessibility

- **연결선은 보조기술에 노출되지 않는다.** 그림이고, 뜻은 두 노드가 갖는다.
- **색만으로 채널을 말한다.** 일곱 톤을 가르는 것이 색뿐이라 색각 이상에서 image 와 audio 를
  구분할 단서가 없다 — SC 1.4.1 결손이다. 채널을 형태(파선 · 굵기)나 라벨로도 말하는 방법은
  아직 정해지지 않았다. **레시피가 채울 칸이 아니다**(위 판정) — 채널을 색 말고 무엇으로도
  말하려면 조형 자체가 바뀌어야 하고, 그것은 제품 `V2EdgeLayers` 와 Figma 변형을 함께
  움직이는 일이다.
- **키보드로 연결선을 고를 수 없다.** 호버로만 삭제 버튼이 뜨므로 포인터가 없으면 연결을 지울
  길이 없다 — SC 2.1.1 결손이다.
- 쉬머는 무한 반복 애니메이션이다. `prefers-reduced-motion` 분기가 **없다** — 제품은 엣지 수로만
  끈다. SC 2.3.3 결손이다.

「Hover 의 흰 잉크가 `hoverLiftAlpha` 이고 그 색이 채널 없는 톤의 실선과 같다」 넷이다.

아래 목록의 1·2·3·8 은 `verify-figma-parity` 가 이미 Figma 쪽에서 잰다.

**남은 5·6·7 은 아무도 재지 않는다.** 그리고 그 자리는 **레시피가 서기를 기다리는 자리가
아니다** — 레시피는 서지 않는다(위 판정). 주기 · 번짐 반경 · 히트 영역 셋 다 제품이 SVG
속성으로 갖는 값이라, 재려면 캔버스에 노드 둘을 놓고 엣지를 실제로 그리는 **제품 쪽 탐침**이
서야 한다. 계약의 `$noProductRender` 가 canvas-edge 를 그 사유로 이미 면제하고 있고, 그
면제를 지우는 회차가 이 셋을 함께 연다.

2. `Tone` 일곱 칸의 실선이 각각 그 채널 토큰을 문다 — accent 램프를 직접 읽지 않는다.
3. `State=Hover` 가 네 톤에서 흰 잉크 한 겹을 더하고, 나머지 세 톤에서는 아무 색도 바꾸지 않는다.
4. 쉬머 하이라이트가 채널 램프의 200 칸이다.
5. 쉬머 주기가 한 값이다 — 사본마다 다르지 않다.
6. 번짐 반경이 톤 표 그대로다.
7. 히트 영역이 보이는 선보다 넓다.
8. Figma 되읽기에서 raw fill · raw stroke 가 각각 0 이다.
