# Figma 화면 조립 규칙

> 작업 절차 전체(정본이 어디인지 · 무엇부터 읽는지 · 끝나고 무엇을 세는지)는
> `.claude/skills/klipse-figma-transplant/SKILL.md` 에 있다. 이 문서는 그중 **조립 규칙**만 담는다.

토큰·컴포넌트·패턴 문서는 **무엇을 그릴지**를 정한다. 이 문서는 **Figma에서 그것을 어떻게
조립하는지**를 정한다. 값이 맞아도 조립이 틀리면 화면은 틀린다 — 2026-08-21의 실패는 전부
값이 아니라 조립 층에서 났다.

## 1. 변수를 페인트에 묶을 때

**`setBoundVariableForPaint` 에 노드에서 읽어온 페인트를 그대로 넘기면 불투명도가 1로 초기화된다.**
실측으로 확인했다 — `opacity: 0.5` 인 페인트를 넘기면 `1` 이 되어 돌아온다. 새로 만든 리터럴을
넘기면 보존된다.

```js
// 틀림 — 알파가 사라진다
n.fills = n.fills.map((p) => figma.variables.setBoundVariableForPaint(p, "color", v));

// 맞음 — 리터럴을 새로 만들고, color 에는 그 변수가 그 모드에서 풀리는 실제 값을 넣는다
const c = resolve(v, mode);
n.fills = [
  figma.variables.setBoundVariableForPaint(
    { type: "SOLID", color: { r: c.r, g: c.g, b: c.b }, opacity: p.opacity ?? 1,
      visible: p.visible !== false, blendMode: p.blendMode ?? "NORMAL" },
    "color", v,
  ),
];
```

이 규칙을 어겨 **묶인 페인트 7,665개의 반투명이 한 번에 사라졌다.** 옅은 틴트가 전부 불투명
덩어리가 되어 흰 버튼 위 흰 글자, 검은 카드 위 검은 글자가 98곳 생겼다.

**`color` 에 실제 값을 넣는 이유**는 따로 있다. 바인딩이 어떤 이유로 렌더에 반영되지 않으면
저장된 색이 보인다. 바탕을 검정으로 두면 그 자리가 검정으로 보인다 — 실제로 앰버 칩의 글자가
검정으로 렌더됐다. 저장색은 항상 변수 값과 같게 유지한다.

**`visible` 도 반드시 넘긴다.** 새 리터럴은 기본이 `visible: true` 라, 숨어 있던 페인트를
매핑하면 그것이 켜진다. 임포트된 SVG의 숨은 흰 배경면이 이렇게 살아나 워드마크 뒤에 회색
상자가 생겼다.

## 2. 알파는 페인트가 아니라 변수에 담는다

제품은 `rgb(var(--gray-000-rgb) / 12%)` 처럼 **바탕색 토큰 + 사용처 알파**로 쓴다. Figma에서는
그 조합을 **알파를 품은 변수**로 세운다 — `gray/000 · a12`.

- 페인트 불투명도에 의존하면 1번 규칙의 사고에 다시 당한다.
- 변수 이름이 제품 표기와 1:1로 읽힌다.
- 설명에 `제품 표기 \`rgb(var(--gray-000-rgb) / 12%)\`` 를 적어 근거를 남긴다.

토큰 자체가 알파를 품은 경우(`--louis-color-stroke-hairline` 등)는 변수 하나로 끝난다.
(이 자리의 예로 적혀 있던 `--dropdown-frame`은 제품에 없다 — P#1이 걷어냈고 헤어라인 정본은
LOUIS가 소유한다.)

## 3. 아이콘은 반드시 라이브러리 컴포넌트의 인스턴스다

**손으로 도형을 그려 아이콘 자리를 채우지 않는다.** 컴포넌트를 만들어 두고 화면에는
`RECTANGLE + VECTOR` 를 그려 넣은 사례가 있었다 — 마스터를 고쳐도 화면이 안 따라온다.

- 아이콘 슬롯의 자식은 `INSTANCE` 여야 한다. `createInstance()` 로 넣는다.
- 인스턴스 이름을 화면마다 다르게 짓지 않는다(`icon/X` 와 `glyph/X` 를 섞지 않는다).
- 라이브러리에 없는 글리프가 필요하면 **먼저 컴포넌트를 만들고** 인스턴스를 쓴다.

## 4. 아이콘 획 두께 = 표시 크기 / 16

화면상 획은 **표시 크기의 1/16**이다. 16px → 1, 20px → 1.25, 24px → 1.5, 32px → 2.
**14px 만 예외로 0.88** 이다(비례값 0.875가 아니라 디자인 확정값).

**Figma의 `resize()` 는 획 두께를 줄이지 않는다.** 32 격자에 획 2.4인 글리프를 20px 자리에
`resize` 로 놓으면 획 2.4가 그대로 남아 두 배 가까이 두꺼워진다. `rescale()` 을 쓰거나 배치 뒤
위 규칙으로 다시 계산한다.

소스 SVG의 `stroke-width` 를 비례 축소하는 것으로는 부족하다 — 원본이 2.4든 1.5든 **표시 크기만
보고** 정한다.

## 5. 임포트한 SVG의 컨테이너 면은 지운다

`createNodeFromSvg` / 에셋 업로드로 들어온 아이콘은 루트 프레임에 **숨은 흰 배경면**을 달고 온다.
벡터 자식이 있는 아이콘 컨테이너의 `fills` 는 비운다. 도형은 벡터가 그린다.

## 6. 이름으로 노드를 고르지 않는다

노드 이름에 자식 설명을 적어 두면(`uploadDropZone (compact: 글리프 | 텍스트 2줄 …)`) 이름 기반
정규식이 **컨테이너를 아이콘으로 오인한다.** 실제로 두 번 발생해 384px 컨테이너의 획이 24가 됐다.

- 아이콘을 고를 때는 **가장 안쪽** 매칭 노드를 쓴다(자식에 또 매칭이 있으면 그쪽이 진짜다).
- 크기 상한을 건다(아이콘은 64px를 넘지 않는다).
- 고친 결과를 크기별로 집계해 눈으로 확인한다.

## 7. 조립은 오토레이아웃으로 한다

컨테이너는 오토레이아웃이 기본이다. 절대배치는 **제품이 실제로 `position: absolute` 인 자리**에만
쓴다(오버레이, 배지, 고정 바, 마스크 레이어).

- 간격은 `itemSpacing` 으로 준다. **간격을 나타내는 빈 프레임을 만들지 않는다** — 제품에 그런
  요소가 없다.
- 항목마다 간격이 다르면(`margin-top` 이 항목별로 붙는 경우) **중첩**한다. 안쪽 스택이 작은
  간격을, 바깥 스택이 큰 간격을 갖는다.
- `flex: 1` 스페이서는 `primaryAxisAlignItems = "SPACE_BETWEEN"` 으로 옮긴다.
- `justify-content` / `align-items` 는 `primaryAxisAlignItems` / `counterAxisAlignItems` 로 옮긴다.

## 8. 리터럴은 변수에 묶지 않는다

제품이 `bg-[#000]` · `bg-[#0093ff]` · `bg-[rgb(0_0_0/55%)]` 처럼 **토큰이 아닌 리터럴**을 쓰는
자리가 있다. 그 자리는 Figma에서도 리터럴로 둔다. 값이 같다고 토큰에 묶으면 모드를 바꿀 때
같이 움직여 틀린다.

노드 이름에 `· #0093ff 리터럴` 처럼 적어 다음 사람이 다시 묶지 않게 한다.

## 9. 모드는 값이 실제로 갈리는 축에만 만든다

모드를 늘리기 전에 **열끼리 값을 비교**한다. 값이 같은 열은 모드가 아니다.

- 실측 사례: 팔레트 컬렉션의 7개 모드 중 **실제로 구분되는 열은 2개**였다. 나머지 5개는
  값이 완전히 같아 패널만 3.5배 넓혔다.
- 차이가 변수 두세 개뿐이라면 모드 대신 **그 변수의 설명에 값을 적는다**.
- 남긴 모드마다 "왜 접히지 않는가"를 컬렉션 설명에 쓴다.

## 10. 텍스트는 스타일로 붙인다

Figma의 텍스트 스타일은 **부분 재정의를 허용하지 않는다** — 스타일을 적용한 뒤 줄높이나 자간을
바꾸면 스타일 연결이 끊긴다.

- 제품이 실제로 재정의하는 자리(`leading-[1]!`, `letter-spacing: 0!`)는 **전용 스타일**을 만든다.
- 제품에 없는 크기·줄높이를 임의로 만들지 않는다. 램프 밖 값이 나오면 그것이 제품에 있는지
  먼저 확인한다.

## 11. 매번 확인하는 것

화면을 조립하거나 고친 뒤 아래를 기계로 센다. 눈으로 대신하지 않는다.

| 항목 | 통과 기준 |
| --- | --- |
| 안 보이는 글자 (글자색 대 배경 대비 < 2:1) | 0 |
| 끊긴 변수 바인딩 | 0 |
| 아이콘 획 규칙(표시 크기/16) 위반 | 0 |
| 아이콘 슬롯의 비-인스턴스 자식 | 0 |
| 저장색과 변수 값의 불일치 | 0 |
| 안 묶인 색 | 제품이 리터럴로 쓰는 자리만 |

대비를 셀 때는 **바인딩된 페인트의 저장색이 아니라 변수가 그 모드에서 푸는 값**을 쓴다. 저장색을
읽으면 오탐과 누락이 함께 생긴다.


## 12. 프로그레시브 블러는 Figma의 점진적 배경 블러로 쓴다

제품은 `backdrop-filter: blur(N)` 에 `mask-image: linear-gradient(...)` 를 씌워 블러를 점진적으로
없앤다. 그라디언트 **면**으로 흉내 내지 않는다 — Figma에 진짜 기능이 있다.

```js
n.fills = [];                       // 마스크를 흉내 낸 그라디언트는 걷어낸다 (제품엔 배경이 없다)
n.effects = [{
  type: "BACKGROUND_BLUR", blurType: "PROGRESSIVE",
  radius: 12,        // 마스크가 불투명한 쪽의 블러 세기
  startRadius: 0,    // 마스크가 투명한 쪽
  startOffset: { x: 0.5, y: 1 },    // 투명한 끝 (정규화 좌표)
  endOffset:   { x: 0.5, y: 0.4 },  // 불투명해지는 지점
  visible: true,
}];
```

`mask-image: linear-gradient(to bottom, black 40%, transparent 100%)` 는
`startOffset {0.5, 1}` → `endOffset {0.5, 0.4}` 다. 가로 마스크면 x 를 쓴다.

**블러 레이어의 z 순서를 확인한다.** `::before` 는 내용 **뒤**다. 앞에 두면 그 아래 글자가 흐려진다.

## 13. 아이콘은 제품 전수를 라이브러리에 올린다

`public/icons/*.svg` 만으로는 부족하다. 제품의 아이콘은 세 곳에 흩어져 있다.

| 출처 | 개수(2026-08-22) | 비고 |
| --- | --- | --- |
| `public/icons/*.svg` | 61 | 파일 |
| `public/*.svg` (루트) | 23 | 브랜드·프로바이더 자산 포함 |
| 컴포넌트 안의 인라인 `<svg>` | 203 | 파일이 없다 — 소스에서 추출해야 한다 |

인라인 글리프는 `.tsx` 에서 `<svg>` 블록을 뽑아 JSX 표현식을 정리한 뒤 올린다. **JSX 표현식을
지우고 나면 `d=` · `cx=` 처럼 값이 빈 속성이 남는다** — 그대로 올리면 업로드가 실패하고, 업로드
URL은 실패해도 소비된다. 올리기 전에 값 없는 속성과 필수 속성을 잃은 요소를 제거한다.

단색 글리프(`currentColor`)는 `gray/000` 에 묶고, 여러 색을 쓰는 브랜드 자산은 원본 색을 지킨다.
색 종류를 세어 자동으로 가른다.

## 14. 길이가 긴 화면은 높이를 뷰포트에 가두지 않는다

랜딩·문서·목록처럼 세로로 긴 화면은 프레임 높이를 1080 에 고정하지 않는다. 세로 오토레이아웃에
`counterAxisSizingMode`/`primaryAxisSizingMode` 를 `AUTO`(hug)로 두어 내용 길이만큼 늘린다.
뷰포트 높이에 가두면 아래 내용이 잘려 검토할 수 없고, 잘린 것을 "없는 것"으로 오인하게 된다.

폭은 고정한다(1920 / 402). **높이만** hug 다.

## 15. 화면 고정(fixed) 레이어는 마지막 자식으로 둔다

GNB · 상단 블러 판 · 토스트처럼 `position: fixed` 이고 z-index 가 본문보다 높은 요소는 프레임의
**마지막 자식**이어야 한다. Figma 는 자식 순서대로 칠하므로, 문서 순서대로 먼저 넣으면 뒤에 오는
본문 섹션이 그 위를 덮어 아예 보이지 않는다. 실제로 `/pricing` 에서 GNB 가 통째로 사라졌다.

절대배치(`layoutPositioning = "ABSOLUTE"`)는 위치만 빼는 것이지 **칠 순서를 바꾸지 않는다.**

## 16. 획 규칙은 단색 UI 아이콘에만 적용한다

4번의 「획 = 표시 크기 / 16」은 `currentColor` 를 따르는 **단색 선 아이콘**의 규칙이다.
여러 색을 쓰는 브랜드 타일(`public/Text.svg` 같은 앱 아이콘, 로고, 프로바이더 마크)은 원본 아트워크가
고정이라 비율대로 축소해야 하고, 그 안의 획도 함께 줄어든다. 이런 자산에 4번을 강요하면 그림이 깨진다.

검증 스크립트는 컴포넌트 이름이 `logo/` 로 시작하거나 설명에 「브랜드 자산」·「다색」이 있으면 4번에서
제외한다. 새 브랜드 자산을 올릴 때 설명에 그 표기를 반드시 남긴다.

## 17. 사양서의 `literal:#hex` 주석에 속지 않는다

사양서가 「면 `--accent-mint-500`(literal:#00c68e)」처럼 적을 때 괄호 안은 **그 토큰이 지금 푸는 값**일
뿐, 제품이 리터럴을 쓴다는 뜻이 아니다. 그대로 리터럴로 넣으면 테마를 갈아도 색이 안 따라온다.
실제로 이 함정으로 582개 페인트가 토큰 대신 하드코딩으로 들어갔다.

**제품 코드에 `var(--x)` 가 보이면 변수에 묶는다.** 리터럴로 두는 건 코드에도 `#hex` / `rgb(...)` 가
직접 박혀 있을 때뿐이고, 그때는 노드 이름에 `literal:` 을 적어 다음 사람이 재검할 수 있게 한다.

## 18. 검증 산식이 틀리면 통과도 실패도 믿을 수 없다

11번 표를 세는 스크립트에서 실제로 났던 오탐 셋:

| 함정 | 증상 | 바로잡는 법 |
| --- | --- | --- |
| `primaryAxisAlignItems === "SPACE_BETWEEN"` 인 컨테이너에 `itemSpacing` 을 더함 | 가로 넘침 536건 오탐 | SPACE_BETWEEN 이면 간격을 0 으로 센다 |
| 변수에 묶인 페인트의 알파를 두 번 곱함 | 글자가 실제보다 어둡게 계산돼 대비 오탐 | Figma 가 `paint.opacity` 를 변수 알파와 동기화한다 — **둘 중 하나만** 쓴다 |
| 그라디언트 면을 배경으로 합성하지 않음 | 그라디언트 버튼 위 흰 라벨이 「대비 1.0」으로 잡힘 | 스톱 색의 평균을 배경으로 합성한다 |

또 대비를 셀 때 **조상의 `explicitVariableModes` 를 따라 내려가며 유효 모드를 갱신**해야 한다.
프레임 모드만 보면 램프가 뒤집히는 구간(`#pricing-faq`, 랜딩 본문, 푸터)이 전부 틀리게 계산된다.

## 19. 형제 둘 다에 세로 FILL 을 주지 않는다

같은 행에 나란히 놓인 카드 둘을 「높이 맞춤」하려고 **양쪽 다** `layoutSizingVertical = "FILL"` 로 두면
높이를 정할 주체가 사라져 컨테이너가 접힌다(`/subscription` 에서 크레딧 카드가 통째로 눌렸다).

**높은 쪽을 HUG 로 두고 낮은 쪽만 FILL** 로 둔다. 그러면 부모가 높은 쪽 높이로 hug 하고 낮은 쪽이
거기에 맞춰 늘어난다.

## 20. 보드 정보구조 — 자산과 화면은 같은 페이지에 두지 않는다

한 페이지에 프레임 95 + 컴포넌트 322 를 같이 두면 겹침이 **223건**(프레임×컴포넌트 217 · 컴포넌트끼리 6)
생긴다. 실제로 그렇게 됐다. 컴포넌트는 어휘고 프레임은 문장이라 유지보수 단위가 다르다.

### 페이지 — 사용자 여정 순

| 페이지 | 담는 것 |
| --- | --- |
| `00 · START HERE` | 보드 규약 · 라우트 색인 · 이 보드에 없는 것 |
| `01 · 획득` | 랜딩 · 마케팅 · 법무 |
| `02 · 가입` | 인증 |
| `03 · 제작` | 앱 셸 |
| `04 · 결제` | 과금 |
| `05 · 운영` | 어드민 · 라우트 경계 |
| `90 · ASSETS` | 화면에서 뽑은 자산 전수 (출처별 섹션 — logo · tile · icon · root · `.glyph` · `.authored`) |
| `99 · 보류` | 범위 밖 (정본이 다른 저장소인 것) |
| `DS · Foundations` | 색 · 타이포 · 간격 등 기반 값의 표본 |
| `DS · Components` | 디자인 시스템 component set 전수 (`figma/readback.json` 의 `components` 가 이 페이지다) |
| `DS · Icons` | 아이콘 component 전수 |

**앞의 여덟은 「제품 화면」이고 뒤의 셋은 「디자인 시스템 어휘」다.** 접두가 갈라 준다 —
숫자 접두(`00`~`99`)는 제품 여정, `DS ·` 접두는 시스템 자신의 정본이다. `90 · ASSETS` 와
`DS · Components` 를 헷갈리지 않는다: 90 은 **화면에서 뽑아낸 것**을 출처별로 모아 둔 자리이고,
DS 는 **시스템이 소유한 계약**이라 `verify-figma-parity` 가 대조하는 대상이다.

라우트 알파벳순으로 깔지 않는다. 알파벳순은 **이름을 이미 아는 것**을 찾을 때만 빠르고, 그건 캔버스가
아니라 `00.2 라우트 색인` 표가 할 일이다. 캔버스는 「결제 실패 화면」처럼 **의미로 찾을 때** 빨라야 한다.

### 섹션 이름은 사양 문서로 가는 조인 키다 — 보드는 제3의 분류 체계를 만들지 않는다

```
<§10.N.n> · <라우트 글롭> · <한국어 이름>
```

페이지는 사람이 찾기 좋은 **여정 순 묶음**이고, 섹션은 사양 문서 `migration/product-screens/10.*.md`
(46 인스코프 라우트)에 **1:1 로 붙는 키**다. 페이지가 한 §10.N 을 둘로 쪼개면(애널리틱스와 어드민이
둘 다 §10.12) 양쪽 섹션이 같은 키를 달고 뒤에 무엇을 담았는지 적는다.

**보드가 자체 분류 번호를 새로 만들면 그 순간 정본이 셋으로 갈라진다**(코드 라우트 트리 · 사양 문서 ·
보드). 섹션 키를 문서 절 번호로 못박는 이유가 이것이다.

문서 절이 없는 화면은 키 대신 사유를 적는다 — 지어내지 않는다.

| 표기 | 뜻 | 예 |
| --- | --- | --- |
| `⚠ 결번` | 어느 §10.N 도 소유하지 않는다 | `404` · `error` · `global-error` (10.4.md 가 「이 절의 범위 밖」이라 명시) |
| `⚠ 미등록` | 문서에도 커버리지 등급에도 없다 | `/creative-media{,-admin}` — **등급을 지어내지 말 것** |
| `⚠ 권위 충돌` | 문서가 소유한다고 적지만 화면 정본이 다른 저장소다 | `/docs` (§10.4 vs klipse-docs 레포) |

### 섹션 이름 끝의 `L3`/`L2` 는 보드가 정하지 않는다

커버리지 등급은 `migration/product-screens/route-coverage-levels.json` 이 정본이다.
**L3 은 「문서만 보고 재구현」 검증을 최근 2라운드 연속 통과한 그룹에만 준다** — 1회 통과는 판정
흔들림과 구분되지 않는다(실제로 §10.2·10.8·10.11·10.12 가 통과→불통과로 뒤집혔다).

섹션 색도 같은 값에서 나온다 — 초록 L3 · 호박 L2 · 붉음 등급 없음. **등급이 바뀌면 보드를 손으로
고치지 말고 JSON 에서 다시 찍는다.** 보드가 등급을 저작하면 그 순간 정본이 둘이 된다.

등급을 **지어내지 않는다.** 커버리지 파일에 없는 라우트는 `등급 없음` 이다. 지금 7개가 그렇다 —
`/nodecanvas?project=`(상태) · `/admin/coupons/[id]/print` · `/creative-media{,-admin}` ·
404 · error · global-error.

### 상시 검산식

```
라우트 프레임 = 보드 항목 × 2 − (반응형 분기가 없는 단일 프레임 수)
상태 프레임   = 상태 보드의 상태 수 × 2
총 프레임     = 라우트 프레임 + 상태 프레임
```

지금은 라우트 `48 × 2 − 1 = 95`, 상태 `6 × 2 = 12`, 합 **107** 이다. 이 등식이 깨지면 프레임이
빠졌거나 중복된 것이다.

**축을 둘로 쪼갠 이유**(2026-09-01 정정). 원래 이 절은 `48 × 2 − 1 = 95` 하나였고 그 95 를 「총
프레임 수」라고 불렀다. 보드는 그보다 12 개 많다 — `/highlight/[projectId]` 가 라우트 색인에서는
항목 **하나**(프레임 2개)인데, 보드에는 `__phase` 6 상태가 뷰포트 둘씩 따로 그려져 있기 때문이다.
95 를 총계로 읽으면 그 12 개가 「중복」으로 보여 **지우려 들게 된다.** 상태 보드는 중복이 아니라
라우트 축이 표현할 수 없는 축이므로, 두 항을 따로 세고 합만 비교한다.

상태 프레임 12 는 산 숫자가 아니라 생성물에서 읽는다 — 보드에 그려 넣은 것이 그 생성물이다.

```
node -e 'const s=require("./figma/app-screens.plan.json").screens;
  console.log(s.filter(x => x.route.includes("__phase")).length)'   # → 12
```

같은 파일이 프레임 id 도 갖는다(`1064:3132` ~ `1064:3143`). **보드 텍스트에 총계를 적을 때는 이
두 항을 나란히 적는다** — 라우트 색인 보드의 안내 TEXT 는 아직 「95개 프레임」 한 수만 적고 있어
같은 함정을 재생산한다(미해결, 라이브 Figma 수정 필요).
**§10.N 인스코프 46 과 보드 항목 48 이 다른 이유는 `00.4` 대조표에 적어 둔다** — 적어 두지 않으면
다음 사람이 48 을 「고치려」 든다. 차이는 리다이렉트 −2 · 범위 밖 docs 하위 −3 · 상태 +1 ·
문서 미소유 +1 · 미등록 +2 · 결번 +3 이다.

### 배치 산식 (높이 216~10122 를 겹치지 않게 놓는 유일한 규칙)

```
DESK_W 1920 · MOB_W 402 · PAIR_GAP 80 · MOB_DX 2000
COL_PITCH 2800 · COLS 4 · ROW_GUT 600
SEC_W 11200 · SEC_PAD_X 160 · SEC_PAD_TOP 240 · SEC_PAD_BOT 200 · SEC_GAP_Y 800

x_desktop(i) = 160 + (i mod 4) × 2800      # 허용 x 8개뿐
x_mobile(i)  = x_desktop(i) + 2000
rowTop(0)    = 240
rowTop(r+1)  = rowTop(r) + ceil100( 그 행 프레임 높이의 최댓값 ) + 600
```

- **한 라우트 = 한 열.** 데스크톱과 모바일을 80px 간격으로 나란히 두고 **윗변을 같은 y 에 맞춘다.**
  가운데 정렬 금지 — GNB 높이 대조가 가장 잦은 측정인데 매번 오프셋을 암산하게 된다.
- **max() 를 쓴다.** `/mypage/upgrade` 는 데스크톱 2492 · 모바일 3276 으로 모바일이 더 높다.
  데스크톱 기준으로 행 높이를 잡으면 784px 겹친다.
- Section 자식의 x/y 는 **섹션 상대 좌표**다(실측 확인). 절대 좌표로 계산하면 전부 어긋난다.
- 섹션은 중첩하지 않는다. 최대 2층(페이지 > 섹션).

## 21. 아이콘 마스터에 잉크가 없으면 화면에서 사라진다

인라인 SVG 에서 추출한 마스터는 `fill`/`stroke` 가 비어 있는 경우가 있다(제품에서는 `currentColor`
로 소비처가 칠하기 때문). 이 마스터는

- Assets 패널·라이브러리 브라우저에서 **빈칸으로 보이고**,
- 색을 덮어쓰지 않은 인스턴스가 **화면에서 통째로 안 보인다.**

실제로 마스터 42개가 비어 있었고 그 때문에 화면 위 아이콘 **90개가 렌더되지 않았다**(사이드바 `+`
38개, 푸터 소셜 12개, 비디오 에디터 툴바 22개 등). 눈으로는 "여백이 넓네" 로 보여서 오래 살아남는다.

**규칙**: 마스터에는 반드시 기본 잉크(`gray/000`)를 준다. 인스턴스는 제품의 `currentColor` 규칙대로
**가장 가까운 텍스트의 색을 상속**시키고, 텍스트가 없는 자리(소셜 버튼 등)만 제품 값을 명시한다.

검증: 아이콘 인스턴스의 도형 자식 중 칠해진 것이 하나도 없으면 실패. 이 항목을 11번 표에 추가한다.

## 22. 이름이 같다고 같은 자산이 아니다 — 합치기 전에 모양을 센다

일괄 추출은 소스 파일 이름으로 컴포넌트를 명명하므로, 한 파일에서 글리프 여러 개가 나오면 **같은
이름이 여러 벌** 생긴다. 이 보드에서는 9종 32개였는데 **모양 서명(자식 타입 · 크기 · path 길이)을
세어 보니 32개가 전부 서로 달랐다.** `icon/GnbWordmarkLogo` 13벌은 지구본 · 달 · 문서 · 로그아웃 ·
사이드바 · 다이아몬드 · 해 · 톱니 · 말풍선 · 화살표 · 롤러 · 방패 · 모니터였다.

**절차**: ① 모양 서명으로 묶는다 → ② 서명이 같은 것만 합치고 인스턴스를 옮긴다 → ③ 서명이 다르면
**대조표를 렌더해 눈으로 확인하고 각각 제 이름을 준다.** 번호 접미(`-1`~`-13`)는 최후의 수단이다.

## 23. 프레임 이름이 곧 색인이다

```
<viewport> <W>×<H> — <route> (<상태 판정>)
```

이름만 보고 라우트·뷰포트·실제 크기·상태를 알 수 있어야 한다. 이 보드에서는 프레임 8개가 이름에서
라우트를 잃고 `desktop 1920×1080 — dark` 로만 남아 있었다 — 어느 화면인지 열어 보기 전에는 알 수 없다.

- `W×H` 는 **실제 노드 크기**여야 한다. hug 로 늘어난 뒤 이름을 갱신하지 않으면 색인이 거짓이 된다
  (실제로 `mobile 402×874` 라고 적힌 프레임이 402×1148 이었다).
- 상태 판정이 없는 프레임은 「어느 분기를 그린 것인지 모르는 프레임」이다. 반드시 채운다.
- 자산은 이름 앞에 `출처:` 태그를 붙인 **설명**으로 분류한다. 생김새가 아니라 출처로 가르는 이유는
  「제품의 무엇과 같아야 하나」의 검증 방법이 출처마다 다르기 때문이다(파일 diff ↔ 소스 줄 대조).

### 자산 이름의 접두가 곧 검증 방법이다

`icon/` 을 전부에 붙이면 **「public 에 파일이 있다」는 거짓 신호**가 된다. 실제로 그 거짓 신호가
같은 이름 32개(§22)의 원인이었다 — 파일이 없는 인라인 글리프가 파일 자산과 같은 접두를 달고 있었다.

| 접두 | 출처 | 검증 방법 | 게시 |
| --- | --- | --- | --- |
| `logo/` | 브랜드 자산 | 원본 색 유지 · 획 규칙 미적용 | O |
| `tile/` | `public/*.svg` 다색 앱 타일 | 파일 diff · currentColor 안 먹음 | O |
| `icon/` | `public/icons/*.svg` | 파일 diff | O |
| `root/` | `public/*.svg` (루트) | 파일 diff | O |
| `.glyph/` | 제품 `.tsx` 안의 인라인 `<svg>` | **소스 `file:line` 대조** — 파일이 없다 | X |
| `.authored/` | **출처 없음** — 보드에서 그렸고 제품 원본을 인용하지 못했다 | **불가** | X |

`.` 접두는 Figma 에서 그 컴포넌트를 라이브러리에 게시하지 않는다. 파일로 검증할 수 없는 자산이
다른 파일로 퍼지지 않게 막는 장치다.

**`.authored/` 는 격리 표시지 분류가 아니다.** 여기 남은 것은 「제품 어디서 왔는지 아직 못 찾은
것」이고, 이 컴포넌트로 값을 재면 **존재하지 않는 제품 사실을 재는 것**이다. 소스를 찾는 즉시
`file:line` 을 설명에 적고 `.glyph/` 로 옮긴다. 이 묶음이 비는 것이 목표다.

## 24. 합성 제품 장면은 고정 빌드에서 직접 잰다

완성된 제품 장면은 클래스 문자열 하나의 합이 아니다. 이미지의 intrinsic ratio, 뷰포트에 따른
컨테이너 높이, 중첩 컴포넌트, 축소 캔버스가 함께 최종 지오메트리를 만든다. 이 중 하나라도 있는
장면을 정적 클래스 하네스에서 재구성해 잰 값은 Figma 입력으로 쓸 수 없다.

- 구조 카탈로그에는 태그·부모자식·표본 텍스트만 둔다. 간격·크기·색·반경은 넣지 않는다.
- 수치와 색은 고정 커밋의 clean production build를 실제 목표 뷰포트에서 렌더한 생성물만 쓴다.
- 생성물은 제품 커밋, 빌드 영수증, 측정 뷰포트, 모든 선언 노드의 rect·계산 스타일, 자산 해시와
  인라인 SVG geometry를 함께 기록한다. 사람이 고치지 않는다.
- 제품 저장소나 빌드가 없거나, checkout이 dirty이거나, 빌드 커밋·영수증·sourcemap이 고정
  커밋과 다르면 **검증 불가가 아니라 실패**다. `SKIPPED`와 exit 0은 허용하지 않는다.
- 측정 생성물이 초록이어도 Figma 구현 완료를 뜻하지 않는다. 대상 컴포넌트 조립과 되읽기 대조가
  모두 끝나기 전까지 manifest의 Figma 상태를 올리지 않는다.

현재 구조 원천은 [`figma/product-specimens.json`](../../figma/product-specimens.json), 측정 생성물은
[`migration/product.scenes.json`](../../migration/product.scenes.json), 생성·검사는
[`scripts/measure-product-scenes.mjs`](../../scripts/measure-product-scenes.mjs)가 소유한다.

## 25. 인스턴스로 바꿀 때 컴포넌트가 «연» TEXT 속성은 반드시 채운다

측정 서브트리를 인스턴스로 치환하면 자식을 버린다 — 컴포넌트가 제 속을 그리기 때문이다. 그런데
버려지는 자식 안에 **컴포넌트가 알 수 없는 것**이 하나 있다: 그 자리의 라벨이다.

채우지 않으면 마스터의 기본 라벨(`버튼`)이 그대로 남고, HUG 인 자리는 그 글자를 물어 접힌다.
실측(2026-09-02): `/settings` 데스크톱의 Button 7개가 전부 「버튼」으로 나와 폭이
113.3·136.95·156.55·184.3·48·138.67·75.27 에서 **49 로** 접혔다. 라벨은 payload 에 처음부터
없었으므로 렌더러에는 고칠 수단이 없었다 — 결함은 생성기에 있었다.

- **속성 키를 손으로 적지 않는다.** Figma 는 이름 뒤에 인스턴스 id 를 붙여 키를 만든다
  (`Label#123:4`). 세트의 `componentPropertyDefinitions` 에서 `type === "TEXT"` 인 것을 실행
  시점에 찾는다. `figma/readback.json` 은 그 꼬리를 잘라 담으므로 이름만 안다.
- **못 찾으면 던진다.** 조용히 기본 라벨로 두면 눈으로만 보이는 결함이 되고, 화면 36장에 퍼진다.
- **8번(색·타이포를 인스턴스에 걸지 않는다)에 걸리지 않는다.** 그 규칙은 컴포넌트가 «정한»
  값을 화면이 덮어써서 시스템 쪽 수정이 전파되지 않게 되는 것을 막는다. TEXT 속성은 반대로
  컴포넌트가 **스스로 연 구멍**이라 채워도 전파가 끊기지 않는다.
- **슬롯과 텍스트의 짝이 1:1 이 아니면 짝을 짓지 않는다.** 어느 글자가 어느 슬롯인지는 측정에
  없는 정보다. 짐작해 채우면 화면이 제품과 다른 글자를 말한다.

본문 블록은 이 규칙의 대상이 아니다 — **텍스트가 글자 그대로 같을 때만** 치환하므로 덮어쓸
차이가 정의상 0 이다. 사이드바(`Product/Gnb Desktop Shell`)는 TEXT 속성이 없다.

**상단 바 두 세트는 대상이다(2026-09-13).** 예전에는 「셸은 라벨을 variant 축(`Content=Settings`)이
나른다」고 적었지만 모바일 세트에는 라벨 축이 없어, 라이브 `/archive`·`/subscription` 모바일
보드가 제품과 다른 「Settings」 를 보이고 있었다. 이제 두 세트는 제품 `mainChromePageNav` 필드
이름을 딴 TEXT 속성 `Label`(Single) · `Parent`·`Current`(Trail)를 연다(앱 셸 plan 의
`textProperties`). 속성이 여럿이라 위의 「1:1 이 아니면 짝짓지 않는다」를 **이름**으로 푼다:

- 어느 글자가 어느 속성인지는 그 variant 의 plan `text[].property` 순서가 정한다 — 측정 breadcrumb
  에서 구분자 「/」를 뺀 순서와 같고, 수가 다르면 생성기가 던진다.
- payload 의 라벨 칸은 문자열이 아니라 **세트의 속성 이름 전부를 키로 가진 객체**다. 이 variant 가
  묶지 않은 속성은 null 이다. 렌더러는 파일의 TEXT 속성 이름 집합이 그 키 집합과 다르면 던진다 —
  속성을 아직 열지 않은 옛 세트에 적용하면 조용히 기본 라벨로 남는 대신 멈춘다.
- 세트 단위 속성은 기본값이 하나라, 마스터와 **덮어쓰지 않은 인스턴스는 모두 그 기본값을 보인다.**
  그래서 앱 셸 러너를 적용하면 그 세트를 인스턴스로 쓰는 **모든** 소비처가 속성을 채워야 끝난다 — 화면 보드의
  generated 트리(보드 러너가 채운다), 결제 장면 컴포넌트(그 러너가 채운다), 숨긴 `legacy/<route>` 그룹, 그리고
  **손으로 조립한 허브 보드**(채우는 생성기가 없다). 2026-09-13 라이브에서 허브 보드의 보이는 바가 일곱이었다
  (`/highlight` · `/videoeditor` · `/canvas` 의 두 뷰포트와 `/analytics/instagram` 데스크톱). 「화면 보드·결제
  장면」만 적었던 옛 문장은 이 일곱을 빠뜨렸다.
- **소비처는 생성물이 아니라 라이브에서 센다.** 적용 전에 `figma-screens-live-check --emit --consumers` 로 세트의
  인스턴스를 전부 뽑아 기준선으로 남기고, 적용 뒤 같은 탐침과 `--consumers <전> <후>` 로 보이는 글자 · 크기 · 면이
  바뀐 곳을 찾는다. 인스턴스에서 글자 내용이나 면을 덮어쓴 소비처(허브 일곱이 그렇다)에서 마스터 변경이 어떻게
  번지는지는 Figma 동작에 달려 있어 코드로 추론하지 않는다.

## 26. 아이콘은 크기가 아니라 «서명»으로 부른다

측정 fixture 는 `<svg>` 의 `viewBox` 와 자손 도형의 기하 속성(`d`·`points`·`cx`…)을 담는데,
트리 변환이 `<path>` 를 「스스로 그릴 것이 없는 노드」로 보아 지운다 — 배경도 테두리도 글자도
없기 때문이다. 그래서 Figma 로 가는 spec 에 아이콘이 **크기만 있는 빈 상자**로 남았고, 보드
원장은 39자리를 「어느 아이콘인지 모른다」로 세었다.

- **서명은 지우기 «앞»에서 뜬다.** `glyphSignature`(`scripts/lib/figma-tree-spec.mjs`)가
  `viewBox|tag(attr=value …)|…` 를 측정값 그대로 잇는다. 반올림도 좌표 정규화도 하지 않는다 —
  서명이 같다는 것은 「비슷한 그림」이 아니라 「같은 소스에서 나왔다」를 뜻해야 한다.
- **이름은 손으로 읽는다.** 경로 데이터 비교로는 닿지 않는다: LOUIS 아이콘 31종은
  `<line>`·`<polyline>`·`<circle>`·`<rect>` 로 그려져 있고 제품 글리프는 전부 `<path>` 라
  문자열이 같은 기하가 0 건이다. 이름·클래스는 측정 트리에 없고(있는 것은 감싼 버튼의
  `aria-label` 이며 그것은 자리의 이름이지 그림의 이름이 아니다), 24 상자 1.8 획인 글리프가
  여덟 중 넷이라 크기+획으로도 갈리지 않는다. 조인표는
  `scripts/lib/figma-glyph-identity.mjs` 가 소유하고 `figma/app-screens.plan.json` 에 실린다.
- **payload 에는 이름만 싣는다.** 서명 하나가 최대 900바이트라 39자리면 조각이 갈라진다.
  축약 키는 `v` 이고, 25번의 라벨(`i` 의 셋째 칸)과 같은 결이다.
- **서명이 표에 없으면 던진다.** 조용히 이름 없이 두면 보드에 회색 상자가 하나 더 늘고,
  원장은 그것을 「생성기가 정체를 버렸다」는 이미 틀린 사유로 세게 된다.
- **이름이 붙었다고 인스턴스를 놓는 것은 아니다.** 여덟 서명 중 LOUIS 아이콘을 그대로 무는
  것은 0 건이다 — 둘은 같은 뜻의 아이콘이 있지만 제품이 24 상자 1.8 획의 인라인 글리프를
  그려 `bespoke` 이고(정본은 24 상자 1.5 획 — [DS-D-0021](decisions/DS-D-0021-icon-size-axis.md)),
  여섯은 LOUIS 31종에 대응 그림이 아예 없어 `missing` 이다. 4번·16번의 획 규칙을 어긴 글리프를
  Figma 에만 정본으로 심으면 두 축이 어긋난다 — 그 승격 판정은
  [DS-D-0038](decisions/DS-D-0038-icons-are-an-asset-axis.md)이 아이콘 축의 미결로 남겨 두었다.

## 27. 라이브에 적용하기 전에 구조를 읽고, 적용한 뒤에 라이브를 계획과 대조한다

화면 보드를 지키는 게이트(`check-figma-app-screens` · `verify-figma-board-composition` ·
`check-figma-board-composition`)는 **계획 파일만** 읽는다. 초록은 「러너가 생성물과 같다」이지
「라이브 보드가 러너를 적용한 결과다」가 아니다. 실측(2026-09-13): 라이브 36 보드 중 34 가 열하루 전
커밋 `9f8483a` 의 계획으로 그려져 있었고 archive 두 보드는 어느 커밋과도 같지 않았는데, 어떤
게이트도 말하지 않았다. 같은 날 조사는 인계서의 「적용하면 손으로 놓인 바 `488:658` 을 지운다」가
코드와도 라이브와도 틀렸음을 드러냈다 — 그 바는 이미 숨긴 `legacy/<route>` 그룹 안에 있었다.

**적용 전에 읽는다(읽기 전용):**

- 보드 프레임의 직계 자식이 `generated/<route> <문맥>` 하나와 숨긴 `legacy/<route>` 그룹뿐인지.
  렌더러는 그 이름의 generated 자식만 지우고, legacy 그룹은 **없을 때만** 만든다 — 그룹이 있으면
  새로 생긴 직계 자식을 묶지도 지우지도 않아 흐름 자식으로 남는다.
- 러너가 찾는 **변수 컬렉션 이름**이 파일에 있는지. 라이브 LOUIS 의 컬렉션은 `Klipse Primitive` ·
  `Klipse Semantic` · `Klipse Semantic Color` 셋이고, 은퇴한 `1 · Palette` · `2 · Semantic` 을 찾는
  컴포넌트 러너는 첫머리에서 던진다(앱 셸 러너는 2026-09-13 에 옮겼다).
- 계획이 쓰는 **세트·variant·TEXT 속성**이 파일에 있는지 — `figma-screens-live-check --sets`. 상단 바 두 세트는
  variant 마다 Auto Layout 축(layoutMode · 축 sizing · 헤어라인 레이아웃 포함)까지 앱 셸 계획의
  `layoutContract` 와 대조한다 — 계산된 높이를 FIXED 로 굳힌 옛 세트가 라이브에 남아 있으면 여기서 보인다.
  세트 러너(앱 셸)가 보드 러너보다 먼저다. 순서를 거꾸로 하면 보드 러너가 「variant 를 찾지 못했다」
  또는 「TEXT 속성이 계획과 다르다」로 던진다.
- 세트 러너가 고칠 **세트의 소비처 전부** — `figma-screens-live-check --emit --consumers` 의 기준선. 세트 러너는
  마스터를 고치므로 generated 트리 밖(손 조립 허브 보드 · legacy · 장면 컴포넌트)에도 번진다. 세트 러너를 돌린 뒤
  같은 탐침으로 `--consumers <전> <후>` 를 돌려, 받아들이지 않은 보이는 변화가 0 인지 보고 나서 보드 러너로 간다.
- 적용 직전에 이름 붙은 Figma 버전을 남긴다(`figma.saveVersionHistoryAsync`) — 렌더러는 옛
  generated 트리를 영구 삭제하므로 버전 기록이 유일한 완전 복구 수단이다. 쓰기이므로 승인이 먼저다.

**적용한 뒤에 대조한다:** `node scripts/figma-screens-live-check.mjs --emit --page <PAGE_ID>` 를 페이지마다
읽기 전용 `use_figma` 로 돌리고 `--check <결과…>` 로 계획과 대조해 **계획 보드 전부를 탐침하고 다름 0** 임을
확인한다. 결과 파일을 빠뜨리면 탐침하지 않은 보드를 대고 실패한다 — 「다름 0」은 대조한 보드 수와 함께만
뜻이 있다. 적용에서 일부러 뺀 보드는 `--expect-differ <frameId>` 로 이름을 대고 받는다. 쓰는 법은
[Figma Sync](figma-sync.md) 「화면 보드 라이브 대조」 절이 소유한다. 이 검사는 CI 에 넣지 않는다 —
Figma 접근이 필요하다.
