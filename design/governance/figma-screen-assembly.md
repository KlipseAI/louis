# Figma 화면 조립 규칙

> 작업 절차 전체(정본이 어디인지 · 무엇부터 읽는지 · 끝나고 무엇을 세는지)는
> `.claude/skills/klipse-figma-transplant/SKILL.md` 에 있다. 이 문서는 그중 **조립 규칙**만 담는다.

토큰·컴포넌트·패턴 문서는 **무엇을 그릴지**를 정한다. 이 문서는 **Figma에서 그것을 어떻게
조립하는지**를 정한다. 값이 맞아도 조립이 틀리면 화면은 틀린다 — 2026-08-21의 실패는 전부
값이 아니라 조립 층에서 났다.

## 1. 변수를 페인트에 묶을 때

**`setBoundVariableForPaint` 에 노드에서 읽어온 페인트를 그대로 넘기면 불투명도가 1로 초기화된다.**
실측으로 확인했다 — `opacity: 0.5` 인 페인트를 넘기면 `1` 이 되어 돌아온다. 새로 만든 리터럴을
넘기면 보존된다.

```js
// 틀림 — 알파가 사라진다
n.fills = n.fills.map((p) => figma.variables.setBoundVariableForPaint(p, "color", v));

// 맞음 — 리터럴을 새로 만들고, color 에는 그 변수가 그 모드에서 풀리는 실제 값을 넣는다
const c = resolve(v, mode);
n.fills = [
  figma.variables.setBoundVariableForPaint(
    { type: "SOLID", color: { r: c.r, g: c.g, b: c.b }, opacity: p.opacity ?? 1,
      visible: p.visible !== false, blendMode: p.blendMode ?? "NORMAL" },
    "color", v,
  ),
];
```

이 규칙을 어겨 **묶인 페인트 7,665개의 반투명이 한 번에 사라졌다.** 옅은 틴트가 전부 불투명
덩어리가 되어 흰 버튼 위 흰 글자, 검은 카드 위 검은 글자가 98곳 생겼다.

**`color` 에 실제 값을 넣는 이유**는 따로 있다. 바인딩이 어떤 이유로 렌더에 반영되지 않으면
저장된 색이 보인다. 바탕을 검정으로 두면 그 자리가 검정으로 보인다 — 실제로 앰버 칩의 글자가
검정으로 렌더됐다. 저장색은 항상 변수 값과 같게 유지한다.

**`visible` 도 반드시 넘긴다.** 새 리터럴은 기본이 `visible: true` 라, 숨어 있던 페인트를
매핑하면 그것이 켜진다. 임포트된 SVG의 숨은 흰 배경면이 이렇게 살아나 워드마크 뒤에 회색
상자가 생겼다.

## 2. 알파는 페인트가 아니라 변수에 담는다

제품은 `rgb(var(--gray-000-rgb) / 12%)` 처럼 **바탕색 토큰 + 사용처 알파**로 쓴다. Figma에서는
그 조합을 **알파를 품은 변수**로 세운다 — `gray/000 · a12`.

- 페인트 불투명도에 의존하면 1번 규칙의 사고에 다시 당한다.
- 변수 이름이 제품 표기와 1:1로 읽힌다.
- 설명에 `제품 표기 \`rgb(var(--gray-000-rgb) / 12%)\`` 를 적어 근거를 남긴다.

토큰 자체가 알파를 품은 경우(`--louis-color-stroke-hairline` 등)는 변수 하나로 끝난다.
(이 자리의 예로 적혀 있던 `--dropdown-frame`은 제품에 없다 — P#1이 걷어냈고 헤어라인 정본은
LOUIS가 소유한다.)

## 3. 아이콘은 반드시 라이브러리 컴포넌트의 인스턴스다

**손으로 도형을 그려 아이콘 자리를 채우지 않는다.** 컴포넌트를 만들어 두고 화면에는
`RECTANGLE + VECTOR` 를 그려 넣은 사례가 있었다 — 마스터를 고쳐도 화면이 안 따라온다.

- 아이콘 슬롯의 자식은 `INSTANCE` 여야 한다. `createInstance()` 로 넣는다.
- 인스턴스 이름을 화면마다 다르게 짓지 않는다(`icon/X` 와 `glyph/X` 를 섞지 않는다).
- 라이브러리에 없는 글리프가 필요하면 **먼저 컴포넌트를 만들고** 인스턴스를 쓴다.

## 4. 아이콘 획 두께 = 표시 크기 / 16

화면상 획은 **표시 크기의 1/16**이다. 16px → 1, 20px → 1.25, 24px → 1.5, 32px → 2.
**14px 만 예외로 0.88** 이다(비례값 0.875가 아니라 디자인 확정값).

**Figma의 `resize()` 는 획 두께를 줄이지 않는다.** 32 격자에 획 2.4인 글리프를 20px 자리에
`resize` 로 놓으면 획 2.4가 그대로 남아 두 배 가까이 두꺼워진다. `rescale()` 을 쓰거나 배치 뒤
위 규칙으로 다시 계산한다.

소스 SVG의 `stroke-width` 를 비례 축소하는 것으로는 부족하다 — 원본이 2.4든 1.5든 **표시 크기만
보고** 정한다.

## 5. 임포트한 SVG의 컨테이너 면은 지운다

`createNodeFromSvg` / 에셋 업로드로 들어온 아이콘은 루트 프레임에 **숨은 흰 배경면**을 달고 온다.
벡터 자식이 있는 아이콘 컨테이너의 `fills` 는 비운다. 도형은 벡터가 그린다.

## 6. 이름으로 노드를 고르지 않는다

노드 이름에 자식 설명을 적어 두면(`uploadDropZone (compact: 글리프 | 텍스트 2줄 …)`) 이름 기반
정규식이 **컨테이너를 아이콘으로 오인한다.** 실제로 두 번 발생해 384px 컨테이너의 획이 24가 됐다.

- 아이콘을 고를 때는 **가장 안쪽** 매칭 노드를 쓴다(자식에 또 매칭이 있으면 그쪽이 진짜다).
- 크기 상한을 건다(아이콘은 64px를 넘지 않는다).
- 고친 결과를 크기별로 집계해 눈으로 확인한다.

## 7. 조립은 오토레이아웃으로 한다

컨테이너는 오토레이아웃이 기본이다. 절대배치는 **제품이 실제로 `position: absolute` 인 자리**에만
쓴다(오버레이, 배지, 고정 바, 마스크 레이어).

- 간격은 `itemSpacing` 으로 준다. **간격을 나타내는 빈 프레임을 만들지 않는다** — 제품에 그런
  요소가 없다.
- 항목마다 간격이 다르면(`margin-top` 이 항목별로 붙는 경우) **중첩**한다. 안쪽 스택이 작은
  간격을, 바깥 스택이 큰 간격을 갖는다.
- `flex: 1` 스페이서는 `primaryAxisAlignItems = "SPACE_BETWEEN"` 으로 옮긴다.
- `justify-content` / `align-items` 는 `primaryAxisAlignItems` / `counterAxisAlignItems` 로 옮긴다.

## 8. 리터럴은 변수에 묶지 않는다

제품이 `bg-[#000]` · `bg-[#0093ff]` · `bg-[rgb(0_0_0/55%)]` 처럼 **토큰이 아닌 리터럴**을 쓰는
자리가 있다. 그 자리는 Figma에서도 리터럴로 둔다. 값이 같다고 토큰에 묶으면 모드를 바꿀 때
같이 움직여 틀린다.

노드 이름에 `· #0093ff 리터럴` 처럼 적어 다음 사람이 다시 묶지 않게 한다.

## 9. 모드는 값이 실제로 갈리는 축에만 만든다

모드를 늘리기 전에 **열끼리 값을 비교**한다. 값이 같은 열은 모드가 아니다.

- 실측 사례: 팔레트 컬렉션의 7개 모드 중 **실제로 구분되는 열은 2개**였다. 나머지 5개는
  값이 완전히 같아 패널만 3.5배 넓혔다.
- 차이가 변수 두세 개뿐이라면 모드 대신 **그 변수의 설명에 값을 적는다**.
- 남긴 모드마다 "왜 접히지 않는가"를 컬렉션 설명에 쓴다.

## 10. 텍스트는 스타일로 붙인다

Figma의 텍스트 스타일은 **부분 재정의를 허용하지 않는다** — 스타일을 적용한 뒤 줄높이나 자간을
바꾸면 스타일 연결이 끊긴다.

- 제품이 실제로 재정의하는 자리(`leading-[1]!`, `letter-spacing: 0!`)는 **전용 스타일**을 만든다.
- 제품에 없는 크기·줄높이를 임의로 만들지 않는다. 램프 밖 값이 나오면 그것이 제품에 있는지
  먼저 확인한다.

## 11. 매번 확인하는 것

화면을 조립하거나 고친 뒤 아래를 기계로 센다. 눈으로 대신하지 않는다.

| 항목 | 통과 기준 |
| --- | --- |
| 안 보이는 글자 (글자색 대 배경 대비 < 2:1) | 0 |
| 끊긴 변수 바인딩 | 0 |
| 아이콘 획 규칙(표시 크기/16) 위반 | 0 |
| 아이콘 슬롯의 비-인스턴스 자식 | 0 |
| 저장색과 변수 값의 불일치 | 0 |
| 안 묶인 색 | 제품이 리터럴로 쓰는 자리만 |

대비를 셀 때는 **바인딩된 페인트의 저장색이 아니라 변수가 그 모드에서 푸는 값**을 쓴다. 저장색을
읽으면 오탐과 누락이 함께 생긴다.


## 12. 프로그레시브 블러는 Figma의 점진적 배경 블러로 쓴다

제품은 `backdrop-filter: blur(N)` 에 `mask-image: linear-gradient(...)` 를 씌워 블러를 점진적으로
없앤다. 그라디언트 **면**으로 흉내 내지 않는다 — Figma에 진짜 기능이 있다.

```js
n.fills = [];                       // 마스크를 흉내 낸 그라디언트는 걷어낸다 (제품엔 배경이 없다)
n.effects = [{
  type: "BACKGROUND_BLUR", blurType: "PROGRESSIVE",
  radius: 12,        // 마스크가 불투명한 쪽의 블러 세기
  startRadius: 0,    // 마스크가 투명한 쪽
  startOffset: { x: 0.5, y: 1 },    // 투명한 끝 (정규화 좌표)
  endOffset:   { x: 0.5, y: 0.4 },  // 불투명해지는 지점
  visible: true,
}];
```

`mask-image: linear-gradient(to bottom, black 40%, transparent 100%)` 는
`startOffset {0.5, 1}` → `endOffset {0.5, 0.4}` 다. 가로 마스크면 x 를 쓴다.

**블러 레이어의 z 순서를 확인한다.** `::before` 는 내용 **뒤**다. 앞에 두면 그 아래 글자가 흐려진다.

## 13. 아이콘은 제품 전수를 라이브러리에 올린다

`public/icons/*.svg` 만으로는 부족하다. 제품의 아이콘은 세 곳에 흩어져 있다.

| 출처 | 개수(2026-08-22) | 비고 |
| --- | --- | --- |
| `public/icons/*.svg` | 61 | 파일 |
| `public/*.svg` (루트) | 23 | 브랜드·프로바이더 자산 포함 |
| 컴포넌트 안의 인라인 `<svg>` | 203 | 파일이 없다 — 소스에서 추출해야 한다 |

인라인 글리프는 `.tsx` 에서 `<svg>` 블록을 뽑아 JSX 표현식을 정리한 뒤 올린다. **JSX 표현식을
지우고 나면 `d=` · `cx=` 처럼 값이 빈 속성이 남는다** — 그대로 올리면 업로드가 실패하고, 업로드
URL은 실패해도 소비된다. 올리기 전에 값 없는 속성과 필수 속성을 잃은 요소를 제거한다.

단색 글리프(`currentColor`)는 `gray/000` 에 묶고, 여러 색을 쓰는 브랜드 자산은 원본 색을 지킨다.
색 종류를 세어 자동으로 가른다.

## 14. 길이가 긴 화면은 높이를 뷰포트에 가두지 않는다

랜딩·문서·목록처럼 세로로 긴 화면은 프레임 높이를 1080 에 고정하지 않는다. 세로 오토레이아웃에
`counterAxisSizingMode`/`primaryAxisSizingMode` 를 `AUTO`(hug)로 두어 내용 길이만큼 늘린다.
뷰포트 높이에 가두면 아래 내용이 잘려 검토할 수 없고, 잘린 것을 "없는 것"으로 오인하게 된다.

폭은 고정한다(1920 / 402). **높이만** hug 다.

## 15. 화면 고정(fixed) 레이어는 마지막 자식으로 둔다

GNB · 상단 블러 판 · 토스트처럼 `position: fixed` 이고 z-index 가 본문보다 높은 요소는 프레임의
**마지막 자식**이어야 한다. Figma 는 자식 순서대로 칠하므로, 문서 순서대로 먼저 넣으면 뒤에 오는
본문 섹션이 그 위를 덮어 아예 보이지 않는다. 실제로 `/pricing` 에서 GNB 가 통째로 사라졌다.

절대배치(`layoutPositioning = "ABSOLUTE"`)는 위치만 빼는 것이지 **칠 순서를 바꾸지 않는다.**

### 15조의 2. 뷰포트를 채우는 고정 레이어는 그 축에서 늘어난다 — 보드 틀은 크기 한계를 갖지 않는다

보드는 측정 뷰포트에서 제품과 같아야 하고, **틀을 늘리고 줄였을 때도 제품처럼 반응해야 한다.** `position: fixed` 의 포함 블록은
뷰포트다. 계산값(`getComputedStyle` 은 위치 지정 요소의 네 변을 쓰인 값 px 로 푼다)에서 양쪽 변이 모두 0 이면 그 축을 뷰포트
끝에서 끝까지 채운 것이므로(`width: 100%` · `inset-x-0` · `100vw` · `top: 0; height: 100dvh` 의 공통 결과) 그 축의 제약을
`STRETCH` 로 건다. 한쪽 변만 선언했어도 같다 — 선언만 보면 `left: 0; width: 100%` 는 왼쪽 고정(MIN)이 된다.

- **실측 사고(2026-10-08).** 공개 페이지 일곱의 상단 바(`left: 0; width: 100%`)가 MIN 으로 서서, 요금 데스크톱 보드를 1920 → 1440
  으로 줄이자 바가 1920 그대로 남아 오른쪽 480(언어 · 테마 · Get started)이 잘렸다. 모바일 402 → 360 에서는 42 넘쳤다. 앱 사이드바
  (`top: 0; height: 100dvh`)는 세로만 늘어나고 가로는 왼쪽에 붙는다(계산값 right 1680). 겹침 뿌리(측정기 `overlays` — 커맨드 팔레트
  배경 · 연체 배너)는 선언이 비어 있어도 계산값으로 같은 판정을 받는다(`figma-tree-spec.mjs` 의 `constraintsFor`).
- **제약 코드는 첫 글자로 줄이지 않는다.** `MIN` 과 `MAX` 는 첫 글자가 같다 — 러너 축약이 둘 다 `"M"` 으로 실어 렌더러가 오른쪽에
  붙은 절대 배치(`/aws/signup` 모서리 단추 `right: 20px`)를 전부 왼쪽 고정으로 읽었다(1440 에서 보드 밖 460). 축 코드(FIXED ·
  FILL)와 같은 표 방식(`CONSTRAINT_CODES` — M · A · S · C)으로 싣는다.
- **보드 틀에 최소 · 최대 폭을 두지 않는다.** 손 조립 시절 틀(랜딩 · 약관 둘)에 남은 최소 960 · 최대 1920(모바일 최대 402) 때문에 보드를
  2560 · 430 으로 넓혀도 틀이 멈췄다. 보드 러너가 조각 0 에서 틀의 네 한계를 걷는다. 뿌리의 뷰포트 폭 한계(`max-width: 100vw`, 전체
  오류 화면)도 측정 폭 상수로 풀려 남지 않게 걷는다 — 뿌리는 이미 틀 폭을 채운다.
- **포함 블록을 채우는 절대 배치도 같다.** `position: absolute` 의 계산값 네 변도 쓰인 값 px 라, 양쪽이 0 이면 포함 블록을 끝에서
  끝까지 채운 것이다(`inset-0` · `inset-x-0` · `left: 0; width: 100%`). 그 축의 크기를 고정 길이로 선언했으면(`width: 400px` 이 마침
  부모 폭과 같은 경우) 늘어나지 않으므로 뺀다. 실측(2026-10-08 늘림 시험): 커맨드 팔레트 배경(겹침 뿌리 안의 `absolute inset-0`)이 MIN
  으로 서서 1440 에서 480, 랜딩 푸터의 페이드(`bottom: 100%` · 계산값 left · right 0)가 모바일 360 에서 42 넘쳤다.
- **가운데에 둔 절대 배치는 CENTER 다.** `left: 50%`(또는 `top: 50%`, `calc(50%)` 포함)는 자기 변을 포함 블록 가운데에 두고, 흔히
  `translate: -50%` 로 자기 가운데를 맞춘다. 어느 쪽이든 부모가 커지거나 줄 때 노드 가운데와 부모 가운데의 거리가 그대로다 — Figma 의
  `CENTER` 가 그 뜻이다(입력칸 안 아이콘 · 노드 캔버스 손잡이 · 미리보기 배지).
- **자동 배치 없는 부모 안의 절대 자식에도 제약을 건다.** 절대 자식만 모인 부모는 자동 배치 없이(NONE) 서는데, 렌더러가 자동 배치 부모의
  절대 자식에만 제약을 걸어 그 안의 자식은 기본(MIN)으로 남았다 — 공개 모바일 메뉴 판(`fixed inset-0` 안의 `absolute inset-0`)이 부모를
  따라 줄지 않아 360 에서 42 넘쳤다.
- 측정 폭에서의 자리 · 크기는 바뀌지 않는다. 제약은 부모가 커지거나 줄 때만 일한다.

### 15조의 3. 화면 높이 뿌리는 보드 높이를 따른다 — 문서 길이 페이지는 hug 그대로(14조)

앱 셸은 뿌리가 `min-height: 100svh`, 그 안의 셸이 `height: var(--app-shell-vh, 100dvh)` 처럼 **뷰포트 높이 단위**로 화면을 채운다.
크기 판정은 뷰포트 단위를 측정 뷰포트 상수(1080 · 874)로 풀어 뿌리를 세로 HUG + 최소 높이 1080, 셸을 FIXED 1080 으로 굳혔다 —
`/archive` 보드를 1080 → 1400 으로 늘리자 아래 320 이 빈 회색이었다. 그래서 뷰포트 높이 단위를 **보드 높이**로 옮긴다
(`build-figma-app-screens.mjs` 의 `fillScreenHeight`).

1. **뿌리.** 높이 · 최소 높이 선언에 뷰포트 높이 단위가 있고 측정 높이 = 보드 높이 = 뷰포트 높이(내용이 아니라 그 단위가 높이를 정했다)면
   세로 FILL 이다. 보드 틀은 세로 자동 배치라 FILL 이 틀 높이다.
2. **사슬.** FILL 이 된 노드의 흐름 자식 가운데 측정 높이가 부모 안쪽 높이(패딩 · 제 margin 을 뺀)와 같고, 높이 · 최소 · 최대 높이 선언에
   뷰포트 높이 단위나 `100%` 가 있는 자식을 세로 FILL 로 잇는다. 세로 부모에서는 흐름 자식이 하나일 때만 잇는다(FILL 이 남는 자리를 다
   받는다). 이미 FILL 인 자식은 판정 없이 사슬을 잇는다. 인스턴스 · 절대 배치는 잇지 않는다 — 절대 배치 셸은 15조의 2 의 제약이 맡는다.
3. **사슬 위 노드의 뷰포트 단위 최소 · 최대 높이는 걷는다.** FILL 이 그 뜻을 대신하고, 남기면 보드를 줄이거나 늘릴 때 1080 에 묶인다.
4. **문서 길이 페이지는 HUG 다.** 측정 높이가 뷰포트보다 긴 화면(공개 원장의 긴 문서 — 요금 · 약관 · 블로그)은 내용이 높이를 정했다.
   그 보드를 세로로 늘렸을 때 뿌리가 따라오지 않는 것은 결함이 아니다(14조).

측정 크기에서는 FILL 이 측정 높이와 같은 값으로 풀리므로 노드 자리 · 크기는 바뀌지 않는다.

### 15조의 4. 흐름 안의 빈 자리 상자는 가로로 부모를 따른다

칠 · 글자 · 자식이 없어도 흐름 안에서 넓이를 가진 상자(스크롤 자리 상자 · 스피너 몸 · 내용이 숨은 grid 칸)는 측정 크기의 빈 상자로
남긴다 — HUG 로 두면 0 으로 접힌다. 그러나 **가로 판정이 FILL 이면 가로는 FILL 로 둔다.** 세로는 측정 높이(FIXED) 그대로다.

- **실측 사고(2026-10-08 늘림 시험).** 랜딩의 스크롤 자리 상자 셋(`height: 3040px` 등 · 폭 선언 없는 block — 부모를 채운다)을 두 축 모두
  굳혀, 데스크톱 보드를 1920 → 1440 으로 줄이자 1920 에 남아 480 넘쳤다(모바일 402 → 360 은 42). 공개 모바일 메뉴 판의 grid 칸(366,
  내용이 숨어 빈 상자)도 같았다.
- 측정 폭에서는 부모 안쪽 폭(grid 면 칸 폭) = 측정 폭이라 자리 · 크기가 같다.

### 15조의 5. 겹침도 선언을 싣고, flex 교차축 가운데에 선 절대 배치는 CENTER 다

제약 판정(15조의 2)은 선언을 본다 — 계산값은 네 변을 전부 px 로 풀어 `right: 12px` 와 「왼쪽 1880」을 가르지 못한다. 측정기는 앱 뿌리
트리에만 선언(CDP)을 붙이고 겹침(`overlays` — 커맨드 팔레트 · 연체 배너)은 계산값만 실었다. 그래서 겹침 노드도 같은 조인 배열에
뿌리 트리 뒤로 잇는다(`measure-product-auth-fixture.mjs` — `__louisAuthFixtureNodes = [...뿌리, ...겹침]`, 붙이는 쪽도 같은 순번).
겹침이 없는 원장은 출력이 바이트로 같다.

- **실측 사고(2026-10-08 늘림 시험).** 연체 배너 닫기 단추(제품 `PastDueBanner.tsx` — `position: absolute; right: 12px`)가 선언 없이
  계산값 left 1880 · right 12 만 있어 MIN 으로 섰고, 보드를 1440 으로 줄이자 468 넘쳤다. 선언이 실리면 가로는 `MAX` 다.
- **flex 교차축 정적 자리.** 한 축의 두 변을 다 비운(`auto` · 선언 없음) 절대 배치는 그 축에서 정적 자리에 선다. flex 부모 안의 정적
  자리는 그 요소가 유일한 flex 항목인 것처럼 정렬한 자리라, 교차축 정렬(`align-self`, 없으면 부모 `align-items`)이 `center` 면 부모
  교차축 가운데다 — 그 축을 `CENTER` 로 건다. 가로 flex 면 세로, 세로 flex 면 가로가 교차축이다. 주축(`justify-content`)은 보지 않는다.
  배너 닫기 단추(배너는 가로 flex · `align-items: center`)는 세로 CENTER, 입력칸 안 아이콘(`left: 8px` · 위아래 선언 없음, 노드 캔버스 ·
  영상 편집기 · 쇼츠 편집 템플릿)도 세로 CENTER 가 된다(`constraintsFor` 의 셋째 인자 — 부모 계산값).
- 측정 폭의 자리 · 크기는 바뀌지 않는다.

### 15조의 6. 고정 폭 + `max-width: 100%` 는 FILL + 최대 폭이다 — 측정 폭에서 같을 때만

`width: 560px; max-width: 100%`(`w-[560px] max-w-full`)는 「그 폭이되 포함 블록보다 넓어지지 않는다」다. Figma 의 FILL + maxWidth(그 폭)가
같은 뜻이다 — 부모가 넓으면 그 폭, 좁으면 부모 폭. FIXED 로 굳히면 부모가 줄어도 그 폭에 남는다(`sizing-provenance.mjs` 의 `decideAxis`).

- **실측 사고(2026-10-08 늘림 시험).** 커맨드 팔레트 대화 상자(제품 `CommandPalette.tsx` — `w-[560px] max-w-full`)가 겹침 선언이 없어
  FIXED 로 풀렸고, 모바일 보드를 360 으로 줄이자 9.5 넘쳤다.
- **parity.** Figma 의 FILL 은 포함 블록이 아니라 Figma 부모의 남는 자리를 채운다 — 세로로 쌓는 부모(세로 flex · block)는 안쪽 폭, 가로 flex
  부모는 안쪽 폭에서 흐름 형제 폭과 간격을 뺀 자리다. 그 자리와 그 폭 중 작은 쪽이 측정 폭과 1 안으로 같을 때만 FILL 로 두고, 아니면(grid
  칸 · 그 밖의 부모 · 형제가 나눠 가짐) FIXED 로 되돌린다(`figma-tree-spec.mjs` convert). 측정 폭의 그림은 바뀌지 않는다.

### 15조의 7. 가로 줄의 auto margin 은 남는 폭이다 — 감싸개는 FILL, 하한은 자식 상자

`margin-left: auto`(줄 오른쪽 끝의 단추) · `margin-right: auto`(앞에 붙인 문구)는 줄의 남는 폭을 먹는다. 계산값은 그 폭을 px 로 풀어
(1272.97 등) margin 감싸개(형제가 있는 자식의 margin 을 옮기는 칠 없는 프레임)의 padding 이 되고, 감싸개는 HUG 라 측정 폭에 굳는다.
선언(`declared`)이 `auto` 인 변은 padding 으로 옮기지 않고, 감싸개를 **가로 FILL · 폭 하한 = 자식 상자(auto 아닌 margin 포함)** 로 두며,
자식은 auto 의 반대쪽에 붙인다 — 왼쪽 auto 는 주축 `MAX`, 오른쪽은 `MIN`, 둘 다면 `CENTER` (`build-figma-app-screens.mjs` wrapSiblingMargins).

- **실측 사고(2026-10-09 늘림 시험 run 2026-10-09a).** 하이라이트 스튜디오 판의 알림 줄(불러오기 실패 「Reload」 · 분석 실패 「Retry」 ·
  완료 클립 받기 단추 · 「분석 중」 안내 문구)이 감싸개 1340 · 1334 · 1470 · 1424 에 굳어, 데스크톱 보드를 1440 으로 줄이자 줄(1056) 밖으로
  나갔다 — 03-app 부모 밖 14 → 22 중 넷.
- **폭이 정해진(HUG 아닌) 가로 줄에서만.** HUG 줄에는 남는 폭이 없고, 자식이 FILL 이면 CSS 에서도 auto margin 이 0 이다.
- **감기는 줄에서 혼자 한 줄을 차지한 감싸개는 그대로 둔다.** 감기 줄의 FILL 은 줄을 고를 때 폭이 0 인 것처럼 앞 항목 뒤에 붙어
  (`splitWrapRowsAtLoneText` 주석의 라이브 탐침), 뒤 항목(업로드 진행 막대, `flex-basis: 100%`)이 그 줄로 올라온다. 오른쪽 auto 로 줄을
  채운 글자와 줄 폭 100% 항목은 그보다 앞서 줄을 끊어 세운다(2026-10-12, 28조 표의 「오른쪽 auto margin 글자 · 줄 폭 100% 항목」) — auto
  margin 은 버려져 감싸개가 생기지 않는다. 여기 남는 것은 그 규칙 밖(칠 · 정렬 · 왼쪽 auto 등)의 감싸개다.
- **parity.** 측정 폭에서 남는 폭 = 측정 margin 이고 같은 줄에 FILL 형제가 없어(CSS 에서 늘어나는 형제가 있으면 auto margin 은 0 이다)
  보이는 자식의 자리 · 크기가 같다. auto 둘이 나눈 남는 폭도 FILL 둘이 나누며, 자식이 줄 양 끝에 붙으므로 자리가 같다. 러너 대조에서
  바뀐 칸은 감싸개의 sizing · 주축 정렬 · 폭 하한과 자식의 margin(→ 감싸개 padding)뿐이다.

### 15조의 8. 뷰포트 무대에서 변환으로 선 층은 SCALE 이다 — 같은 여백 상자는 STRETCH

랜딩 장면(하이라이트 · 끝 장면)은 무대(sticky `[height:100lvh]`)의 `absolute left-0 top-0` 층에 스크립트가 무대 크기에서 계산한
`translate3d(x, y)` · 폭 · 높이를 프레임마다 쓴다(제품 `HighlightShowcase.tsx` · `highlightScene.ts` 의 `frame(scrolled, stage)`). 선언으로는
왼쪽 · 위 0 이라 MIN 이 되고, 측정 자리는 변환 안에만 있다. 제품은 무대가 줄면 자리를 다시 계산해 무대 안에 둔다.

- **판정.** 계산값 `transform` 이 이동만 있는 `matrix(1, 0, 0, 1, tx, ty)` 이고, 그 축의 이동이 0 이 아니며, 그 축의 시작 변 선언이 없거나 0 이고 끝 변
  선언이 없으면 그 축을 `SCALE`(무대에 비례)로 건다. 무대가 뷰포트 높이 단위로 선 상자일 때만 — 부모에서 `inset: 0` 절대 상자를 건너 올라가 처음
  만나는 상자의 높이 선언이 `100lvh` · `100svh` · `100dvh` · `100vh` 다(`figma-tree-spec.mjs` 의 `transformPlacedAxes` · `viewportStage`).
  노드 캔버스의 React Flow 노드도 `translate` 로 서지만 무대가 뷰포트 단위가 아니어서 빠진다 — 그 노드는 창이 줄어도 캔버스 좌표에 머문다.
- **같은 여백 상자.** 그런 층을 형제로 둔 무대에서 선언이 `left: Npx; width: Mpx` 이고 계산값의 양쪽 여백이 같은 상자(모바일 제목 칸 — `titleColumn`
  의 `{ left: 20, width: stage.width - 40 }`)는 그 축을 `STRETCH` 로 건다. 여백이 다른 데스크톱 제목(왼쪽 192 · 오른쪽 1128)은 그대로다.
- **실측 사고(2026-10-12 늘림 시험 run 2026-10-12b).** 랜딩 데스크톱을 1440 으로 줄이자 하이라이트 칸 다섯이 1379 에 남아 무대 밖으로 108, 끝 장면
  카드가 151 나갔다(부모 밖 7 가운데 6). 모바일 360 에서는 칸 다섯이 22, 제목 칸(362)이 22 나갔다.
- **SCALE 은 근사다.** 제품은 칸의 폭과 높이를 함께 줄이지만(16:9 유지) Figma 의 SCALE 은 축마다 부모에 비례한다 — 폭 시험에서 칸은 폭만 줄고 높이는
  무대 높이를 따른다. 무대 안에 머무는 것이 제품과 같은 반응이고, 모양까지 같지는 않다.
- 측정 크기에서는 SCALE · STRETCH 가 측정 자리 · 크기로 풀린다 — 자리 · 크기는 바뀌지 않는다.

### 15조의 9. 뷰포트 겹침을 채운 외동 절대 자식은 흐름 FILL 이다

Figma 는 **제약으로 크기가 바뀐 자동 배치 프레임의 FILL 자식을 다시 배치하지 않는다.** 공개 모바일 메뉴 판(`fixed inset-0` 안의 `absolute inset-0`
세로 flex)을 보드와 함께 360 으로 줄이면 판과 그 자식은 STRETCH 로 360 이 되는데, 자식 안의 FILL grid 는 366 에 남는다. FILL 을 다시 걸면 324 로 풀린다
(라이브 탐침 2026-10-14). 판을 세로 자동 배치로 두고 자식을 흐름 FILL 로 두면 처음부터 풀린다.

- **판정.** 부모가 `position: fixed` 이고 자동 배치 없이(NONE) 서며, 자식이 하나이고 · 자동 배치를 가지며 · 두 축 `STRETCH` · 부모 상자와 자리 · 크기가
  같고(0.5 안) · 부모에 패딩 · 테두리가 없으면, 부모를 세로 자동 배치로 · 자식을 흐름 `FILL`/`FILL` 로 둔다(`figma-tree-spec.mjs` 의 `soleSpanningChild`).
  CSS 에서 그 자식은 부모의 안쪽 상자 전체이고 흐름 FILL 도 같은 상자다.
- **실측 사고(2026-10-12 늘림 시험 run 2026-10-12b).** 공개 모바일 보드 전부의 넘침 2 · 부모 밖 1(`div FH` +24)이 이것이다.
- 흐름 안의 절대 부모(편집기 · 노드캔버스 · 랜딩 장면의 같은 모양)는 늘림 시험이 그 결함을 보이지 않아 넓히지 않았다.

### 15조의 10. 줄 수를 자르는 글자(`line-clamp`)는 칸 폭 FILL + 그 줄 수 말줄임이다 — 줄을 옮긴 글자의 HUG 예외

`-webkit-line-clamp: N`(Tailwind `line-clamp-N` = `overflow: hidden; display: -webkit-box; -webkit-box-orient: vertical; -webkit-line-clamp: N`)인
글자 상자는 **블록 폭**이다 — 세로 flex 의 stretch 항목이면 칸 폭, 블록 흐름이면 포함 블록 폭이고 글자 폭이 아니다. 줄은 그 폭에서 감기고 N 줄에서
말줄임으로 잘린다. Figma 의 같은 뜻은 가로 FILL · `textTruncation = "ENDING"` · `maxLines = N` 이다.

- **판정.** 원장의 축에는 `-webkit-line-clamp` 가 없다. 크로미움(151)은 line-clamp 를 건 `-webkit-box` 의 `display` 를 계산값 `flow-root` 로 낸다(실측:
  같은 h3 · 폭 150 칸에서 line-clamp-2 는 `flow-root` · 150 × 48, 없으면 `block` · 150 × 96). 계산값 `display: flow-root` + `overflow: hidden` · 줄바꿈
  허용(`nowrap` · `pre` 아님)인 글자 상자를 그것으로 읽고, N 은 안쪽 높이 / 줄 높이다 — 정수배일 때만(`figma-tree-spec.mjs` 의 `lineClampOf`, payload `lc`).
- **줄을 옮긴 글자의 HUG(15조 「줄을 옮긴 글자는 폭을 글자에 맞춘다」)에서 뺀다.** 그 HUG 의 이유는 «Figma 글꼴로 줄이 칸보다 몇 px 넓으면 한 번 더 감겨
  상자가 길어진다»였다. 자르는 상자는 N 줄보다 길어질 수 없어(`maxLines`) 그 위험이 높이를 바꾸지 못한다 — 2026-10-12 판단(「Figma 에서 옮긴 줄의 폭을
  재기 전에는 FILL 로 돌리지 않는다」)이 걸린 사고의 원인이 이 상자에는 없다. 측정 폭에서 Figma 줄 폭(랜딩 모바일 뉴스 카드 ko 「모델이 추가되었습니다.」
  HUG 145)이 칸(150)보다 좁아 다시 감기지도 않는다.
- **실측 사고(2026-10-14 늘림 시험 run 2026-10-14a).** 랜딩 모바일 360 의 뉴스 카드 제목 둘(`NewsCarousel.tsx` HEADLINE `line-clamp-2`)이 줄을 옮긴 HUG 145 로 서서
  129 칸 밖으로 16 나갔다. 제품은 129 칸에서 다시 감기고 두 줄에서 잘린다.
- **parity.** 측정 폭에서 FILL 폭 = 측정 폭(150 = 150), 높이 = N × 줄 높이(48)다. 원장의 `wrapLines` 가 N 보다 많아도(「ElevenLabs audio / models are now /
  available.」 셋, 높이 48) 보이는 것은 N 줄이다. 칸 폭 FILL 이 아닌(HUG 판정) 자르는 글자에는 렌더러가 줄 수를 걸지 않는다.

### 15조의 11. 백분율 자리의 절대 배치는 부모에 비례한다 — 글자는 가까운 닻

`left: 5%; width: 15%`(하이라이트 완료 스튜디오의 구간 막대) · `left: calc(var(--studio-tick) * 1%)`(시간 눈금 글자)처럼 시작 변이 포함 블록의
백분율인 절대 배치는 부모 폭이 바뀌면 자리가 비례해 움직인다. Figma 의 SCALE 이 그 뜻이다(자리와 크기를 부모에 비례).

- **판정.** 위치가 `absolute` 이고 시작 변 선언에 `%` 가 있으며(50% 가운데 맞춤은 15조의 2 CENTER 가 먼저) 끝 변 선언이 없고, 계산값 시작 변 / 부모 안쪽
  크기 p 가 0 과 1 사이일 때(`top: 100%` 로 아래에 펼친 메뉴 · `left: 0%` 는 비율 자리가 아니다 — 옛 판정). 글자가 아니면 SCALE. 글자는 크기도 백분율이
  아닌 한 p 에 가장 가까운 닻이다 — p ≤ 0.25 MIN · p ≥ 0.75 MAX · 그 사이 CENTER(`figma-tree-spec.mjs` 의 `constraintsFor` · `percentOf`).
- **글자에 SCALE 을 걸지 않는 이유(라이브 탐침 2026-10-14).** SCALE 은 글자 상자 폭도 줄인다 — 하이라이트 완료 모바일을 360 으로 줄이자 폭 맞춤 「1:30」이
  23 → 20.4 의 높이 맞춤 글자로 바뀌어 두 줄(높이 36)로 감겼다. 제품 눈금 글자는 `translateX(-p%)` 로 x = p × (부모 폭 − 글자 폭)이고 폭은 그대로다 — Figma 에
  같은 제약이 없어 기울기(0 · ½ · 1)가 가장 가까운 닻을 쓴다. 오차는 p 와 닻의 차 × 줄어든 폭 이하다(360 에서 「1:30」 5.7).
- **실측 사고(2026-10-12 늘림 시험 run 2026-10-12b).** 하이라이트 완료 모바일 360 에서 눈금 「1:30」(366 줄의 x 307)과 끝 구간 막대(x 311 · 폭 55)가 MIN 으로
  남아 324 줄 밖으로 6 · 42 나갔다.
- **SCALE 은 근사다(15조의 8 과 같다).** 고정 폭 상자(편집기 눈금 1 × 6)는 폭도 비례해 줄어든다. 측정 크기에서는 자리 · 크기가 그대로다.

### 15조의 12. 가로 줄의 외동 항목에 걸린 auto 여백은 주축 가운데다

`width: min(540px, 100%); margin-inline: auto`(홈 배너 글 상자 — `appHomeSceneStyles.ts` bannerContent)는 가로 flex 슬라이드에서 남는 폭을 양쪽 여백으로 나눠

### 15조의 13. 접힌 감싸개의 칸 정렬은 자식이 받고, NONE 부모 안에서 제약으로 늘어나는 자동 배치 프레임은 외동 FILL 을 제약으로 바꾼다

### 15조의 14. 부모 폭을 따르는 계산 폭은 FILL 이다 — `min-width: 100%` · 폭 변수를 나눈 열 · 변수 `inset`

- **판정.** 선언 폭이 `%` 없는 `var()` · `calc()` 이고 계산값 `min-width` 가 `100%` 면, 측정 폭이 부모 자리와 같을 때(15조의 6 대조) FILL 이다 — 계산 폭이 부모보다 넓었으면
  FIXED 로 되돌린다(`sizing-provenance.mjs`). 그런 줄이 grid 이면, 폭 선언과 같은 변수(`var(--x)`)로 정한 열은 남는 폭(`fr`)이다(`gridColumnTracks`). 줄 폭에서 다른 열을 뺀
  나머지가 그 변수다.
- **변수 `inset`.** CDP 는 `inset: 0 0 0 var(--vem-rail-width, 64px)` 처럼 변수를 품은 줄임 선언의 긴 이름을 빈 문자열로 준다. 제약 판정 전에 비어 있는 긴 이름을 CSS 순서(1~4 값)로
  채운다(`insetLonghands`) — 레인 덮개가 왼쪽 고정(MIN)에서 STRETCH 가 된다.
- **SCALE 부모를 꽉 채운 자식.** 여백 0 · 크기가 같은 STRETCH 자식은 부모 축이 SCALE 이면 그 축도 SCALE 로 둔다(`scaleFlushChildren`) — 둘은 같은 뜻인데 Figma 가 SCALE 로 늘어난
  부모 안의 STRETCH 자식을 반올림한 변 차이로 옮겨 클립 필름 상자가 2560 에서 0.67 넓었다(라이브 탐침, SCALE 로 두면 같다).
- **근거(제품).** 편집기 타임라인 줄(`width: calc(64px + var(--sequence-time-axis-width)); min-width: 100%`)의 변수는 `VideoEditModal.tsx` 가 레인 상자 폭(clientWidth − 64)에서
  계산해 쓴다 — 줄은 늘 부모를 따른다.
- **실측 사고(2026-10-14b).** 편집기 데스크톱 1440 에서 줄 둘이 FIXED 1888 로 1408 부모 밖에 480.
- **남은 것은 제품도 그렇다.** 클립 필름 칸은 제품이 `count = ceil(상자 폭 / 칸 폭)` 개를 깔고 상자가 `overflow: hidden` 이라(`clipFilmstrip.tsx`) 마지막 칸이 상자 끝을 가로지른다.

### 15조의 15. 스크립트가 부모 안에 비율을 지켜 맞춘 상자는 가로 FILL + 비율 잠금이다

- **판정.** 두 축 선언이 px(스크립트가 `style.width · height` 를 쓴다) · 흐름 자식이 그 하나 · 한 축이 부모 안쪽과 같고(0.5 안) 다른 축은 1 넘게 짧고 양쪽 여백이 같다(1 안)
  (`figma-tree-spec.mjs` 의 `containFitOf`). 가로 FILL + 비율 잠금(렌더러 `ar` — 측정 크기로 깐 뒤 FILL 을 걸기 전에 `lockAspectRatio()`)이고, 높이가 정한 쪽(높이 = 부모 안쪽)이면
  측정 폭이 최대 폭이다.
- **근거(제품).** 편집기 미리보기 출력 틀은 `VideoEditModal.tsx` 의 출력 틀 ResizeObserver 가 부모 안쪽에 16:9 로 맞춘다 — 넓으면 높이가, 좁으면 폭이 부모를 채운다.
- **실측 사고(2026-10-14b).** 데스크톱 1440 에서 1216 틀이 835 부모 밖으로 190, 모바일 360 에서 402 틀이 21.
- **근사.** 보드 높이를 늘리면 제품은 부모 높이로 다시 맞추지만 Figma 는 최대 폭에 머문다(부모 밖으로 나가지 않는다). 측정 크기에서 FILL 폭 = min(부모 안쪽, 최대 폭) = 측정 폭이다.

### 15조의 16. grid 칸 되짚기는 시작 좌표도 칸 안으로 들인다 — 간격 0 이면 앞 칸의 끝과 뒤 칸의 시작이 같은 값이다

- **판정.** 자식의 칸(행 · 열)은 바깥 상자(여백 포함)의 시작 · 끝 좌표가 드는 트랙으로 정한다. 끝 좌표는 0.01 빼고 **시작 좌표는 0.01 더한다**
  (`figma-tree-spec.mjs` 의 `gridPlacements`). 둘이 짝이어야 경계 위의 값이 어느 쪽 칸인지 갈린다.
- **왜.** 칸 찾기는 「정확히 드는 칸」을 먼저 고른다(`value >= start && value <= end`). 간격(`gap`)이 0 인 grid 는 0행 끝과 1행 시작이 같은 값이라, 1행에서 시작하는
  자식이 0행으로 잡힌다. 그러면 두 행에 걸친 형제(`grid-template-areas` 의 같은 이름이 두 행에 있는 칸)와 자리가 겹친다고 보아 되짚기를 통째로 버리고, 렌더러가
  자동 배치로 깔아 칸이 밀린다.
- **실측 사고(2026-10-14).** `/models/[slug]` 데스크톱 머리(`grid-template-areas: 'text media' 'actions media'`, 간격 0)의 버튼 줄은 시작 539 가 첫 행 끝 539 와 같아
  첫 행으로 잡혔다. 미디어(두 행 걸침)와 겹친다고 보아 되짚기를 버려, 버튼 줄이 셋째 칸에 서서 머리가 **64 길어졌다**. 고친 뒤 보드 3471:9269 의 머리 높이가 제품과 같다.
  같은 규칙으로 편집기 모바일 러너(`/videoeditor/[projectId]`)의 칸 배치도 바뀌어 다시 보냈다.
- **같이 지키는 것.** 간격이 2 보다 좁은 grid(쿠폰 인쇄 격자 · 간격 1)에서 정확히 드는 칸을 먼저 고르는 규칙(2026-10-07)은 그대로다 — 0.01 은 경계 값만 가른다.

### 15조의 17. 상자를 다 깎는 `clip-path: inset()` 은 보이지 않는 것이다

- **판정.** 계산값 `clip-path` 가 `inset(…)` 이고(1~4 값, `round` 뒤는 보지 않는다) 위 + 아래 깎기가 상자 높이 이상이거나 왼쪽 + 오른쪽 깎기가 상자 폭 이상이면, 그 노드와
  서브트리를 그리지 않는다(`figma-tree-spec.mjs` 의 `isVisible` → `clipPathHidesAll`). `%` 는 그 축의 상자 크기로, 길이는 px 로 푼다. 다른 도형(`circle` · `polygon` ·
  `path`)과 덜 깎은 `inset` 은 그대로 그린다.
- **왜.** 투명도 · `display` · `visibility` 가 그대로라 측정에는 보이는 노드로 남는다. 제품은 닫힌 상태를 이 방식으로 숨기고 열릴 때 깎기를 애니메이션으로 푼다.

### 15조의 18. 아래 변에 붙은 절대 배치 상자는 내용 높이다 — 세로 HUG 로 위로 자란다

### 15조의 20. 끈적 장면은 제 스크롤 자리에서 잰다 — 무대마다 가장 많이 보이는 프레임

랜딩의 스크롤 장면(히어로 · 개요 캔버스 · 컴포지션 · 하이라이트 · 크리에이터 · 끝 장면)은 긴 트랙(섹션) 안에 `position: sticky` 무대(높이 =

아래 무대는 아직 시작 전이라 층이 `opacity: 0` 이거나 비어 있다 — 30540 짜리 랜딩 데스크톱이 노드 396 으로 잡혔다(컴포지션 3 · 크리에이터 6 ·
개요 18). 동작 줄이기도 이 장면들을 끄지 않는다(제품 결정 2026-09-28 — 스크롤이 곧 진행이다).

- **어디서 쓰나.** 측정기 화면 명세에 `scenes: true` 를 단 화면(`measure-product-auth-fixture.mjs` 의 `PUBLIC_ROUTES` — 지금은 `/`). 다른 화면은 종전과
  같다. 다른 장면 화면(예: 앰배서더)도 같은 깃발 하나로 쓴다.
- **무대 찾기.** 뿌리 아래 요소 중 계산값 `position: sticky` · 높이 = 뷰포트 높이(±2) · 부모(트랙)가 뷰포트보다 긴 것. 무대 안의 무대는 세지 않는다.
- **프레임 고르기.** 트랙의 붙는 구간(트랙 윗변 ~ 트랙 아랫변 − 뷰포트)을 17 등분(`STICKY_SCENE_SAMPLES`)해 스크롤하고, 자리마다 무대 안 요소의
  **실효 불투명도 합**(조상 불투명도를 곱한 값, 화면에 걸친 면이 있고 `visibility: hidden` 이 아닌 것만)을 센다. 가장 큰 자리(같으면 앞 자리)가
  그 장면의 프레임이다. 장면마다 시간표가 달라 고정 진행률(0 · 0.5 …)은 어떤 장면에서는 빈 무대다 — 이 점수는 장면을 모르는 채로 「제품이 그
  장면에서 가장 많이 보여 주는 순간」을 고르고, 반쯤 떠오른 층보다 다 떠오른 층이 이긴다.
- **그 자리에서 잰다.** 고른 자리로 스크롤하고, 재생 중인 영상 · 소리를 멈춰 0초에 세운 뒤(재생 시간 글자가 안정을 막는다 — 측정 패스가 끝나지 않는
  CSS 애니메이션을 0 에 세우는 것과 같은 처리) 가라앉히고, 기본 흐름과 **같은 두 패스 · 조인 · 재시도**로 문서를 다시 잰다(`measureStable`).
- **잇기.** 그 측정의 무대 서브트리로 맨 위 측정의 같은 경로 서브트리를 바꾼다. 무대는 **흐름 자리**(맨 위에서 잰 자리 — 트랙 윗변)에 둔다 — 붙어
  있는 무대는 뷰포트 맨 위에 서므로 서브트리를 통째로 (맨 위 무대 y − 그 프레임의 무대 y)만큼 옮긴다. 보드에서는 트랙 윗변에 그 프레임이 서고 아래로
  트랙의 남은 높이가 이어진다. 원장의 화면 기록 `stickyScenes` 에 무대 경로 · 고른 scrollY · 진행률 · 점수 · 노드 수가 남는다.

  그 세트를 붙이면 큰 그림이 작은 상자에 들어간다. 무대 안은 측정한 노드 그대로 그리고, 배율은 「배율이 걸린 서브트리」(`applyTransformScale`)가 맞춘다.
- **확인.** `--scene-shots=<폴더>` 로 고른 자리의 뷰포트 캡처를 남긴다(원장은 그대로 쓴다) — 보드의 장면과 제품 프레임을 나란히 대조한다.

### 15조의 21. 영상은 포스터로, 바탕 그림은 인스턴스로 — 그림을 파일로 가진 자리만

보드는 `<img src>` 만 그림으로 이었다(IMAGE_COMPONENTS). 랜딩은 그림의 절반을 다른 길로 그린다 — 히어로 배경은 `<video poster>`, 하이라이트 격자
25칸과 모바일 숏폼은 `background-image: url(…)` 다. 측정 트리에 바탕 없는 상자만 남아 히어로는 흰 바탕에 흰 글자, 하이라이트는 빈 격자로 그려졌다.

- **영상.** 측정기는 `<video>` 에 `poster` 속성이 있으면 그 경로를 `src` 로 싣는다(`<img>` 와 같은 정규화 — 같은 출처면 pathname). 프레임은 디코더
  상태라 파일이 아니다 — 제품이 첫 칠 · 감소 모션에서 보여 주는 포스터가 그 자리의 그림이다. tree-spec 은 포스터가 있는 영상을 그림으로 본다
  (`hasOwnPaint`) · `src` 를 싣는다. 포스터가 없는 영상(노드캔버스 영상 노드 `#t=0.1` 처럼 첫 프레임을 쓰는 자리)은 종전처럼 src 없이 남는다.
- **바탕 그림.** 계산된 `background-image` 가 **url 한 겹**(`url("…")` 그대로)이고 그 url 이 IMAGE_COMPONENTS 에 이어져 있으면 잇는다. 자식이
  없으면 그 상자가 곧 이미지 인스턴스다. 자식이 있으면 바탕은 모든 자식 아래에 칠해지므로 **맨 앞 자식**으로 두 축 STRETCH ABSOLUTE 인스턴스를
  끼운다(경로 `<부모>.bg`, 15조의 13 과 같은 제약). `background-size: cover` 와 컴포넌트의 이미지 채움(FILL)은 둘 다 가운데를 채우며 자른다.
  그라디언트와 겹친 바탕 · 이어지지 않은 url 은 건드리지 않고 plan 감사본 `unmappedBackgrounds` 에 남긴다. 쌓임 순서 정렬(`orderByStacking`)
  «뒤에» 돈다 — 끼운 자식은 측정 스타일이 없다. 보드에만 건다(부품 러너는 바뀌지 않는다).
- **자산.** 제품 public 원본을 `90 · 자산` 「U · image/」 에 원본 픽셀 크기의 이미지 채움 컴포넌트(`image/landing/<이름>`)로 올린다. webp 는
  Figma 에서 단색 회색으로 그려지므로 PNG 로 바꿔 `upload_assets` 의 `nodeIds` 로 원시 바이트를 보낸다. 라이브 목록은 `figma-live-assets-probe` 로 다시 뜬다.
- **크기 0 카메라.** 컴포지션 장면은 크기 없는 절대 배치 상자(`preserve-3d` 카메라) 안에 1600×1000 판을 넘쳐 그린다. 측정기는 크기 0 이라
  상자째 버렸다(판과 영상이 원장에 없었다). 넘침이 보이는(`overflow: visible`) 크기 0 HTML 상자가 면이 있는 자식을 가지면 svg 넘침과 같이 건너뛰고
  안으로 내려간다(불투명도 0 이면 그대로 버린다). 3D 변환은 Figma 에 없으므로 판은 화면에 투영된 경계 상자로 평평하게 선다.
- **실측(2026-10-15, 앵커 54b62a8a).** `/` 의 히어로 포스터 · 개요 캔버스 노드의 사진(`node-showcase-sofa`) · 끝 장면 하늘 첫 칸(`sky-start`) ·
  하이라이트 격자 25칸 · 모바일 숏폼 포스터 · 컴포지션 판 포스터(en) — 컴포넌트 30개(3532:28989~29017 · 3535:3601). 끝 장면의 하늘은 제품이

### 15조의 22. 칸을 채운 줄 옮긴 글자는 FILL 이다 — 다시 감기는지는 렌더러가 Figma 에서 잰다

24조 「줄을 옮긴 글자는 폭을 글자에 맞춘다」(2026-10-01)는 제품 줄바꿈을 실은 글자를 폭 맞춤(HUG)으로 두었다 — Figma 글꼴이 칸보다 몇 px 넓으면
한 줄을 더 감아 문서가 길어지기 때문이다. 2026-10-12 판단은 «원장에 줄마다의 폭이 없어» FILL 로 돌리지 않았다. 그 폭은 Figma 만 안다. 그래서 잰다.

- **판정.** 줄을 옮긴 글자(`wrapLines` 2 줄 이상) 가운데 판정 폭이 FILL 인 것(블록 글자 · stretch 된 칸을 채운 글자)은 가로 FILL · 세로 HUG(높이 자동)로
  두고 [줄 수, 줄 높이] 를 싣는다(`build-figma-app-screens.mjs` 의 `hugCarriedLines` → payload `fw`). 조건은 종전과 같다 — 시작 정렬, 부모가 HUG 아님, 세로
  쌓기(교차축 시작) 또는 흐름 자식 하나, 내용 시작선에 붙음. 판정 폭이 FIXED(폭 선언)인 글자는 제품도 줄지 않으므로 종전대로 HUG 다.
- **줄 상자를 혼자 채운 inline 글자도 같다.** 계산값 `display: inline` 인 칠 없는 글자 잎(`<p><a>Next option…</a></p>`, 표 칸의 `<strong>`)은 판정이 HUG(「inline
  — 콘텐츠가 결정한다」)지만 부모 블록의 줄 폭에서 감긴다. 감기지 않았어도 줄이 좁아지면 감기므로 같은 FILL + `fw` 다. 칠이 있는 inline(코드 칩)은 면이
  줄 폭으로 늘어나므로 뺀다.
- **렌더러의 되돌림.** 보드를 다 세운 뒤(텍스트 스타일 · 범위 서식 · 절대 배치가 걸린 뒤, `settleResizeResponse`) 측정 폭에서 글자 높이를 잰다. 줄 수 × 줄
  높이(측정 높이와 줄 수 × 줄 높이 중 큰 쪽)보다 반 줄 넘게 높으면 Figma 글꼴이 한 줄을 더 감은 것이라 그 글자만 종전의 폭 맞춤(HUG ·

### 15조의 23. 줄어드는 flex 항목은 줄의 남는 폭을 채운다 — `min-w-0` 과 감기는 글자

감기지 않는 가로 flex 줄(`flex-wrap: nowrap`)의 항목은 `flex-shrink` 가 0 이 아니면 줄이 좁아질 때 자기 최소 폭까지 줄어든다. 크기 판정은 「grow 0 · 폭
선언 없음 — 콘텐츠가 결정한다」로 HUG 를 내서, 보드를 줄이면 측정 폭에 남아 줄 밖으로 나갔다.

- **판정(계산값 · 선언).** 줄 안의 흐름 항목이 `flex-shrink > 0` 이고 다음 중 하나면 «줄어드는 항목»이다(`figma-tree-spec.mjs` 의 `flexShrinkItemOf`).
  ① `min-width: 0` 선언(Tailwind `min-w-0`) + 안에 줄일 수 있는 글자 — 한 줄 말줄임(`white-space: nowrap` + `overflow: hidden`) 또는 감긴 글자. 제품의 말줄임
  관용구(`min-w-0 truncate`)다. ② 칠 없는 제 글자뿐인 항목으로 줄바꿈 허용(`nowrap · pre` 아님) · `overflow: visible` · 시작 정렬 — `min-width: auto` 여도 가장 긴
  낱말까지 줄며 감긴다(CSS flex 의 자동 최소 크기). 같은 줄에 그런 항목이 둘 이상이거나 늘어나는 형제(`flex-grow > 0`)가 있으면 서지 않는다(Figma 는
  남는 폭을 FILL 끼리 똑같이 나눠 측정 폭이 무너진다). 감기지 않는 줄은 `nowrap` 만이다(`wrap` · `wrap-reverse` 는 아니다).
- **Figma.** 가로 FILL. 측정 폭에서 이미 줄었으면(안의 글자가 실제로 잘렸다 — 측정기 `truncated`, 또는 감겼고 줄의 흐름 항목 + 간격이 줄 안쪽 폭을 채웠다) 최대 폭
  없이, 아니면 측정 폭을 최대 폭으로 둔다 — FILL 이 측정 폭보다 넓어지지 않아 측정 폭의 그림이 같다. 글자 잎이면 15조의 22 의 `fw` 되돌림도 싣는다. 잘리지
  않았던 말줄임 글자는 `fw` 셋째 칸(1)으로 표시해, 렌더러가 페이지에 띄운 복제본으로 Figma 글꼴의 한 줄 폭을 재고 상한보다 넓으면(측정 폭에서 없는 «…» 가
  생긴다) 폭 맞춤으로 되돌린다. 내용으로 서는(HUG) 줄 안이면 남는 폭이
  없으므로 크기 조합 풀이(`reconcileFigmaSizing`)가 HUG 로 되돌리고 최대 폭을 걷는다.
- **실측 사고(늘림 시험 run 2026-10-15m).** /admin roles 모바일 360(3521:228) — 권한 체크 줄(label 348)의 설명 묶음 span(`min-w-0`, 안에 `truncate` 설명) 336 이
  29 밖으로(줄 셋). /admin ambassador 모바일 360(3521:230) — 지원자 머리 줄의 이름 묶음 span 320(`min-w-0`, 안에 `min-w-0 truncate` 이름)이 줄 308 밖으로,
  뒤의 갈매기 아이콘까지 밀려났다. 데스크톱 1440(3521:227)의 권한 줄도 같은 자리다.

### 15조의 24. 크기가 포함 블록을 따르는 절대 배치는 STRETCH · SCALE 이다 — 백분율 크기와 뷰포트 무대를 덮은 층

15조의 2 는 «양쪽 변이 0» 인 절대 배치만 늘였다. 가운데에 두고(`left: 50%` + `translate(-50%)`) 크기를 백분율로 준 상자와, 스크립트가 무대 크기를 px 로
쓴 상자는 CENTER(크기 고정)로 섰다.

- **판정(`constraintsFor` · `coverOf`).** 절대 배치(글자 아님)의 그 축 크기 선언이 백분율(`width: 100%`)이면 — 측정 자리에서 부모 상자를 덮었으면(자리 · 크기가
  0.5 안) `STRETCH`, 가운데 맞춤(`left: 50%`)이면 자리와 크기가 함께 비례하므로 `SCALE`. 크기 선언이 px 여도 두 축 모두 부모를 덮었고, 부모에서 «부모를 덮은
  상자»만 건너 올라가 처음 만나는 상자의 높이 선언이 뷰포트 높이 단위(`100vh` · `100lvh` …)면 두 축 `STRETCH` 다 — 무대(뷰포트)를 px 로 덮는 값은 스크립트가
  무대 크기를 쓴 것이다. 디자인 px 가 뷰포트 두 축과 우연히 같을 일은 없다. 덮지 않은 px 상자(15조의 2 의 `width: 400px` 이 부모와 같은 경우)는 그대로다.
- **근거(제품).** 랜딩 크리에이터 장면(`CreatorProgramScene.tsx`) — 창은 `absolute left-1/2 top-1/2` + `width · height = windowRect(expand, stage)`(다 펼친 프레임에서
  무대 크기), 안쪽 판은 `width: stage.width; height: stage.height` 이고 무대가 ResizeObserver 로 다시 잰다. 편집기 클립 색 미리보기 판은 `left: 50%; top: 50%;
  width: 100%; height: 100%`.
- **실측 사고(늘림 시험 run 2026-10-15n).** 랜딩 모바일 360(359:2986) — 「FRAME div AA」 402 가 360 무대 밖으로 42, 데스크톱 1440(359:2032)은 1920 이 480.
  편집기 클립 색 패널 모바일 360(3549:23850)의 판 402 가 360 틀 밖으로, 데스크톱 1440(3549:23849)은 1216 이 835 틀 밖으로.

### 15조의 25. 표 폭을 채운 표의 줄은 FILL 이다 — 여러 칸 줄은 측정 칸 폭 비율의 grid

CSS 표의 줄 묶음(`thead · tbody · tfoot`)과 줄(`tr`)은 늘 표의 폭이다. 크기 판정은 `display: table-row(-group)` 에 걸리는 규칙이 없어(UNRESOLVED) 측정 폭
FIXED 로 굳혔고 칸(`td · th`)도 그랬다.

- **판정(`build-figma-app-screens.mjs` 의 `fillTableRows`).** 표가 가로 FILL(`width: 100%`)이고 세로로 쌓으면, 측정 폭이 표 안쪽 폭과 같은(1 안) 줄 묶음 · 줄을
  FILL 로 둔다. 칸이 하나인 줄은 칸도 FILL 이다. 칸이 여럿인 줄은 한 행 grid 로 바꾸고 열을 측정 칸 폭을 무게로 한 `fr` 열(FLEX)로 둔다 — Figma 가로 줄의
  FILL 은 남는 폭을 똑같이 나눠 측정 칸 폭(673 · 168 · 269 …)이 무너지기 때문이다. 측정 폭에서 열 폭 = 측정 칸 폭이다. grid 에는 가로 줄의 교차축
  정렬이 없어, 줄 높이를 채우지 않는 칸에 칸 안 세로 정렬(`ga`)로 넘긴다.
- **근사.** CSS 자동 표 배치는 남는 폭을 열 내용 폭의 비율로 나누므로 같은 방향이지만, 열의 `min-width`(분석 표 「Video」 240)는 Figma grid 열에 없어 싣지
  못한다. 표가 칸 폭으로 선 가로 스크롤 표(약관 · 개인정보 모바일 「표 칸은 측정 폭」)는 FILL 이 아니라 건드리지 않는다.

### 15조의 26. 상자를 따라 늘어나는 그림은 상자와 함께 SCALE 한다 — `preserveAspectRatio="none"`

### 15조의 32. 세로 flex 의 교차축 맞춤 항목이 칸 폭에 닿았으면 칸을 따라 줄어든다 — fit-content 는 칸 폭에서 잘린다

세로 flex(`flex-direction: column`)에서 교차축을 늘이지 않는(`align-items: flex-start` · `center` …) 항목의 폭은 내용 폭(fit-content) —
`min(max-content, 칸 폭)` 이다. 크기 판정은 「콘텐츠가 결정한다」로 HUG 를 내는데, 내용이 칸보다 넓어 칸 폭으로 잘린(그래서 감긴) 항목은 CSS 에서 칸 폭이고
칸이 좁아지면 함께 줄며 다시 감긴다. Figma HUG 는 안의 글자 폭에 남아 보드를 줄이면 칸 밖으로 나갔다. 15조의 23 은 가로 줄(주축)의 줄어듦이고 이 조는
세로 쌓기의 교차축이다.

- **판정(`figma-tree-spec.mjs` 의 `crossClampedItemOf`).** 부모가 세로 flex · 항목의 교차축 맞춤(`align-self`, 없으면 부모 `align-items`)이 `normal` · `stretch` 아님
  · 흐름 항목 · 폭 선언 없음 · 측정 폭이 부모 안쪽 폭과 1 안에서 같다 · 안에(깊이 4, 인스턴스 · 절대 배치 밖) 감긴 글자(`wrapLines` 2 줄 이상) 또는 말줄임 글자가
  있다. 마지막 조건이 «내용이 실제로 칸보다 넓었다»는 증거다 — 우연히 칸 폭과 같은 단추 묶음은 서지 않는다.
- **Figma.** 가로 FILL · 최대 폭 없음. 측정 폭에서 FILL = 칸 안쪽 폭 = 측정 폭이라 그림이 같다. 항목이 FILL 이 되면 안의 블록 글자도 HUG 부모에 묶이지 않아 FILL
  로 남고(크기 조합 풀이), 줄 옮긴 글자는 15조의 22 의 `fw` 되돌림을 싣는다.
- **근거(제품).** LOUIS 쪽 머리(`flex-col flex-wrap items-start`, 제목 묶음 `flex: 1 1 auto; min-width: 0`) — 모바일에서 제목 · 설명 묶음이 칸 폭 390 으로 잘려 설명이

### 15조의 33. 두 축을 덮은 자동 배치 덮개의 외동 FILL 카드는 여백 둔 가로 STRETCH 다 — `min(고정, 100vw − gutter)` 카드 포함

- **판정(`figma-tree-spec.mjs` convert 의 15조의 33 갈래).** 절대 배치 · 가로 자동 배치 · 두 축 제약 STRETCH · SCALE(두 축을 덮은 덮개) · 측정 크기로 선(HUG 아님) ·
  가로 여백(padding)이 있는 덮개의 외동 흐름 자식이 ① 가로 FILL 이고 최대 폭에 닿지 않았거나 ② 폭 선언이 `min(<px>, <vw · % 식>)` 이고 측정 폭이 그 px 보다 작다

## 16. 획 규칙은 단색 UI 아이콘에만 적용한다

4번의 「획 = 표시 크기 / 16」은 `currentColor` 를 따르는 **단색 선 아이콘**의 규칙이다.
여러 색을 쓰는 브랜드 타일(`public/Text.svg` 같은 앱 아이콘, 로고, 프로바이더 마크)은 원본 아트워크가
고정이라 비율대로 축소해야 하고, 그 안의 획도 함께 줄어든다. 이런 자산에 4번을 강요하면 그림이 깨진다.

검증 스크립트는 컴포넌트 이름이 `logo/` 로 시작하거나 설명에 「브랜드 자산」·「다색」이 있으면 4번에서
제외한다. 새 브랜드 자산을 올릴 때 설명에 그 표기를 반드시 남긴다.

## 17. 사양서의 `literal:#hex` 주석에 속지 않는다

사양서가 「면 `--accent-mint-500`(literal:#00c68e)」처럼 적을 때 괄호 안은 **그 토큰이 지금 푸는 값**일
뿐, 제품이 리터럴을 쓴다는 뜻이 아니다. 그대로 리터럴로 넣으면 테마를 갈아도 색이 안 따라온다.
실제로 이 함정으로 582개 페인트가 토큰 대신 하드코딩으로 들어갔다.

**제품 코드에 `var(--x)` 가 보이면 변수에 묶는다.** 리터럴로 두는 건 코드에도 `#hex` / `rgb(...)` 가
직접 박혀 있을 때뿐이고, 그때는 노드 이름에 `literal:` 을 적어 다음 사람이 재검할 수 있게 한다.

## 19. 형제 둘 다에 세로 FILL 을 주지 않는다

같은 행에 나란히 놓인 카드 둘을 「높이 맞춤」하려고 **양쪽 다** `layoutSizingVertical = "FILL"` 로 두면
높이를 정할 주체가 사라져 컨테이너가 접힌다(`/subscription` 에서 크레딧 카드가 통째로 눌렸다).

**높은 쪽을 HUG 로 두고 낮은 쪽만 FILL** 로 둔다. 그러면 부모가 높은 쪽 높이로 hug 하고 낮은 쪽이
거기에 맞춰 늘어난다.

| `90 · 자산 — 아이콘 · 로고 · 제품 부품` | 왼쪽 열 — 화면에서 뽑은 자산(출처별 섹션 A~H: logo · tile · icon · root · `.glyph` · `.authored` · 대형 · 장면, 그리고 R 제품 글리프 · T 옛 랜딩 캡처). 오른쪽 — 측정 제품 컴포넌트 섹션 I~Q · S 를 주제별 줄로(셸 → 결제 · 업그레이드 장면 → 요금 페이지 → 보드 부품) |
| `99 · 보류 — 범위 밖` | 범위 밖 (정본이 다른 저장소인 것) |
| (구분선) | |
| `작업 · …` | **디자인 시스템 밖** — 시안 · 서비스소개서 · 콘텐츠 디자인 · DS 정리 검토. 생성기 · 게이트가 읽지 않는다 |

**접두가 역할을 가른다.** `DS ·` 는 시스템 자신의 정본, 숫자(`00`~`99`)는 제품 화면과 그 자산, `작업 ·` 은 시스템 밖이다.
`90 · 자산` 과 `DS · Components` 를 헷갈리지 않는다: 90 은 **화면에서 뽑아낸 것**을 모아 둔 자리이고, DS 는 **시스템이 소유한
계약**이라 `verify-figma-parity` 가 대조하는 대상이다.

- **이름으로 찾는 도구가 있는 페이지.** `DS · Components` 는 `figma-readback-emit` · `figma-live-check` 가 이름으로 찾는다 — 바꾸면 그
  둘을 같은 변경에서 고친다. 제품 러너는 계획의 `pageId` 로 먼저 찾고 `pageName` 은 예비값이다(예비값도 새 이름으로 맞춘다).
- **섹션 이름은 생성기가 찾는 열쇠다.** `90 · 자산` 의 섹션(I~Q · R · S)은 러너가 이름으로 찾는다 — 이름을 바꾸면 생성기 상수와 라이브를
  같은 변경에서 옮긴다(안 그러면 러너가 섹션을 새로 만든다). 자리(x · y)는 러너가 섹션을 만들 때만 정하므로 옮겨도 된다. 같은 글자를 두
  섹션에 주지 않는다 — `O` 가 셋이던 것을 R(글리프) · S(부품)로 갈랐다.
- **DS 세트는 분류 섹션 안에 산다.** 섹션은 한 층뿐이다(중첩 금지). `figma-live-check` 가 최상위와 섹션 자식을 함께 돌며 같은 부모 안의 세트
  겹침과 섹션끼리의 겹침을 센다 — 한 줄로 쌓여 있던 동안 세트 아홉 쌍이 서로를 덮고 있었다.
- **구분선은 이름 없는 선이다**(`figma.createPageDivider()` — 이름은 줄표 · 별표 · 공백만 된다). 묶음 이름은 페이지 접두가 대신한다.
- **옮기기 · 붙이기도 글꼴이 필요하다.** `figma.root.insertChild`(페이지 순서)와 `section.appendChild` 가 그 안 글자의 글꼴이 로드되지
  않았으면 던진다 — 원자적으로 되돌아가니 오류 메시지의 글꼴을 로드하고 다시 보낸다.

라우트 알파벳순으로 깔지 않는다. 알파벳순은 **이름을 이미 아는 것**을 찾을 때만 빠르고, 그건 캔버스가
아니라 `00.2 라우트 색인` 표가 할 일이다. 캔버스는 「결제 실패 화면」처럼 **의미로 찾을 때** 빨라야 한다.

### 섹션 이름은 사양 문서로 가는 조인 키다 — 보드는 제3의 분류 체계를 만들지 않는다

```
<§10.N.n> · <라우트 글롭> · <한국어 이름>
```

페이지는 사람이 찾기 좋은 **여정 순 묶음**이고, 섹션은 사양 문서 `migration/product-screens/10.*.md`
(46 인스코프 라우트)에 **1:1 로 붙는 키**다. 페이지가 한 §10.N 을 둘로 쪼개면(애널리틱스와 어드민이
둘 다 §10.12) 양쪽 섹션이 같은 키를 달고 뒤에 무엇을 담았는지 적는다.

**보드가 자체 분류 번호를 새로 만들면 그 순간 정본이 셋으로 갈라진다**(코드 라우트 트리 · 사양 문서 ·
보드). 섹션 키를 문서 절 번호로 못박는 이유가 이것이다.

문서 절이 없는 화면은 키 대신 사유를 적는다 — 지어내지 않는다.

| 표기 | 뜻 | 예 |
| --- | --- | --- |
| `⚠ 결번` | 어느 §10.N 도 소유하지 않는다 | `404` · `error` · `global-error` (10.4.md 가 「이 절의 범위 밖」이라 명시) |
| `⚠ 미등록` | 문서에도 커버리지 등급에도 없다 | `/creative-media{,-admin}` · `/mypage/upgrade/bulk-{success,fail}` · `/subscription/coupons` — **등급을 지어내지 말 것** |
| `⚠ 권위 충돌` | 문서가 소유한다고 적지만 화면 정본이 다른 저장소다 | `/docs` (§10.4 vs klipse-docs 레포) |

### 섹션 이름 끝의 `L3`/`L2` 는 보드가 정하지 않는다

커버리지 등급은 `migration/product-screens/route-coverage-levels.json` 이 정본이다.
**L3 은 「문서만 보고 재구현」 검증을 최근 2라운드 연속 통과한 그룹에만 준다** — 1회 통과는 판정
흔들림과 구분되지 않는다(실제로 §10.2·10.8·10.11·10.12 가 통과→불통과로 뒤집혔다).

섹션 색도 같은 값에서 나온다 — 초록 L3 · 호박 L2 · 붉음 등급 없음. **등급이 바뀌면 보드를 손으로
고치지 말고 JSON 에서 다시 찍는다.** 보드가 등급을 저작하면 그 순간 정본이 둘이 된다.

등급을 **지어내지 않는다.** 커버리지 파일에 없는 라우트는 `등급 없음` 이다. 지금 10개가 그렇다 —
`/nodecanvas?project=`(상태) · `/admin/coupons/[id]/print` · `/creative-media{,-admin}` ·
`/mypage/upgrade/bulk-{success,fail}` · `/subscription/coupons` · 404 · error · global-error.

### 상시 검산식

```
라우트 프레임 = 보드 항목 × 2 − (반응형 분기가 없는 단일 프레임 수)
상태 프레임   = 상태 보드의 상태 수 × 2
총 프레임     = 라우트 프레임 + 상태 프레임
```

지금은 라우트 `51 × 2 − 1 = 101`, 상태 `(6 + 6) × 2 = 24`, 합 **125** 이다(2026-09-26 에 미등록 라우트 셋과 결제 성공 화면 넷의
`?preview=` 상태 여섯을 더했다). 이 등식이 깨지면 프레임이 빠졌거나 중복된 것이다. `figma-board-layout-check --index` 가 색인 요약 ·
색인 이름의 수를 보드에서 센 수와 대조한다.

**축을 둘로 쪼갠 이유**(2026-09-01 정정). 원래 이 절은 `48 × 2 − 1 = 95` 하나였고 그 95 를 「총
프레임 수」라고 불렀다. 보드는 그보다 12 개 많다 — `/highlight/[projectId]` 가 라우트 색인에서는
항목 **하나**(프레임 2개)인데, 보드에는 `__phase` 6 상태가 뷰포트 둘씩 따로 그려져 있기 때문이다.
95 를 총계로 읽으면 그 12 개가 「중복」으로 보여 **지우려 들게 된다.** 상태 보드는 중복이 아니라
라우트 축이 표현할 수 없는 축이므로, 두 항을 따로 세고 합만 비교한다.

상태 프레임 24 는 산 숫자가 아니라 생성물에서 읽는다 — 보드에 그려 넣은 것이 그 생성물이다. 상태 보드의 화면 키에는 개발용
후크의 쿼리(`?__phase=` · `?preview=`)가 붙는다.

```
node -e 'const s=require("./figma/app-screens.plan.json").screens;
  console.log(s.filter(x => x.route.includes("?")).length)'   # → 24
```

같은 파일이 프레임 id 도 갖는다(`__phase` `1064:3132` ~ `1064:3143` · `?preview` `2108:2507` ~ `2108:2518`). **보드 텍스트에 총계를 적을 때는 이
두 항을 나란히 적는다** — 라우트 색인 보드의 안내 TEXT 는 2026-09-26 부터 「라우트 프레임 101 + 상태
프레임 24 = 125」로 둘을 나란히 적는다(그전에는 「95개 프레임」 한 수였다).
**§10.N 인스코프 46 과 보드 항목 51 이 다른 이유는 `00.4` 대조표에 적어 둔다** — 적어 두지 않으면
다음 사람이 51 을 「고치려」 든다. 차이는 리다이렉트 −2 · 범위 밖 docs 하위 −3 · 상태 +1 ·
문서 미소유 +1 · 미등록 +5 · 결번 +3 이다. 00.4 의 다른 쪽 검산(제품 앵커 `2c6bdacf` 의 화면 52 ↔ 보드 51)은
리다이렉트 −2 · 렌더 계약 검사 화면 `/louis-render-contract` −1 · 에디터 상태 +1 · `/docs` +1 이다 — 앵커에는
`/docs` 가 없다(정본이 klipse-docs 로 옮겨 갔다). page.tsx 수(49)가 옛 대조와 같은 것은 `/docs` 넷이 빠지고
새 페이지 넷이 들어온 우연이다.

### 배치 산식 (높이 216~10122 를 겹치지 않게 놓는 유일한 규칙)

```
DESK_W 1920 · MOB_W 402 · PAIR_GAP 80 · MOB_DX 2000
COL_PITCH 2800 · COLS 4 · ROW_GUT 600
SEC_W 11200 · SEC_PAD_X 160 · SEC_PAD_TOP 240 · SEC_PAD_BOT 200 · SEC_GAP_Y 800

x_desktop(i) = 160 + (i mod 4) × 2800      # 허용 x 8개뿐
x_mobile(i)  = x_desktop(i) + 2000
rowTop(0)    = 240
rowTop(r+1)  = rowTop(r) + ceil100( 그 행 프레임 높이의 최댓값 ) + 600
```

- **한 라우트 = 한 열.** 데스크톱과 모바일을 80px 간격으로 나란히 두고 **윗변을 같은 y 에 맞춘다.**
  가운데 정렬 금지 — GNB 높이 대조가 가장 잦은 측정인데 매번 오프셋을 암산하게 된다.
- **max() 를 쓴다.** `/mypage/upgrade` 는 데스크톱 2492 · 모바일 3276 으로 모바일이 더 높다.
  데스크톱 기준으로 행 높이를 잡으면 784px 겹친다.
- Section 자식의 x/y 는 **섹션 상대 좌표**다(실측 확인). 절대 좌표로 계산하면 전부 어긋난다.
- 섹션은 중첩하지 않는다. 최대 2층(페이지 > 섹션).

## 21. 아이콘 마스터에 잉크가 없으면 화면에서 사라진다

인라인 SVG 에서 추출한 마스터는 `fill`/`stroke` 가 비어 있는 경우가 있다(제품에서는 `currentColor`
로 소비처가 칠하기 때문). 이 마스터는

- Assets 패널·라이브러리 브라우저에서 **빈칸으로 보이고**,
- 색을 덮어쓰지 않은 인스턴스가 **화면에서 통째로 안 보인다.**

실제로 마스터 42개가 비어 있었고 그 때문에 화면 위 아이콘 **90개가 렌더되지 않았다**(사이드바 `+`
38개, 푸터 소셜 12개, 비디오 에디터 툴바 22개 등). 눈으로는 "여백이 넓네" 로 보여서 오래 살아남는다.

**규칙**: 마스터에는 반드시 기본 잉크(`gray/000`)를 준다. 인스턴스는 제품의 `currentColor` 규칙대로
**가장 가까운 텍스트의 색을 상속**시키고, 텍스트가 없는 자리(소셜 버튼 등)만 제품 값을 명시한다.

검증: 아이콘 인스턴스의 도형 자식 중 칠해진 것이 하나도 없으면 실패. 이 항목을 11번 표에 추가한다.

## 22. 이름이 같다고 같은 자산이 아니다 — 합치기 전에 모양을 센다

일괄 추출은 소스 파일 이름으로 컴포넌트를 명명하므로, 한 파일에서 글리프 여러 개가 나오면 **같은
이름이 여러 벌** 생긴다. 이 보드에서는 9종 32개였는데 **모양 서명(자식 타입 · 크기 · path 길이)을
세어 보니 32개가 전부 서로 달랐다.** `icon/GnbWordmarkLogo` 13벌은 지구본 · 달 · 문서 · 로그아웃 ·
사이드바 · 다이아몬드 · 해 · 톱니 · 말풍선 · 화살표 · 롤러 · 방패 · 모니터였다.

**절차**: ① 모양 서명으로 묶는다 → ② 서명이 같은 것만 합치고 인스턴스를 옮긴다 → ③ 서명이 다르면
**대조표를 렌더해 눈으로 확인하고 각각 제 이름을 준다.** 번호 접미(`-1`~`-13`)는 최후의 수단이다.

## 23. 프레임 이름이 곧 색인이다

```
<viewport> <W>×<H> — <route> (<상태 판정>)
```

이름만 보고 라우트·뷰포트·실제 크기·상태를 알 수 있어야 한다. 이 보드에서는 프레임 8개가 이름에서
라우트를 잃고 `desktop 1920×1080 — dark` 로만 남아 있었다 — 어느 화면인지 열어 보기 전에는 알 수 없다.

- `W×H` 는 **실제 노드 크기**여야 한다. hug 로 늘어난 뒤 이름을 갱신하지 않으면 색인이 거짓이 된다
  (실제로 `mobile 402×874` 라고 적힌 프레임이 402×1148 이었다).
- 상태 판정이 없는 프레임은 「어느 분기를 그린 것인지 모르는 프레임」이다. 반드시 채운다.
- **상태 판정은 그려진 화면이지 라우트의 의도가 아니다.** fixture 는 인증만 우회하고 쿼리 · 데이터가 없으므로
  `/mypage/topup/success` 보드가 그리는 것은 「충전 성공」이 아니라 「결제 정보 없음 → 충전 반영 지연 안내」다.
  2026-09-26 에 결제 결과 보드 14장이 라우트 이름을 풀어 쓴 판정(「충전 성공 결과」 · 「구독 결제 실패」)을 달고
  있었다 — fixture 의 보이는 글자로 다시 적었다.
- **라우트 색인(START HERE 00.2)은 보드 이름의 사본이다.** 손으로 고치지 않고 보드 이름에서 다시 찍는다.
  (157)에서 보드 이름 열 개를 고칠 때 색인이 따라오지 않아 52 칸이 보드와 달랐다(2026-09-26 발견).
- **기계로 센다 — `scripts/figma-board-layout-check.mjs`.** 이름 문법 · 실제 크기 · 상태 빈칸, 20조 배치 산식,
  `--index` 를 주면 색인 칸까지 대조한다. Figma 접근이 필요해 CI 밖이다(`--emit` 탐침을 읽기 전용으로 돌리고
  결과를 `--check` 에 준다). 이 스크립트가 없던 동안 보드 107 장 가운데 30 장이 어긋나 있었다 — 괄호 없는 이름 6 ·
  옛 캡처 높이를 단 hug 보드 9 · 의도를 적은 결제 결과 14 · 반올림 1. 의미(「그려진 상태인가」)는 기계가 모른다 —
  그것은 fixture 의 보이는 글자와 대조해 사람이 적는다.
- 자산은 이름 앞에 `출처:` 태그를 붙인 **설명**으로 분류한다. 생김새가 아니라 출처로 가르는 이유는
  「제품의 무엇과 같아야 하나」의 검증 방법이 출처마다 다르기 때문이다(파일 diff ↔ 소스 줄 대조).

### 자산 이름의 접두가 곧 검증 방법이다

`icon/` 을 전부에 붙이면 **「public 에 파일이 있다」는 거짓 신호**가 된다. 실제로 그 거짓 신호가
같은 이름 32개(§22)의 원인이었다 — 파일이 없는 인라인 글리프가 파일 자산과 같은 접두를 달고 있었다.

| 접두 | 출처 | 검증 방법 | 게시 |
| --- | --- | --- | --- |
| `logo/` | 브랜드 자산 | 원본 색 유지 · 획 규칙 미적용 | O |
| `tile/` | `public/*.svg` 다색 앱 타일 | 파일 diff · currentColor 안 먹음 | O |
| `icon/` | `public/icons/*.svg` | 파일 diff | O |
| `root/` | `public/*.svg` (루트) | 파일 diff | O |
| `.glyph/` | 제품 `.tsx` 안의 인라인 `<svg>` | **소스 `file:line` 대조** — 파일이 없다 | X |
| `.authored/` | **출처 없음** — 보드에서 그렸고 제품 원본을 인용하지 못했다 | **불가** | X |

`.` 접두는 Figma 에서 그 컴포넌트를 라이브러리에 게시하지 않는다. 파일로 검증할 수 없는 자산이
다른 파일로 퍼지지 않게 막는 장치다.

**`.authored/` 는 격리 표시지 분류가 아니다.** 여기 남은 것은 「제품 어디서 왔는지 아직 못 찾은
것」이고, 이 컴포넌트로 값을 재면 **존재하지 않는 제품 사실을 재는 것**이다. 소스를 찾는 즉시
`file:line` 을 설명에 적고 `.glyph/` 로 옮긴다. 이 묶음이 비는 것이 목표다.

## 24. 합성 제품 장면은 고정 빌드에서 직접 잰다

완성된 제품 장면은 클래스 문자열 하나의 합이 아니다. 이미지의 intrinsic ratio, 뷰포트에 따른
컨테이너 높이, 중첩 컴포넌트, 축소 캔버스가 함께 최종 지오메트리를 만든다. 이 중 하나라도 있는
장면을 정적 클래스 하네스에서 재구성해 잰 값은 Figma 입력으로 쓸 수 없다.

- 구조 카탈로그에는 태그·부모자식·표본 텍스트만 둔다. 간격·크기·색·반경은 넣지 않는다.
- 수치와 색은 고정 커밋의 clean production build를 실제 목표 뷰포트에서 렌더한 생성물만 쓴다.
- 생성물은 제품 커밋, 빌드 영수증, 측정 뷰포트, 모든 선언 노드의 rect·계산 스타일, 자산 해시와
  인라인 SVG geometry를 함께 기록한다. 사람이 고치지 않는다.
- 제품 저장소나 빌드가 없거나, checkout이 dirty이거나, 빌드 커밋·영수증·sourcemap이 고정
  커밋과 다르면 **검증 불가가 아니라 실패**다. `SKIPPED`와 exit 0은 허용하지 않는다.
- 측정 생성물이 초록이어도 Figma 구현 완료를 뜻하지 않는다. 대상 컴포넌트 조립과 되읽기 대조가
  모두 끝나기 전까지 manifest의 Figma 상태를 올리지 않는다.

현재 구조 원천은 [`figma/product-specimens.json`](../../figma/product-specimens.json), 측정 생성물은
[`migration/product.scenes.json`](../../migration/product.scenes.json), 생성·검사는
[`scripts/measure-product-scenes.mjs`](../../scripts/measure-product-scenes.mjs)가 소유한다.
측정 서버와 브라우저는 **바깥 네트워크를 끊고** 띄운다([`scripts/lib/block-external-network.cjs`](../../scripts/lib/block-external-network.cjs)).
고정 빌드가 원격 데이터를 불러 `/blog` 가 그날의 게시글을 그렸고, 제품이 그대로인데 게이트가 날에 따라 빨갰다 —
원격 데이터가 그리는 자리는 빈 상태로 기록한다([Updates](../updates/README.md) (159)).

### 화면을 재기 전에 그 화면이 어느 세션으로 보이는지 먼저 정한다

화면 보드 생성기(`build-figma-app-screens`)가 읽는 측정 원장은 세션 상태마다 따로다 — 한 서버로 모든 화면을 재면 어떤 화면은
다른 화면으로 넘어간 채 재진다(`redirected: true`). 2026-09-28 에 둘을 직접 겪었다.

| 세션 | 원장 · 측정 | 담는 화면 | 넘어가는 화면 |
| --- | --- | --- | --- |
| 로그인(인증 우회) | `product.auth-fixture.json` · `measure-product-auth-fixture` | 보호 앱 화면(홈 · 설정 · 구독 · 결제 · 하이라이트 단계) | 인증 화면 — 로그인된 사용자를 `/archive` 로 보낸다 |
| 로그아웃 | `product.anonymous-fixture.json` · 같은 측정기 `--anonymous` | 인증 화면 · 404 · 한 뷰포트짜리 공개 화면 | 보호 앱 화면 |
| 서버가 확인하는 로그인 | **없다** — 서버가 받는 가짜 세션이 필요하다 | 허브 셋 · 편집기 · 어드민(서버 컴포넌트가 `getUser()` → `redirect("/")`) | 인증 우회로는 못 넘는다(우회는 브라우저 쪽이다) |

- **LOUIS CSS 는 이 저장소 판으로 잰다(2026-10-07, 소유자 결정).** 제품 앵커는 `@klipse-design/css` 를 자기 package.json 의 SHA 로
  고정해 받는다(a4125565 → 021c2b63, 9월 중순). 그 판으로 재면 그 뒤 LOUIS 작업(메뉴 면 · 헤어라인 · 선택 행 표식 · 표 hover ·
  primary 빛 · 모달 가림막 · 코치마크 · 포커스 링 없음 …)이 보드에 빠진다 — 제품의 작업 브랜치들은 이미 더 새 판을 고정해 쓴다.
  측정기 둘(`measure-product-auth-fixture` 전 모드 · `measure-product-sidebar-states`)은 개발 서버를 띄우기 전에 픽스처의
  `generated/` 를 `packages/css/generated` 로 덮고, 판이 바뀌면 `.next` 를 지운다(webpack 은 node_modules 를 버전으로 캐시한다).
  원장의 `louisCss` 는 출처와 제품이 고정한 SHA(`productPinned`)만 적는다 — **판의 해시는 적지 않는다.** 적으면 LOUIS CSS 를 고친
  모든 커밋이 값이 그대로인 원장의 `--check` 까지 빨갛게 만든다(로그인 원장 한 벌이 2시간 넘게 걸린다). 판이 화면 값을 바꿨는지는
  `--check` 가 값으로 잡는다. **LOUIS CSS 를 고치면 그 부품이 보이는 화면을 다시 잰다** — 게이트가 없는 원장(세션 · 공개)은 아무도
  대신 알려 주지 않는다. 제품 코드는 앵커 그대로다(dev 의 화면 개편은
  들어가지 않는다). 제품과 DS 의 차이를 재는 `measure-product-components` 는 일부러 고정 판과 비교하므로 덮지 않는다.
  구현은 `scripts/lib/louis-css-overlay.mjs`.
- **넘어간 화면은 그리지 않는다.** 생성기는 `redirected` 인 화면을 대상으로 받지 않는다. 측정기는 그 화면을 별칭(`screenAliases`)으로
  기록해 둔다 — 왜 못 그렸는지가 원장에 남는다.
- **쿼리가 있어야 제 화면이 나오는 진입은 쿼리를 싣는다.** `/aws/signup` 은 `token` 이 없으면 `/signup` 으로 보낸다 — 토큰은 제출할 때만
  쓰이므로 가짜 토큰으로 연 화면이 마켓플레이스에서 들어온 사용자의 화면이다. 개발용 후크(`?__phase=` · `?preview=`)와 달리 상태 보드가
  아니라 라우트의 기본 보드다.
- **긴 공개 페이지는 공개 원장이 문서 전체를 잰다(2026-09-29).** 인증 · 로그아웃 원장은 뷰포트와 겹치는 노드만 잰다. 장면 측정기의 원장은
  공개 페이지를 재지만 화면마다 탐침 몇(뿌리 · 제목 · 이미지)만 싣고 노드 트리가 없어 보드를 생성할 수 없다. 그래서 같은 측정기의 공개
  모드(`--public`)가 로그아웃 상태로 **문서 끝까지의 노드**(가로는 뷰포트 안)를 별도 원장 `product.public-fixture.json` 에 싣고, 보드는
  뷰포트 창이 아니라 문서 높이로 선다(`fullPage`).
- **서버가 로그인을 확인하는 화면은 세션 원장에서 잰다(2026-09-29).** 허브 셋은 서버 컴포넌트가 `supabase.auth.getUser()` 로 사용자를
  확인한다 — 인증 우회는 브라우저 쪽이라 통과하지 못한다. `getUser()` 는 토큰을 풀지 않고 Supabase 인증 서버에 묻으므로, 세션 모드
  (`--session`)가 로컬 가짜 Supabase(`scripts/lib/fixture-fake-supabase.mjs`)를 띄워 인증에는 고정 사용자로, 데이터 조회에는 **빈
  목록**으로 답하게 하고 브라우저 문맥에 `@supabase/ssr` 세션 쿠키를 넣는다. 지어낸 데이터로 화면을 채우지 않는다 — 프로젝트가 없는 사용자의
  화면이다. 원장은 `product.session-fixture.json`, 가짜 서버가 받은 요청 목록을 함께 싣는다.
- **글자는 줄과 경계 공백을 싣는다(2026-09-28).** 측정기의 글자 추출(`ownText`)은 `<br>` 을 줄바꿈으로, 글자와 요소가 맞닿은 공백을
  한 칸으로 남긴다 — 옛 추출은 글자 노드만 이어 `trim` 해서 `/recover` 안내의 두 줄이 한 줄로, 가입의 「account? Log in」 이 「account?Log in」
  으로 그려졌다. 글자 노드끼리는 옛처럼 공백으로 잇는다. 인증 원장은 분석 빈 상태 제목의 `<br>` 네 곳만 바뀌었다 — 제품은 두 줄, 보드는 한 줄이었다. **보드에는 글자 끝 공백을 NBSP 로
  싣는다** — Figma 의 폭 자동 글자는 끝 공백을 폭에 넣지 않아, 원장에 살린 공백이 보드에서 다시 사라졌다. payload 에는 `\u00a0`
  이스케이프로 적는다(옮겨 적을 때 여느 공백으로 바뀌지 않게).
- **감긴 줄을 싣는다(2026-09-29).** 보드 글꼴은 제품 글꼴(`system-ui` = 맥 Chrome 의 SF Pro 등)과 너비가 달라 폭만 옮기면 줄이 다른
  자리에서 꺾인다 — 데이터 삭제 상태 첫 문단(제품 두 줄 · 보드 한 줄, 아래가 25.6 위), 구독 크레딧 안내(두 줄 · 한 줄, 격자가 17.6 짧아
  가운데 선 본문이 올라갔다). 측정기가 직계 글자 노드를 한 자씩 Range 로 재서 보이는 줄마다의 글자(`wrapLines`)를 싣고 — `<br>` 보다 줄이
  많을 때만 — 생성기는 **그리는 글자**만 그 줄을 줄바꿈으로 이어 쓴다(`scripts/lib/measured-text.mjs`). `ownText` 는 그대로 둔다 — 서명 ·
  매칭 · 라벨 대조의 열쇠라 흔들리면 인스턴스 치환이 끊긴다. 결제 결과 본문 · 결제 상태 생성기도 같은 함수로 그린다(요금제 장면 생성기는 감긴 행을
  고정 폭 상자와 Figma 에서 잰 줄 폭 표로 이미 꺾는다).
- **줄을 옮긴 글자는 폭을 글자에 맞춘다(2026-10-01).** 제품 줄바꿈을 넣어도 글자 상자가 칸 폭(FILL · FIXED, 높이 맞춤)이면 Figma 는 제 글꼴로
  한 줄이 칸보다 몇 px 넓을 때 그 줄을 **한 번 더** 감는다 — 개인정보 데스크톱 「The Company processes … User Data Policy」 줄이 720 을 넘겨 두
  줄 문단이 세 줄이 됐고, 그런 문단이 쌓여 약관 · 개인정보 보드 끝이 18 ~ 92 내려갔다(끝 대조 · 글자 대조, 줄바꿈 없는 옛 손 보드 글자는 Figma 가
  스스로 두 줄로 감았다). 줄을 옮긴 글자는 가로 · 세로 HUG 로 둬 줄바꿈이 제품 자리에서만 일어나게 한다(`hugCarriedLines`). 상자 폭이 바뀌어도
  자리가 같은 경우만 — 시작 정렬, 폭이 정해진 세로 쌓기(교차축 시작) 또는 흐름 자식 하나, 측정 상자가 부모 내용 시작선에 붙음. 가운데 · 끝 정렬과
  여러 자식이 선 가로 줄 · grid 칸의 글자는 칸 폭 그대로다. 줄이 칸보다 넓으면 몇 px 칸 밖으로 나가는데, 자르는 부모가 아니면 보이지 않는다.
  **폭이 부모 안쪽 폭과 같아도 FILL 로 돌리지 않는다(2026-10-12 판단).** 늘림 시험에서 이 HUG 는 줄이 좁아지면 부모 밖으로 나가지만(/highlight
  모바일 설명 문단 390 · 세 줄), 「여유 ≤ 2px 이거나 부모가 FILL 축이면 FILL」은 측정 폭 parity 를 지키지 못한다 — 다시 감기는 위험은 상자
  여유가 아니라 줄 여유로 정해지고 원장에는 줄마다의 폭이 없으며, 이 규칙을 낳은 개인정보 문단이 바로 폭 = 부모 폭(데스크톱 720 = 720 · 모바일
  483.61 = 483.61)이다. 하이라이트 단계 모바일의 가운데 정렬 두 줄 안내(HUG 340 / 칸 342, flex 항목 판정의 HUG)도 같은 이유로 둔다. Figma 에서
  옮긴 줄의 폭을 재기 전에는 바꾸지 않는다. **예외 — 줄 수를 자르는 글자(`line-clamp`)는 칸 폭 FILL + 말줄임이다(2026-10-14, 15조의 10)** — N 줄보다
  길어질 수 없어 다시 감기는 위험이 높이를 바꾸지 못한다. **2026-10-15 — 판정 폭이 FILL 인 글자는 FILL 로 두고 렌더러가 Figma 에서 줄 폭을 잰다(15조의 22).**
  측정 폭에서 한 줄 더 감긴 글자만 이 항의 폭 맞춤으로 되돌아간다 — 위 판단이 기다리던 «Figma 에서 잰 줄 폭»을 렌더러가 보드마다 잰다.
  렌더러의 「첫 줄 굵은 범위는 글자 상자를 1 키운다 → 측정 높이로 고정」 보정도 폭 맞춤 글자에 함께 건다 — 높이 맞춤에만 걸었더니 폭 맞춤으로
  바꾼 개인정보 목록의 「라벨: 설명」 항목이 하나마다 다시 1 씩 커졌다(렌더러는 모든 러너에 들어가므로 러너 전부가 바뀌지만 결과가 바뀌는 보드는
  굵은 범위의 여러 줄 폭 맞춤 글자를 가진 보드뿐이다 — 그 보드만 다시 보낸다).
- **조각이 여럿인 보드는 바뀐 첫 조각부터 끝까지 순서대로 보낸다(2026-10-01).** 앞 조각은 뒤 조각의 자리를 자리표시로 다시 세운다 — 본문 열을
  싣는 조각 01 을 다시 보내면 02 ~ 04 의 자리가 자리표시가 된다. 01 과 04 를 동시에 보냈더니 04 가 먼저 들어가 01 에 지워졌고, 바뀌지 않은 02 를
  빼먹어 자리가 비었다. 보드마다 한 줄로 이어 보내고(에이전트 하나에 조각 둘, 다음 에이전트는 앞이 끝난 뒤), 바뀌지 않은 조각도 그 뒤라면 보낸다.
- **SVG 선 도형은 한 변만 있어도 싣는다(2026-09-29).** 측정기는 상자의 폭 · 높이가 둘 다 있어야 보이는 노드로 실었다 — 가로선 · 세로선
  `<path>`(더하기 `M3.75 12H20.25` · `M12 3.75V20.25`, 지구본 적도 `M3 12h18`)는 한 변이 0 이라 버려졌고, 선으로만 된 아이콘은 svg 에 뷰박스만
  남아 서명이 비었다(허브 「New Canvas」 · 요금 체크 표시). SVG 도형(`SVGGeometryElement`)은 한 변만 있어도 싣는다 — 빈 서명은 서로 다른 아이콘을
  한 이름으로 묶는다.
- **입력칸의 값은 그 칸의 글자다(2026-09-29).** 값은 글자 노드가 아니라 측정기가 `value` 로 따로 싣고(비밀번호 제외), 트리 변환이 글자로
  옮긴다 — 쿠폰 수량 입력칸의 「1」이 보드에서 비어 있었다.
- **문단의 인라인 조각 순서를 싣는다(2026-09-30).** 제 글자와 인라인 요소가 섞인 노드는 자식 순서대로 글자 조각(문자열)과 요소 자식 순번(수 —
  자식 경로의 끝 칸)을 `inlineRuns` 로 싣는다(`<br>` 은 "\n"). `ownText` 는 요소를 빼고 이어 붙여 순서를 잃는다 — 트리 변환이 이것으로 문단을
  글자 하나 + 범위 서식으로 다시 짓는다(28조).
- **next/image 는 원본 주소를 싣는다(2026-09-30).** 최적화 주소(`/_next/image?url=…`)의 경로만 남기면 모든 이미지가 하나로 접혀 자산 조인표가
  원본을 고를 수 없었다 — `url` 쿼리의 원본(`/symbol.png`)을 `src` 로 싣는다.
- **측정 트리의 부모는 경로가 아니라 `parentPath` 다.** 측정기는 `display: contents` 요소를 싣지 않고 그 자식을 가장 가까운 보이는 조상에
  붙여 적는다. 경로를 잘라 부모를 구하던 생성기는 그 가지를 통째로 버렸다 — 로그아웃 원장의 인증 화면 모바일 여덟 장이 측정 노드 23 중
  3 만 남은 빈 보드로 생성됐고 생성기는 초록이었다(인증 2열의 오른쪽 칸이 모바일에서 `display: contents`). 이제 생성기는 부모를 못 찾은
  노드가 하나라도 있으면 멈춘다(`figma-tree-spec.mjs` `buildHierarchy`, 카나리아가 그 멈춤을 지킨다).

## 25. 인스턴스로 바꿀 때 컴포넌트가 «연» TEXT 속성은 반드시 채운다

측정 서브트리를 인스턴스로 치환하면 자식을 버린다 — 컴포넌트가 제 속을 그리기 때문이다. 그런데
버려지는 자식 안에 **컴포넌트가 알 수 없는 것**이 하나 있다: 그 자리의 라벨이다.

채우지 않으면 마스터의 기본 라벨(`버튼`)이 그대로 남고, HUG 인 자리는 그 글자를 물어 접힌다.
실측(2026-09-02): `/settings` 데스크톱의 Button 7개가 전부 「버튼」으로 나와 폭이
113.3·136.95·156.55·184.3·48·138.67·75.27 에서 **49 로** 접혔다. 라벨은 payload 에 처음부터
없었으므로 렌더러에는 고칠 수단이 없었다 — 결함은 생성기에 있었다.

- **속성 키를 손으로 적지 않는다.** Figma 는 이름 뒤에 인스턴스 id 를 붙여 키를 만든다
  (`Label#123:4`). 세트의 `componentPropertyDefinitions` 에서 `type === "TEXT"` 인 것을 실행
  시점에 찾는다. `figma/readback.json` 은 그 꼬리를 잘라 담으므로 이름만 안다.
- **못 찾으면 던진다.** 조용히 기본 라벨로 두면 눈으로만 보이는 결함이 되고, 화면 36장에 퍼진다.
- **8번(색·타이포를 인스턴스에 걸지 않는다)에 걸리지 않는다.** 그 규칙은 컴포넌트가 «정한»
  값을 화면이 덮어써서 시스템 쪽 수정이 전파되지 않게 되는 것을 막는다. TEXT 속성은 반대로
  컴포넌트가 **스스로 연 구멍**이라 채워도 전파가 끊기지 않는다.
- **슬롯과 텍스트의 짝이 1:1 이 아니면 짝을 짓지 않는다.** 어느 글자가 어느 슬롯인지는 측정에
  없는 정보다. 짐작해 채우면 화면이 제품과 다른 글자를 말한다.

본문 블록은 이 규칙의 대상이 아니다 — **텍스트가 글자 그대로 같을 때만** 치환하므로 덮어쓸
차이가 정의상 0 이다. 사이드바(`Product/Gnb Desktop Shell`)는 TEXT 속성이 없다.

**상단 바 두 세트는 대상이다(2026-09-13).** 예전에는 「셸은 라벨을 variant 축(`Content=Settings`)이
나른다」고 적었지만 모바일 세트에는 라벨 축이 없어, 라이브 `/archive`·`/subscription` 모바일
보드가 제품과 다른 「Settings」 를 보이고 있었다. 이제 두 세트는 제품 `mainChromePageNav` 필드
이름을 딴 TEXT 속성 `Label`(Single) · `Parent`·`Current`(Trail)를 연다(앱 셸 plan 의
`textProperties`). 속성이 여럿이라 위의 「1:1 이 아니면 짝짓지 않는다」를 **이름**으로 푼다:

- 어느 글자가 어느 속성인지는 그 variant 의 plan `text[].property` 순서가 정한다 — 측정 breadcrumb
  에서 구분자 「/」를 뺀 순서와 같고, 수가 다르면 생성기가 던진다.
- payload 의 라벨 칸은 문자열이 아니라 **세트의 속성 이름 전부를 키로 가진 객체**다. 이 variant 가
  묶지 않은 속성은 null 이다. 렌더러는 파일의 TEXT 속성 이름 집합이 그 키 집합과 다르면 던진다 —
  속성을 아직 열지 않은 옛 세트에 적용하면 조용히 기본 라벨로 남는 대신 멈춘다.
- 세트 단위 속성은 기본값이 하나라, 마스터와 **덮어쓰지 않은 인스턴스는 모두 그 기본값을 보인다.**
  그래서 앱 셸 러너를 적용하면 그 세트를 인스턴스로 쓰는 **모든** 소비처가 속성을 채워야 끝난다 — 화면 보드의
  generated 트리(보드 러너가 채운다), 결제 장면 컴포넌트(그 러너가 채운다), 숨긴 `legacy/<route>` 그룹, 그리고
  **손으로 조립한 허브 보드**(채우는 생성기가 없다). 2026-09-13 라이브에서 허브 보드의 보이는 바가 일곱이었다
  (`/highlight` · `/videoeditor` · `/canvas` 의 두 뷰포트와 `/analytics/instagram` 데스크톱). 「화면 보드·결제
  장면」만 적었던 옛 문장은 이 일곱을 빠뜨렸다.
- **소비처는 생성물이 아니라 라이브에서 센다.** 적용 전에 `figma-screens-live-check --emit --consumers` 로 세트의
  인스턴스를 전부 뽑아 기준선으로 남기고, 적용 뒤 같은 탐침과 `--consumers <전> <후>` 로 보이는 글자 · 크기 · 면이
  바뀐 곳을 찾는다. 인스턴스에서 글자 내용이나 면을 덮어쓴 소비처(허브 일곱이 그렇다)에서 마스터 변경이 어떻게
  번지는지는 Figma 동작에 달려 있어 코드로 추론하지 않는다.

## 26. 아이콘은 크기가 아니라 «서명»으로 부른다

측정 fixture 는 `<svg>` 의 `viewBox` 와 자손 도형의 기하 속성(`d`·`points`·`cx`…)을 담는데,
트리 변환이 `<path>` 를 「스스로 그릴 것이 없는 노드」로 보아 지운다 — 배경도 테두리도 글자도
없기 때문이다. 그래서 Figma 로 가는 spec 에 아이콘이 **크기만 있는 빈 상자**로 남았고, 보드
원장은 39자리를 「어느 아이콘인지 모른다」로 세었다.

- **서명은 지우기 «앞»에서 뜬다.** `glyphSignature`(`scripts/lib/figma-tree-spec.mjs`)가
  `viewBox|tag(attr=value …)|…` 를 측정값 그대로 잇는다. 반올림도 좌표 정규화도 하지 않는다 —
  서명이 같다는 것은 「비슷한 그림」이 아니라 「같은 소스에서 나왔다」를 뜻해야 한다.
- **이름은 손으로 읽는다.** 경로 데이터 비교로는 닿지 않는다: LOUIS 아이콘 31종은
  `<line>`·`<polyline>`·`<circle>`·`<rect>` 로 그려져 있고 제품 글리프는 전부 `<path>` 라
  문자열이 같은 기하가 0 건이다. 이름·클래스는 측정 트리에 없고(있는 것은 감싼 버튼의
  `aria-label` 이며 그것은 자리의 이름이지 그림의 이름이 아니다), 24 상자 1.8 획인 글리프가
  여덟 중 넷이라 크기+획으로도 갈리지 않는다. 조인표는
  `scripts/lib/figma-glyph-identity.mjs` 가 소유하고 `figma/app-screens.plan.json` 에 실린다.
- **payload 에는 이름만 싣는다.** 서명 하나가 최대 900바이트라 39자리면 조각이 갈라진다.
  축약 키는 `v` 이고, 25번의 라벨(`i` 의 셋째 칸)과 같은 결이다.
- **서명이 표에 없으면 던진다.** 조용히 이름 없이 두면 보드에 회색 상자가 하나 더 늘고,
  원장은 그것을 「생성기가 정체를 버렸다」는 이미 틀린 사유로 세게 된다.
- **이름이 붙었다고 인스턴스를 놓는 것은 아니다.** 여덟 서명 중 LOUIS 아이콘을 그대로 무는
  것은 0 건이다 — 둘은 같은 뜻의 아이콘이 있지만 제품이 24 상자 1.8 획의 인라인 글리프를
  그려 `bespoke` 이고(정본은 24 상자 1.5 획 — [DS-D-0021](decisions/DS-D-0021-icon-size-axis.md)),
  여섯은 LOUIS 31종에 대응 그림이 아예 없어 `missing` 이다. 4번·16번의 획 규칙을 어긴 글리프를
  Figma 에만 정본으로 심으면 두 축이 어긋난다 — 그 승격 판정은
  [DS-D-0038](decisions/DS-D-0038-icons-are-an-asset-axis.md)이 아이콘 축의 미결로 남겨 두었다.
- **그림은 측정한 도형으로 그린다(2026-09-30).** 이름(`v`)만으로는 보드의 `<svg>` 자리가 칠도 자식도 없는 빈 상자였다 — 테마 토글의
  모니터 · 해 · 달, 언어 선택의 지구본, 프로필 자리의 사람 원이 화면에서 통째로 빠져 있었다(라이브 보드에서 자식 0 · 칠 0 으로 확인).
  트리 변환이 도형의 기하 속성과 계산된 칠 · 획(`fill` · `stroke` · 두께 · 끝모양 · 이음 · 점선 · 불투명도)으로 SVG 를 조립하고
  (`glyphMarkup`, 축약 키 `vs`, 속성은 홑따옴표), 렌더러가 `figma.createNodeFromSvg` 로 svg 자리의 자식 「glyph」 를 그린 뒤 칠 · 획을
  값이 같은 변수에 묶는다(없으면 리터럴 + `unboundColors`). 크기는 측정 상자다. 라이브 대조는 「glyph」 안으로 내려가지 않는다(기대값은
  `FRAME:glyph` 하나). 이것은 LOUIS 인스턴스를 심는 일이 아니라 **제품이 그린 그림을 그대로 옮기는 일**이다 — 위의 `bespoke` ·
  `missing` 판정은 그대로다.
- **`<img>` 는 src 로 부른다(2026-09-28).** `<img>` 는 그림이 파일이라 측정에 모양이 없고, 렌더러가 빈 상자로 그렸다 —
  인증 화면 브랜드 패널 · 카드 위의 로고가 통째로 빠졌다(캡처로 확인). 생성기의 `IMAGE_COMPONENTS` 가 src 를 LOUIS 90 · 자산의
  컴포넌트에 잇고(`/klipse-dark.svg` → `logo/klipse-dark` 처럼), id 와 실재는 `figma/live-assets.json` 이 증거다 — 없으면 멈춘다.
  렌더러는 id 로 찾되 이름까지 같아야 인스턴스를 놓고, 측정 폭으로 `rescale` 한다. 표에 없는 src 는 빈 상자로 남고 plan 감사본의
  `unmappedImages` 에 적힌다 — `<img>` 는 제 색으로 그려지므로(`currentColor` 가 닿지 않는다) 컴포넌트의 색을 대조한 뒤에만 잇는다.
  `/icons/youtube.svg` 는 검정 획이고 `icon/youtube` 는 `color/gray/000`(라이트 검정)이라 이었다 — 획 두께는 DS 아이콘 규칙(표시 크기/16)을
  따르는 컴포넌트가 3.0, 원본을 늘려 그리는 제품이 3.6 이다. 축약 키는 `im` 이다.

## 27. 라이브에 적용하기 전에 구조를 읽고, 적용한 뒤에 라이브를 계획과 대조한다

화면 보드를 지키는 게이트(`check-figma-app-screens` · `verify-figma-board-composition` ·
`check-figma-board-composition`)는 **계획 파일만** 읽는다. 초록은 「러너가 생성물과 같다」이지
「라이브 보드가 러너를 적용한 결과다」가 아니다. 실측(2026-09-13): 라이브 36 보드 중 34 가 열하루 전
커밋 `9f8483a` 의 계획으로 그려져 있었고 archive 두 보드는 어느 커밋과도 같지 않았는데, 어떤
게이트도 말하지 않았다. 같은 날 조사는 인계서의 「적용하면 손으로 놓인 바 `488:658` 을 지운다」가
코드와도 라이브와도 틀렸음을 드러냈다 — 그 바는 이미 숨긴 `legacy/<route>` 그룹 안에 있었다.

**적용 전에 읽는다(읽기 전용):**

- 보드 프레임의 직계 자식이 `generated/<route> <문맥>` 하나와 숨긴 `legacy/<route>` 그룹뿐인지.
  렌더러는 그 이름의 generated 자식만 지우고, legacy 그룹은 **없을 때만** 만든다 — 그룹이 있으면
  새로 생긴 직계 자식을 묶지도 지우지도 않아 흐름 자식으로 남는다.
- 러너가 찾는 **변수 컬렉션 이름**이 파일에 있는지. 라이브 LOUIS 의 컬렉션은 `Klipse Primitive` ·
  `Klipse Semantic` · `Klipse Semantic Color` 셋이고, 은퇴한 `1 · Palette` · `2 · Semantic` 을 찾는
  러너는 첫머리에서 던진다. 앱 셸 러너가 2026-09-13 에, 컴포넌트 · 체크아웃 · 결제 장면 · 업그레이드 ·
  sidebar-states 러너가 2026-09-14 에, 앱 화면 보드 렌더러가 같은 날 뒤에 옮겼다([Updates](../updates/README.md) (133) · (135) —
  보드는 역할 이름 없이 값으로 찾되 컬렉션 · 측정 테마의 모드를 계획 `colour` 가 정하고 없으면 던진다) — 남은 것은 `/pricing`
  러너다. 옮긴 생성기는 계획의 `bindings`
  를 되읽기(`figma/readback.json`)의 라이브 변수와 대조해 없는 컬렉션 · 변수가 새면 멈추고(`scripts/lib/figma-live-variables.mjs`
  의 `assertBindings`), 칠하는 자리마다 **측정 색과 값이 같은 역할**을 고른다 — 역할 · 선언 · 라이브 해석값 대조표는 계획의
  `colorEvidence` 가, 값이 같은 변수가 없어 고정 페인트로 칠하는 역할은 사유와 함께 `bindings.unbound` 가 갖고, 러너는 그
  역할을 `unboundColors` 로 돌려준다.
- 계획이 쓰는 **세트·variant·TEXT 속성**이 파일에 있는지 — `figma-screens-live-check --sets`. 상단 바 두 세트는
  variant 마다 Auto Layout 축(layoutMode · 축 sizing · 헤어라인 레이아웃 포함)까지 앱 셸 계획의
  `layoutContract` 와 대조한다 — 계산된 높이를 FIXED 로 굳힌 옛 세트가 라이브에 남아 있으면 여기서 보인다.
  세트 러너(앱 셸)가 보드 러너보다 먼저다. 순서를 거꾸로 하면 보드 러너가 「variant 를 찾지 못했다」
  또는 「TEXT 속성이 계획과 다르다」로 던진다.
- 세트 러너가 고칠 **세트의 소비처 전부** — `figma-screens-live-check --emit --consumers` 의 기준선. 세트 러너는
  마스터를 고치므로 generated 트리 밖(손 조립 허브 보드 · legacy · 장면 컴포넌트)에도 번진다. 세트 러너를 돌린 뒤
  같은 탐침으로 `--consumers <전> <후>` 를 돌려, 받아들이지 않은 보이는 변화가 0 인지 보고 나서 보드 러너로 간다.
- **러너가 찾는 노드가 파일에 있는지, 그리고 러너가 그것을 쓰기 전에 찾는지.** 계획이 노드 id 를 들고 있으면 그 id 가
  사라진 뒤에도 게이트는 초록이다. sidebar-states 러너는 편집 장면의 옛 원본 id 여섯을 들고, 세트 칠을 **쓴 뒤에** 그 id 를 찾다
  던질 자리였다(2026-09-15 사전 점검 · 모의 재현 — [Updates](../updates/README.md) (137)). 러너는 필요한 대상을 이름 · 구조로
  **전부 찾은 뒤에만** 쓴다 — 닻은 보드 프레임 하나(이름으로 확인)이고, 그 아래는 생성기가 지은 이름과 자리로 찾는다. 없거나
  둘이면 첫 쓰기 전에 던진다. sidebar-states 생성기는 템플릿의 「찾기」 구간에 쓰기가 섞였는지 글자로 막는다. 적용 전 확인은 그
  러너의 찾기 단계만(쓰기 0) 라이브에서 돌려 반환 id 를 보는 것이다.
- 적용 직전에 이름 붙은 Figma 버전을 남긴다 — 렌더러는 옛 generated 트리를 영구 삭제하므로 버전 기록이
  유일한 완전 복구 수단이다. 쓰기이므로 승인이 먼저다. **`use_figma` 에서는 `figma.saveVersionHistoryAsync` 가
  지원되지 않는다**(2026-09-14 실측 — 첫 문장에서 「not a supported API」로 던졌고 그 뒤 쓰기는 없었다). 버전은
  사람이 Figma 앱에서 남기고, 남기지 못한 채 적용한다면 그 사실을 승인 질문에 넣는다.

**적용한 뒤에 대조한다:** `node scripts/figma-screens-live-check.mjs --emit --page <PAGE_ID>` 를 페이지마다
읽기 전용 `use_figma` 로 돌리고 `--check <결과…>` 로 계획과 대조해 **계획 보드 전부를 탐침하고 다름 0** 임을
확인한다. 결과 파일을 빠뜨리면 탐침하지 않은 보드를 대고 실패한다 — 「다름 0」은 대조한 보드 수와 함께만
뜻이 있다. 적용에서 일부러 뺀 보드는 `--expect-differ <frameId>` 로 이름을 대고 받는다. 쓰는 법은
[Figma Sync](figma-sync.md) 「화면 보드 라이브 대조」 절이 소유한다. 이 검사는 CI 에 넣지 않는다 —
Figma 접근이 필요하다.

## 28. 계산된 크기는 숫자로 굳히지 않는다 — 고른 값만 고정한다

Figma 의 축은 **제품에서 그 크기를 누가 정했는지**로 정한다. 측정 rect 는 답이지 입력이 아니다. 사람이 고른
값(선언)만 고정하고, 레이아웃이 계산한 값은 hug · fill · 최소/최대 · 제약으로 옮긴다. 계산된 값을 수로 옮기면
그 값을 만든 자식 하나가 바뀌는 날 수만 남아 조용히 틀린다.

| 제품에서 크기를 정한 것 | Figma | 이 저장소에서 그렇게 지은 자리 |
| --- | --- | --- |
| `width` · `height` · `size` 의 px · 토큰 선언, 아이콘 · 아바타 같은 고정 자산 | FIXED(선언값) | 상단 바 사이드바 토글 `[height:32px]` · 프로필 버튼, 결제 결과 버튼 높이 `h-16` |
| 선언 없음 · `fit-content` — 패딩과 자식이 정한다 | HUG + 패딩 | 앱 상단 바 두 세트 — 패딩 8 + 가장 큰 자식 + 패딩 8 + 헤어라인 |
| `flex: 1` · `width: 100%` · `1fr` 트랙 · stretch | FILL | 상단 바 breadcrumb nav, 요금제 덱의 카드(`repeat(N, 1fr)`), 결제 결과 본문 글자, 편집 장면 속성 판의 안쪽 프레임(판 폭 · 제약 가로 STRETCH, 행은 FILL — 판 트랙이 324 → 240 으로 옮겨질 때 안쪽이 324 에 남아 값 열이 잘렸다, [Updates](../updates/README.md) (152)) |
| `min-*` · `max-*` | HUG · FILL + 최소 · 최대. `max-width: min(Npx, 100%)` 처럼 한계 자체가 식이면 px 쪽이 Figma 한계다 — computed 도 식을 풀지 않고 문자열로 두므로 px 만 읽으면 한계가 사라진다 | 요금제 카드 `min-h-[560px]`, 결제 결과 본문 `width: min(520px, 100%)`, 앱 화면 보드 `/mypage/upgrade` 의 카드 격자 컨테이너 `max-width: min(1300px, 100%)` — 한계가 빠져 격자가 본문 1672 를 채웠고 카드가 256.8 → 331.2 로 넓어졌다(Updates (161)) |
| `margin-inline: auto`(최대 폭에 닿은 FILL 블록의 가운데 정렬) | 부모 교차축 정렬 `CENTER` + 그 여백은 지운다. 형제가 모두 가로 FILL 일 때만 — 교차축 정렬이 형제에게 아무 일도 하지 않는다. 여백이 auto 였다는 것은 좌우 여백이 같고 (부모 안쪽 폭 − 폭) / 2 로 닫히는지로 본다. 측정 margin 이 좌우 모두 0 으로 읽혀도 자리(rect)가 부모 안쪽의 가운데이면 같은 판정이다 — 측정기가 flex 항목의 auto margin 사용값을 때때로 0 으로 읽는다(`/settings` 데스크톱 본문, 세 번 재어 0 · 124 · 0) | 앱 화면 보드 `/mypage/upgrade` · `/subscription` 데스크톱의 본문 컨테이너 — Auto Layout 에 margin 이 없어 형제가 있는 자식의 여백이 버려졌고 본문 왼쪽에 붙었다(Updates (161)) |
| 내용으로 서는(HUG) 축의 `justify-content: space-between` | 주축 정렬 MIN + itemSpacing = `gap`. CSS 는 남는 공간이 없어 gap 만 남지만 Figma 의 SPACE_BETWEEN 은 itemSpacing 을 버리고 HUG 축에서 간격을 0 으로 접는다 | 결제 성공 미리보기 모바일의 결제 정보 행(dt · dd 세로, gap 16) — 행마다 16 씩 올라가 마지막 행이 111 위에 섰다(`dropHugSpaceBetween`, 보드 글자 자리 대조로 찾았다) |
| 형제가 있는 자식의 `margin` | 칠 없는 감싸개(자식 하나, 방향 · 교차축 정렬은 부모를 따른다)로 싸고 margin 을 감싸개 padding 으로. 축마다 자식이 FILL 이면 감싸개도 FILL, 아니면 HUG. 음수(번짐)는 감싸개가 들고 가 다음 줄대로 조상이 받는다. **GRID 부모도 같다** — 감싸개는 세로 오토 레이아웃이고 칸 안 정렬(`gridAlign`)을 넘겨받는다(margin 상자가 칸에 선다) | 결제 결과 보드 14 장과 미리보기 12 장의 본문 `margin-top: 108` — 렌더러가 자식이 하나일 때만 margin 을 옮기는데 그 판정이 붙이는 순간에 돌아, 첫 자식의 margin 은 부모 padding 으로 새고 둘째부터는 버려졌다. 본문이 상단 바에 붙었다(제품 h1 y 165 · 보드 64, `build-figma-app-screens` 의 `wrapSiblingMargins`). GRID 부모는 「칸이 정한다」며 건너뛰었는데 행이 HUG 라 margin 이 칸에 남지 않았다 — 로그인 모바일 열에서 로고 링크 `margin-bottom: 24` 가 열 아래 padding 이 되고 버튼 · 링크 줄의 `margin-top: 8` 이 버려져 로고 y 278 → 285.5 · 폼 388 → 371.5(제품 캡처와 나란히 놓아 찾았다, 2026-09-29) |
| 좌우 음수 `margin`(부모 padding 밖으로 번지는 자식) | 번짐은 padding 을 가진 조상이 받는다. 직계 부모 padding 이 모자라면 칠 · 자르기 없는 부모가 모자란 만큼 넓어져 번짐을 들고 올라가고, 번짐을 받은 조상의 다른 흐름 형제는 깎은 padding 만큼 감싸개 padding 으로 제자리를 지킨다. 칠 · 자르기가 있는 노드는 넓히지 않는다(못 옮긴 번짐은 계획 `bleedUnresolved` 에 남는다). 위아래 번짐 · 형제가 있는 가로 줄은 렌더러의 「자식 하나」 규칙 그대로 | 앱 상단 바(좌 −16 · 우 −8, 모바일 −6) — padding 0 인 부모 안에 갇혀 제품보다 안쪽에 섰고(설정 · 구독 · 쿠폰 · highlight · 보관함), 바가 첫 자식인 보드(결제 결과 · bulk · 요금제)에서는 부모 padding 을 통째로 깎아 뒤의 본문까지 padding 없이 섰다(요금제 카드 격자 가운데 4 · 모바일 bulk 본문 402 ↔ 390, `build-figma-app-screens` 의 `hoistBleed`, 보드 글자 자리 대조로 찾았다) |
| 형제 사이의 위아래 음수 `margin`(겹치거나 당기는 이웃) | 음수 간격을 가진 이웃 둘을 칠 없는 세로 쌓기 하나로 묶고 간격을 (부모 간격 + 음수 margin)으로 — Figma 는 음수 간격을 받는다. 세로 쌓기와 한 열 GRID 에서만(여러 열이면 칸 배치가 바뀐다), 늘어난 행이 있는 GRID 는 건드리지 않는다. 묶음의 교차축 정렬은 부모 또는 채우지 않는 자식의 칸 정렬을 따르고, 두 자식의 칸 정렬이 다르면 묶지 않는다(계획 `negativeGapsUnresolved`) | 로그인 · 가입 · 비밀번호 화면의 입력칸 한 쌍(`margin-bottom: -1` 로 테두리를 겹친다)이 1 벌어져 폼이 제품보다 1 컸고(172 ↔ 171), 로그인 데스크톱 아래 링크 줄(`margin-top: -12`)은 12, 가입 안내 문단(`-4`)은 4 아래에 섰다(`build-figma-app-screens` 의 `pairNegativeGaps`) |
| 블록 흐름의 세로 margin 겹침 | 측정 자리로 판정한다 — 첫 · 마지막 자식이 패딩 · 테두리 없는 부모의 콘텐츠 가장자리에 붙어 있으면 그 margin 은 부모 밖으로 나간 것이라 0 으로, 이웃 사이가 두 margin 의 합이 아니라 큰 쪽이면 작은 쪽을 0 으로. 양수 margin · 블록 흐름만(flex · grid 는 겹치지 않는다). 제 글자를 떼어낸 노드도 본다 — 떼어낸 글자 조각은 margin 이 없어 판정에 끼지 않는다 | 요금제 머리의 마지막 h2 `margin-bottom: 18` 이 부모 안에 더해져 카드 격자가 18 아래에 섰고, 약관 문단의 겹친 margin 이 모두 더해져 보드가 148 길었다(`figma-tree-spec` 의 `collapsedBlockMargins`, 2026-09-30). 글자를 떼어낸 노드를 건너뛰자 글자 뒤 하위 목록의 `margin-bottom: 8` 이 항목 안에 갇혀 약관 다음 항목이 4 씩 밀렸다(2026-10-01) |
| 트랙 선언이 없는 grid 의 아이템(암시적 한 열) | 가로 FILL — `justify-self` 기본(normal)은 칸을 채운다. 트랙 규칙이 서지 않아 flex 규칙으로 떨어지면 grid 에는 주축이 없어 「콘텐츠가 결정」(HUG)이 됐다 | 문의 모바일의 소개 `aside`(칸 370)가 HUG 로 서고 안의 글자가 HUG 부모 안의 FILL 로 접혀 164 폭으로 줄이 늘었다 — 미해결 HUG · FILL 13 자리가 풀렸다(`sizing-provenance`, 2026-09-30) |
| `minmax(a, Nfr)` 트랙의 grid 아이템 | 가로 FILL(트랙이 남는 공간을 나눠 갖는다) — `Nfr` 단독 트랙과 같다. 판정 정규식이 `fr` 앞 단어 경계(`\bfr`)를 요구해 숫자 뒤의 `fr` 이 한 번도 맞지 않았다 | 문의 데스크톱의 두 칸(`minmax(0, 0.8fr) minmax(0, 1.2fr)`)이 HUG 로 떨어져 폼 전체가 140 폭으로 줄었다(`sizing-provenance` grid 트랙, 2026-09-30) |
| 크기 0 인 flex 아이템 뒤의 `gap` | 측정기는 넓이 없는 노드를 싣지 않는다 — 앞에서부터 채우는 한 줄 flex(`justify-content` 가 normal · flex-start · start, 감기 · 역순 없음)에서 자식의 측정 위치가 기대 위치보다 `gap` 의 정수배만큼 뒤에 있으면 그만큼을 그 자식의 앞 margin 으로(위 margin 규칙대로 부모 padding · 감싸개가 받는다). 글자를 떼어낸 노드는 조각 자리가 추정이라 보지 않는다 | 하이라이트 상태 보드 12장의 본문 래퍼(`gap: 24px`) — 첫 자식이 비어 있는 알림 자리라 section 이 24 아래에서 시작하는데, 보드는 래퍼 맨 위에 붙여 문구가 모두 24 올라갔다(`figma-tree-spec` 의 `hiddenGapMargins`, 보드 글자 자리 대조로 찾았다, 2026-09-29) |

**하지 않는 것:**

- 측정 rect 로 `resize()` 한 축을 FIXED 로 남기기 — 그 축에 선언 근거가 없으면 계산값을 굳힌 것이다.
- 제품이 흐름(`position: static`)인 자식을 `layoutMode = "NONE"` 에 x/y 로 놓기(7번의 연장).
- TEXT 를 `textAutoResize = "NONE"` 과 측정 폭 · 높이로 고정하기.
- 세트가 이미 있다는 이유로 기하 reconcile 을 건너뛰기 — 세트 러너는 매 실행 레이아웃을 **제자리에서** reconcile 한다.
  기존 variant 와 노드는 지우지 않는다(같은 id 로 새 자리에 옮기거나, 계획에 없으면 숨겨 `retired/` 로 둔다) —
  인스턴스의 TEXT 속성 값과 override 가 그 노드 id 에 걸려 있다. 칠만 다시 거는 것도 건너뛴 것이다 — 컴포넌트 러너가 옛
  사이드바 세트의 + 버튼(제품이 걷었고 계획에 없다)을 칠만 다시 건 채 보이게 두었고, 칠이 변수에 묶여 있어 페인트 감사도 통과했다
  ([Updates](../updates/README.md) (133) 「옛 compound 행」).
- 생성기 가드 · 치환 매처가 계산 결과를 `=== N` 이나 `|Δ| ≤ 1` 로 비교하기 — 가드는 선언이 있는지와 측정이 그
  선언의 식으로 **닫히는지**를 보고(앱 셸 생성기: 바 높이 = 패딩 + 가장 큰 자식 + 헤어라인, 업그레이드 생성기: 헤더
  높이 = 렌더러가 그리는 자식의 합), 매처는 구조 서명과 글자 서열로 판정한다.
- 노드 이름 · 컴포넌트 설명에 측정 수(`Measured 1628×1004`)를 리터럴로 박기 — 계획 rect 에서 조립한다.
- 계산된 크기를 두 기록에 사본으로 두기 — 담긴 쪽 기록에서 읽는다. 예: AppTopBar 의 두 슬롯은 같은 CSS 규칙이라
  둘 다 높이를 선언하지 않고 담은 것을 hug 하므로, `verify-figma-parity` 계약이 후행 슬롯 높이를 ProgressRing
  기록(`progress-ring.sizes.base.size`)에서, 선행 슬롯 높이를 사이드바 토글이 든 IconButton 기록
  (`icon-button.sizes.md.height`)에서 `from` 으로 읽는다. 사본의 값이 지금 담긴 쪽과 같아도 걷는다 — 후행 슬롯의
  사본도 ProgressRing 이 옮기기 전까지는 같았다.
- 규범 문서 · 결정 · 기록 주석이 계산 결과를 조건 없이 사실로 적기 — 산식과 조건(뷰포트 · 줄 수 · 담은 것)을 적고
  수치는 원장 키로 인용한다.

**고정을 허용하는 자리.** Figma 가 제품의 식을 표현하지 못해 수를 둘 수밖에 없는 자리다. 이때는 계획이나 컴포넌트
설명에 사유를 남기고, 사유 없는 FIXED 는 계산값을 굳힌 것으로 센다.

1. **세트 variant 의 기본 폭.** 제품이 부모를 채우는(`100%` · stretch) 컴포넌트는 마스터에 채울 부모가 없다 — 기본값만
   측정 폭으로 두고 소비처 인스턴스가 FILL 한다(상단 바 두 세트, 결제 결과 본문 모바일, 메인 표면).
2. **뷰포트.** 장면 · 보드 프레임의 크기는 뷰포트 자체다.
3. **`flex-shrink` 로 감긴 글자.** Figma 에는 수축으로 줄이 감기는 흐름이 없어 측정 상자 폭을 둔다(요금제 가격 행 —
   Figma 자연 폭 줄별 증거로 같은 자리에서 접히는지 확인한다). 감기는 줄에서 혼자 한 줄을 차지해 줄 폭까지 줄어든 글자는 **여기에 들지
   않는다** — 줄어든 폭이 줄 폭이라 그 자리에서 줄을 끊고 줄 폭 FILL 로 둔다(공개 푸터 모바일 주소 칸, 위 표 · 2026-10-09). 측정 폭으로
   굳힌 첫 판은 늘림 시험 360 에서 넘쳤다.
4. **관측 크롭.** 뷰포트 밖 내용이 높이를 정하는 조각(`Product/Upgrade Plan Card Visible Slice`)은 측정 높이로 자른다.
5. **HUG 부모 아래 FILL 자식 · hug 할 내용이 없는 빈 잎.** Figma 는 HUG 부모의 FILL 자식을 최소 크기로 접는다. **먼저 수 없이
   푼다** — 자식의 측정 크기가 자기 내용 크기(패딩 + 자식 측정 크기 + 간격)와 같으면 CSS 의 grow · stretch 가 아무 일도 하지 않은
   것이라 자식을 HUG 로 옮긴다(`/settings` 세그먼트 버튼의 가로 — (135)). 부모의 최소 크기가 측정 크기를 덮거나 교차축에 FILL 이
   아닌 형제가 있으면 CSS 와 같은 크기가 나와 손댈 것이 없다. **자식의 최소 크기가 측정 크기를 덮는 자리는 FILL 로 두지 않는다**
   (2026-09-30) — 늘이기가 아무 일도 하지 않아 자식이 최소에 선 것인데, Figma 는 HUG 부모의 주축 크기를 FILL 자식의 최소로만 세워
   형제가 부모 밖으로 넘쳤다(문의 모바일 메시지 칸: textarea FILL · 최소 200 + 첨부 줄 57 → 부모 200, 그 아래가 65 올라갔다). 잎은
   측정 크기 `FIXED`, 자동 배치 프레임은 HUG(최소 크기가 측정을 지킨다)로 옮긴다. **교차축 자식이 모두 FILL 이고 그 가운데 내용 폭을
   잴 수 없는 자식(글자 잎 · 인스턴스)이 있으면 부모를 측정 폭 `FIXED` 로 세운다**(2026-09-30) — CSS 의 부모 폭은 자식의 max-content
   인데 원장에 한 줄 글자의 글자 폭이 없어(블록 글자의 측정 상자는 늘어난 폭이다) 어느 자식이 폭을 정했는지 되짚을 수 없고, Figma 는
   모두 FILL 이면 부모를 최소로 접는다. 부모 판정(HUG)이 틀린 것이 아니라 Figma 가 그 조합을 나타내지 못하는 자리다(문의 데스크톱 안내

## 29. 측정 모드는 측정 섹션에 건다 — 마스터에 건 명시 모드는 인스턴스로 번진다

세트 러너는 측정한 테마로 마스터를 미리보기하려고 `setExplicitVariableModeForCollection` 을 건다. **그 모드를 마스터 ·
variant 에 걸면 인스턴스가 그대로 물려받아, 놓인 자리(보드)의 모드를 이긴다.** 실측(2026-09-22, 앵커 적용 S7):
sidebar-states 러너가 편집기 상단 바 마스터 `477:4999` 에 `Klipse Semantic Color=Dark` 를 걸자, 라이트 보드 `39:3` 안
인스턴스의 글자 넷이 `#fafafa` 로 풀려 대비가 11.89 → 1.69:1 이 됐다. 라이트 보드 위 다크 잉크는 제품 어느 테마에도 없다.

- 측정 모드는 세트를 담는 **측정 섹션**에만 건다. 마스터 · variant · 인스턴스에는 그 컬렉션의 명시 모드를 두지 않는다 —
  세트 페이지에서는 섹션의 모드로 미리보기되고, 보드에서는 놓인 자리의 모드로 풀린다.
- 러너가 전에 건 명시 모드는 `clearExplicitVariableModeForCollection` 으로 **그 컬렉션만** 걷는다. `resetOverrides` 가
  아니다 — 다른 override 는 그대로 둔다.
- 생성기가 막는다. sidebar-states 생성기는 템플릿 전체를 TypeScript 파서로 읽어 `pin(measuredSection)` 밖의 `pin` 과
  `setExplicitVariableModeForCollection` 직접 호출을 멈추고, `verify-gates` canary 셋이 그 확인이 무는지 본다.
- 적용 전에 센다: 마스터 · variant 의 명시 모드와, 그 인스턴스마다 놓인 자리의 유효 모드(조상의 `explicitVariableModes`,
  없으면 컬렉션 기본값). 둘이 다른 소비처가 있으면 적용 뒤 보이는 값이 바뀐다.

**아직 이 조항을 따르지 않는 러너가 있다.** 앱 셸 · 컴포넌트 러너는 variant · 마스터에도 측정 모드를 건다
(`figma-product-app-shell-renderer.js` · `figma-product-components-renderer.js` 의 `pin(variant)` 등). 그 소비처 가운데
놓인 자리의 모드가 다른 곳이 있는지는 아직 세지 않았다 — [Updates](../updates/README.md) (152) 「남은 것」.

## 30. 흐림 없는 링 그림자는 선이다 — 안쪽은 INSIDE 획, 바깥은 OUTSIDE 획, 둘 다 레이아웃 밖

LOUIS 는 헤어라인을 테두리가 아니라 그림자로 발행한다 — `--louis-hairline-inset: inset 0 0 0 var(--louis-border-width-hairline)
var(--louis-color-stroke-hairline)`(`packages/css/src/base.css`). 선택 표시 링도 그림자다(쿠폰 요금제 카드 `0 0 0 1.5px`). 둘 다
**박스 크기를 바꾸지 않는 선**이다.

- **안쪽 링(흐림 0 · `inset`)은 INSIDE 획으로 옮긴다.** 변마다 두께를 가진다(`0.5px 0 0 0 inset` 은 왼쪽 선 하나). 획이어야 변수
  (`color/stroke-hairline` · `border-width/hairline`)에 묶인다. 그림자로 두면 묶이지 않는다.
- **바깥 링(흐림 0 · 오프셋 0 · 퍼짐 > 0)은 OUTSIDE 획으로 옮긴다.** Figma 는 그림자 퍼짐을 내용을 자르지 않는 프레임에서
  그리지 않는다 — 그림자로 두면 선택 링이 **보이지 않는다**(2026-09-26 실측).
- **테두리 안쪽의 같은 색 링은 테두리에 합친다(2026-09-29).** CSS 의 `inset` 링은 테두리 **안쪽**(패딩 상자 가장자리)부터 그려지는데
  Figma 의 INNER_SHADOW 는 프레임 가장자리부터 그려진다 — 테두리가 있는 자리에 링을 그림자로 두면 두 겹이 한 자리에 겹친다. 로그인
  입력칸의 포커스(테두리 1 + 링 1, 둘 다 검정 40%)가 제품 2px 이 보드에서 짙은 1px 이 됐다(제품 캡처와 나란히 놓아 찾았다). 링 색이
  테두리 색과 같으면 변마다 두께를 더한 하나의 INSIDE 획으로 싣고, 더한 두께를 패딩에서 뺀다 — 테두리는 레이아웃에 들고 링은 들지
  않으므로, 합친 획(레이아웃에 든다)이 그만큼 내용을 밀지 않게. 패딩이 링보다 얇은 변이 있거나 색이 다르면 합치지 않는다(그림자로 남는다).
- **둘 다 레이아웃에 넣지 않는다**(`strokesIncludedInLayout = false`). GRID 프레임은 획을 레이아웃에 넣는 것이 기본이라, 두면
  0.5 선이 위아래로 더해져 카드가 1px 커진다(쿠폰 요금제 카드 70 → 71). CSS 테두리(`border`)는 박스에 들어가므로 이 규칙 밖이다.
- **획 변수는 역할로 고른다.** 값이 같은 변수가 여럿이면 `color/stroke-hairline` > `color/stroke-*` > 첫 변수. 헤어라인 #171B22 12% 의
  첫 변수는 `color/accent-secondary-hover`(눌림 면)였다.
- **색 표기를 둘 다 읽는다.** 계산값은 `rgb()` 와 `color(srgb …)` 가 섞인다. 그림자 파서가 앞의 것만 읽던 동안 보드 42장의 헤어라인이
  **통째로 빠져** 있었다(그림자 2개만 남음). 트리 변환이 `color(srgb …)` 를 버리면 `verify-gates` 카나리아가 문다.

## 31. 보드 안의 제품 전용 컨트롤은 측정 서브트리 그대로 제품 세트가 된다 — 보드는 그 인스턴스를 쓴다

소유자 결정 「Figma 먼저, 생성기로 묶어서」(2026-09-26, [DS-D-0071](decisions/DS-D-0071-product-sets-count-as-coverage.md))의 조립 쪽
규칙이다. LOUIS 에 대응이 없는 제품 전용 컨트롤(보드 구성 원장의 「미보유」)은 손으로 컴포넌트를 그리지 않는다.

- 보드 생성기의 `PARTS` 가 그 자리의 **측정 서브트리**를 보드와 같은 변환 · 같은 렌더러로 제품 컴포넌트 variant 에 채운다(90 · 자산
  「S · product/Parts」). 빈 variant 를 먼저 세우고 러너가 채운다 — 보드 프레임과 같은 순서다.
- 보드는 같은 서브트리를 그 variant 의 인스턴스로 쓴다. 판정은 본문 세트 치환과 같은 **글자 서열 · 구조 서명 · 뷰포트**이고, 서명 함수
  (`contentSignatureOf`)를 치환 라이브러리와 함께 써서 부품과 보드가 규칙 차이로 어긋날 수 없다.
- `anchor`(부품 서브트리의 글자 서열)가 측정과 다르면 생성기가 멈춘다 — 측정 경로가 다른 노드를 가리키게 된 것이다.
- 자식이 없는 자리(글자를 제 몸에 든 버튼)는 **잎 서명**으로 맞춘다 — 부품 서명에 태그가 실리고, 매처는 잎을 잎 서명하고만 태그까지
  같을 때 맞춘다. 본문 세트에는 잎 서명이 없어 잎을 보지 않는다.
- 여럿이 고정 목록 하나로 그려지는 컨트롤(테마 칩 여섯)은 칩이 아니라 **줄**을 부품으로 한다 — 칩마다 세트를 두면 라벨만 다른
  variant 가 늘어난다.
- 보드 생성기의 `CONTENT_INSTANCES_BY_SET` 이 세트마다 보드 인스턴스 수를 잠근다. 첫 대상: `Product/Gift Plan Option` 8 ·
  `Product/Quantity Stepper` 2(`/subscription/coupons`). 둘째 묶음으로 보드 구성 원장의 「미보유」가 0 이 됐다 —
  `Product/Analytics Connect Button` 2 · `Product/Highlight Theme Chips` 2 · `Product/Checkout Agreement` 1. 셋째 묶음은 결제 성공
  미리보기 보드의 안내 상자 둘 — `Product/Billing Status Alert` 2 · `Product/Bulk Coupon Notice` 4. 넷째 묶음(글자 속성)으로 보드 구성
  원장의 「미보유」가 다시 0 이 됐다.
- **글자마다 다른 반복 칩은 글자 속성 부품이 된다**(`label`). 서명이 글자 서열이면 쿠폰 코드 칩(코드마다 글자가 다르다)을 칩 하나로
  묶을 수 없다. `label` 이 있는 부품은 글자가 아니라 **모양**(잎 · 태그 · 칠과 타이포 `lookOf` · 뷰포트)으로 맞추고, 그 모양의 잎
  가운데 `labelPattern` 에 드는 글자만 받는다. 부품 러너가 세트에 TEXT 속성(이름 = `label`)을 열어 글자 노드를 묶고, 보드는 칩마다
  글자를 인스턴스 속성으로 넣는다 — `Product/Coupon Code Chip` 45(bulk 성공 미리보기 데스크톱 30 · 모바일 15).

## 32. 간격 · 패딩은 값이 같은 변수에 묶는다 — 값을 적는 자리와 묶는 자리를 한 함수로 둔다

`setBoundVariable("paddingTop", v)` 는 필드를 **변수가 푸는 값으로 바꾼다.** 측정값을 적은 뒤 다른 수로 풀리는 변수에 묶으면 결합이
측정값을 덮어쓴다 — 계획과 생성물 대조는 적은 값을 보고 초록인데, 라이브는 변수의 값으로 선다.

- **실측 사고(2026-09-28).** 사이드바 셸 렌더러가 헤더 패딩 8 · 12 · 0 · 12 를 적은 뒤 넷 다 `spacing/12` 에 묶어, 라이브 셸이
  12 · 12 · 12 · 12 로 섰다 — 메뉴가 4 내려가고 업그레이드 버튼이 12 올라갔다. 메뉴 행은 처음 지을 때의 왼쪽 패딩 4(`spacing/4`)가
  남아 있었다 — 재정렬 경로가 패딩을 다시 걸지 않았다(제품 8). 데스크톱 보드 27장의 사이드바 글자가 제품보다 x −4 · y +4, 업그레이드
  글자가 y −12 였다([Updates](../updates/README.md) (167)).
- **한 함수로 건다.** 값과 결합을 같은 함수가 정한다 — 값이 같은 `spacing/<n>` 을 찾고, 그 변수가 적을 값과 다른 수로 풀리면 던지고,
  0 은 결합을 푼다(`figma-product-components-renderer.js` 의 `bindSpacing` · `bindPadding`). 값을 대입한 줄과 따로
  `node.setBoundVariable("…", V.spacing12)` 처럼 변수 이름을 박지 않는다 — 두 줄이 갈라지는 순간 이 사고가 난다.
- **재정렬 경로도 매 실행 모든 기하 축을 계획대로 건다**(패딩 · 간격 · 크기). 「세트가 없을 때만 건다」 · 「옮길 때만 건다」는 측정이
  옮겨도 라이브가 따라오지 않는 자리다. 값이 같으면 결과가 같으니 매번 걸어도 멱등이다.
- **생성기가 먼저 멈춘다.** 러너에 싣는 간격 값마다 결합 변수가 있는지 생성기가 본다 — 없으면 러너가 라이브에서 던지기 전에 멈춘다.
- **보는 법.** 구조 해시(`figma-screens-live-check`)는 인스턴스 안으로 들어가지 않아 이 종류를 보지 못한다. 보드 글자 상자를 측정
  fixture 의 글자 rect 와 짝지어 x · 세로 가운데 차를 재야 드러난다 — 이번 사고도 그 대조의 중앙값 4 로 찾았다.
