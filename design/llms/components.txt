### Button

사용자가 즉시 실행할 수 있는 명확한 액션을 표현한다. 제품별 버튼 스타일을 만들기 전에 공용
Button 계약으로 해결할 수 있는지 먼저 확인한다.

#### Availability

| Surface       | 상태           | 근거                                                      |
| ------------- | -------------- | --------------------------------------------------------- |
| Web           | `partial`      | public export와 acceptance test 11건; 아래 남은 증거 참조 |
| Figma         | `partial`      | library draft의 component set 40 variant와 parity 대조 통과; publish 전 |
| Documentation | `done`         | 이 문서                                                   |
| Maturity      | `experimental` | 제품 소비 증거와 visual regression이 아직 없음            |

#### API

```tsx
import { Button } from "@klipse-design/react";

<Button variant="primary">새 프로젝트 만들기</Button>
<Button variant="secondary">취소</Button>
<Button variant="danger">삭제</Button>
```

소비자는 `@klipse-design/css`의 `layers.css`를 root layout 최상단에서 먼저 import하고
`styles.css`(또는 Tailwind 사용 시 `styles.layer.css`)를 함께 불러온다.

링크 이동이 목적이면 클릭으로 navigation을 흉내 내지 말고 Link primitive를 사용한다.

#### Anatomy

1. Root — 네이티브 `<button>`과 hit area
2. Left icon — 선택 사항, 장식이면 보조 기술에서 숨김
3. Label — 결과를 설명하는 텍스트
4. Right icon — 선택 사항, 장식이면 보조 기술에서 숨김
5. Progress indicator — loading일 때 label 의미와 함께 제공

#### Properties

| Prop         | 값                                        | 기본값    | 설명                                            |
| ------------ | ----------------------------------------- | --------- | ----------------------------------------------- |
| `variant`    | `primary`, `secondary`, `ghost`, `danger` | `primary` | 강조와 의미                                     |
| `size`       | `md`, `sm`                                | `md`      | 시각 크기; hit area 계약은 별도 유지            |
| `loading`    | boolean                                   | `false`   | 중복 실행 차단, `aria-busy`, progress indicator |
| `leftIcon`   | ReactNode                                 | —         | 라벨 앞 보조 아이콘                             |
| `rightIcon`  | ReactNode                                 | —         | 라벨 뒤 보조 아이콘                             |
| native props | ButtonHTMLAttributes                      | —         | `disabled`, `aria-*`, event                     |

`type` 기본값은 `button`이다. 폼 제출은 호출부가 `type="submit"`을 명시한다.

#### Hierarchy와 variants

| Variant     | 용도                | 원칙                                               |
| ----------- | ------------------- | -------------------------------------------------- |
| `primary`   | 핵심 진행·생성 액션 | 한 영역의 최우선 액션에 사용                       |
| `secondary` | 취소·대안           | primary를 보조                                     |
| `ghost`     | 툴바·저강조 액션    | 면이 없어도 발견 가능한 위치에서 사용              |
| `danger`    | 삭제·초기화         | 결과를 구체적으로 설명하고 필요하면 확인 단계 제공 |

강조 수준을 색만으로 결정하지 않고, 같은 영역에 경쟁하는 primary를 여러 개 두지 않는다.

#### States

상태 이름의 뜻은 [Interaction states](../foundations/interaction-states.md)가 소유한다.
Button은 토글이 아니므로 `pressed`(`aria-pressed`)를 갖지 않는다 — 누르는 중은 `active`다.

| 상태          | 계약                                                   |
| ------------- | ------------------------------------------------------ |
| Enabled       | 라벨만으로 결과를 예측할 수 있음                       |
| Hover         | hover에서만 기능을 드러내지 않음                       |
| Active        | 누르고 있는 동안의 feedback. reduced-motion에서 scale 이동 제거 |
| Disabled      | 실행되지 않으며 이유가 필요하면 인접 설명 제공         |
| Focus-visible | 배경과 테마에 관계없이 2px 이상 명확한 indicator       |
| Loading       | label 의미 유지, 중복 실행 차단, `aria-busy=true`      |

#### Content

- 결과를 예측할 수 있는 짧은 동사형 라벨을 쓴다: `저장`, `업로드`, `삭제`.
- `확인`, `다음`처럼 맥락 없이는 결과를 알 수 없는 라벨은 구체화한다.
- 진행 문구 끝에 ellipsis를 붙이지 않는다.
- 번역과 200% 확대에서 잘리면 버튼 폭 또는 action layout을 바꾼다.

#### Accessibility

- 아이콘 전용 버튼은 accessible name을 제공한다.
- disabled처럼 보이지만 동작하는 요소를 만들지 않는다.
- loading 중 현재 focus를 제거하지 않는다.
- 주요 액션 hit area는 44×44 CSS px 이상을 목표로 한다.
- `aria-disabled`를 사용하면 click과 keyboard activation을 모두 명시적으로 차단한다.

#### Acceptance tests

- pointer click, Enter, Space가 각각 정확히 한 번 실행된다.
- disabled와 loading에서 모든 activation 경로가 차단된다.
- loading 시작·완료 시 accessible name과 focus가 예측 가능하다.
- light/dark/high contrast에서 focus-visible이 보인다.
- KO/EN/JA 긴 라벨, 200% zoom, 320px container에서 핵심 텍스트가 사라지지 않는다.
- reduced-motion에서 active/loading 의미가 유지된다.
- **아이콘 유무로 높이가 달라지지 않는다.** md·sm 모두에서 `leftIcon`/`rightIcon`을 준 버튼과
  주지 않은 버튼의 높이가 같다.
- 구조값이 [`figma/components.measured.json`](../../figma/components.measured.json)과 일치한다.

| `variant` | `Variant` (primary/secondary/ghost/danger) | 옵션 집합을 parity 게이트가 `ButtonVariant`와 대조한다 |
| `size` | `Size` (md/sm) | `ButtonSize`와 대조한다 |
| `loading` | `State=Loading` | boolean prop이 Figma에서는 state variant다 |
| `disabled` | `State=Disabled` | 같은 이유 |
| — | `State=Hover`, `State=Active` | 코드에서는 CSS 상태다. Figma에 CSS 상태가 없어 variant로 둔다 |
| `children` | Label 텍스트 | |

Figma component의 모든 fill·stroke는 변수에, 모든 텍스트는 text style에 바인딩된다(raw 값 0).
focus-visible 링은 브라우저가 그리므로 Figma variant로 두지 않는다.

활성화는 네이티브 `<button>`에 맡긴다. pointer click, Enter, Space가 각각 정확히 한 번 실행되는 것은
브라우저가 보장하며, keydown으로 클릭을 흉내 내면 중복 실행이 된다.

`loading`은 네이티브 `disabled`를 쓰지 않는다. 네이티브 disabled는 현재 focus를 제거하는데 규범이
이를 금지하기 때문이다. 대신 `aria-disabled`로 표시하고 activation을 명시적으로 막는다. 검증은 두
층으로 한다 — 실제 포인터는 actionability에서 차단되고, 프로그램적 click과 keyboard는 컴포넌트가
막는다.

#### Specification

구조값은 [`figma/components.measured.json`](../../figma/components.measured.json)이 정본이고 실제
브라우저 측정으로 고정된다. 코드가 이 값을 만드는지는
`packages/react/test/component-geometry.browser.test.tsx`가, Figma가 이 값과 같은지는 parity
게이트가 매 실행 검증한다.

| 항목        | md                                  | sm                                  |
| ----------- | ----------------------------------- | ----------------------------------- |
| 높이        | `layout-control-height-md` 40px     | `layout-control-height-sm` 32px     |
| 최소 폭     | 없음                                | `layout-control-minimum-width-sm` 48px |
| padding     | 0 / `space-control-lg` 16px         | 0 / `space-control-md` 12px         |
| gap         | `space-control-sm` 8px              | `space-control-xs` 4px              |
| border      | `border-width-hairline` 0.5px       | `border-width-hairline` 0.5px       |
| radius      | `radius-control` 12px               | `radius-control` 12px               |
| 타이포      | `body-sm-medium` 14px / 21px        | `body-sm-medium` 14px / 21px        |
| spinner     | 18px (`1em` + border 2)             | 18px (`1em` + border 2)             |
| 아이콘 슬롯 | `icon-size-md` 20px                 | `icon-size-sm` 16px                 |

**이 값들은 제품 배포 코드에서 채택한 것이다.** 근거와 채택/편차 판정은
[`migration/product.measured.json`](../../migration/product.measured.json)에 있고 게이트가 매 실행
확인한다.

두 가지가 제품과 다르고 사유가 그 파일에 적혀 있다.

- **높이가 `height`가 아니라 `min-block-size`다.** 일반 라벨에서는 제품과 정확히 같은 40/32가
  나오고, KO/EN/JA 긴 라벨이나 200% 확대에서는 잘리는 대신 자란다. 제품은 `nowrap`이라 그 경우
  라벨이 넘친다.
- **타이포가 size 축이 아니다.** 제품과 같이 md·sm 모두 14px/21px를 쓴다. 이전 DS는 sm에서
  caption 12px로 줄여 제품과 달랐다.

아이콘이 붙은 쪽은 padding을 2px 줄인다(md 16→14, sm 12→10). 아이콘의 자체 시각 여백 때문에
텍스트-only 대비 그 쪽이 넓어 보이는 것을 보정하는 것이며 제품과 같다.

#### Known deviations

- **`danger` variant가 tonal이다.** solid danger를 표현할 `color-action-danger*` 토큰이 아직 없어
  `color-status-danger-*`로 대체했다. `DS-P3-014` 단위 9가 토큰을 추가하면 갱신한다.
  Button은 foreground와 background를 **쌍으로** 쓰므로 대비가 성립한다. 같은 토큰을 텍스트 색으로만
  쓰면 중립 표면에서 무너지는데, 그 실측은 [Menu / Popover](../components/menu-popover.md)의 Known deviations에 있다.
- **고정 높이가 없다.** 높이를 padding과 line-height로 결정하고 44px 타깃은 `kds-hit-target`이
  보장한다. 제품과 픽셀 단위로 맞추려면 control height 토큰이 필요하다(DS-P3-014).
- **네 variant 전부 WCAG AA에 미달한다.** owner가 제품의 공용 Button을 정본으로 채택했고,
  그 제품 Button이 네 variant 모두 4.5에 못 미친다. axe 실측값이다.

  | variant | 전경 | 배경 | 대비 |
  | --- | --- | --- | --- |
  | `primary` | `#fafafa` | `#0088ff` | **3.37** |
  | `secondary` | `#777d89` | 흰 배경 | **4.13** |
  | `ghost` | `#777d89` | 흰 배경 | **4.13** |
  | `danger` | `#fafafa` | `#ff4b59` | **3.14** |

  이 미달은 제품이 이미 갖고 있는 것이고 DS가 그것을 그대로 재현한다. 해소하려면 면을 어둡게
  하거나(primary는 `blue.700` 6.12, secondary는 `neutral.700` 6.35) 라벨을 18.66px bold 이상으로
  키워야 하며 둘 다 브랜드 판정 대상이다. 같은 사유가 token source의 `contrastPairs[].note`,
  axe 테스트의 허용 목록, `migration/product.measured.json`에 있다.
- **아이콘 슬롯 크기를 Button이 소유한다.** [Iconography](../foundations/iconography.md)는 글리프
  크기를 아이콘이 소유한다고 하지만, 슬롯에 크기를 두지 않으면 호출부가 넘긴 아이콘 크기가 그대로
  버튼 높이가 된다. sm에 기본(20px) 아이콘을 넣으면 높이가 28이 아니라 **30**이 됐고, 같은 줄의
  버튼들이 아이콘 유무로 어긋났다. 높이가 호출부에 따라 달라지는 것은 컨트롤이 아니므로 슬롯을
  md 20 / sm 16으로 고정하고 글리프를 슬롯에 맞춘다. 컨테이너 크기는 컨트롤이 소유한다는 같은
  문서의 규칙과는 어긋나지 않는다.

## Icon Button

- Source: design/components/icon-button.md
- Maturity: experimental

### Icon Button

라벨 없이 아이콘만으로 액션을 표현한다. 공간이 없어서가 아니라 **아이콘 하나로 뜻이 명확할 때만**
쓴다. 뜻이 흔들리면 [Button](../components/button.md)에 라벨을 쓴다.

#### Availability

| Surface       | 상태           | 근거                                                      |
| ------------- | -------------- | --------------------------------------------------------- |
| Web           | `partial`      | public export와 acceptance test; visual regression과 제품 소비 증거 없음 |
| Figma         | `partial`      | component set 40 variant (Variant 4 × Size 2 × State 5). publish는 DS-F-008 |
| Documentation | `done`         | 이 문서                                                   |
| Maturity      | `experimental` | 규범과 구현이 같은 변경 단위에서 처음 선다                |

#### 왜 Button의 prop이 아닌가

`Button`을 아이콘 전용으로 렌더한 결과를 실측했다 — **md 54×38, sm 46×30으로 정사각이 아니다.**
빈 라벨과의 `gap` 8px과 좌우 padding이 그대로 남기 때문이다. 기하가 다르다.

기하보다 결정적인 것은 **접근성 계약이 다르다**는 점이다. Button은 이름이 children에서 오므로
`label`을 필수로 만들 수 없다. Icon Button은 라벨이 없으면 **이름이 아예 없는 버튼**이 되므로
`label`을 필수 prop으로 강제한다. "children이 비었을 때만 필수"는 타입으로 표현할 수 없다.

#### API

```tsx
import { IconButton } from "@klipse-design/react";
import { IconTrashSimple } from "@klipse-design/react/icons";

<IconButton label="삭제" variant="ghost" onClick={remove}>
  <IconTrashSimple />
</IconButton>
```

#### Anatomy

1. Root — 네이티브 `<button>`, 정사각형
2. Glyph — 아이콘 하나. 항상 장식이며 보조 기술에서 숨는다
3. 이름 — `label`이 `aria-label`이 된다. 화면에는 보이지 않는다

#### Properties

| Prop        | 값                                        | 기본값    | 설명                                        |
| ----------- | ----------------------------------------- | --------- | ------------------------------------------- |
| `label`     | string                                    | **필수**  | accessible name. 생략할 수 없다             |
| `variant`   | `primary`, `secondary`, `ghost`, `danger` | `ghost`   | Button과 같은 축                            |
| `size`      | `md`, `sm`                                | `md`      | md 40×40, sm 32×32                          |
| `pressed`   | boolean                                   | —         | 토글일 때만 준다. `aria-pressed`가 된다     |
| `disabled`  | boolean                                   | `false`   | 네이티브 비활성                             |

`children`은 아이콘 하나다. 텍스트를 넣지 않는다.

#### Hierarchy와 variants

- variant는 Button과 같은 네 축을 쓴다. 새 시각 언어를 만들지 않는다.
- **기본값이 `ghost`인 이유**: 아이콘 전용 버튼은 대개 밀집한 도구 영역에 놓인다. 그 자리에서
  `primary`가 기본이면 화면에 경쟁하는 강조가 늘어난다.
- 크기는 padding이 아니라 **한 변의 길이**로 정한다 — `layout-control-height-md`(40)와
  `layout-control-height-sm`(32). Button은 고정 높이가 없지만 Icon Button은 정사각이 계약이므로
  높이를 직접 소유한다.
- 한 영역에 아이콘 전용 버튼이 여럿이면 강조를 나누지 말고 전부 `ghost`로 둔다. 아이콘만으로는
  강조 차이가 라벨만큼 읽히지 않는다.

#### States

상태 이름의 뜻은 [Interaction states](../foundations/interaction-states.md)가 소유한다.
Icon Button은 `active`(누르는 중)와 `pressed`(토글 켜짐)를 **둘 다** 갖는 첫 컴포넌트다.

| 상태       | 표현                                      | 비고                                        |
| ---------- | ----------------------------------------- | ------------------------------------------- |
| default    | variant의 기본 면                         |                                             |
| hover      | 면 강조만 바뀐다                          | hover에서만 드러나는 기능을 두지 않는다     |
| active     | `scale: 0.98`                             | reduced-motion에서는 이동을 제거한다        |
| pressed    | `aria-pressed`와 면 강조                  | **토글에만** 쓴다                           |
| disabled   | 네이티브 `disabled`, 전경 disabled 색     | 클릭이 실행되지 않고 그렇게 보인다          |

- `pressed`와 `active`는 **다른 축**이다. `active`는 누르고 있는 동안이고 `pressed`는 토글의 켜짐
  상태다. 둘을 같은 시각으로 표현하면 토글이 눌린 것인지 켜진 것인지 구분되지 않는다.
- `pressed`는 토글에만 쓴다. 한 번 실행되고 끝나는 액션에 주면 스크린리더가 상태를 잘못 읽는다.
- **hover와 active는 `pressed`를 덮지 않는다.** 지속 상태를 일시적 상태가 지우면 포인터를 얹는
  동안 토글이 꺼진 것으로 보인다. 실제로 그렇게 돼 있었다 — pressed primary에 hover하면 배경이
  variant 색으로 되돌아가고 글자만 pressed 색으로 남았다. CSS 특정성이 `[aria-pressed]`(0,2,0)보다
  `:hover[data-variant]`(0,3,0)가 높았기 때문이다. hover/active 규칙에서 pressed를 제외해 고쳤다.
- **`pressed`에는 별도의 hover 면이 없다.** 켜진 상태에서 포인터 피드백이 사라진다. Known
  deviations 참조.
- `loading` 상태는 아직 없다. Known deviations 참조.

#### Interaction and responsive behavior

- **시각 크기와 hit area를 분리한다.** 컴포넌트가 `.kds-hit-target`을 직접 붙이므로, sm이 32×32로
  보여도 실제 히트 영역은 44×44다 — 보이지 않는 의사 요소가 중앙에 깔린다
  ([Inclusive Design](../foundations/inclusive-design.md)). 호출부가 따로 감쌀 필요가 없다.
- 뷰포트로 크기를 자동 전환하지 않는다. 밀집도는 화면 폭이 아니라 **그 자리의 역할**이 정한다.

#### Content

- `label`은 동사로 쓴다 — "삭제", "닫기", "재생". 아이콘 이름("휴지통")이 아니다.
- 토글이면 **현재 상태가 아니라 수행할 동작**을 쓴다. 음소거 상태에서 라벨은 "음소거 해제"다.

#### Accessibility

- 이름은 `label` 하나에서 온다. 아이콘에는 `label`을 주지 않는다 — 주면 이름이 두 겹으로 읽힌다
  ([Iconography](../foundations/iconography.md)).
- 아이콘은 항상 `aria-hidden`이다. Icon Button이 감싸는 span이 그것을 보장한다.
- `pressed`를 준 경우에만 `aria-pressed`가 붙는다. 주지 않으면 속성 자체가 없다 — `false`를 늘
  붙이면 일반 버튼이 토글로 노출된다.
- focus ring은 `.kds-focus-ring`이 소유한다.

#### Specification

| 항목      | md                              | sm                              |
| --------- | ------------------------------- | ------------------------------- |
| 한 변     | `layout-control-height-md` 40px | `layout-control-height-sm` 32px |
| 글리프    | `icon-size-md` 20px             | `icon-size-md` 20px             |
| radius    | `radius-control` 12px           | `radius-control` 12px           |

글리프 크기가 두 size에서 같은 이유: 아이콘은 **컨테이너와 독립**이다(Iconography Size model).
20px 글리프가 40 컨테이너에서 여백 10, 32에서 여백 6을 갖는다.

#### Implementation

- `packages/react/src/icon-button/icon-button.tsx`
- `packages/css/src/component/icon-button.css`
- variant/state 시각은 `.kds-button`의 규칙을 재사용하지 않고 자체 선택자를 갖는다. 공유하면
  Button의 padding 계약이 정사각 계약과 충돌한다.

#### Known deviations

| 항목 | 상태 | 사유 |
| --- | --- | --- |
| pressed의 hover 면 | 없음 | `background-inset`보다 한 단계 강한 중립 표면 토큰이 없다. 만들면 hover가 pressed를 덮지 않으면서도 피드백을 줄 수 있다. DS-P3-014 대상 |
| Figma 글리프 색 | instance override | Figma에는 `currentColor`가 없어 아이콘 instance 안 vector의 stroke를 variant마다 직접 변수에 다시 묶었다. 아이콘 정본이 바뀌어도 이 override는 따라오지 않는다 — 재적용은 수동이다 |
| `loading` 상태 | 없음 | 아이콘 자리에 무엇을 넣을지 미정. Button의 loading과 같은 축인지 판정이 필요하다 |
| 제품 32×32 radius 12 ↔ 모바일 40×40 radius 14 | 미채택 | 제품은 ≤719px에서 radius를 14로 바꾼다. 뷰포트로 radius를 바꾸는 근거를 찾지 못해 12로 고정했다 |

#### Acceptance tests

1. md가 40×40, sm이 32×32 정사각이다.
2. 시각 크기와 무관하게 히트 영역이 44×44 이상이다.
3. `label`이 accessible name으로 정확히 한 번 노출된다.
4. 내부 아이콘이 accessibility tree에 노출되지 않는다.
5. `pressed`를 주지 않으면 `aria-pressed` 속성이 없다.
6. `pressed`를 주면 `aria-pressed`가 그 값으로 붙는다.
7. `disabled`면 클릭 핸들러가 실행되지 않는다.
8. 부모 `color` 변경이 글리프에 반영된다.
9. 두 size의 글리프 계산 박스가 모두 20px다.
10. 토글이 켜진 상태를 hover가 덮지 않는다.

  `Button`으로는 정사각이 되지 않는다는 실측이 근거다.

## Menu / Popover

- Source: design/components/menu-popover.md
- Maturity: experimental

### Menu / Popover

트리거와 가까운 곳에서 짧은 액션 목록 또는 복합 설정을 제공하는 비모달 overlay다. 이 문서는 과거
구현의 평균이 아니라 이 저장소가 유지할 **목표 계약**이다.

#### Availability

| Surface       | 상태           | 근거                                                        |
| ------------- | -------------- | ----------------------------------------------------------- |
| Web           | `partial`      | `ActionMenu`·`CompositePopover` public export, 실브라우저 회귀 35건 |
| Figma         | `partial`      | component set 5 variant (항목 상태). 패널 component는 남음. publish는 DS-F-008 |
| Documentation | `done`         | 이 문서                                                     |
| Maturity      | `experimental` | 시각 회귀와 수동 screen-reader 검토가 아직 없음            |

#### When to use

- **Action menu**: 한 트리거에서 서로 독립적인 짧은 명령 목록을 연다. 예: `새로 만들기`, 카드 더보기.
- **Composite popover**: 계정 정보, 테마 세그먼트, 언어 선택처럼 서로 다른 종류의 컨트롤을 한 패널에
  묶는다. 현재 프로필 패널은 이 유형이다.
- **Submenu**: 정보 구조상 반드시 필요한 한 단계의 하위 액션만 제공한다. 두 단계를 넘기지 않는다.

다음에는 사용하지 않는다.

- 값 하나를 선택하는 폼 필드는 Select/Listbox를 사용한다. `menu` 역할로 폼 선택을 흉내 내지 않는다.
- 사용자의 작업을 막고 결정을 요구하면 [Dialog](../components/dialog.md)를 사용한다.
- 설명만 제공하면 Tooltip을 사용한다.
- 계속 보여야 하는 탐색·도구 모음은 페이지 내 Navigation/Toolbar로 둔다.
- 작은 화면에서 내용이 길어 독립적인 탐색 흐름이 되면 Sheet 또는 페이지로 전환한다. 역할만 menu인
  풀스크린 화면을 만들지 않는다.

#### Variants

| Variant             | 패널 역할                           | 내부 탐색                                       | 대표 사용처         |
| ------------------- | ----------------------------------- | ----------------------------------------------- | ------------------- |
| `action-menu`       | `menu`                              | 방향키 roving focus, Home/End, typeahead        | create/card actions |
| `composite-popover` | 이름이 있는 비모달 `dialog`         | 자연스러운 Tab 순서, 내부 위젯은 각자 패턴 사용 | profile controls    |
| `submenu`           | 부모와 같은 overlay branch의 `menu` | Right/Left 또는 Enter/Escape로 진입·복귀        | 짧은 하위 명령      |

프로필처럼 버튼, 링크, 세그먼트, Listbox가 섞인 패널에 `role="menu"`를 붙이지 않는다. 반대로 순수 명령
목록을 이름만 dialog로 만들고 방향키 탐색을 생략하지 않는다.

#### Anatomy

1. **Trigger** — 이름, `aria-expanded`, 패널과의 관계를 소유한다.
2. **Anchor** — 위치 계산에 쓰는 요소다. 보통 Trigger와 같지만 합성 트리거에서는 분리할 수 있다.
3. **Portal host** — 클리핑과 stacking context에서 패널을 분리하는 앱 공용 overlay root다.
4. **Panel** — 표면, 접근성 역할, 충돌 보정, 스크롤 경계를 소유한다.
5. **Group label / separator** — 액션 묶음의 의미를 보조한다. 빈 장식 행을 menuitem으로 만들지 않는다.
6. **Item / control** — 전체 행이 하나의 히트 영역이고, 상태와 accessible name을 가진다.
7. **Nested overlay** — submenu, Listbox, color picker 등이다. 부모와 같은 overlay branch에 등록한다.

#### Properties

아래는 프레임워크에 종속되지 않는 public contract다. 구현체 이름은 달라도 의미를 바꾸지 않는다.

| Property           | 값/형태                                  | 기본값                         | 설명                                                     |
| ------------------ | ---------------------------------------- | ------------------------------ | -------------------------------------------------------- |
| `kind`             | `action-menu`, `composite-popover`       | 컴포넌트 정체성                | 역할과 키보드 패턴을 결정한다. prop이 아니라 별도 컴포넌트로 표현한다 |
| `open`             | `boolean`                                | controlled일 때 필수           | `defaultOpen`과 동시에 지정하지 않는다                    |
| `defaultOpen`      | `boolean`                                | `false`                        | uncontrolled 초기 상태. `onOpenChange`는 두 방식 모두에서 호출된다 |
| `onOpenChange`     | `(open, reason) => void`                 | 선택                           | `trigger`, `select`, `escape`, `outside`, `route`, `programmatic`을 구분 |
| `close(reason)`    | imperative handle                        | —                              | 소비자만 아는 reason(`route`)을 발행하는 유일한 통로      |
| `trigger`          | interactive element                      | 필수                           | 단 하나의 소유 trigger                                    |
| `panelLabel`       | 문자열 또는 id 참조                      | 필수                           | panel의 accessible name                                   |
| `placement`        | `top`, `bottom`, `left`, `right`         | `bottom`                       | 선호 방향이며 충돌 시 flip 가능                           |
| `align`            | `start`, `center`, `end`                 | `start`                        | anchor와 panel 정렬                                       |
| `offset`           | `--kds-overlay-offset`                   | 8px                            | **prop이 아니다.** overlay 표면 CSS가 소유한다            |
| `collisionPadding` | `--kds-overlay-collision-padding`        | 8px                            | **prop이 아니다.** 위와 같다                              |
| `portalHost`       | app overlay root                         | Provider가 소유                | 컴포넌트가 host를 고르지 않는다. 앱에서 한 번 정한다      |
| `branchId`         | opaque overlay branch id                 | 자동 생성                      | **입력받지 않는다.** 중첩 등록은 별도 수단이 제공한다     |
| `initialFocus`     | `first-enabled`, `last-enabled`, `surface`, ref, `none` | variant 고정 (§Focus) | 기본값을 임의로 바꾸지 않는다                |
| `closeOnSelect`    | `boolean`                                | action-menu `true` / composite-popover `false` | item 단위로 덮을 수 있다          |
| `disabled`         | `boolean`                                | `false`                        | trigger와 모든 열기 경로를 비활성화한다. **panel과 item으로 전파하지 않는다** |
| `disabledItems`    | `skip`, `announce`                       | `announce`                     | menu 단위 단일 전략. item이 개별로 고르지 않는다          |

`onOpenChange`의 reason은 분석용 장식이 아니다. 닫힌 뒤 포커스를 어디에 둘지, route 이동 전에 닫을지,
선택 콜백을 중복 실행하지 않을지를 결정하는 계약이다.

`programmatic`은 소비자가 `open`을 직접 내려 닫힌 경우다. 이것이 어휘에 있어야 하는 이유는 그 경로가
실제로 소비자에게 도달하기 때문이다 — 없으면 구현이 다른 reason 하나를 빌려 쓰게 되고, 그러면 포커스
정책이 갈린다.

`offset`·`collisionPadding`·`branchId`가 prop이 아닌 것은 축소가 아니라 소유권 정리다. 앞의 둘을
인스턴스마다 바꿀 수 있게 하면 같은 종류의 overlay가 화면마다 다른 간격을 갖게 되고, `branchId`를
받으면 중첩 판정의 정합성을 호출부가 책임지게 된다.

#### States

| 상태      | Panel DOM과 포인터                                   | 포커스·ARIA                                           |
| --------- | ---------------------------------------------------- | ----------------------------------------------------- |
| Closed    | unmount 또는 `hidden` + `inert`; hit testing 불가    | trigger `aria-expanded="false"`                       |
| Opening   | 위치 계산이 끝나기 전 `visibility:hidden`; 클릭 불가 | panel을 잘못된 좌표에 먼저 노출하지 않음              |
| Open      | `pointer-events:auto`; 최상위 활성 branch            | trigger `aria-expanded="true"`; variant별 초기 포커스 |
| Closing   | 시각적 exit만 허용; 즉시 `inert`와 pointer 차단      | trigger `aria-expanded="false"`, `aria-controls` 제거; 선택 액션 재실행 불가; 자식 branch도 함께 닫는다 |
| Disabled  | panel을 열 수 없음                                   | 네이티브 `disabled` 우선                              |
| Item busy | 해당 액션 중복 실행 차단, spinner와 `aria-busy` 제공 | 전체 메뉴를 불필요하게 닫지 않음                      |

`opacity: 0`과 `aria-hidden`만으로 닫힌 panel을 유지하지 않는다. 그 안의 링크와 버튼이 Tab 순서에 남기
때문이다.

#### Interaction

##### Open and close

- pointer로 Trigger를 누르면 연다. 열린 Trigger를 다시 누르면 닫혀야 하며, 열림 상태라는 이유로 Trigger에
  `pointer-events:none`을 주지 않는다.
- `Enter`/`Space`는 열고 첫 enabled item으로 이동한다. `ArrowDown`은 첫 item, `ArrowUp`은 마지막 item으로
  연다.
- `Escape`는 최상위 nested overlay부터 한 단계씩 닫는다. 부모까지 닫혔을 때 Trigger로 포커스를 돌린다.
- route 변경, Trigger unmount, viewport 소유권 변경 시 닫는다.
- Action menu에서 `Tab`/`Shift+Tab`은 menu를 닫고 문서의 다음/이전 포커스 대상으로 이동한다.
- Composite popover에서는 Tab이 패널의 자연스러운 순서를 돈다. 마지막에서 다음 문서 대상으로 나가면
  panel을 닫고 그 다음 문서 대상에 focus를 유지한다. `Shift+Tab` 이탈도 같은 원칙을 역방향으로 적용한다.
  비모달 popover이므로 배경 전체를 inert로 만들지 않는다.

##### Action menu keyboard

| 키                 | 동작                                      |
| ------------------ | ----------------------------------------- |
| `ArrowDown/Up`     | enabled item 사이를 순환                  |
| `Home/End`         | 첫/마지막 enabled item                    |
| 문자 키            | 현재 위치 다음부터 locale-aware typeahead |
| `Enter/Space`      | 현재 item을 한 번 실행                    |
| `ArrowRight`       | submenu가 있으면 열고 첫 item으로 이동    |
| `ArrowLeft/Escape` | submenu를 닫고 부모 item으로 복귀         |

Disabled item 전략은 menu 단위로 하나만 고른다(`disabledItems`). `skip`은 네이티브 `disabled`로 표기해
탐색에서 빠지고, `announce`는 `aria-disabled="true"`로 표기해 방향키가 지나가되 활성화되지 않는다. 두
표기를 한 menu 안에서 섞지 않는다 — 섞이면 시각적으로 같아 보이는 두 항목이 서로 다른 탐색 규칙을 갖는다.
링크 item에는 네이티브 `disabled`가 없으므로 `skip` 전략에서도 별도 표기가 필요하다.

`Enter`/`Space`는 브라우저가 합성하는 `click`으로 처리한다. keydown을 따로 달면 같은 입력이 두 번
실행된다. 그래서 이 표의 `Enter/Space` 행과 `ArrowRight` 행은 서로 다른 계층에서 구현된다 — 전자는
activation, 후자는 keydown이다.

item은 네이티브 `<button>` 또는 `<a href>`여야 한다. 링크 item은 새 탭 열기와 주소 복사를 유지해야
하므로 `<button>`으로 흉내 내지 않는다.

action menu의 item 목록은 가상화하지 않는다. Home/End·typeahead·`aria-setsize`가 렌더되지 않은 항목을
볼 수 없기 때문이다. 목록이 그만큼 길면 Listbox 또는 페이지로 전환한다.

문자 키 typeahead는 IME 조합 중에는 동작하지 않는다. 조합을 시작하는 keydown의 `isComposing`이 아직
`false`이므로 조합 플래그와 `keyCode 229`를 함께 본다.

##### Pointer and outside interaction

외부 클릭 판정은 단일 `panelRef.contains(target)`로 끝내지 않는다. 다음 모두를 **같은 overlay branch의
내부**로 처리한다.

- Trigger와 Panel
- body로 다시 portal된 submenu/Listbox
- 검색 input, scrollbar, color picker처럼 Panel에서 연 nested overlay
- pointer capture 중인 drag control

구현은 `event.composedPath()`와 branch registry를 우선 사용한다. nested overlay가 별도 DOM subtree라는
이유로 부모의 outside handler가 먼저 닫히면 안 된다. 내부 `pointerdown`에서 panel을 unmount하거나
`preventDefault()`해 후속 `click`을 없애지 않는다. item의 `click`/키보드 activation이 완료된 뒤
`onOpenChange(false, "select")`와 item action이 정확히 한 번 실행돼야 한다.

외부 이벤트 정책:

1. document capture 단계에서 가장 위 branch 하나만 검사한다.
2. composed path에 branch member가 있으면 아무것도 닫지 않는다.
3. 외부라면 현재 branch만 닫고, 클릭이 배경에 전달돼도 안전한지 명시한다.
4. modal 위의 popover라면 modal branch의 자식으로 등록해 modal 자체를 닫지 않는다.
5. branch가 `closing`에 들어가면 자식 branch도 같은 tick에 닫는다. 자식 panel은 부모 panel의 자손이
   아니라 overlay host의 형제이므로 부모의 `inert`에 덮이지 않고, activation 봉인도 인스턴스 단위라
   자식에는 걸리지 않는다. 전파하지 않으면 exit 동안 자식 항목이 보이고 눌리고 실행된다.

##### "열리지만 선택되지 않음" 금지 계약

Panel이 보이는 것과 선택 가능한 것은 같은 완료 조건이다. 다음 중 하나라도 실패하면 `open`으로 보지
않는다.

- Panel과 모든 item이 실제 hit-test 대상이다.
- Panel이 덮는 좌표에 더 높은 투명 레이어가 없다.
- 부모 outside handler가 내부 `pointerdown`에 반응하지 않는다.
- Trigger 비활성화가 Panel이나 portal subtree로 전파되지 않는다.
- exit node가 새 Panel 위에서 포인터를 가로채지 않는다.
- item activation 전에 unmount되지 않고 callback이 한 번 실행된다.

#### Focus

primitive는 초기 focus 정책과 return focus 규칙을 제공하지만 **기본값을 정하지 않는다.** 어느
variant가 무엇을 받는지는 이 절이 소유한다. 순서는 primitive의 것이다 — 초기 focus는 위치가 확정된
뒤 `open`에서 한 번, return focus는 exit 이전 `closing` 진입 시점이다.

##### 초기 focus

| Variant             | 초기 focus                                              |
| ------------------- | ------------------------------------------------------- |
| `action-menu`       | 첫 enabled item. `ArrowUp`으로 열면 마지막 enabled item |
| `submenu`           | 첫 enabled item                                         |
| `composite-popover` | panel root                                              |

**입력 수단으로 갈리지 않는다.** Properties 표의 "입력 방식 의존"은 `ArrowUp`으로 열 때만 마지막
item이 되는 것을 뜻하며, 그 정보는 trigger의 keydown이 직접 가지고 있다. pointer 여부를
`event.detail === 0` 같은 heuristic으로 역추론하지 않는다 — 그 판정은 엔진과 보조기술에 따라 달라져
이 저장소가 검증할 수 없고, 잘못 갈리면 키보드 사용자가 항목에 도달할 경로를 잃는다.

action-menu에 panel root를 쓰지 않는 이유는 roving `tabIndex`와 결합했을 때 막다른 길이 되기
때문이다. roving에서는 활성 item 하나만 tab stop이고 panel 자신은 `tabIndex="-1"`이므로, panel에
focus가 있는 상태의 `Tab`은 자손이 아니라 문서의 다음 대상으로 나간다. 그리고 이 문서는 action
menu의 `Tab`이 menu를 닫도록 정하고 있다. 즉 panel root는 "열렸는데 방향키로만 도달 가능한" 상태를
만든다.

**첫 enabled item이지 첫 focusable이 아니다.** `disabledItems: "announce"`인 menu의 첫 항목이
disabled이면 둘이 갈린다. 어느 전략이든 초기 focus는 건너뛴 뒤의 첫 enabled item이다.

**후보가 0개면 panel root로 강등한다.** 비동기 로딩, 검색 결과 0건, 권한상 전 항목 비활성인
menu에서 초기 focus가 조용히 사라지면 키보드로 패널에 도달할 방법이 없어진다. 안내 문구는
`menuitem`이 아니라 panel의 `aria-describedby` 대상 또는 `role="status"`로 둔다.

`composite-popover`가 panel root인 근거는 자손이 자연 Tab 순서로 tabbable이라는 점이다. panel이
focus를 가지면 다음 `Tab`이 실제로 그 자손으로 들어가고, 이때 panel 이름이 먼저 읽힌다. 성립 조건
셋은 모두 구현 계약이다.

1. panel root에 `tabIndex="-1"`이 있다. 없으면 `focus()`가 아무 일도 하지 않고 **조용히 `none`으로
   강등된다.**
2. panel에 accessible name이 있다. `panelLabel`이 필수인 것이 이 조건을 만족한다.
3. 프로그램적 focus가 `:focus-visible`을 유발하지 않는다. 브라우저 heuristic이므로 시각 회귀로
   고정한다.

초기 focus는 open당 한 번이다. **이미 이 overlay 또는 그 자손 overlay 안에 focus가 있으면 보내지
않는다** — 부모와 자식이 같은 프레임에 열릴 때 부모가 자식에게서 focus를 빼앗으면, 그 이동이 자식의
바깥 판정을 발화시켜 사용자가 아무것도 하지 않았는데 자식이 닫힌다.

##### `none`의 허용 조건

`none`은 기본값이 아니다. panel은 문서 끝 overlay host에 있으므로 trigger에서의 가상 커서 훑기가
panel 내용에 닿지 않고, `aria-controls`를 따라가는 조작은 보조기술마다 달라 계약으로 삼을 수 없다.
다음을 **모두** 만족할 때만 쓴다.

- panel에 focusable 자손이 하나도 없다(순수 정보 표시).
- trigger가 `aria-describedby`로 panel 내용을 직접 참조한다.
- 그 예외를 사용처 문서에 근거와 함께 남긴다.

##### Return focus

| reason         | 발생 경로                                         | focus 대상                              |
| -------------- | ------------------------------------------------- | --------------------------------------- |
| `escape`       | Escape 한 단계                                    | 이 단계의 trigger — submenu면 부모 item |
| `select`       | item 활성화 + `closeOnSelect`                     | trigger                                 |
| `trigger`      | 열린 trigger 재활성화, submenu의 `ArrowLeft`      | trigger — submenu면 부모 item           |
| `outside`      | 바깥 pointer, Tab 이탈                            | **옮기지 않는다**                       |
| `route`        | route 변경, trigger unmount, viewport 소유권 변경 | **옮기지 않는다** — route owner가 소유  |
| `programmatic` | 소비자가 `open`을 직접 내림                       | trigger가 살아 있으면 trigger           |

**submenu는 부모 item을 trigger로 넘긴다.** 넘기지 않아도 primitive가 부모 panel 안으로 되돌리므로
포커스가 문서 밖으로 튀지는 않지만, 복귀 대상이 "부모 panel의 첫 항목"이 되어 사용자가 있던 자리와
달라진다. 규범이 요구하는 것은 **연 자리로 돌아가는 것**이다.

return focus의 **시점**은 exit 완료가 아니라 `closing` 진입이다. panel이 아직 DOM에 있는 동안 동기로
옮기고 그 직후 subtree를 inert로 만든다. 순서를 뒤집으면 복원 대상이 사라진 뒤에 focus를 옮기게 되어
body로 떨어진다. 따라서 exit 모션 동안 화면에는 패널이 보이지만 focus와 accessibility tree에서는 이미
없다 — 의도한 상태이며 exit duration이 그 구간의 상한이다.

#### Portal and layer rules

- 기본은 앱 root 옆의 전용 overlay root에 portal한다. `overflow:hidden`, `transform`, `filter`, `contain`,
  `isolation`이 있는 화면 조상 안에서 z-index를 올리는 방식으로 해결하지 않는다.
- inline panel은 조상 클리핑과 stacking context가 없다는 테스트가 있을 때만 허용한다.
- raw z-index 대신 `layer-content < layer-sticky < layer-popover < layer-modal < layer-critical`의 의미
  토큰을 사용한다. nested menu는 임의로 1,200 같은 값을 쓰지 않고 부모 branch 안에서 순서를 얻는다.
- scroll, resize, visual viewport 변화, anchor ResizeObserver에 반응해 위치를 다시 계산한다. viewport와
  safe area를 넘으면 flip/shift하고, 최대 높이를 설정해 panel 자체가 스크롤한다.
- 위치 계산 전에는 보이지 않아야 한다. CSS의 임시 `top/right`를 한 프레임 노출하지 않는다.
- Tooltip은 포인터를 막지 않는다. 장식 pseudo-element도 항상 `pointer-events:none`이다.

#### Responsive behavior

- 320px viewport와 200% 확대에서 panel 폭은 `min(preferred, viewport - 2 * collisionPadding)`을 넘지 않는다.
- action menu는 최소 Trigger 폭 이상, 기본 200px을 권장한다. 프로필 composite popover는 240px을 기준으로
  하되 긴 번역과 200% 확대에서 내용 폭으로 확장하거나 작은 화면 variant로 바꾼다.
- 높이가 부족하면 `max-height`와 내부 스크롤을 사용한다. viewport 밖 item을 잘라내지 않는다.
- touch에서는 각 action의 hit area를 44px 이상 권장한다. 시각 행이 40px이면 인접 패딩으로 44px의
  유효 타깃을 확보한다.
- mobile Sheet로 전환하면 기존 menu가 아니라 이름 있는 modal dialog가 된다. focus trap, scroll lock,
  닫기 버튼 계약도 함께 전환한다.

#### Content

- item label은 결과를 예측할 수 있는 짧은 명사 또는 동사형으로 쓴다: `설정`, `새 비디오 편집`, `삭제`.
- danger item은 색만 바꾸지 않고 명확한 동사를 사용한다.
- 아이콘은 라벨을 반복 설명하지 않으며 장식이면 보조 기술에서 숨긴다.
- group label과 separator를 남발하지 않는다. 두 item 이하의 그룹은 별도 heading 없이 배치할 수 있다.
- KO/EN/JA에서 말줄임이 액션 의미를 없애면 줄바꿈 또는 폭 확장을 택한다.

#### Accessibility

##### Action menu

- Trigger: `aria-haspopup="menu"`, `aria-expanded`, 고유한 `aria-controls`. `aria-controls`는 panel이
  마운트돼 있고 `closing`이 아닌 동안에만 부여한다 — 존재하지 않거나 inert인 노드를 가리키면 접근성
  검사가 오류를 내고 "제어 대상으로 이동"이 아무 데도 가지 않는다.
- Panel: `role="menu"`, 이름이 필요한 경우 `aria-labelledby`.
- Item: 동작에 따라 `menuitem`, `menuitemcheckbox`, `menuitemradio`. `aria-checked`는 후자 둘에서만
  유효하며, `menuitem`에 붙이면 접근성 검사가 허용되지 않은 속성으로 판정한다 — 시각 체크 표시와
  접근성 상태가 갈린다.
- roving `tabIndex`로 panel 안의 Tab stop은 하나만 둔다.

##### Composite popover

- Trigger: `aria-haspopup="dialog"`, `aria-expanded`, 고유한 `aria-controls`.
- Panel: `role="dialog"`, `aria-modal="false"`를 생략하고 `aria-labelledby` 또는 locale-aware label을 제공.
- 내부 버튼, 링크, segmented control, Listbox는 각자의 네이티브/ARIA 역할을 유지한다.
- 같은 페이지에 GNB가 여러 번 마운트될 수 있으므로 `profile-popover` 같은 고정 id를 복제하지 않는다.

공통으로 visible focus ring, disabled 상태, reduced-motion, 200% 확대를 지원한다. Panel이 닫혀 있으면 그
자손은 accessibility tree와 Tab 순서에서 제외돼야 한다.

#### Specification

| Part/state     | 목표 token/recipe                                      | 검증                       |
| -------------- | ------------------------------------------------------ | -------------------------- |
| Panel surface  | `color-background-menu` — 라이트 neutral-100 / 다크 neutral-800 | light/dark/high contrast   |
| Panel radius   | `radius-overlay` = 16px                                | visual regression          |
| Panel padding  | `space-overlay-inset` = 6px                            | item hit area 유지         |
| Panel border   | 없음. 헤어라인은 `elevation-menu`의 0.5px 스프레드     | 레이아웃 박스 불변         |
| Item radius    | `radius-overlay-item` = 10px                           | hover/focus/selected state |
| Item 사이 간격 | `space-overlay-item-gap` = 2px                         | 행이 붙지 않는다           |
| Item 내부 gap  | `space-overlay-item-content-gap` = 6px                 | 아이콘·라벨 간격           |
| Item 전경      | `color-foreground-menu-item` — 알파 86%                | light/dark                 |
| Item hover     | `color-action-menu-item-hover` — 반투명 오버레이       | 배경이 달라도 같은 정도    |
| Item height    | 44px 이상 (`layout-control-hit-target-minimum`)        | pointer/touch target       |
| Danger 전경    | `color-action-danger` = #ff4b59                        | 중립 표면 위 대비          |
| Danger hover   | `color-action-menu-danger-hover` — red 알파            | light/dark                 |
| Anchor offset  | 8px                                                    | collision/flip             |
| Panel width    | 최소 160px, composite 240px reference                  | 긴 locale 문구와 200% zoom |
| Elevation      | `elevation-menu` — ambient + 0.5px 헤어라인 2겹        | overlay hierarchy          |
| Open motion    | opacity + scale, `motion-overlay-enter`; origin=anchor | reduced-motion 대체        |
| Reduced motion | transform 제거, 짧은 opacity 또는 즉시 전환            | motion preference          |
| Layer          | `layer-popover`, 숫자 리터럴 금지                      | nested overlay stack       |

표의 값 대부분은 제품의 공용 토큰(`--dropdown-*`)에서 채택했다. 채택/편차 판정과 근거는
[`migration/product.measured.json`](../../migration/product.measured.json)에 있고 게이트가 매 실행
확인한다.

**항목 높이 44px과 focus ring은 제품을 따르지 않는다.** 제품 항목은 37px이고 focus ring이 없다.
둘 다 WCAG 계약이라 제품에 맞춰 낮추지 않았다. **`danger` 전경을 제품 값으로 바꾼 것이 문서가
이미 인정하던 대비 결함을 해소한다** — 이전 `status-danger-foreground`는 중립 표면 위에서
무너졌다.

#### Implementation

- Web source: `packages/react/src/menu/**`, `packages/react/src/popover/**`,
  `packages/react/src/anchored/**`
- CSS recipe: `packages/css/src/component/menu-popover.css`
- Public import: `import { ActionMenu, CompositePopover, OverlayProvider } from "@klipse-design/react"`
- Tests: `packages/react/test/menu-{keyboard,pointer,submenu}.browser.test.tsx` (실브라우저 35건,
  두 motion context에서 각각)

소비자는 앱 root에 `OverlayProvider`를 한 번 둔다. host와 scroll owner를 앱이 한 번만 해석하게 하는
것이 계약이며, 컴포넌트가 host를 고르면 인스턴스마다 stacking과 inert 경계가 달라진다.

`kind`는 prop이 아니라 컴포넌트다. `ActionMenuItem`을 `CompositePopover` 안에 두면 문맥이 없어
던진다 — 프로필 패널에 `role="menu"`를 붙이는 것을 타입과 런타임에서 모두 막는다.

##### 계층 분담

| 계약 | 소유 |
| --- | --- |
| Escape 단계별 닫힘, 바깥 판정, activation exactly-once, presence, focus 복원 시점, branch lineage | overlay primitive (DS-P3-005) |
| roving `tabIndex`, 방향키·Home/End·PageUp/Down, typeahead, aria 배선, 열림 통지, submenu 진입·복귀 | 이 recipe |
| 표면·item·group·separator의 시각 표현 | `menu-popover.css` |

키보드 리스너는 panel DOM 노드에 **native로** 붙인다. React 이벤트는 DOM이 아니라 React 트리로
전파되는데 `ActionMenuSubContent`는 부모 Content의 React 서브트리 안에 있으므로, React 핸들러를 쓰면
submenu의 방향키가 부모 핸들러까지 실행해 focus가 부모로 튀고 그 focusout이 submenu를 닫는다.
두 panel은 DOM에서 **형제**이므로 native 리스너에는 그 문제가 없다.

`Enter`/`Space`에 keydown 핸들러를 붙이지 않는다. 브라우저가 이미 click을 합성하므로 더하면 두 번
실행된다. `<a href>`만 예외인데, `<a>`의 Space는 click을 합성하지 않고 페이지를 스크롤하기 때문이다.

#### Known deviations

- **바깥 클릭이 드물게 배경 액션을 실행한다 — 간헐 결함.** 규범이 차단급으로 지정한 계약
  ("바깥 클릭은 메뉴만 닫고 배경 액션을 실행하지 않는다")이 전체 suite 실행 **36회 중 1회** 깨졌다. 실측한 증상은 **패널은 정상적으로 닫히는데 클릭이 배경까지 도달하는 것**이고,
  `browser-reduced-motion` project에서만 관측됐다. 단일 테스트 20회, 단일 project(reduced-motion) 10회로는
  재현되지 않아 **파일 간 상태 간섭**으로 보인다.

  후보 기제는 `OverlayDismissRegion`의 게이트다. 이 layer가 store의 topmost가 아니면
  `shouldConsiderOutside`가 false를 반환하고, 그 경로는 하부 유틸의 dismiss만 취소한 뒤
  **클릭을 삼킬 리스너를 등록하지 않는다.** 그 뒤 다른 경로가 패널을 닫으면 클릭은 그대로 배경에
  떨어진다. 즉 store에 **이전 테스트의 record가 남아 topmost가 어긋난 상태**가 조건일 수 있다.
  【추정】 — 계측으로 확증하지 못했다.

  **추측으로 dismiss 로직을 고치지 않는다.** 재현이 36회에 1회라 고침의 효과를 증명할 수 없고,
  증명되지 않은 수정은 이 경로에서 더 나쁜 회귀를 만든다. 재현 절차와 관측 기록을 남기고
  계측 가능한 형태가 될 때 판정한다.

- **`surface-overlay` 대신 `color-background-overlay`를 쓴다.** Specification 표가 대는 이름의 토큰이
  소스에 없다. DS-P3-014가 이름을 정리하면 갱신한다.
- **panel padding이 6px이 아니라 4px이다.** `space-overlay-inset`이 없어 `space-control-xs`로
  대체했다. DS-P3-014가 토큰을 추가하면 변수 한 줄만 바꾼다.
- **panel에 hairline border가 있다.** Specification 표에는 없지만 dark에서 `elevation-popover`
  그림자만으로는 표면 경계가 서지 않는다.
- **item에 `.kds-hit-target`을 쓰지 않는다.** 그 유틸의 44px `::after`는 항목 중앙에 겹쳐 놓이므로
  간격 없이 쌓이는 행에서 인접 항목의 hit 영역을 2px씩 가로챈다. 행 자체를 44px로 만든다.
- **`offset`과 `collisionPadding`을 인스턴스별로 바꿀 수 없다.** 값은 overlay 표면 CSS 한 블록이
  소유하고 Provider가 1회 측정한다.
- **Anchor를 Trigger와 분리할 수 없다.** Anatomy 2번이 허용한 분리는 아직 public 수단이 없다.
- **한국어 typeahead가 동작하지 않는다.** 비편집 요소에서 IME가 켜져 있으면 keydown의 `key`가 완성
  음절로 오지 않는다. 구현은 조합 중 오작동만 막고 매칭은 `compositionend`가 도착하는 환경에서만
  시도한다. macOS·Windows 실기 측정이 `stable` 승격 전 조건이다.
- **`ArrowRight`/`ArrowLeft`가 RTL에서 반전되지 않는다.**
- **composite popover의 inset이 action menu보다 크다(8px vs 4px).** `.kds-hit-target`을 쓰는 컨트롤은
  44px 타겟을 시각 박스 밖으로 확장하는데, 패널이 스크롤 컨테이너라 그 초과분이 유령 스크롤바가 된다.
  action menu는 행 자체를 44px로 만들어 그 유틸을 쓰지 않으므로 4px을 유지한다 — 거기서 8px을 쓰면
  안쪽 곡률이 item radius보다 작아져 모서리가 뚫린다. 두 값이 다른 것은 실수가 아니다.
- **danger item의 톤이 일반 item과 거의 구분되지 않는다.** 워크샵에서 실측한 대비는 light
  **1.21**, dark **1.14**다(danger 텍스트 : 일반 텍스트). `status-danger-*`는 foreground와
  background가 **함께 쓰이도록 만들어진 쌍**이고 두 테마에서 서로 값이 뒤바뀐다 — light의
  `danger-foreground`(짙은 적갈)가 dark에서는 `danger-background`다. 그래서 텍스트 색으로만 쓰면
  light에서는 hue로 겨우 읽히고 dark에서는 사실상 사라진다. 해소에는 중립 표면 위에서 성립하는
  danger foreground 토큰이 필요하며 `DS-P3-014`가 소유한다. 그때까지 파괴적 액션의 신호는 규범이
  이미 요구하는 **명확한 동사 라벨**이 진다.
- **바깥 클릭도 최상위 branch 하나만 닫는다.** submenu가 열려 있으면 두 번 눌러야 전체가 닫힌다.
  외부 이벤트 정책 3을 그대로 따른 결과이며, 실사용에서 어색하다는 근거가 모이면 규범을 먼저 고친다.
- **`route`로 닫으면 포커스가 body로 떨어질 수 있다.** 포커스를 옮기지 않는 것이 그 reason의 계약이고,
  새 화면이 포커스를 잡는 것이 정상 경로다.

#### Extraction baseline

Klipse product에서 관측된 “프로필 팝오버는 열리지만 메뉴가 선택되지 않음”은 허용 variant가 아니라
차단급 회귀다. 비규범 근거는 [`KP-OVERLAY-001`](../../migration/product-baseline.md)에 보존한다.
새 구현은 특정 원인을 추측해 복사하지 않고 branch, hit-test, activation exactly-once 계약과 아래
회귀 테스트로 문제를 차단한다.

#### Overlay behavior layer

이 문서의 pointer·keyboard·branch·stacking 계약은 `packages/react/src/overlay/`의 내부 primitive가
구현한다. Menu와 Popover는 그 위에 얹히는 recipe이며 **순서를 다시 쓰지 않는다.**

primitive는 public 표면이 아니다 — 경계와 그 이유는
[DS-D-0011](../governance/decisions/DS-D-0011-overlay-primitive-boundary.md)이 소유한다.

| 계약 | 구현 | 회귀 테스트 |
| --- | --- | --- |
| 선택이 닫힘보다 먼저, 정확히 한 번 | `overlay/activation-guard.ts`, `overlay/dismiss-region.tsx` | `overlay-pointer.browser.test.tsx` |
| 바깥 판정은 `composedPath()` + branch registry | `overlay/branch-registry.ts` | `overlay-pointer`, `overlay-store.node` |
| Escape는 최상위 한 단계만 | `overlay/overlay-store.ts` | `overlay-keyboard.browser.test.tsx` |
| 위치 확정 전 비가시·비 hit-test | `overlay/presence.ts` + `base.css` | `overlay-presence.browser.test.tsx` |
| exit 완료와 unmount가 같은 source | `overlay/presence.ts`의 `readExitDuration` | `overlay-presence.browser.test.tsx` |
| anchor 기준 배치와 `--kds-overlay-*` seam | `overlay/positioner.tsx`, `component/overlay.css` | `overlay-presence.browser.test.tsx` |

non-modal에서 Tab으로 focus가 빠져나가 닫히는 경로의 reason은 **`outside`** 다. 새 reason을 만들지
않은 이유는 focus 정책이 `outside`와 같기 때문이다 — 둘 다 포커스를 옮기지 않는다(DS-D-0011 결정 4).

#### Pre-implementation blockers

- ~~공유 positioning, dismiss layer, overlay branch primitive가 없다.~~ **해소(DS-P3-005).** 위
  Overlay behavior layer 참조.
- ~~semantic layer token의 컴포넌트 소비와 nested portal 소유권 구현이 없다.~~ **해소(DS-P3-005).**
  `.kds-layer-*` 유틸을 primitive가 붙이고, 자손 branch는 부모 layer를 물려받는다.
- ~~action menu 방향키, Home/End, typeahead, roving focus test가 없다.~~ **해소(DS-P3-006).**
- ~~composite popover의 initial/return focus와 Tab 정책이 구현되지 않았다.~~ **해소(DS-P3-006).**
  위 §Focus가 variant별 매핑과 reason별 return focus를 소유한다.
- ~~Menu·Popover의 public export가 없다.~~ **해소(DS-P3-006).**
- published Figma component와 Web parity evidence가 없다(DS-F-006-menu-popover).

#### Migration

1. portal, positioning, branch registry, dismiss layer를 가진 headless `Overlay` primitive를 먼저 만든다.
2. 그 위에 `ActionMenu`와 `CompositePopover`를 별도 public API로 만든다.
3. 프로필 composite popover의 테마·언어 nested overlay를 같은 branch에 등록한다.
4. create menu와 card menu를 action-menu variant로 옮긴다.
5. 로컬 document/window listener와 raw z-index를 제거하고 Figma variant를 연결한다.

기존 CSS hook이나 panel id를 호환해야 하면 한 릴리스 동안 adapter를 두되, 새 사용처에 구 API를 노출하지
않는다. 사용자 영향 변경은 [Updates](../updates/README.md)에 기록한다.

#### Migration acceptance tests

##### Pointer regression

- Trigger 클릭 → Panel visible → action item 클릭 시 callback이 **정확히 한 번** 실행된다.
- 링크, destructive action과 logout item도 pointer와 touch에서 각각 한 번만 실행된다.
- 언어 Trigger → portaled Listbox option 클릭 시 부모가 pointerdown에서 먼저 닫히지 않고 값이 변경된다.
- 테마 세그먼트 클릭은 Panel을 유지하고 선택 상태만 바꾼다.
- panel 안 scrollbar, nested overlay, disabled item 클릭을 outside로 오판하지 않는다.
- panel 바깥 클릭은 최상위 branch 하나만 닫고 배경 액션을 뜻하지 않게 실행하지 않는다.
- exit 중인 투명 panel과 pseudo-element가 새 panel/item hit test를 막지 않는다.

##### Keyboard and focus

- Action menu를 Enter/Space/ArrowUp/ArrowDown으로 열고 모든 enabled item을 방향키로 탐색·실행한다.
- Home/End, typeahead, submenu Right/Left, Escape의 단계별 닫힘을 검증한다.
- Composite popover는 Tab 순서가 시각 순서와 같고, Escape는 Trigger로 복귀하며 Tab 이탈은 다음/이전 문서
  대상에 focus를 유지한다.
- 닫힌 panel의 자손이 Tab 순서와 accessibility tree에 없다.
- 동일 화면에 두 인스턴스를 렌더해 id가 중복되지 않는다.
- pointer로 연 action menu도 첫 enabled item에서 시작하고, 첫 항목이 `aria-disabled`여도 같다.
- `ArrowUp`으로 열면 마지막 enabled item으로 간다.
- enabled item이 0개인 menu는 panel root가 focus를 받는다.
- submenu의 Escape와 `ArrowLeft`가 모두 부모 item으로 복귀한다.
- `outside`와 `route`로 닫을 때 포커스가 이동하지 않고, 같은 fixture의 `escape`는 이동한다.
- 소비자가 `open`을 직접 내리면 reason이 `programmatic`이고 trigger로 돌아간다.
- `closing` 진입과 같은 tick에 trigger의 `aria-expanded`가 `false`가 되고 `aria-controls`가 사라진다.
- submenu가 열린 채 부모를 닫으면 같은 tick에 submenu 항목이 accessibility tree에서 사라지고 클릭해도
  콜백이 실행되지 않는다.
- root `disabled`가 강제로 열린 panel의 item을 비활성화하지 않는다.
- `Shift+Tab` 역방향 이탈도 정방향과 같은 원칙을 따른다.

##### Layout and accessibility

- scroll, resize, zoom, visual viewport 변화에도 Panel이 anchor를 따라가고 viewport를 벗어나지 않는다.
  정적 1회 측정으로는 이 계약을 검증할 수 없다 — 변화를 만든 뒤 다시 측정해야 한다.
- 320px, 200% 확대, KO/EN/JA 긴 라벨, light/dark, reduced-motion을 검증한다.
- 접근성 검사에서 role 구조, accessible name, `aria-expanded/controls`, focus-visible 오류가 없다.
  자동 검사가 `role="menu"`의 accessible name 누락은 잡지 못하므로 그 항목은 별도 단언으로 고정한다.
- forced-colors에서 하이라이트된 danger item의 배경과 전경이 서로 다른 시스템 색이다.

이 테스트와 Figma variant가 연결되고 알려진 편차가 닫히기 전에는 `stable`로 승격하지 않는다.

## Tooltip

- Source: design/components/tooltip.md
- Maturity: experimental

### Tooltip

포인터나 키보드 focus가 컨트롤에 머무를 때 **짧은 보조 설명**을 띄운다. 이름을 대신하지 않고
보강한다. 이름이 없어서 tooltip이 필요하다면 그건 tooltip이 아니라 라벨이 빠진 것이다.

#### Availability

| Surface       | 상태           | 근거                                                      |
| ------------- | -------------- | --------------------------------------------------------- |
| Web           | `partial`      | public export와 acceptance test; visual regression과 제품 소비 증거 없음 |
| Figma         | `partial`      | component set 4 variant (Side). publish는 DS-F-008        |
| Documentation | `done`         | 이 문서                                                   |
| Maturity      | `experimental` | 규범과 구현이 같은 변경 단위에서 처음 선다                |

#### When to use

- 아이콘 전용 컨트롤의 **이름을 보강**할 때. 이름 자체는 [Icon Button](../components/icon-button.md)의 `label`이
  소유하고, tooltip은 그것을 눈으로도 보이게 한다.
- 단축키·현재 값·짧은 제약을 덧붙일 때.

쓰지 않는 경우가 더 중요하다.

- **상호작용이 필요한 내용은 넣지 않는다.** 링크·버튼·입력이 들어가야 하면
  [Menu / Popover](../components/menu-popover.md)다. Tooltip은 포인터를 얹을 수 없다.
- **오류·경고를 tooltip으로만 알리지 않는다.** 포인터가 없는 사용자에게 도달하지 않는다.
- **긴 문장을 넣지 않는다.** 두 줄을 넘으면 화면에 상시 표시할 자리를 찾는다.

#### API

```tsx
import { Tooltip } from "@klipse-design/react";
import { IconButton } from "@klipse-design/react";
import { IconTrashSimple } from "@klipse-design/react/icons";

<Tooltip content="삭제 (⌫)">
  <IconButton label="삭제">
    <IconTrashSimple />
  </IconButton>
</Tooltip>
```

`children`은 **하나의 상호작용 가능한 요소**다. tooltip은 그 요소에 `aria-describedby`를 붙인다.

#### Anatomy

1. Trigger — `children`. tooltip은 이 요소를 감싸지 않고 **속성만 붙인다**
2. Surface — portal된 설명 표면. `role="tooltip"`
3. Arrow — 선택. 방향을 가리킨다

#### Properties

| Prop           | 값                                        | 기본값  | 설명                                          |
| -------------- | ----------------------------------------- | ------- | --------------------------------------------- |
| `content`      | ReactNode                                 | **필수**| 설명. 상호작용 요소를 넣지 않는다             |
| `side`         | `top`, `bottom`, `left`, `right`          | `top`   | 선호 방향. 공간이 없으면 뒤집힌다             |
| `openDelay`    | number (ms)                               | `300`   | 포인터 진입 후 열리기까지. 제품 값             |
| `disabled`     | boolean                                   | `false` | tooltip을 띄우지 않는다. trigger는 그대로다   |
| `children`     | ReactElement                              | **필수**| 상호작용 가능한 요소 하나                     |

#### Hierarchy와 variants

variant가 없다. Tooltip은 강조 축을 갖지 않는다 — 위계를 표현해야 하면 그건 tooltip이 아니다.

#### States

| 상태     | 표현                                  | 비고                                              |
| -------- | ------------------------------------- | ------------------------------------------------- |
| closed   | 렌더되지 않는다                       | DOM에도 없다                                      |
| open     | `role="tooltip"`, `aria-describedby`  | 지연 후 열린다                                    |
| disabled | 아무것도 열리지 않는다                | trigger의 동작은 영향받지 않는다                  |

- **닫힘은 지연 없이 즉시**다. 열 때만 지연이 있다. 포인터가 떠났는데 설명이 남으면 어느 컨트롤의
  설명인지 알 수 없다.
- 키보드 focus는 **지연 없이** 연다. 지연은 포인터가 지나가는 것을 열림으로 오인하지 않기 위한
  것이고, focus는 의도된 이동이다.

#### Interaction and responsive behavior

- 포인터 진입·focus로 열리고, 이탈·blur·`Escape`·스크롤로 닫힌다.
- **tooltip 표면은 포인터 이벤트를 받지 않는다.** 받으면 표면 위로 포인터가 이동했을 때 trigger가
  이탈로 판정돼 깜빡인다.
- **터치에는 열리지 않는다.** 터치에는 hover가 없고, 길게 눌러 여는 방식은 컨텍스트 메뉴와
  충돌한다. 터치 사용자에게 필요한 정보라면 화면에 둔다.
- 화면 경계에서 방향이 뒤집힌다. 위치 계산은 overlay primitive가 소유한다.
- **anchor와의 간격을 자체 숫자로 갖지 않는다.** overlay 표면 CSS가 소유하고 Provider가 1회
  측정한 값을 쓴다 — 여기서 다시 쓰면 Menu·Dialog와 간격이 갈린다.

#### Content

- 한 줄, 길어도 두 줄. 마침표를 찍지 않는다.
- trigger의 이름을 그대로 반복하지 않는다. "삭제" 버튼에 "삭제"를 띄우면 스크린리더가 이름과
  설명으로 두 번 읽는다. 덧붙일 것이 없으면 tooltip을 두지 않는다.
- 단축키는 이름 뒤에 붙인다 — "삭제 (⌫)".

#### Accessibility

- 표면은 `role="tooltip"`이고 trigger는 `aria-describedby`로 그것을 가리킨다. **`aria-labelledby`가
  아니다** — tooltip은 이름이 아니라 설명이다.
- **trigger는 자기 이름을 스스로 갖는다.** tooltip이 이름의 유일한 출처가 되면 포인터 없는
  사용자에게 이름이 없다.
- `Escape`로 닫힌다. 열려 있는 동안 focus는 trigger에 남는다 — tooltip으로 focus가 이동하지 않는다.
- tooltip은 focusable이 아니다.

#### Specification

| 항목        | 값                                                      |
| ----------- | ------------------------------------------------------- |
| 타이포      | `typography-caption-regular` (12px)                     |
| padding     | `space-control-xs` 4px / `space-control-sm` 8px         |
| radius      | `radius-control-sm` 8px                                 |
| 테두리      | 1px `color-border-tooltip`                              |
| 배경        | `color-background-inverse` — **페이지와 반전된다**       |
| 전경        | `color-foreground-on-inverse`                           |
| 그림자      | `elevation-tooltip` (테마마다 색이 다르다)              |
| layer       | `layer-popover`                                         |
| 최대 폭     | min(320px, 사용 가능 폭)                                |
| anchor 간격 | `--kds-overlay-offset` 8px — Menu·Dialog와 같은 값       |
| collision   | `--kds-overlay-collision-padding` 8px                    |
| 열림 지연   | 300ms                                                   |
| 닫힘        | 즉시                                                    |
| 열림 모션   | `motion-tooltip-enter` 140ms, scale 0.97 → 1            |

`radius-control-sm`(8px)은 이 컴포넌트가 첫 소비자다. 제품 실측에서 8px이 가장 많이 쓰이는
radius인데 semantic 이름이 없었다.

**표면이 반전된다는 것이 이 컴포넌트의 핵심이다.** 라이트에서 어두운 면에 밝은 글자, 다크에서
그 반대다. 이전 DS는 `background-inset`을 써서 페이지와 같은 극성이었고 제품과 정반대였다.
`color-background-inverse`/`color-foreground-on-inverse`는 Toast가 먼저 세운 토큰인데 값이 제품의
tooltip 면과 정확히 같았다.

**모션이 아예 걸리지 않고 있었다.** `animation-duration`과 `animation-timing-function`만 있고
`animation-name`이 없었다. 값만 적어 두고 실제로 도는지 확인하지 않은 결과다. 제품의
140ms/`cubic-bezier(0.23, 1, 0.32, 1)`와 scale 0.97을 채택했다.

#### Implementation

- `packages/react/src/tooltip/tooltip.tsx`
- `packages/css/src/component/tooltip.css`
- 위치 계산은 overlay primitive의 `OverlayPositioner`/`OverlayAnchor`/`OverlayPositioned`를 쓴다.
  focus scope·inert·scroll lock·dismissable layer는 **쓰지 않는다** — tooltip은 focus를 가져가지
  않고 바깥 클릭을 삼키지도 않는다. DS-D-0011의 primitive 소비자가 Menu·Dialog에 이어 셋이 된다.

#### Known deviations

| 항목 | 상태 | 사유 |
| --- | --- | --- |

#### Acceptance tests

1. 포인터 진입 후 지연이 지나면 열린다.
2. 지연 전에 포인터가 떠나면 열리지 않는다.

5. `Escape`로 닫히고 focus는 trigger에 남는다.
6. 열려 있는 동안 trigger의 `aria-describedby`가 표면 id를 가리킨다.
7. 닫히면 `aria-describedby`가 사라진다.
8. 표면의 `role`이 `tooltip`이다.
9. 표면이 포인터 이벤트를 받지 않는다.
10. `disabled`면 열리지 않는다.
11. trigger의 accessible name이 tooltip 내용으로 바뀌지 않는다.

## Toast

- Source: design/components/toast.md
- Maturity: experimental

### Toast

사용자가 방금 한 일의 결과를 **짧게 알리고 스스로 사라진다.** 확인을 요구하지 않고, 흐름을 끊지
않으며, 놓쳐도 되는 정보만 담는다. 놓치면 안 되는 것은 toast가 아니다.

#### Availability

| Surface       | 상태           | 근거                                                      |
| ------------- | -------------- | --------------------------------------------------------- |
| Web           | `partial`      | public export와 acceptance test; visual regression과 제품 소비 증거 없음 |
| Figma         | `partial`      | component set 2 variant (Tone). publish는 DS-F-008        |
| Documentation | `done`         | 이 문서                                                   |
| Maturity      | `experimental` | 규범과 구현이 같은 변경 단위에서 처음 선다                |

#### When to use

- 되돌릴 수 있는 작업의 완료 — "저장했습니다", "복사했습니다".
- 배경에서 끝난 작업의 결과 — "내보내기가 끝났습니다".

쓰지 않는 경우.

- **확인이나 선택이 필요하면** [Dialog](../components/dialog.md)다. toast는 스스로 사라지므로 답을 받을 수 없다.
- **사용자가 반드시 읽어야 하면** 화면에 남는 자리를 준다. toast는 놓쳐도 되는 것만 담는다.
- **폼 입력 오류**는 해당 필드 옆에 둔다. 화면 반대편에서 사라지는 알림으로는 어디를 고쳐야 할지
  알 수 없다.
- **진행률**은 toast가 아니다. 자동으로 사라지면 진행이 끝난 것처럼 읽힌다.

#### API

```tsx
import { ToastProvider, useToast } from "@klipse-design/react";

function App() {
  return (
    <ToastProvider>
      <Editor />
    </ToastProvider>
  );
}

function Editor() {
  const { toast } = useToast();
  return <Button onClick={() => toast("저장했습니다")}>저장</Button>;
}
```

`toast(message)` 또는 `toast({ message, tone, duration })`. 반환값은 그 toast를 지우는 함수다.

#### Anatomy

1. Viewport — 화면 하단 중앙에 고정된 live region. 항상 DOM에 있고 비어 있을 수 있다
2. Toast — 메시지 하나
3. Message — 한 줄 텍스트

#### Properties

`useToast().toast(input)`의 입력.

| 필드       | 값                     | 기본값    | 설명                                        |
| ---------- | ---------------------- | --------- | ------------------------------------------- |
| `message`  | string                 | **필수**  | 한 줄. 문자열만 받는다                      |
| `tone`     | `neutral`, `danger`    | `neutral` | `danger`는 assertive로 알린다               |
| `duration` | number (ms)            | `4000`    | 자동 소멸까지. `0`이면 자동으로 사라지지 않는다 |

`message`가 `ReactNode`가 아니라 **string인 이유**: live region은 텍스트를 읽는다. 요소를 넣으면
보조 기술이 읽는 내용과 화면에 보이는 것이 갈린다. 링크나 버튼이 필요하면 toast가 아니다.

#### Hierarchy와 variants

`tone` 둘뿐이다. `neutral`은 결과 보고이고 `danger`는 실패 보고다. 성공을 따로 두지 않는다 —
toast가 떴다는 사실 자체가 이미 "그 일이 일어났다"이므로 색으로 한 번 더 말할 필요가 없다.

#### States

| 상태     | 표현                                       | 비고                                     |
| -------- | ------------------------------------------ | ---------------------------------------- |
| entering | CSS `animation` (마운트 시 1회)            | 아래에서 올라오며 나타난다. 상태 속성을 두지 않는다 — 마운트가 곧 신호다 |
| visible  | 상태 속성 없음                             | 타이머가 돈다                            |
| paused   | `data-kds-paused="true"`                   | 포인터가 얹혀 있거나 안에 focus가 있다   |

- **포인터가 얹히거나 안에 focus가 들어오면 타이머가 멈춘다.** 읽는 중에 사라지면 알림이 아니다.
  떠나면 남은 시간부터 다시 흐른다 — 처음부터 다시 세지 않는다.

#### Interaction and responsive behavior

- 화면 **하단 중앙**에 쌓인다. 최신이 아래다 — 시선이 마지막으로 머문 곳에 가장 새 소식이 온다.
- **동시에 최대 3개**를 보여준다. 초과분은 대기했다가 자리가 나면 들어온다.
- **modal 위에 뜬다.** `layer-critical`을 쓴다. dialog 안에서 일어난 일의 결과가 dialog 뒤로
  숨으면 안 된다.
- 포인터를 받는다 — 읽는 동안 멈추려면 얹을 수 있어야 하기 때문이다. 이 점이 [Tooltip](../components/tooltip.md)과
  정반대다.

#### Content

- 한 문장, 마침표 없음. "저장했습니다" — "저장이 완료되었습니다."가 아니다.
- **결과를 말하고 방법을 말하지 않는다.** "3개 항목을 지웠습니다"이지 "삭제 API 호출 성공"이 아니다.
- 실패는 무엇이 안 됐는지 말한다. "저장하지 못했습니다"이지 "오류가 발생했습니다"가 아니다.

#### Accessibility

- Viewport는 항상 DOM에 있는 live region이다. **나중에 만들면 읽히지 않는다** — 보조 기술은
  region이 존재한 뒤의 변화만 감지한다.
- `neutral`은 `role="status"`(polite), `danger`는 `role="alert"`(assertive)로 알린다. 두 tone은
  **서로 다른 region**에 들어간다. 한 region의 `aria-live`를 바꾸면 그 시점의 변경이 유실된다.
- toast는 focus를 가져가지 않는다. 사용자가 하던 일을 끊지 않는다.
- `duration: 0`이 아닌 한 자동으로 사라지므로 **닫기 버튼을 두지 않는다.** 대신 포인터·focus로
  멈춘다. 닫기 버튼은 focus 순서에 끼어들고, 사라지는 대상에 focus를 두면 focus가 소실된다.

#### Specification

| 항목        | 값                                                       |
| ----------- | -------------------------------------------------------- |
| 위치        | 하단 중앙 고정, 아래 여백 `space-layout-section` 24px     |
| 스택 간격   | `space-control-sm` 8px                                   |
| 동시 표시   | 3                                                        |
| 타이포      | `typography-body-sm-regular` (14px)                      |
| padding     | `space-control-md` 12px / `space-toast-inline` 20px      |
| radius      | `radius-overlay` 16px                                    |
| 배경        | `color-background-inverse-translucent` — **70% 반투명**   |
| 배경 흐림   | `backdrop-filter: blur(--kds-blur-surface)` 10px         |
| 전경        | `color-foreground-on-inverse`                            |
| danger 배경 | `color-status-danger-background`                         |
| danger 전경 | `color-status-danger-foreground`                         |
| 그림자      | `elevation-toast` — drop 1겹                             |
| layer       | `layer-critical`                                         |
| 최대 폭     | 420px                                                    |
| 자동 소멸   | 4000ms                                                   |

`color-background-inverse`와 `color-foreground-on-inverse`는 이 컴포넌트가 첫 소비자다. 기존
`color-foreground-inverse`는 두 모드 모두 `neutral-0`이라 **다크에서 밝아지는 반전 표면 위에서는
쓸 수 없다** — 그 토큰은 `action-primary` 위 텍스트를 위한 것이다.

#### Effects

Figma에서 이 컴포넌트가 갖는 effect를 종류와 순서까지 고정한다. parity 게이트가 매 실행 대조하며,
`INNER_SHADOW`가 `DROP_SHADOW`로 바뀌거나 blur radius가 변수에서 풀려 숫자로 박히면 실패한다.

| 순서 | 종류 | 값 |
| --- | --- | --- |
| 1 | `DROP_SHADOW` | y 8 · blur 20 · spread 0 · 검정 16% |
| 2 | `BACKGROUND_BLUR` | radius가 `blur/surface` 변수에 묶인다 |

글래스 베벨 inset 2겹은 owner 결정으로 제거했다 — 이 디자인 시스템에 글래스 섀도우 개념을 두지
않는다.

#### Implementation

- `packages/react/src/toast/toast.tsx`
- `packages/css/src/component/toast.css`
- overlay primitive를 쓰지 않는다. toast는 anchor가 없고 focus를 가져가지 않으며 바깥 클릭과
  무관하다 — positioner·dismissable layer·focus scope 중 어느 것도 해당하지 않는다. Provider가
  자기 viewport를 만든다.

#### Acceptance tests

1. `toast()`를 부르면 메시지가 나타난다.
2. `duration`이 지나면 스스로 사라진다.
3. `duration: 0`이면 사라지지 않는다.
4. 반환된 함수를 부르면 사라진다.
5. 포인터를 얹으면 타이머가 멈추고, 떠나면 다시 흐른다.

8. 두 region이 toast 없이도 처음부터 DOM에 있다.
9. toast가 focus를 가져가지 않는다.
10. 최신 toast가 목록의 마지막에 온다.
11. Provider 없이 `useToast`를 쓰면 명확한 오류를 던진다.

## Project Card

- Source: design/components/project-card.md
- Maturity: experimental

### Project Card

프로젝트 하나를 썸네일과 제목으로 보여 주고, 눌러서 연다.

Klipse의 홈과 허브 화면은 전부 이 카드의 격자다. 제품에는 이 카드의 정의가 **4벌** 있다 — 앱 홈,
노드캔버스 홈, 하이라이트 허브, 비디오 에디터 허브. 네 벌의 기하가 서로 같아서, 이 컴포넌트의
값은 DS가 정한 것이 아니라 **제품 정본을 옮긴 것**이다.

#### Availability

| Surface       | 상태           | 근거                                                            |
| ------------- | -------------- | --------------------------------------------------------------- |
| Web           | `partial`      | public export 10종과 실브라우저 acceptance test 6건; visual regression과 제품 소비 증거 없음 |
| Figma         | `partial`      | component 하나. parity 게이트가 자손 기하·타이포·흐림·자식 순서를 대조하고 변조 canary 7종이 검출력을 고정한다. publish는 DS-F-008 |
| Documentation | `done`         | 이 문서                                                          |
| Maturity      | `experimental` | 규범과 구현이 같은 변경 단위에서 처음 선다                       |

#### When to use

- 격자 안에서 프로젝트·하이라이트·영상 같은 **시각 결과물 하나**를 대표할 때.
- 썸네일이 내용을 설명하고 제목이 그것을 확인해 주는 관계일 때.

쓰지 않는 자리.

- 썸네일이 없고 글만 있는 목록. 그것은 목록 행이지 카드가 아니다.
- 한 번에 하나만 보이는 상세 화면의 헤더.

#### API

```tsx
<ProjectCard>
  <ProjectCardMedia aspectRatio={1}>
    <ProjectCardThumbnail>
      <img src={thumbnail} alt="" />
    </ProjectCardThumbnail>
    <ProjectCardOverlay>
      <ProjectCardEyebrow>하이라이트</ProjectCardEyebrow>
      <ProjectCardTitle>여름 여행</ProjectCardTitle>
      <ProjectCardMeta>3일 전 편집</ProjectCardMeta>
    </ProjectCardOverlay>
  </ProjectCardMedia>

  {/* 클릭 타깃은 카드 전체를 덮는 형제다. 순서가 계약이다 — Media → Action → Adornment. */}
  <ProjectCardAction href={`/highlight/${id}`} />
  <ProjectCardAdornment placement="top-end">{menu}</ProjectCardAdornment>
</ProjectCard>
```

**프레임을 링크로 만들지 않는다.** 처음 구현은 root 자체가 `<a>`였고, 그러면 슬롯의 더보기 버튼이
`<a>` 안의 대화형 자손이 되어 HTML이 무효가 되고 보조기술에서 동작이 정의되지 않는다. 이 문서가
바로 그 사용을 예시로 들고 있었다. 그래서 링크를 카드 전체에 늘려 깔고 슬롯을 그 **위**에 형제로
둔다.

#### Anatomy

**자식 순서가 계약이다** — Media → Action → Adornment. 숫자 z-index를 쓰지 않으므로 칠 순서가 곧
DOM 순서이고, 슬롯이 Action 앞에 오면 슬롯 안의 컨트롤이 클릭 타깃에 덮여 눌리지 않는다.

1. **Card** — 프레임. 반경과 헤어라인 테두리를 소유하며 대화형이 아니다.
2. **Media** — 비율이 고정된 면. 썸네일·자리표시·오버레이의 좌표계다.
3. **Thumbnail** — 썸네일 자리. `<img>`나 `<video>`를 그대로 담는다.
4. **Overlay** — 미디어 하단의 제목 띠. 흐림 층을 소유한다.
5. **Eyebrow / Title / Meta** — 오버레이 안의 세 줄. 각각 한 줄로 잘린다.
6. **Action** — 카드 전체를 덮는 클릭 타깃. `<a>` 또는 `<button>`이다.
7. **Adornment** — 카드 모서리의 슬롯. 상태 칩과 더보기 메뉴가 들어간다.

#### Properties

| part | prop | 값 | 기본 | 뜻 |
| --- | --- | --- | --- | --- |
| Action | `href` | string | 없음 | 있으면 `<a>`, 없으면 `<button>` |
| Media | `aspectRatio` | number | `1` | 폭 대 높이. **양수가 아니면 무시한다** |
| Adornment | `placement` | `top-start` \| `top-end` | `top-end` | 붙는 모서리 |

나머지는 각 요소의 네이티브 속성을 그대로 받는다.

`aspectRatio`가 0이나 음수면 미디어 면의 높이가 0이 되어 카드가 테두리만 남고 그 안의 절대 위치
자식이 전부 사라진다. 계산 결과가 실수로 흘러드는 자리라 컴포넌트가 막는다.

#### Hierarchy와 variants

variant 축이 없다. 카드의 강조는 카드가 아니라 **썸네일**이 만든다. 상태(생성 중, 실패 등)는
`ProjectCardAdornment` 안의 별도 컴포넌트가 표현하며 카드 자신의 축으로 두지 않는다 — 제품의 네
벌이 이미 그렇게 하고 있고, 카드에 상태 축을 만들면 화면마다 다른 상태 어휘가 카드로 새어 들어온다.

#### States

| state | 표현 |
| --- | --- |
| Default | 헤어라인 테두리, 변형 없음 |
| Hover | 카드 자신은 바뀌지 않는다. 슬롯 안의 컨트롤이 드러난다 |
| Active | `scale(0.975)`. `:has(.kds-project-card-action:active)`로 **클릭 타깃만** 본다 — 프레임에 직접 걸면 슬롯의 버튼을 눌러도 카드가 줄어든다 |
| Focus visible | 링은 프레임에 그린다. 투명한 클릭 타깃에만 링이 뜨면 무엇이 선택됐는지 모른다 |

**hover에서 카드 면을 바꾸지 않는다.** 카드의 대부분은 썸네일이고 그 위에 어떤 강조를 얹어도
이미지에 따라 결과가 달라진다. 제품 네 벌도 hover에서 면을 바꾸지 않는다.

#### Interaction and responsive behavior

- 클릭 타깃이 네이티브 `<a>`/`<button>`이므로 Enter·Space·새 탭·링크 복사가 브라우저 기본으로 동작한다.
- 세 줄은 모두 한 줄로 잘린다. 카드 폭은 격자가 정하므로 줄바꿈을 허용하면 카드마다 높이가 다르다.
- 오버레이 높이는 px이 아니라 **미디어 높이의 30%를 하한으로** 갖는다
  (`block-size: fit-content; min-block-size: 30%`). 큰 카드에서는 30%가 이기고, 세 줄과 여백의 합이
  그보다 커지는 작은 카드에서는 내용이 이긴다. 경계는 미디어 높이 약 310px이며 격자의 최소 트랙
  240px은 그 아래다.

  처음 구현은 `block-size: 30%`만 두었다. 절대 위치 박스의 확정 크기라 내용이 커져도 자라지 않고
  **글자가 띠 위로 넘쳤다** — 240px에서 띠 71.4px에 내용 92.8px이라 eyebrow가 흐림이 0인 구간에
  놓였다. 실측으로 찾아 고쳤고 테스트가 최소 트랙에서 그것을 고정한다.
- `prefers-reduced-motion`에서 누름 변형을 없앤다.

#### Content

- **Eyebrow**는 종류나 분류 한 단어다. 문장을 쓰지 않는다.
- **Title**은 사용자가 지은 이름이다. 길이를 제한하지 않고 잘라서 보여 준다.
- **Meta**는 시각이나 상태 한 조각이다. 두 정보를 이어 붙이지 않는다 — 잘리면 둘 다 못 읽는다.
- 썸네일의 `alt`는 **빈 문자열**이다. 제목이 바로 옆에 있어 같은 정보를 두 번 읽히지 않는다.

#### Accessibility

- 클릭 타깃이 네이티브 `<a>`/`<button>`이다. 제품의 네 벌은 전부 `<article>`에 `onClick`을 걸어
  **키보드로 열 수 없고** 스크린 리더에 버튼으로도 읽히지 않는다. 그 구조는 옮기지 않았다.
- **클릭 타깃 안에 대화형 자손을 두지 않는다.** `ProjectCardAdornment`는 그 형제이며 위에 칠해진다.
- 클릭 타깃의 이름은 `ProjectCardTitle`에서 온다. id는 호출부가 만들면 카드가 여럿일 때 겹치므로
  컴포넌트가 인스턴스마다 발급한다. 제목이 없는 카드는 `aria-label`을 직접 준다.
- focus ring은 프레임에 그린다(`:has()`).
- **오버레이 글자의 대비는 썸네일에 달려 있어 보장되지 않는다.** 흐림이 뒤를 고르게 만들지만
  값을 고정하지는 못한다. 아래 Known deviations를 본다.

#### Specification

| 축 | 값 | 토큰 |
| --- | ---: | --- |
| 반경 | 16px | `radius-card` |
| 오버레이 높이 하한 | 미디어의 30% | — |
| 테두리 | 0.5px | `border-width-hairline` + `color-border-subtle` |
| 미디어 배경 | — | `color-background-canvas` |
| 오버레이 여백 | 16px | `space-layout-gutter` |
| 줄 간격 | 4px | `space-stack-xs` |
| 줄 높이 | 1.2 | — |
| 배경 흐림 | 10px | `blur-surface` |
| 제목 | body-md-medium | `typography-body-md-medium` |
| Eyebrow·Meta | body-sm-regular | `typography-body-sm-regular` |
| 누름 | `scale(0.975)` | — |

#### Effects

**프로그레시브 블러 하나뿐이다.** 오버레이의 `::before`가 `backdrop-filter: blur(10px)`에 위로
사라지는 mask를 걸어, 아래는 온전히 흐리고 위로 갈수록 흐림이 사라진다.

| 위치(아래에서) | 남는 흐림 |
| ---: | ---: |
| 0% | 1 |
| 55% | 1 |
| 70% | 0.8 |
| 85% | 0.4 |
| 100% | 0 |

불투명 스크림을 덮는 방식과 다르다. 스크림은 썸네일의 색을 지우지만 흐림은 색을 남기면서 글자 뒤의
고주파 성분만 없앤다. Figma에서는 같은 뜻을 `BACKGROUND_BLUR`의 `PROGRESSIVE` 모드가 표현한다.

정지점은 [`figma/components.measured.json`](../../figma/components.measured.json)이 갖는다 — 코드와
Figma가 같은 원천을 본다.

#### Implementation

- `.kds-project-card`는 격자 트랙을 채운다(`inline-size: 100%`). 프레임이 내용에 맞춰 줄어들면
  미디어 폭이 `100%`라 서로를 참조해 0으로 접힌다 — 240px 트랙에서 2px(테두리만)로 쟀다.
- `box-sizing`을 카드와 오버레이에 **명시한다.** 소비자의 reset에 기대면 결과가 달라지고, 오버레이가
  content-box면 30% 띠에 여백 32px이 더해져 39%가 된다.
- 숫자 z-index를 쓰지 않는다. 칠 순서는 곧 DOM 순서다 — 흐림 층은 `::before`라 트리 순서에서 앞이고
  텍스트 wrapper가 `position: relative`로 그 위에 온다. 카드 수준에서는 **Media → Action →
  Adornment**가 그 계약이다.
- 썸네일은 `ProjectCardThumbnail`이 자리를 잡는다. CSS가 `.kds-project-card-media > img`를 직접
  잡으면 Next.js `Image`처럼 래퍼를 하나 더 만드는 컴포넌트를 넣는 순간 선택자가 빗나간다.
- 누름 전환은 `transition-property`에 **`scale`**을 적는다. `scale`은 `transform`과 별개 property라
  `transform`만 적으면 선언이 아무것도 전이하지 않는다 — 이 저장소의 네 컴포넌트가 그 상태였다.

#### Known deviations

- **오버레이 대비를 보장하지 못한다.** 흰 썸네일 위의 밝은 글자, 검은 썸네일 위의 어두운 글자가
  가능하다. 제품은 하이라이트 카드에 한해 dominant color의 광도를 계산해 글자색을 뒤집지만, 나머지
  카드는 테마 색을 그대로 쓴다. DS도 같다. 해소하려면 썸네일의 평균 광도를 읽어야 하며 그것은
  런타임 계약이라 이 컴포넌트가 소유할 수 없다.
- **줄 높이 1.2가 리터럴이다.** tight 축의 typography 토큰이 소스에 없다. 제품도 같은 이유로
  `--project-card-overlay-line-height`를 따로 두며, 그 변수는 카드 4벌에서만 쓰인다(15곳) — 타입
  스케일의 축이 아니라 카드의 값이다. **Figma에서는 이것이 text style을 못 쓰게 만든다** — Figma
  text style은 all-or-nothing이라 줄 간격만 덮으면 style 연결이 끊긴다. 그래서 세 줄은 style에
  묶이지 않고 parity 게이트가 `fontSize`와 `lineHeightPercent`를 직접 대조한다.
- **미디어 배경이 light에서 제품과 7/255 다르다.** 제품은 `palette-gray-200`(#e3e4e8), DS는
  `color-background-canvas`(light #f1f1f3 · dark #171b22)다. dark는 정확히 같다. 이 한 자리를 위해
  색 계단을 늘리지 않는다.
- **위계를 opacity가 아니라 토큰으로 만든다.** 제품은 같은 색에 0.72/0.7을 곱한다. 그러면 결과가
  뒤에 놓인 썸네일에 따라 달라진다.

#### Acceptance tests

1. 240px 트랙 안에서 카드가 접히지 않는다(폭이 트랙과 같다).
2. `aspect-ratio` 기본값에서 카드의 폭과 높이가 같다.
3. 반경이 16px이고 `radius-card`에서 온다.
4. 측정 폭 360에서 오버레이 띠가 미디어 높이의 정확히 30%다.
5. **최소 트랙 240에서 내용이 띠 위로 넘치지 않고, 띠가 30%보다 커진다.**
6. 오버레이 `::before`의 `backdrop-filter`가 `blur(10px)`이고, mask가 Effects 표의 다섯 정지점을
   그대로 갖는다.
7. **슬롯 안의 버튼이 실제로 눌린다** — 그 좌표의 최상위 요소가 그 버튼이고, 클릭이 카드로 새지
   않는다. DOM 순서를 되읽는 것으로는 증명되지 않는다.
8. 클릭 타깃이 카드의 padding box 전체를 덮고 **대화형 자손을 하나도 갖지 않는다.**
9. 클릭 타깃의 `aria-labelledby`가 제목의 id를 가리킨다.
10. `href`가 있으면 `<a>`, 없으면 `<button>`으로 렌더된다.
11. `aspectRatio`가 0이면 무시하고 기본 1을 쓴다.
12. 누름 전환이 실제로 걸린다 — `transition-property`에 `scale`이 있다.

## Text Field

- Source: design/components/text-field.md
- Maturity: experimental

### Text Field

한 줄 텍스트를 입력받는다.

**제품에 공용 구현이 없다.** 텍스트 입력 정의가 약 40벌이고 다섯 계열로 갈리며 계열 사이에 합의가
없다 — 인증 floating-label 9벌, 테두리 박스 5벌, 테두리 없는 채운 면 9벌, 투명 인라인 rename 8벌,
노드 캔버스 프롬프트 5벌. 그래서 이 컴포넌트의 값은 제품 정본을 옮긴 것이 **아니라 DS가 정한
것**이고, 어디서 갈라지는지는 [`product.measured.json`](../../migration/product.measured.json)이
사유와 함께 갖는다.

#### Availability

| Surface       | 상태           | 근거                                                        |
| ------------- | -------------- | ------------------------------------------------------------ |
| Web           | `partial`      | public export와 실브라우저 acceptance test 8건; visual regression과 제품 소비 증거 없음 |
| Figma         | `partial`      | component set 8 variant(Size×State). parity 게이트가 Box·Label·Value·Message를 자손으로 대조한다. publish는 DS-F-008 |
| Documentation | `done`         | 이 문서                                                      |
| Maturity      | `experimental` | 규범과 구현이 같은 변경 단위에서 처음 선다                   |

#### When to use

- 자유 형식의 짧은 텍스트를 한 줄로 받을 때 — 이름, 이메일, 검색어, URL.

쓰지 않는 자리.

- 여러 줄. 그것은 Textarea이며 이 컴포넌트의 축이 아니다.
- 정해진 목록에서 고르는 것. 그것은 Select다.
- 체크박스·라디오·파일. 각자 다른 컴포넌트다.

#### API

```tsx
<TextField
  label="프로젝트 이름"
  placeholder="예: 여름 여행"
  description="공백 없이 입력합니다"
  suffix={<IconButton size="sm" label="지우기" onClick={clear}><IconX /></IconButton>}
/>

<TextField label="이름" invalid description="이미 쓰는 이름입니다" />
```

#### Anatomy

1. **Stack** — 라벨·박스·메시지를 세로로 담는다.
2. **Label** — 시각 라벨. `htmlFor`로 입력에 연결된다.
3. **Box** — **시각적 필드.** 높이·여백·테두리·반경·배경을 소유하고 포커스 링을 받는다.
4. **Prefix / Suffix** — 박스 안의 슬롯. 아이콘과 버튼이 들어간다.
5. **Control** — 실제 `<input>`. 박스가 시각을 소유하므로 여기는 비어 있다.
6. **Message** — 도움말 또는 오류. 한 자리를 나눠 쓴다.

**시각적 필드가 `<input>`이 아닌 이유.** 접두 아이콘과 접미 버튼을 필드 *안에* 두려면 `<input>`
하나로는 안 된다. 제품의 가장 큰 계열(인증 9벌)도 같은 구조를 쓴다.

#### Properties

| prop | 값 | 기본 | 뜻 |
| --- | --- | --- | --- |
| `label` | ReactNode | 없음 | 시각 라벨. 없으면 `aria-label`이 필수다 |
| `size` | `md` \| `sm` | `md` | 시각 크기. 글자 크기는 바뀌지 않는다 |
| `description` | ReactNode | 없음 | 필드 아래 한 줄. `invalid`면 오류 문구가 된다 |
| `invalid` | boolean | `false` | 오류 상태 |
| `prefix` / `suffix` | ReactNode | 없음 | 박스 안의 슬롯 |
| `type` | `text` \| `email` \| `password` \| `search` \| `tel` \| `url` | `text` | 텍스트 입력만 다룬다 |

나머지는 `<input>`의 네이티브 속성을 그대로 받는다.

#### Hierarchy와 variants

variant 축이 없다. 필드는 강조 단계를 갖지 않는다 — 한 폼 안에서 어떤 필드가 다른 필드보다
"주요"하다는 표현은 시각이 아니라 순서와 라벨이 맡는다.

#### States

| state | 표현 |
| --- | --- |
| Default | `color-border-control` 테두리 |
| Hover | **바뀌지 않는다** |
| Focus | 박스가 `:focus-within`으로 공유 링을 받는다 |
| Invalid | `color-border-danger` 테두리 **+ 오류 문구 + `aria-invalid`** |
| Disabled | `color-border-subtle` 테두리, 전경 `color-foreground-disabled` |

**hover에서 아무것도 바꾸지 않는다.** 필드의 어포던스는 보이는 테두리와 텍스트 커서가 맡는다.
제품의 필드들도 대부분 hover 상태를 갖지 않는다.

**Focus는 states 표에 없다.** 색이 아니라 outline이라 면·전경·테두리 세 값으로 표현되지 않는다 —
브라우저 테스트가 따로 대조한다.

#### Interaction and responsive behavior

- 박스 어디를 눌러도 텍스트 커서가 나온다(`cursor: text`). 슬롯 안의 버튼은 자기 커서를 갖는다.
- 높이는 `min-block-size`다. 200% 확대나 긴 값에서 잘리는 대신 자란다.
- 폭은 호출부가 정한다. 필드가 스스로 폭을 갖지 않는 이유는 폼의 격자가 그것을 소유하기 때문이다.

#### Content

- **Label**은 무엇을 넣는지를 말한다. "이름"이지 "이름을 입력하세요"가 아니다.
- **Placeholder**는 예시다. 라벨을 대신하지 않는다 — 입력을 시작하면 사라지기 때문이다.
- **Description**은 제약이나 형식을 말한다. `invalid`일 때는 **무엇이 틀렸고 어떻게 고치는지**를
  말한다. "잘못된 입력"이 아니라 "이미 쓰는 이름입니다".
- 도움말과 오류가 같은 자리를 쓴다. 둘이 동시에 뜨면 어느 것을 읽어야 하는지 모른다.

#### Accessibility

- **라벨이 필수다.** 시각 라벨이 없으면 `aria-label`을 준다. 제품의 대부분의 필드는 시각 라벨이
  없고 placeholder가 그 역할을 대신하는데, 그 구조는 옮기지 않았다.
- id는 컴포넌트가 인스턴스마다 발급한다. 호출부가 만들면 같은 화면에 필드가 여럿일 때 겹친다.
- **오류를 색만으로 알리지 않는다.** `aria-invalid`와 `aria-describedby`로 연결된 문구가 함께 뜨고,
  그 문구는 `role="alert"`이라 뜨는 즉시 읽힌다. 도움말은 alert가 아니다 — 화면을 여는 것만으로
  스크린 리더가 시끄러워지면 안 된다.
- 포커스 링은 박스가 받는다. `<input>`에 걸면 링이 글자 주위에만 뜨고 슬롯이 밖에 남는다.
- placeholder는 `color-foreground-secondary`다. `foreground-tertiary`는 light에서 배경 대비
  **3.96:1**로 4.5:1에 미달한다.

#### Specification

| 축 | md | sm | 토큰 |
| --- | ---: | ---: | --- |
| 높이 | 40px | 32px | `layout-control-height-md` / `-sm` |
| 좌우 여백 | 16px | 12px | `space-control-lg` / `-md` |
| 슬롯 간격 | 8px | 8px | `space-control-sm` |
| stack 간격 | 4px | 4px | `space-control-xs` |
| 반경 | 12px | 12px | `radius-control` |
| 테두리 | 0.5px | 0.5px | `border-width-hairline` |
| 값 타이포 | 14/1.5 | 14/1.5 | `typography-body-sm-regular` |
| 라벨 타이포 | 14/1.5 | 14/1.5 | `typography-body-sm-medium` |
| 메시지 타이포 | 12 | 12 | `typography-caption-regular` |

기하가 Button과 같은 계단인 이유는 하나다 — 같은 화면에 나란히 서는 컨트롤이 서로 다른 높이를
갖지 않게 하려는 것이다. 제품은 30·34·44·48px이 섞여 있다.

#### Effects

없다. 그림자도 흐림도 쓰지 않는다.

#### Implementation

- `caret-color`를 **선언하지 않는다.** 브라우저 기본이 `currentColor`이고 값 텍스트가
  `foreground-primary`이므로 자동으로 따라간다. 전용 토큰을 만들면 값과 캐럿이 따로 놀 수 있다.
- placeholder에 `opacity: 1`을 명시한다. Firefox가 기본으로 낮추는데, 대비를 계산해 놓고 브라우저가
  다시 흐리게 만들면 의미가 없다.
- 박스는 `<label>`이 아니라 `<div>`다. `<label>`로 두면 슬롯 안의 버튼을 눌러도 입력이 포커스를
  가져가 버튼이 동작하지 않는다.

#### Known deviations

- **제품과 거의 모든 축이 다르다.** 정본이 없으므로 "다르다"가 결함이 아니다. 각 축의 판정은
  [`product.measured.json`](../../migration/product.measured.json)의 `text-field`에 있다.
- **Figma의 Focus는 링을 stroke로 그린다.** CSS는 `outline`인데 Figma에 outline이 없어 바깥으로
  나가는 사각형 stroke로 표현한다. 두께는 같고(`border-width-ring` 2px) 모서리 반경만 근사다.
- **Textarea가 없다.** 제품에는 여러 줄 입력이 최소 5벌 있다(노드 캔버스 프롬프트 계열). 같은
  박스 구조로 확장할 수 있으나 이번 범위가 아니다.
- **`color-border-control`을 쓴다.** 그런데 IconButton은 같은 자리에 `color-border-default`를
  쓴다 — 컨트롤 테두리의 정본이 저장소 안에서 아직 정해지지 않았다. 값도 다르다(전자는 반투명,
  후자는 불투명). 이 불일치는 이 컴포넌트가 만든 것이 아니라 드러낸 것이다.

#### Acceptance tests

1. md/sm의 높이·좌우 여백·슬롯 간격·반경·테두리·타이포가 `components.measured.json`과 같다.
2. Default·Invalid·Disabled의 면·전경·테두리가 states 표와 같다.
3. 포커스 링을 **박스**가 받고, 입력 자신은 링을 그리지 않으며, 접미 슬롯이 박스 안에 있다.
4. placeholder가 `foreground-secondary`이고 값과 다르며 `opacity: 1`이다.
5. 라벨의 `for`가 입력을 가리키고, 라벨을 누르면 입력에 포커스가 간다.
6. 필드가 둘 있을 때 두 입력의 id가 다르다.
7. `invalid`면 `aria-invalid="true"`, `aria-describedby`가 메시지를 가리키고, 메시지가
   `role="alert"`이며 문구가 실제로 있다.
8. `invalid`가 아니면 메시지가 `role="alert"`이 **아니다.**

## Empty State

- Source: design/components/empty-state.md
- Maturity: experimental

### Empty State

목록이나 영역에 보여 줄 것이 없을 때, 그 사실과 다음 행동을 알린다.

제품에 정의가 **9벌** 있다 — 앱 홈 2, 하이라이트 2, 비디오 에디터 5. 그중 하나(하이라이트의 둘째)는
조건상 도달할 수 없는 죽은 분기라 살아 있는 것은 8벌이다. 아홉 벌은 거의 합의하지 않는다.

| 축 | 갈림 |
| --- | --- |
| 세로 여백 | 80px 2벌 · 64px 1벌 · 선언 없음 나머지 |
| 블록 간격 | 12px 2벌 · 16px 1벌 |
| 제목 계층 | 있음 2벌 · 없음 나머지 |
| 행동 유도 | 있음 3벌 · 없음 6벌 |
| **배경·테두리·반경** | **9벌 전부 없음** |

마지막 줄이 유일한 합의이고, 그것을 그대로 옮겼다. 나머지는 두 홈이 동의한 값을 정본으로 골랐다 —
근거가 가장 두껍다.

#### Availability

| Surface       | 상태           | 근거                                                          |
| ------------- | -------------- | -------------------------------------------------------------- |
| Web           | `partial`      | public export와 실브라우저 acceptance test 7건; visual regression과 제품 소비 증거 없음 |
| Figma         | `partial`      | component 하나. parity 게이트가 Graphic·Title·Description·Action을 자손으로 대조한다. publish는 DS-F-008 |
| Documentation | `done`         | 이 문서                                                        |
| Maturity      | `experimental` | 규범과 구현이 같은 변경 단위에서 처음 선다                     |

#### When to use

- 목록·격자·패널에 항목이 **하나도 없을 때**.
- 사용자가 아직 아무것도 만들지 않아 다음 행동을 안내해야 할 때.

쓰지 않는 자리.

- **불러오지 못했을 때.** 그것은 오류이며 사용자가 취할 행동이 다르다 — 없으면 만들면 되고
  실패했으면 다시 시도해야 한다. 제품의 프로젝트 피커는 둘을 같은 빨간 표현으로 합쳐 두었는데,
  그 구조는 옮기지 않았다.
- **불러오는 중일 때.** 그것은 로딩이다. 빈 상태를 먼저 보여 주면 곧 사라질 "없습니다"를 읽힌다.
- 검색·필터 결과가 없을 때는 **같은 컴포넌트를 쓰되 문구가 다르다.** 아래 Content를 본다.

#### API

```tsx
<EmptyState
  graphic={<IconFolder />}
  title="아직 프로젝트가 없습니다"
  description="첫 번째 영상을 만들어보세요."
  action={<Button variant="primary" size="sm" leftIcon={<IconPlus />}>만들기</Button>}
/>
```

#### Anatomy

1. **Container** — 세로 가운데 정렬 stack. **면을 갖지 않는다.**
2. **Graphic** — 64px 슬롯. 선택이다.
3. **Title** — heading. 무엇이 없는지 말한다.
4. **Description** — 선택. 다음에 무엇을 하면 되는지 말한다.
5. **Action** — 선택. 보통 Button 하나다.

#### Properties

| prop | 값 | 기본 | 뜻 |
| --- | --- | --- | --- |
| `title` | ReactNode | 필수 | 제목 |
| `description` | ReactNode | 없음 | 설명 |
| `graphic` | ReactNode | 없음 | 64px 그래픽 |
| `action` | ReactNode | 없음 | 행동 유도 |
| `headingLevel` | `2`–`6` | `2` | 제목의 heading 단계 |

`headingLevel`을 컴포넌트가 고정하지 않는 이유는 빈 상태가 놓이는 자리에 따라 문서 구조가 달라지기
때문이다. 섹션 안이면 `3`, 페이지 본문이면 `2`다.

#### Hierarchy와 variants

variant 축이 없다. 빈 상태의 강조는 시각이 아니라 **행동 유도의 유무**가 만든다 — 사용자가 지금
할 수 있는 것이 있으면 버튼을 주고, 없으면 사실만 말한다.

#### States

상태 축이 **없다.** 제품 9벌 중 hover·focus·disabled를 스스로 갖는 것이 0벌이고, 빈 상태는 대화형
요소가 아니다. 그 안의 행동 유도 버튼이 자기 상태를 갖는다.

#### Interaction and responsive behavior

- 폭은 부모가 정한다. 설명은 `44ch`로 제한된다 — 넓은 화면에서 한 줄로 늘어나면 눈이 되돌아오지
  못한다. `ch`라서 확대해도 줄당 글자 수가 유지된다.
- 세로 여백 80px은 부모가 짧으면 그대로 넘친다. 빈 상태를 넣는 영역은 최소 높이를 스스로 가져야
  한다 — 그것은 이 컴포넌트가 아니라 레이아웃의 계약이다.

#### Content

제품의 문구를 읽어 보면 어조가 하나로 모인다.

- **Title**은 "아직 …가 없습니다" 꼴이다. 마침표를 찍지 않는다.
- **Description**은 해요체 권유이며 마침표를 찍는다 — "첫 번째 영상을 만들어보세요."
- 검색·필터 결과가 없을 때는 **다른 문구다.** "해당하는 프로젝트가 없습니다 / 다른 검색어를
  시도해 보세요." 처음 만드는 것과 못 찾은 것은 다음 행동이 다르다.
- 제품에는 이 두 문구가 사전에 정의돼 있으나 **어떤 화면도 렌더하지 않는 죽은 문구**가 둘 있다
  (`archive.empty.cta`, `archive.emptyFilter`). 문구가 있는데 화면에 없는 것은 제품 부채이며 DS가
  고칠 문제가 아니다.
- 컴포넌트가 문구를 갖지 않는다. 제품의 노드캔버스 허브는 영상용 문구를 그대로 재사용해 캔버스
  화면에서 "첫 번째 영상을 만들어보세요"라고 말한다 — 문구를 컴포넌트에 고정하면 그런 일이 생긴다.

#### Accessibility

- 제목이 **heading**이다. `div`로 두면 스크린 리더가 지나쳐 "왜 아무것도 없는지"를 알 수 없다.
- **`aria-live`를 붙이지 않는다.** 빈 상태는 목록이 로드된 결과이고 로딩을 알리는 것은 이미 다른
  요소의 일이다. 여기에 live region을 두면 화면을 옮길 때마다 다시 읽힌다. 제품도 빈 상태에는
  live region을 두지 않는다(로딩 상태에만 있다).
- **그래픽은 `aria-hidden`이다.** 제목이 말하는 것을 반복할 뿐이다.

#### Specification

| 축 | 값 | 토큰 |
| --- | ---: | --- |
| 세로 여백 | 80px | — |
| 좌우 여백 | 16px | `space-layout-gutter` |
| 블록 간격 | 12px | `space-stack-md` |
| 액션 추가 간격 | 4px | `space-control-xs` |
| 그래픽 | 64px | `icon-size-xl` |
| 제목 | 20/600 | `typography-body-lg-semibold` |
| 설명 | 16/400 | `typography-body-md-regular` |
| 설명 최대 폭 | 44ch | — |
| 배경·테두리·반경 | 없음 | — |

세로 여백 80px에 토큰을 만들지 않은 이유는 **소비처가 여기 하나뿐**이기 때문이다.
[spacing-radius.md](../foundations/spacing-radius.md)가 "두 개 이상의 사용처"를 토큰 승격 조건으로
두고 있어 리터럴을 한 줄에 격리했다.

#### Effects

없다.

#### Implementation

- 그래픽 슬롯이 크기를 소유한다(`inline-size`/`block-size` 64px). 안에 들어오는 아이콘이 자기
  크기를 갖고 와도 슬롯을 채운다 — Icon 컴포넌트의 기본은 20px이라 그냥 넣으면 작게 나온다.
- 액션은 `margin-block-start`로 한 단계 더 떨어진다. 읽는 것과 누르는 것 사이의 경계다.

#### Known deviations

- **아홉 벌 중 어느 것과도 정확히 같지 않다.** 정본이 없으므로 "다르다"가 결함이 아니다. 두 홈이
  동의한 값을 골랐고, 각 축의 판정은
  [`product.measured.json`](../../migration/product.measured.json)에 있다.
- **오류 상태를 다루지 않는다.** 제품은 프로젝트 피커에서 "없음"과 "실패"를 같은 표현으로 합치고
  색을 하드코딩했다(`rgb(251 146 150 / 0.95)`). 그 둘을 가르는 것이 이 컴포넌트의 판단이며, 오류
  표현은 별도 컴포넌트가 소유해야 한다.
- **세로 여백이 리터럴이다.** 80px 소비처가 하나뿐이라 토큰으로 승격하지 않았다.
- **Figma는 액션의 추가 간격을 padding으로 만든다.** CSS는 액션에 `margin-block-start: 4px`를
  더해 앞 요소와 16px 떨어지는데, Figma auto-layout에는 자식별 간격이 없어 같은 4px을 Action
  프레임의 위쪽 padding으로 표현한다. 결과는 같고 표현이 다르다.
- **설명 폭이 Figma에서 근사다.** CSS는 `44ch`이고 Figma에 `ch` 단위가 없어 16px 기준 400px을 쓴다.

#### Acceptance tests

1. 여백·간격·그래픽 크기·타이포가 `components.measured.json`과 같다.
2. **배경·배경 이미지·테두리·반경·그림자가 모두 없다.**
3. 제목이 heading이고 `headingLevel`이 태그를 바꾼다.
4. 그래픽·설명·액션이 모두 선택이며 없으면 DOM에도 없다.
5. 그래픽이 `aria-hidden="true"`다.
6. root에 `aria-live`도 `role`도 없다.
7. 제목이 `foreground-primary`, 설명이 `foreground-secondary`다.

## Badge

- Source: design/components/badge.md
- Maturity: experimental

### Badge

한 조각의 상태나 분류를 라벨로 붙인다.

제품에 배지 계열 정의가 **65벌** 있고 공용 구현은 0이다. 기하가 흩어져 단일 정본이 없다 —
반경 7갈래(999·12·10·8·6·5·4), 세로 여백 7갈래(0·1·1.5·2·3·4·6).

**gap registry가 적은 "톤 4 + 상태 5"는 둘 다 틀렸다.**

- "톤 4"는 `InspectorPill`의 tone prop 네 갈래를 센 것인데, **네 톤 클래스의 선언이 바이트 단위로
  같다.** 축이 죽어 있다.
- "상태 5"는 하이라이트 히스토리 카드만 맞다. 그것을 복제한 비디오 에디터는 3개뿐이고, 앱 홈의
  4변형은 **네 색이 전부 `var(--gray-400)`로 같다.** 여기도 축이 죽어 있다.
- 제품 전체의 실제 톤 값은 최소 11종이다.

#### Availability

| Surface       | 상태           | 근거                                                          |
| ------------- | -------------- | -------------------------------------------------------------- |
| Web           | `partial`      | public export와 실브라우저 acceptance test 7건; visual regression과 제품 소비 증거 없음 |
| Figma         | `partial`      | component set 5 variant(Tone). parity 게이트가 Label을 자손으로 대조한다. publish는 DS-F-008 |
| Documentation | `done`         | 이 문서                                                        |
| Maturity      | `experimental` | 규범과 구현이 같은 변경 단위에서 처음 선다                     |

#### When to use

- 항목 하나의 **상태**를 옆에 붙일 때 — 완료, 실패, 처리 중.
- 항목의 **분류**를 한 단어로 표시할 때 — 공개 범위, 플랜, 종류.

쓰지 않는 자리.

- **누를 수 있어야 할 때.** 그것은 Button이거나 Chip이며 다른 컴포넌트다. 배지는 대화형이 아니다.
- **증감률과 개수.** 제품은 그것을 알약(999px)으로 그리고 상태 어휘를 갖지 않는다. 관리자 5벌과
  대시보드 6벌이 그 무리이며 **별도 컴포넌트**다. 여기 축으로 접지 않았다.
- 긴 설명. 배지는 한 줄로 잘린다.

#### API

```tsx
<Badge tone="success">완료</Badge>
<Badge tone="danger" icon={<IconXCircle />}>실패</Badge>
<Badge tone="warning" dot>처리 중</Badge>
<Badge>초안</Badge>
```

#### Anatomy

1. **Root** — `<span>`. 면·글자·반경을 소유한다.
2. **Icon** 또는 **Dot** — 선택. 라벨 앞에 온다. 크기가 글자를 따라간다.
3. **Label** — 자식 텍스트. 한 줄로 잘린다.

#### Properties

| prop | 값 | 기본 | 뜻 |
| --- | --- | --- | --- |
| `tone` | `neutral` \| `success` \| `warning` \| `danger` \| `info` | `neutral` | 의미 축 |
| `icon` | ReactNode | 없음 | 라벨 앞 아이콘(`1em`) |
| `dot` | boolean | `false` | 라벨 앞 점(`0.5em`). `icon`이 있으면 무시된다 |

**기본이 `neutral`인 이유.** 상태가 없는 배지가 다수다(분류·개수 라벨). 색을 기본값으로 두면 아무
뜻도 없는 곳에 의미가 붙는다.

#### Hierarchy와 variants

`tone`이 유일한 축이다. 제품의 상태 어휘는 최소 17벌이고 화면마다 다른데, 그것을 그대로 옮기면
DS가 제품의 도메인을 떠안는다. **네 상태 + 중립으로 접고**, 어느 도메인 값이 어느 tone인지는
호출부가 정한다.

크기 축이 없다. 배지는 이미 가장 작은 단위이고, 제품의 높이 분포(19·22·26px)는 크기 단계가 아니라
서로 다른 무리의 값이다.

#### States

상태 축이 **없다.** 배지는 대화형이 아니라 hover·focus·press를 갖지 않는다. `tone`이 variant
축이고 각 tone은 하나의 표현만 갖는다.

#### Interaction and responsive behavior

- 폭은 라벨이 정한다. 자리가 모자라면 말줄임으로 잘리고 **높이는 유지된다** — 배지가 두 줄이 되면
  그것이 놓인 행의 높이가 흔들린다.
- 44px hit target 규범의 대상이 **아니다.** 그것은 누를 수 있는 것의 계약이다.

#### Content

- 라벨은 **한 단어 또는 짧은 명사구**다. "완료"이지 "처리가 완료되었습니다"가 아니다.
- **색이 유일한 신호가 되지 않게 라벨이 상태를 말해야 한다.** 초록 배지에 "완료"라고 쓰는 것이지
  초록만으로 완료를 뜻하게 하지 않는다. 색각 이상에서 tone은 전달되지 않는다.
- 같은 상태를 화면마다 다르게 부르지 않는다. 제품은 "완료"를 done·completed·finished로 부르는
  자리가 갈려 있다.

#### Accessibility

- **아이콘과 점은 `aria-hidden`이다.** 라벨이 말하는 것을 반복하는 장식이다.
- 배지에 `role`을 주지 않는다. 상태가 **바뀌는 것을 알려야 한다면** 그것은 배지가 아니라 그
  배지를 감싼 live region의 일이다.
- tone은 색만 바꾸므로 위 Content의 규칙이 접근성 계약의 일부다.

#### Specification

| 축 | 값 | 토큰 |
| --- | ---: | --- |
| 높이 | 26px | (여백 4+4 + 행간 18) |
| 세로 여백 | 4px | `space-control-xs` |
| 좌우 여백 | 8px | `space-control-sm` |
| 아이콘·점 간격 | 4px | `space-control-xs` |
| 반경 | 8px | `radius-control-sm` |
| 타이포 | 12/1.5 | `typography-caption-regular` |
| 아이콘 | `1em` | — |
| 점 | `0.5em` | — |
| 테두리 | 없음 | — |

**이 기하를 고른 이유.** 상태 배지의 대표는 하이라이트 히스토리 카드의 것이고
(`highlightSceneStyles.ts:760`), 그 여백 4/8px과 반경 8px이 **기존 토큰에 정확히 맞는다.**
gap registry가 "가장 복잡한" 것으로 지목한 배지이며 비디오 에디터가 그것을 복제해 두 벌이 같다.
새 토큰이 하나도 필요하지 않았다.

아이콘을 `1em`으로 둔 이유는 [iconography.md](../foundations/iconography.md)가 12px을 "4px 격자
밖"이라며 거부해 두었기 때문이다. 글자를 따라가게 하면 그 판정을 다시 열지 않아도 된다.

#### Effects

없다.

#### Implementation

- 면과 글자를 짝지은 `color-status-*` 토큰을 쓴다. 네 쌍은 `contrastPairs`에 `minimum 4.5`로
  선언돼 있고 실측 대비는 9.09~11.98이다.
- 테두리 축을 열지 않는다. tone마다 border 토큰이 필요한데 `color-border-danger` 하나만 있고
  나머지 셋에는 대응이 없다.

#### Known deviations

- **면을 칠하는 방식이 제품과 다르다.** 제품의 상태 배지는 다섯 상태의 **면이 전부 `gray-800`으로
  같고 글자색만 갈린다.** 게다가 light/dark 값이 같아 밝은 테마에서도 어두운 배지가 뜬다. 여기서는
  면과 글자를 짝지어, 색각 이상에서 글자색 하나에 기대지 않고 두 값이 게이트에 묶이게 했다.
- **배지 면이 페이지 면과 명도로는 거의 구별되지 않는다.** 실측 대비는 light에서
  `background-surface` 대비 1.03~1.14, dark에서 1.02~1.23이다.
  [color-theme.md](../foundations/color-theme.md)가 의미 있는 비텍스트 그래픽에 3:1을 요구하지만,
  **배지의 의미를 나르는 것은 면이 아니라 라벨(11:1)**이고 면은 색상(hue) 차이로 보인다. 명도
  대비를 3:1로 올리면 톤이 배지가 아니라 경고처럼 보인다. 수용하고 여기 적는다.
- **`contrastPairs`에 면 대 면 축이 아예 없다.** 선언된 12쌍은 전부 글자 대 면이다. 위 수치는
  게이트가 계산하지 않으며, 그 결손은 이 컴포넌트가 만든 것이 아니라 드러낸 것이다.
- **알약 무리를 다루지 않는다.** 증감·개수 칩은 별도 컴포넌트이며 아직 없다.

#### Acceptance tests

1. 높이·여백·간격·반경·타이포가 `components.measured.json`과 같다.
2. 다섯 tone의 면과 글자가 states 표와 같고, **다섯이 서로 다른 색을 만든다.**
3. `<span>`이며 tabindex·role이 없고 포인터 커서가 아니다.
4. 아이콘과 점이 `aria-hidden`이고 크기가 각각 `1em`·`0.5em`이며 점 색이 글자를 따라간다.
5. `icon`과 `dot`을 함께 주면 점이 렌더되지 않는다.
6. 라벨이 길어도 한 줄로 잘리고 높이가 유지된다.
7. 테두리 두께가 0이다.

## Spinner

- Source: design/components/spinner.md
- Maturity: experimental

### Spinner

끝나는 시점을 모르는 작업이 진행 중임을 알린다.

제품의 로딩 표현은 약 **62벌**이다 — 회전 링 22, 스켈레톤 15, 텍스트 쉬머 11, 진행률 5, 그 외.
gap registry가 적은 "레시피 5종 · Skeleton 0종"은 둘 다 틀렸다. 회전 keyframe 이름은 **18개인데
본문은 전부 `to { rotate: 360deg }` 한 종류**다.

**다만 이번에는 정본이 뚜렷하다.** 공용 `LoadingSpinner`가 있고 그 recipe가 700ms · linear로
[DS-D-0016](../governance/decisions/DS-D-0016-loop-motion.md)이 세운 `motion-loop`와 정확히 같다.
링 구조도 그대로 옮겼다.

#### Availability

| Surface       | 상태           | 근거                                                          |
| ------------- | -------------- | -------------------------------------------------------------- |
| Web           | `partial`      | public export와 실브라우저 acceptance test 8건이 두 motion context에서 각각 돈다 |
| Figma         | `partial`      | component set 2 variant(Size). parity 게이트가 Track·Arc를 자손으로 대조한다. publish는 DS-F-008 |
| Documentation | `done`         | 이 문서                                                        |
| Maturity      | `experimental` | 규범과 구현이 같은 변경 단위에서 처음 선다                     |

#### When to use

- 끝나는 시점을 **모르는** 작업 — 서버 응답 대기, 업로드 시작 전 준비.
- 버튼이나 행 안에서 그 자리의 작업이 진행 중임을 표시할 때.

쓰지 않는 자리.

- **진행률을 아는 작업.** 회전 주기는 진행률이 아니라 한 바퀴의 시간이며 얼마나 남았는지에 대해
  아무것도 말하지 않는다([motion.md](../foundations/motion.md)의 Loop 절). 아는 값이 있으면
  determinate 표시를 쓴다.
- **자리가 정해진 콘텐츠가 곧 올 때.** 그것은 스켈레톤이며 다른 컴포넌트다.

#### API

```tsx
<Spinner label="불러오는 중" />
<Spinner size="sm" label="저장 중" />

{/* 부모가 이미 알리고 있을 때는 장식이다 */}
<span aria-busy="true">생성 중 <Spinner /></span>
```

#### Anatomy

1. **Root** — `<span>`. 색을 물려받고 접근성 역할을 소유한다.
2. **Ring** — 회전하는 원. 링이 **둘**이다.
   - 트랙 — 네 변이 모두 칠해진 흐린 원
   - 진행 — 위쪽 한 조각만 칠해진 원

**링을 root와 분리한 이유.** root가 회전하면 그 안에 넣은 텍스트나 슬롯이 함께 돈다.

**트랙이 있는 이유.** 없으면 회전하는 조각이 어디를 도는지 보이지 않아 "무언가 깜빡인다"로 읽힌다.
이전 DS의 spinner는 트랙 없이 위쪽 테두리만 비웠고, 그것은 제품과 다른 표현이었으며 편차로 선언된
적도 없었다.

#### Properties

| prop | 값 | 기본 | 뜻 |
| --- | --- | --- | --- |
| `size` | `md` \| `sm` | `md` | 16px / 12px |
| `label` | string | 없음 | 읽히는 이름. **있으면 알리고 없으면 숨는다** |

**`label`에 기본값을 두지 않는다.** 제품에는 `aria-label="Loading"`이 하드코딩된 자리가 있는데,
DS가 기본 문자열을 배포하면 그 하드코딩을 시스템 전체로 퍼뜨리는 셈이 된다. 문구는 i18n을 가진
호출부가 소유한다.

#### Hierarchy와 variants

tone 축이 없다. **색을 물려받는다** — 버튼 안에서는 버튼 글자색, 본문에서는 본문 색이 된다.
spinner에 semantic 색을 고정하면 놓이는 자리마다 어긋난다.

#### States

상태 축이 **없다.** 대화형이 아니다.

#### Interaction and responsive behavior

- 회전은 700ms 등속이다. 가감속이 붙으면 회전이 맥박처럼 뛰어 "진행 중"이 아니라 "잘못됨"으로
  읽힌다. `linear`는 제품의 회전 22벌이 **전수 일치하는 유일한 축**이다.
- **`prefers-reduced-motion`에서 회전이 멈춘다.** 짧아지는 것이 아니라 사라진다 — `0ms`짜리
  애니메이션을 무한 반복하는 것은 성립하지 않는다. 그때도 진행 중이라는 의미는 `role="status"`와
  `aria-busy`가 유지한다.

#### Content

- `label`은 **무엇이 진행 중인지** 말한다. "로딩"이 아니라 "불러오는 중", "저장 중".
- 문구 끝에 말줄임표를 붙이지 않는다. 스크린 리더가 점을 읽는다.

#### Accessibility

- `label`이 있으면 `role="status"` · `aria-live="polite"` · `aria-busy="true"` · `aria-label`.
- `label`이 없으면 `aria-hidden="true"`. 라벨을 가진 부모가 이미 진행을 알리고 있을 때 쓴다 —
  그 자리에서 spinner가 또 알리면 스크린 리더가 같은 사실을 두 번 읽는다.
- **reduced-motion에서 회전이 멈춰도 위 두 계약은 그대로다.** 그것이 loop의 reduce 대체다.

#### Specification

| 축 | md | sm | 토큰 |
| --- | ---: | ---: | --- |
| 지름 | 16px | 12px | — |
| 링 두께 | 2px | 1px | `border-width-ring` / 그 절반 |
| 주기 | 700ms | 700ms | `motion-loop` |
| easing | linear | linear | `motion-loop` |
| 트랙 | 현재 색 22% | 같음 | — |
| 진행 | 현재 색 | 같음 | — |

**지름을 토큰으로 만들지 않은 이유**는 두 값이 이 컴포넌트에만 있기 때문이다.
[spacing-radius.md](../foundations/spacing-radius.md)가 "두 개 이상의 사용처"를 승격 조건으로 둔다.
`icon-size-sm`이 16px이지만 spinner는 아이콘이 아니라 값이 우연히 같을 뿐이며, 한쪽이 움직일 때
다른 쪽이 따라갈 이유가 없다.

**sm의 링을 `calc(ring / 2)`로 적은 이유.** 12px 원에 2px 링을 두르면 가운데가 거의 남지 않는다.
리터럴 1px 대신 관계로 적으면 `border-width-ring`이 움직일 때 함께 따라온다.

#### Effects

없다.

#### Implementation

- 회전 keyframe은 `base.css`의 **공용 `kds-spin` 하나**다. Button·Menu·Spinner가 같은 것을
  가리킨다. 제품이 이름 18개에 본문 1종을 가진 것과 같은 중복이 이 저장소에도 둘 있었고,
  이 컴포넌트를 세우면서 합쳤다.
- `transform: rotate()`가 아니라 개별 속성 `rotate`다. motion.md의 Loop 절이 그것을 허용
  property로 선언했으며 `scale`·`translate`와 합성된다.
- 트랙 색은 `color-mix(in srgb, currentcolor 22%, transparent)`다. semantic 색 토큰으로 표현되지
  않는다 — `currentColor`에 달려 있고 그것은 놓이는 자리마다 다르다.

#### Known deviations

- **크기 토큰이 없다.** 위 Specification의 사유대로 승격 조건을 만족하지 않는다.
- **determinate 진행률을 다루지 않는다.** 제품의 진행률 표시 2벌은 두께·색·전환이 셋 다 다르고,
  `role="progressbar"`는 저장소 전체에 **1곳**뿐이며 `<progress>` 요소는 **0곳**이다. 별도
  컴포넌트이며 아직 없다.
- **스켈레톤과 텍스트 쉬머를 다루지 않는다.** 제품에 각각 15벌·11벌 있다. 같은 loop lifecycle을
  쓰되 축이 다르다.
- **Figma는 링을 채운 arc 밴드로 그린다.** CSS는 두 겹의 `border`인데 Figma에는 "테두리 한 변만
  칠하기"가 없다. stroke로 그리면 `innerRadius: 0`인 파이 조각의 외곽선(중심으로 가는 반지름 두
  줄)이 함께 그려진다 — 실측으로 확인하고 fill + `innerRadius`로 바꿨다. 결과는 같고 표현이 다르다.
- **Figma는 `currentColor`를 표현하지 못한다.** 문서용으로 `foreground-primary`를 쓴다. 실제로는
  놓이는 자리의 글자색이 된다.
- **제품의 공용 `LoadingSpinner`에는 `prefers-reduced-motion` 처리가 없다.** 비공용 정의 중 일부는
  갖고 있다. 공용을 그대로 승격하면 그 결함이 시스템 전체로 퍼지므로 여기서는 넣었다.

#### Acceptance tests

1. md/sm의 지름과 링 두께가 `components.measured.json`과 같고, 폭과 높이가 같다(정원).
2. 링이 둘이며 트랙은 네 변이 칠해지고 진행은 위쪽 한 조각만 칠해진다.
3. 트랙 색이 진행 색과 다르다(같은 색의 흐린 것이다).
4. 색을 물려받는다 — 부모의 `color`가 진행 색이 된다.
5. `animation-duration`·`timing-function`이 `motion-loop`에서 오고 `animation-name`이 공용
   `kds-spin`이다.
6. reduced-motion에서 `animation-iteration-count`가 `1`이고, 그때도 `role="status"`와
   `aria-busy="true"`가 그대로다.
7. `label`이 없으면 `aria-hidden="true"`이고 role·live·busy가 모두 없다.
8. 기본 라벨 문자열을 배포하지 않는다.

## Checkbox

- Source: design/components/checkbox.md
- Maturity: experimental

### Checkbox

독립적인 켜짐/꺼짐을 고른다. 여럿을 동시에 고를 수 있다.

**제품에 공용 정본이 있는데 21벌 중 2벌만 쓴다.** `globals.css:990`의 `.app-native-checkbox`
(20×20 · `accent-color`)이고, 이유를 제품이 스스로 적어 두었다 — 그 클래스가 **cascade layer
밖**이라 `@layer utilities` 안의 어떤 유틸리티도 이길 수 없어서, 색 하나를 바꾸려는 소비처가
클래스를 떼고 선언을 통째로 베껴야 했다. 갈라지는 축은
[`product.measured.json`](../../migration/product.measured.json)이 사유와 함께 갖는다.

#### Availability

| Surface       | 상태           | 근거                                                                                 |
| ------------- | -------------- | ------------------------------------------------------------------------------------ |
| Web           | `partial`      | public export와 실브라우저 acceptance test 14건이 두 motion context에서 각각 돈다; visual regression, Figma component와 제품 소비 증거 없음 |
| Figma         | `not-ready`    | component set이 아직 없다. DS-F-006-checkbox가 소유한다                              |
| Documentation | `done`         | 이 문서                                                                              |
| Maturity      | `experimental` | 규범과 구현이 같은 변경 단위에서 처음 선다                                           |

#### When to use

- 서로 **독립적인** 켜짐/꺼짐 — 약관 동의, 옵션 켜기, 목록의 다중 선택.
- 목록 머리의 **일괄 선택.** 그 자리에서 `indeterminate`가 "일부만 골랐다"를 말한다.

쓰지 않는 자리.

- 서로 배타적인 값 중 하나 고르기. 그것은 Segmented Control 또는 radio다.
- 즉시 적용되는 설정 켜기/끄기. 그것은 Switch이며 아직 카탈로그에 없다. 체크박스는 폼을
  **제출해야** 반영된다는 뜻을 갖는다.
- 필터 알약. 그것은 다중 선택이더라도 Badge/Chip의 모양을 갖는다.

#### API

```tsx
<Checkbox label="약관에 동의합니다" checked={agreed} onCheckedChange={setAgreed} />

<Checkbox
  label={`전체 선택 (${selected.length}/${items.length})`}
  checked={selected.length === items.length}
  indeterminate={selected.length > 0 && selected.length < items.length}
  onCheckedChange={selectAll}
/>
```

#### Anatomy

1. **Row** — `<label>`. 상자와 라벨을 담고 클릭 영역을 소유한다.
2. **Control** — `<input type="checkbox">`. **상자가 곧 입력이다.**
3. **Mark** — 컨트롤의 `::before`. 체크와 부분 선택 막대가 이 자리를 나눠 쓴다.
4. **Label** — 상자 옆 글자.

**입력을 숨기고 형제를 그리지 않는다.** `appearance: none`이면 입력 자신을 칠할 수 있고, 숨기면
라벨 연결과 포커스가 두 곳으로 갈라진다. 제품의 signup 계열 6벌이 숨기는 구조인데 그 대가로
`:focus-visible`을 형제 선택자로 옮겨야 했다.

#### Properties

| prop | 값 | 기본 | 뜻 |
| --- | --- | --- | --- |
| `label` | ReactNode | 없음 | 상자 옆 글자. 없으면 `aria-label`이 필수다 |
| `checked` | boolean | 없음 | 주면 controlled가 된다 |
| `defaultChecked` | boolean | 없음 | 비제어 초기값 |
| `indeterminate` | boolean | `false` | 부분 선택. 아래 States |
| `onCheckedChange` | `(checked: boolean) => void` | 없음 | 값이 바뀔 때 |

나머지는 `<input>`의 네이티브 속성을 그대로 받는다.

**크기 축이 없다.** 제품 정본이 20px이고 나머지 값(14px · 브라우저 기본)은 서로 합의하지 않으며
두 번째 소비처도 없다. 필요해지면 그때 추가한다.

#### Hierarchy와 variants

variant 축이 없다. 체크박스는 강조 단계를 갖지 않는다.

#### States

| state | 표현 |
| --- | --- |
| Default | 면 `color-background-surface`, 테두리 `color-border-strong`, 표시 없음 |
| Checked | 면·테두리 `color-action-primary`, 체크 표시 `color-foreground-inverse` |
| Indeterminate | 면·테두리 `color-action-primary`, **가로 막대** `color-foreground-inverse` |
| Disabled | 면 `color-background-inset`, 테두리 `color-border-subtle`, 표시 `color-foreground-disabled` |
| Focus | 컨트롤이 공유 링을 받는다 |

**Indeterminate가 Checked를 이긴다.** 네이티브에서 두 상태는 동시에 참일 수 있고, 그때 화면은
"일부"를 보여야 한다 — 부분 선택은 선택이 아니다. 두 규칙이 소스 순서로 갈리므로 CSS가 그 승패를
명시적으로 고정한다.

**hover에서 아무것도 바꾸지 않는다.** 상자가 이미 테두리로 자기를 알리고, 라벨이 커서를 바꾼다.

#### Interaction and responsive behavior

- 라벨을 눌러도 값이 바뀐다. 상자가 20px이라 **라벨이 클릭 영역의 대부분을 담당한다.**
- 연결은 `id`가 아니라 `<label>`의 포함 관계가 만든다. 같은 화면에 여럿이 있어도 겹치지 않는다.
- 라벨이 여러 줄이면 상자는 **첫 줄 옆에** 남는다.
- Space가 값을 바꾼다. Enter는 바꾸지 않는다 — 폼 안에서 Enter는 제출이다.

#### Content

- 라벨은 **켰을 때 참이 되는 문장**이다. "알림을 받지 않음"이 아니라 "알림 받기"다. 부정형은
  끄는 동작이 이중 부정이 된다.
- 일괄 선택 라벨에는 개수를 함께 둔다. "전체 선택 (2/5)"가 `indeterminate`의 뜻을 글자로도 말한다.

#### Accessibility

- **네이티브 `<input type="checkbox">`다.** Space, `:indeterminate` 의사 클래스, 폼 제출,
  forced-colors가 전부 브라우저의 것이다.
- `indeterminate`는 **콘텐츠 속성이 없는 DOM 프로퍼티라** JSX로 넘어가지 않는다. 컴포넌트가 매
  렌더 뒤에 ref로 맞추고, `aria-checked="mixed"`를 함께 준다 — 프로퍼티만으로는 보조기술이
  "일부"를 읽지 못하는 경우가 있다.
- 라벨이 없으면 `aria-label`이 필수다.
- forced-colors에서 면 색이 시스템 색으로 치환돼 표시가 배경과 같아지므로 `CanvasText`로 되돌린다.
- **부분 선택을 색으로만 알리지 않는다.** 막대와 체크는 모양이 다르고, 일괄 선택 라벨의 개수가
  같은 사실을 글자로도 말한다.

#### Specification

| 축 | 값 | 토큰 |
| --- | ---: | --- |
| 상자 | 20×20px | 리터럴 — 제품 정본 채택 |
| 테두리 | 0.5px | `border-width-hairline` |
| 반경 | 8px | `radius-control-sm` |
| 상자–라벨 간격 | 8px | `space-control-sm` |
| 체크 표시 | 5×9px, 2px 획 | 리터럴 |
| 부분 선택 막대 | 10×2px | 리터럴 |
| 라벨 타이포 | 14/1.5 | `typography-body-sm-regular` |

상자 20px은 제품 정본 `.app-native-checkbox`의 값이다. 리터럴로 남긴 이유는 소비처가 이 컴포넌트
하나뿐이기 때문이며 Spinner·Slider와 같은 판정이다.

#### Effects

없다. 그림자도 흐림도 쓰지 않는다.

#### Implementation

- `accent-color`를 쓰지 않는다. 그것은 면 색 하나만 주고 **체크 표시의 굵기·반경·포커스 링·부분
  선택 막대를 전부 브라우저가 정한다** — 테마와 플랫폼마다 다르다. 제품의 signup 계열 6벌이 이미
  직접 그리는 것도 같은 이유다.
- 표시는 `::before` 하나가 두 상태를 나눠 쓴다. 회전한 테두리로 그리는 이유는 CSS package가
  아이콘 자산을 소비하지 않기 때문이다([DS-D-0008](../governance/decisions/DS-D-0008-icon-source.md)).
- 제품의 전역 클래스는 **cascade layer 밖**에 있어 소비처가 이길 수 없었다. 이 저장소의 컴포넌트
  CSS는 전부 `@layer`에 들어가므로 같은 함정이 없다.

#### Known deviations

- **선택하지 않은 상자의 테두리 대비가 WCAG 2.2 SC 1.4.11(3:1)에 미달한다.** 상자 면 대비 실측은
  `color-border-control` 1.27/1.63 · `color-border-default` 1.38/2.93 ·
  **`color-border-strong` 2.52/4.61**(라이트/다크)이고, **테두리 토큰 셋 중 어느 것도 라이트에서
  3:1을 넘지 못한다.** 가장 가까운 `border-strong`을 골랐고 라이트의 2.52는 남는다. 이 실측은
  인계서 (2b) 컨트롤 테두리 정본 판정의 입력이며, 해소하려면 새 값이 필요하므로 owner 판정이다.
  선택된 상태의 면은 3.12/4.90으로 통과한다.
- **`color-border-strong`의 첫 소비처가 여기다.** 인계서 (1a)가 "소비처 0이고 이름이 가리키는 것이
  그 이름을 안 쓴다"고 분류한 넷 중 하나인데, 이제 이름이 뜻과 맞는 소비처가 생겼다 — 경계가
  반드시 보여야 하는 자리다. 그 토큰의 처분 판정을 다시 해야 한다.
- **크기 축이 없다.** 좁은 목록 행에서 20px이 클 수 있으나 두 번째 소비처가 확인되기 전에는
  만들지 않는다.
- **Switch가 없다.** 즉시 적용되는 설정에는 다른 컴포넌트가 필요하다.
- **자동 접근성 검사가 1.4.11을 보지 않는다.** axe의 `color-contrast`는 텍스트만 본다 — 위 수치는
  손으로 계산했고 게이트가 재지 않는다.

#### Acceptance tests

1. 상자 크기·반경·테두리 토큰·간격·라벨 타이포가 `components.measured.json`과 같다.
2. 체크 표시의 폭·높이·획 두께가 계약과 같고 위·왼 변이 비어 있다.
3. 부분 선택 막대의 폭·높이가 계약과 같고 **체크와 폭이 다르다.**
4. `checked`와 `indeterminate`가 동시에 참이면 **막대가 이기고** 체크의 테두리가 남지 않는다.
5. 선택하지 않았을 때는 표시가 보이지 않는다.
6. Default·Checked·Disabled의 면·테두리·라벨 색이 states 표와 같다.
7. 라벨을 눌러도 값이 바뀌고 콜백이 그 값을 받는다.
8. Space가 값을 켜고 끈다.
9. controlled일 때 호출부의 값이 이긴다.
10. `indeterminate`면 `aria-checked="mixed"`다.
11. `disabled`면 클릭과 키보드로 값이 바뀌지 않고 콜백이 불리지 않는다.
12. 포커스 링이 **키보드에서만** 나타나고 두께가 `border-width-ring`이다.
13. 라벨 있음·선택됨·부분 선택·라벨 없음 넷 모두 자동 접근성 검사에 위반이 없다.

## Selectable List Row

- Source: design/components/selectable-list-row.md
- Maturity: experimental

### Selectable List Row

master-detail의 좌측 열에서 하나를 고른다.

제품 실측은 **3벌**이고 [gap registry](../../migration/figma-gap-registry.md)의 수치가 **처음으로
맞았다**(하이라이트 2 · 에디터 1). 셋이 합의하는 것은 골격이다 — 가로 flex 행, 선행 슬롯, 글자
묶음, 커서 포인터, hover 면, **전환 140ms ease.** 갈라지는 것은 선택을 무엇이 소유하느냐다.

#### Availability

| Surface       | 상태           | 근거                                                                                 |
| ------------- | -------------- | ------------------------------------------------------------------------------------ |
| Web           | `partial`      | public export와 실브라우저 acceptance test 12건이 두 motion context에서 각각 돈다; visual regression, Figma component와 제품 소비 증거 없음 |
| Figma         | `partial`      | component set 3 variant(State). parity 게이트가 Marker·Text·Title·Meta·Media·Trailing을 자손으로 대조하며 raw fill 0이다. publish는 DS-F-008 |
| Documentation | `done`         | 이 문서                                                                              |
| Maturity      | `experimental` | 규범과 구현이 같은 변경 단위에서 처음 선다                                           |

#### When to use

- **하나를 고르는** 목록의 행 — 클립 리뷰, 소스 선택, 버전 목록. 고른 것의 상세가 옆이나 아래에 뜬다.
- 행 전체가 클릭 대상이고, 그 안에 다른 버튼이 없을 때.

쓰지 않는 자리.

- **여럿을 고르는 목록.** 그때 선택은 행이 아니라 [Checkbox](../components/checkbox.md)가 갖는다. 행을 버튼으로
  만들면서 안에 체크박스를 넣으면 **컨트롤이 중첩된다.** 제품의 에디터 소스 목록이 그 형태이고,
  그것은 이 컴포넌트가 아니라 Checkbox + 행 레이아웃이다.
- 메뉴 항목. 그것은 [Menu / Popover](../components/menu-popover.md)이며 열렸다 닫히는 표면 안에 있다.
- 앱 셸 사이드바. 그것은 [Sidebar Nav Item](../components/app-shell-parts.md)이며 목적지로 이동한다.
- 카드 격자. 그것은 [Project Card](../components/project-card.md)다.
- 행 안에 버튼이 여럿 필요할 때. 행을 버튼으로 만들 수 없으므로 다른 구조가 필요하다.

#### API

```tsx
{clips.map((clip, index) => (
  <SelectableListRow
    key={clip.id}
    selected={index === activeIndex}
    media={<img src={clip.thumbnail} alt="" width={96} height={54} />}
    title={clip.name}
    meta={`${clip.start} · ${clip.duration}초`}
    trailing={<span>{index + 1}</span>}
    onClick={() => setActiveIndex(index)}
  />
))}
```

#### Anatomy

1. **Row** — `<button type="button">`. **행 전체가 컨트롤이다.**
2. **Media** — 선행 슬롯. 썸네일이 들어가고 크기는 호출부가 정한다.
3. **Text** — 제목과 보조 문구를 세로로 담는다.
4. **Trailing** — 후행 슬롯. 시간·개수 같은 짧은 값.
5. **Marker** — 선택된 행의 선행 표식.

#### Properties

| prop | 값 | 기본 | 뜻 |
| --- | --- | --- | --- |
| `selected` | boolean | `false` | 선택 여부. `aria-current="true"`가 된다 |
| `title` | ReactNode | **필수** | 제목 줄. 한 줄로 잘린다 |
| `meta` | ReactNode | 없음 | 제목 아래 보조 문구. 한 줄로 잘린다 |
| `media` | ReactNode | 없음 | 선행 슬롯 |
| `trailing` | ReactNode | 없음 | 후행 슬롯. **버튼을 넣지 않는다** |
| `disabled` | boolean | `false` | 비활성 |

나머지는 `<button>`의 네이티브 속성을 그대로 받는다. `title`은 HTML 전역 속성과 이름이 겹치므로
행의 제목 쪽 뜻으로 덮어썼다.

**크기 축이 없다.** 행의 높이는 내용이 정한다 — 썸네일이 96px이면 96px 줄이고 글자만 있으면
글자 줄이다. 제품 3벌도 고정 높이를 갖지 않는다.

#### States

| state | 표현 |
| --- | --- |
| Default | 면 없음, 전경 `color-foreground-secondary` |
| Hover | 면 `color-action-ghost-hover`, 전경 `color-foreground-primary` |
| Selected | 면 `color-background-inset` **+ 3px 선행 표식** `color-action-primary`, 전경 `color-foreground-primary` |
| Disabled | 전경 `color-foreground-disabled`, hover가 면을 칠하지 않는다 |
| Focus | 행이 공유 링을 받는다 |

**선택된 행에서도 보조 문구는 `color-foreground-secondary`로 남는다.** 둘 다 primary가 되면
제목과 보조의 위계가 사라진다.

#### Interaction and responsive behavior

- 제목·보조 문구·후행 슬롯 어디를 눌러도 행이 받는다. 행 자체가 버튼이기 때문이다.
- 목록을 **Tab이 훑는다.** 방향키 roving을 흉내 내지 않는다 — 그것은 `listbox`의 계약이고
  이 컴포넌트는 버튼 목록이다. `listbox`가 필요하면 별도 컴포넌트다.
- 제목과 보조 문구는 **줄바꿈이 아니라 말줄임**으로 줄어든다. 행 높이가 항목마다 달라지면
  목록이 튄다.
- 폭은 호출부가 정한다. 행은 `inline-size: 100%`다.

#### Content

- 제목은 그 항목을 **구별하는 것**이다. 순번이 아니라 이름이다.
- 보조 문구에는 시각·길이처럼 **비교에 쓰는 값**을 둔다. 설명 문장을 넣지 않는다 — 잘린다.
- 후행 슬롯은 한두 글자다. 그보다 길면 보조 문구로 내린다.

#### Accessibility

- **선택을 `aria-current`가 소유한다.** [Sidebar Nav Item](../components/app-shell-parts.md)과 같은 판정이다 —
  시각 전용 속성을 두면 화면에는 선택으로 보이는데 보조기술에는 아무것도 전달되지 않는다.
- **선택을 면 하나로 전달하지 않는다.** 아래 Implementation의 실측을 보라.
- 썸네일은 장식이므로 `alt=""`가 기본이다. 썸네일에만 있는 정보가 있으면 제목이 그것을 말해야 한다.
- forced-colors에서 면과 표식이 모두 시스템 색으로 치환되므로 테두리로 선택을 다시 세운다.
- 행이 버튼이므로 Enter와 Space가 모두 실행한다. 네이티브의 동작이다.

#### Specification

| 축 | 값 | 토큰 |
| --- | ---: | --- |
| 안쪽 여백 | 8px | `space-control-sm` |
| 슬롯 간격 | 8px | `space-control-sm` |
| 반경 | 10px | `radius-overlay-item` |
| 글자 묶음 간격 | 4px | `space-stack-xs` |
| 선택 표식 | 3px | 리터럴 |
| 제목 타이포 | 14/1.5 | `typography-body-sm-medium` |
| 보조 타이포 | 12/1.5 | `typography-caption-regular` |
| 미디어 반경 | 8px | `radius-control-sm` |

**기하는 제품 값을 그대로 옮기지 않았다.** 제품의 gap 10px과 반경 14px에 맞는 semantic 토큰이
없고, 새 토큰은 token source를 바꿔 Figma 재적용이 따라온다. 대신 **DS에 이미 있는 선택 가능한
행**인 Sidebar Nav Item의 값(`space-control-sm` · `radius-overlay-item` · `body-sm-medium`)을
따랐다 — 같은 성질의 두 컴포넌트가 다른 기하를 갖지 않게 하는 것이 더 중요하다.

#### Effects

없다. 그림자도 흐림도 쓰지 않는다.

#### Implementation

**선택 면 하나에 기대면 다크에서 사라진다.** Sidebar Nav Item은 `aria-current` +
`color-background-inset`만으로 선택을 표현하는데, 그것이 성립하는 이유는 **사이드바가 캔버스 위에
있기 때문**이다. 다크에서 `background-inset`은 `surface`·`menu`·`overlay`와 **같은 색**이고,
목록은 표면 위에도 놓인다.

실측(2026-08-18, 표면 위):

| 테마 | 표면 | 선택 면 | 구분되는가 |
| --- | --- | --- | --- |
| light | `#fafafa` | `#eaebee` | 예 |
| dark | `#313644` | `#313644` | **아니오** |

그래서 3px 선행 표식을 함께 그린다. 색 하나로 상태를 전달하지 않는 것은 그 자체로도 맞다.
테스트가 두 테마에서 표식의 존재와 색을 각각 확인한다.

#### Known deviations

- **`Sidebar Nav Item`에 같은 위험이 남아 있다.** 그 컴포넌트는 면만으로 선택을 표현하며, 앱 셸
  사이드바가 캔버스 위에 있는 동안에만 성립한다. 표면 위에 놓이는 배치가 생기면 선택이 사라진다.
- **여럿 고르기를 다루지 않는다.** 제품 3벌 중 1벌(에디터 소스 목록)이 그 형태이고 그것은
  Checkbox가 소유한다.
- **`listbox`가 아니다.** 방향키 roving과 typeahead가 없다. 목록이 길어져 Tab이 부담이 되면
  `listbox` 계약을 갖는 별도 컴포넌트가 필요하다.
- **제품의 반응형 전환을 옮기지 않았다.** 하이라이트의 행은 900px 이하에서 220px 세로 카드로
  바뀌는데, 그것은 행이 아니라 **다른 컴포넌트로의 전환**이라 패턴이 소유할 문제다.
- **선택 표식 3px에 토큰이 없다.** 소비처가 하나뿐이라 승격하지 않았다.
- **Figma의 State는 코드에 없는 축이다.** 코드에서 `selected`는 boolean prop이고 `disabled`는
  `<button>`의 네이티브 속성인데, Figma에는 boolean 상태의 시각 표현이 없어 variant로 둔다.
  parity 계약이 그 사유와 함께 `figmaOnlyProperties`로 선언한다.

#### Acceptance tests

1. 안쪽 여백·슬롯 간격·반경·글자 묶음 간격·제목/보조 타이포가 `components.measured.json`과 같다.
2. Default·Hover·Selected·Disabled의 면과 전경이 states 표와 같다.
3. **표면 위에서 light·dark 두 테마 모두 선택 표식이 있고 폭과 색이 계약과 같다.**
4. 선택하지 않은 행에는 표식이 없다.
5. 선택을 `aria-current="true"`가 소유하고 목록에 하나만 있다.
6. 행이 `<button type="button">`이고 보조 문구를 눌러도 클릭이 **한 번만** 실행된다.
7. 긴 제목이 말줄임으로 줄고 한 줄에 남는다.
8. 선택된 행에서도 보조 문구가 제목과 다른 색이다.
9. `disabled`면 클릭이 실행되지 않고 hover가 면을 칠하지 않는다.
10. 포커스 링이 **키보드에서만** 나타나고 두께가 `border-width-ring`이다.
11. Tab이 다음 행으로 이동한다.
12. 자동 접근성 검사에 위반이 없다.

## Segmented Control

- Source: design/components/segmented-control.md
- Maturity: experimental

### Segmented Control

한 줄에 놓인 두셋 중 하나를 고른다.

**제품에 공용 구현이 둘 있는데 서로 아무것도 공유하지 않는다.** `SegmentedToggle` 컴포넌트(파일
주석이 스스로 SSOT라고 적어 두었다, 3벌)와 `useSegmentedControlThumb` 훅(4벌, 훅만 공유하고
스타일은 복붙)이고, 트랙 padding 4↔3, 트랙 반경 12↔8, 썸 반경 8↔6, easing 셋, 비활성 글자
42%↔58%↔55%↔48%가 전부 다르다. 정본을 `SegmentedToggle`로 잡았고 갈라지는 축은
[`product.measured.json`](../../migration/product.measured.json)이 사유와 함께 갖는다.

#### Availability

| Surface       | 상태           | 근거                                                                                   |
| ------------- | -------------- | -------------------------------------------------------------------------------------- |
| Web           | `partial`      | public export와 실브라우저 acceptance test 14건이 두 motion context에서 각각 돈다; visual regression과 제품 소비 증거 없음 |
| Figma         | `partial`      | component set 2 variant(Size). parity 게이트가 Track·Segment·Segment-Selected·Label을 자손으로 대조하며 raw fill·stroke 0이다. publish는 DS-F-008 |
| Documentation | `done`         | 이 문서                                                                                |
| Maturity      | `experimental` | 규범과 구현이 같은 변경 단위에서 처음 선다                                             |

#### When to use

- 선택지가 **둘에서 넷**이고, 라벨이 짧으며, 전부 한눈에 보여야 할 때 — 테마, 정렬 기준, 기간,
  보기 방식.
- 고른 값이 **같은 화면의 내용을 다시 그릴 때.** 다른 곳으로 이동하지 않는다.

쓰지 않는 자리.

- **패널을 바꿀 때.** 그것은 Tabs이며 아직 카탈로그에 없다. 제품의 대시보드 상단
  `DASHBOARD_TABS` 다섯 자리가 그쪽이다.
- 선택지가 다섯 이상이거나 라벨이 길 때. 그것은 Select 또는 Menu다.
- 켜고 끄는 것. 그것은 Switch이며 아직 카탈로그에 없다.
- 여럿을 동시에 고를 때. 그것은 Checkbox 그룹이다.
- 목적지로 이동할 때. 그것은 링크다.

#### API

```tsx
<SegmentedControl label="테마" value={theme} onValueChange={setTheme}>
  <SegmentedControlItem value="system">시스템</SegmentedControlItem>
  <SegmentedControlItem value="light">라이트</SegmentedControlItem>
  <SegmentedControlItem value="dark">다크</SegmentedControlItem>
</SegmentedControl>
```

#### Anatomy

1. **Track** — `<fieldset>`. 면·반경·헤어라인과 padding을 소유한다.
2. **Legend** — 그룹 이름. 시각적으로 숨기고 보조기술에 남긴다.
3. **Segment** — `<label>`. 시각을 소유한다.
4. **Input** — 숨겨진 `<input type="radio">`. 선택 상태와 키보드를 소유한다.

**시각적 세그먼트가 `<input>`이 아닌 이유.** radio를 그대로 그릴 수 없고, 라벨이 면·반경·포커스
링을 받아야 아이콘과 글자를 함께 담을 수 있다. Text Field가 박스를 `<input>` 바깥에 둔 것과 같은
구조다.

#### Properties

| prop | 값 | 기본 | 뜻 |
| --- | --- | --- | --- |
| `label` | string | **필수** | 그룹 이름. `<legend>`가 되고 화면에서는 숨는다 |
| `value` | string | **필수** | 현재 값. 항상 controlled다 |
| `onValueChange` | `(value: string) => void` | **필수** | 값이 바뀔 때 |
| `size` | `md` \| `sm` | `md` | 트랙 높이와 타이포 |
| `disabled` | boolean | `false` | 그룹 전체를 비활성한다 |

`SegmentedControlItem`은 `value`와 `disabled`를 받는다.

**비제어 모드가 없다.** 세그먼트 컨트롤의 값은 거의 언제나 화면의 다른 부분을 다시 그리는
입력이라 호출부가 이미 그 값을 갖고 있다. 내부 상태를 두면 두 곳에 같은 값이 산다.

#### Hierarchy와 variants

variant 축이 없다. 세그먼트 컨트롤은 강조 단계를 갖지 않는다 — 한 화면에 두 개가 있어도 어느
쪽이 "주요"한지는 시각이 아니라 배치가 말한다.

#### States

| state | 표현 |
| --- | --- |
| Default | 면 없음(트랙 색이 보인다), 전경 `color-foreground-secondary` |
| Hover | 전경 `color-foreground-primary`. **면은 바뀌지 않는다** |
| Selected | 면 `color-background-raised`, 전경 `color-foreground-primary` |
| Disabled | 전경 `color-foreground-disabled`, `cursor: not-allowed` |
| Focus | 세그먼트가 공유 링을 받는다 |

**hover에서 면을 바꾸지 않는다.** 바꾸면 얹은 것과 선택된 것이 같은 표현이 되어 어느 쪽이 현재
값인지 순간 읽히지 않는다. 제품 B는 hover에 면을 칠하고 선택에도 면을 칠해 이 문제를 갖는다.

**Selected는 면과 전경을 함께 바꾼다.** 제품 B 계열은 선택을 색 하나로만 전달하고 aria도 없어서,
색각 이상과 스크린 리더 양쪽에서 현재 값이 사라진다.

#### Interaction and responsive behavior

- 폭은 호출부가 정한다. 트랙은 내용 크기로 자라되 `max-inline-size: 100%`라 컨테이너를 넘지 않는다.
- 세그먼트는 내용 크기를 기준으로 늘고 준다. 좁아지면 라벨이 **줄바꿈이 아니라 말줄임**으로
  줄어든다 — 줄바꿈하면 트랙 높이가 변해 옆에 선 컨트롤과 어긋난다.
- 선택 면이 움직이는 전환이 **없다.** 아래 Known deviations.

#### Content

- 라벨은 **한 단어**를 목표로 한다. "최신"이지 "최신 순으로 정렬"이 아니다.
- 라벨 길이를 서로 비슷하게 맞춘다. 하나만 길면 그 세그먼트가 트랙을 지배한다.
- `label`은 무엇을 고르는 축인지를 말한다. "테마"이지 "테마를 선택하세요"가 아니다.

#### Accessibility

- **네이티브 radio 그룹이다.** 방향키 roving, 끝에서 되돌기, "3 중 1" 그룹 안내, 폼 제출,
  forced-colors가 전부 브라우저의 것이다. Button이 활성화를, Slider가 범위를 네이티브에 맡긴
  것과 같은 이유다.
- 제품은 선택을 셋으로 다르게 전달한다 — `aria-pressed`(A), **아무것도 없음**(B), `role="tab"`(C).
  패널을 바꾸지 않고 값을 고르는 것은 radiogroup이며 그 하나를 골랐다.
- **`<fieldset>` + `<legend>`인 이유.** legend가 그룹에 이름을 붙이는 유일한 네이티브 경로다.
  `role="radiogroup"` + `aria-label`을 얹은 `<div>`는 안의 네이티브 radio와 역할이 겹친다.
  제품 A는 `<span aria-label>`을 쓰는데, role 없는 span의 `aria-label`은 보조기술이 무시한다.
- **포커스 링을 세그먼트가 받는다.** radio는 숨겨져 있어 거기 걸면 화면 밖에 그려진다.
  제품의 여섯 레시피 **어디에도 포커스 표시 선언이 없다.**
- forced-colors에서는 면 색이 시스템 색으로 치환돼 선택이 사라지므로 테두리로 다시 세운다.
- radio 그룹 이름은 컴포넌트가 인스턴스마다 발급한다. 호출부가 만들면 같은 화면에 컨트롤이 둘일
  때 그룹이 합쳐져 한쪽을 고르면 다른 쪽 선택이 풀린다.

#### Specification

| 축 | md | sm | 토큰 |
| --- | ---: | ---: | --- |
| 트랙 높이 | 40px | 32px | `layout-control-height-md` / `-sm` |
| 트랙 padding | 4px | 4px | `space-control-xs` |
| 트랙 반경 | 12px | 12px | `radius-control` |
| 트랙 헤어라인 | 0.5px | 0.5px | `border-width-hairline` |
| 세그먼트 높이 | 32px | 24px | 트랙 − 2×padding |
| 세그먼트 반경 | 8px | 8px | `radius-control-sm` |
| 세그먼트 좌우 여백 | 12px | 8px | `space-control-md` / `-sm` |
| 슬롯 간격 | 8px | 8px | `space-control-sm` |
| 타이포 | 14/1.5 | 12/1.5 | `typography-body-sm-medium` / `typography-caption-medium` |

**세그먼트 반경은 바깥 반경에서 padding을 뺀 값이다** — 12 − 4 = 8. 중첩한 모서리가 어긋나지
않고, 두 값 다 기존 토큰이라 새 토큰이 필요 없었다.

높이가 Button·Text Field·Slider와 같은 계단인 이유는 하나다 — 나란히 서는 컨트롤이 서로 다른
높이를 가지면 줄이 어긋난다. 제품 A는 36px이고 그 값은 이 저장소의 어떤 컨트롤과도 맞지 않는다.

#### Effects

**트랙의 헤어라인은 테두리가 아니라 spread-only box-shadow다.** `border`를 쓰면 border-box
안쪽이 줄어 세그먼트 높이가 40 − 8 − 2×테두리가 되는데, 브라우저가 DPR 1에서 0.5px을 1px로
올리므로 그 값이 화면마다 달라진다. 그림자는 레이아웃을 건드리지 않아 세그먼트가 정확히 32로
남는다. 제품 A의 `box-shadow: var(--dropdown-frame)`가 같은 기법이며 그 축은 채택했다.

선택 면에 그림자를 두지 않는다. 제품 A는 헤어라인 프레임을 얹지만, 면 색이 이미 트랙과 다르므로
경계가 그것으로 읽힌다.

#### Implementation

- 트랙 면 `color-background-inset`과 선택 면 `color-background-raised`는 **한 테마에서 죽지 않는
  유일한 짝이다.** 다크에서 `inset`·`surface`·`menu`·`overlay` 넷이 같은 색이고 라이트에서
  `raised`·`overlay`·`surface` 셋이 같다.
- 트랙에 헤어라인을 두는 이유도 같다 — 다크에서 `inset`이 `surface`와 같아, 표면 위에 놓인
  트랙이 테두리 없이는 보이지 않는다.
- 세그먼트의 `flex`는 `1 1 auto`다. `1 1 0`으로 두면 기준 크기가 0이라 **여유가 있는데도 라벨이
  잘린다.**
- `<fieldset>`의 기본 여백·테두리를 스스로 지운다. reset은 opt-in이라 소비자가 켜지 않을 수 있다.

#### Known deviations

- **선택 면이 움직이지 않는다.** 제품 여섯 중 넷이 220~240ms 슬라이딩 썸을 갖고 그것이 이
  컴포넌트에서 가장 널리 합의된 축인데, DS에 그 전환을 부를 토큰이 없다.
  [Motion](../foundations/motion.md)은 semantic recipe로 `layout-change`를 **이름만 예약해 두고**
  실제 토큰은 없으며, lifecycle도 `enter`·`exit`·`loop` 셋뿐이다. 넷째 lifecycle을 세우는 것은
  DS-D-0016이 `loop`에 한 것과 같은 크기의 변경이고, token source가 바뀌면 Figma 변수·style을 다시
  적용해야 하므로 이 변경 단위 밖이다. 이름이 맞지 않는 기존 motion 토큰(`overlay-enter` 등)을
  빌려 쓰지 않는다 — `radius-card`와 같은 함정이 된다.
- **제품의 슬라이딩 썸 구현이 셋으로 갈린다.** JS `offsetWidth`(A), JS `getBoundingClientRect` +
  ResizeObserver(B), CSS만(C). 위 토큰이 서면 어느 쪽을 채택할지 함께 정한다.
- **Tabs가 없다.** 제품의 `DASHBOARD_TABS` 다섯 자리는 패널을 바꾸므로 이 컴포넌트가 아니다.
- **아이콘 슬롯의 크기 계약이 없다.** `gap`만 정해 두었고 아이콘은 호출부가 넣는다.
- **RTL에서 방향키 방향을 검증하지 않았다.** 네이티브 radio의 동작에 맡긴다.

#### Acceptance tests

1. md/sm의 트랙 높이·padding·반경·헤어라인 토큰·세그먼트 높이·반경·좌우 여백·슬롯 간격·타이포가
   `components.measured.json`과 같다.
2. 세그먼트 반경이 트랙 반경에서 트랙 padding을 뺀 값과 같다.
3. Default·Hover·Selected·Disabled의 면과 전경이 states 표와 같다.
4. **트랙 면과 선택 면이 light·dark 두 테마 모두에서 서로 다르다.**
5. 선택이 색이 아니라 radio의 `checked`로 전달된다.
6. 그룹 이름이 `<legend>`이고 화면에서는 숨겨지되 지워지지 않는다.
7. 방향키가 값을 옮기고 끝에서 되돈다.
8. 컨트롤이 둘일 때 radio 그룹 이름이 서로 다르고 각자 자기 선택을 갖는다.
9. 클릭이 값을 바꾸고 이전 선택이 풀린다.
10. 포커스 링을 **세그먼트**가 받고 키보드에서만 나타나며 두께가 `border-width-ring`이다.
11. 그룹 `disabled`가 자손 입력 전부를 `:disabled`로 만들고 값이 바뀌지 않는다.
12. 항목 하나만 비활성할 수 있고 나머지는 살아 있다.
13. 두 크기 모두 자동 접근성 검사에 위반이 없다.

## Slider

- Source: design/components/slider.md
- Maturity: experimental

### Slider

정해진 범위 안에서 하나의 수를 고른다.

**제품에 공용 구현이 없다.** 정의가 37벌이고 일곱 레시피로 갈리며 **레시피 사이에 합의하는 축이
하나도 없다** — 트랙 높이 2·4·20·28px, 썸 0·10·12·14·16px, 채움 색 다섯 갈래다. 그래서 이
컴포넌트의 값은 제품 정본을 옮긴 것이 **아니라 DS가 정한 것**이고, 어디서 갈라지는지는
[`product.measured.json`](../../migration/product.measured.json)이 사유와 함께 갖는다.

#### Availability

| Surface       | 상태           | 근거                                                                                 |
| ------------- | -------------- | ------------------------------------------------------------------------------------ |
| Web           | `partial`      | public export와 실브라우저 acceptance test 16건이 두 motion context에서 각각 돈다; visual regression, Figma component와 제품 소비 증거 없음 |
| Figma         | `not-ready`    | component set이 아직 없다. DS-F-006-slider가 소유한다                                |
| Documentation | `done`         | 이 문서                                                                              |
| Maturity      | `experimental` | 규범과 구현이 같은 변경 단위에서 처음 선다                                           |

#### When to use

- 값이 **연속적이고** 대략의 위치가 정확한 숫자보다 중요할 때 — 투명도, 볼륨, 재생 속도, 줌.
- 조정한 결과를 **즉시 볼 수 있을 때.** 슬라이더의 값은 미리보기가 대신 읽어 준다.

쓰지 않는 자리.

- 정확한 수를 입력해야 할 때. 그것은 숫자 Text Field다. 둘을 나란히 두는 것은 괜찮다.
- 선택지가 다섯 이하의 이산값일 때. 그것은 Segmented Control이다.
- 켜고 끄는 것. 그것은 Switch이며 아직 카탈로그에 없다.
- **범위(시작–끝) 선택.** 손잡이가 둘인 형태는 이 컴포넌트의 축이 아니다.

#### API

```tsx
<Slider label="투명도" min={0} max={1} step={0.05} value={opacity}
  onValueChange={setOpacity} formatValue={(v) => `${Math.round(v * 100)}%`} />

<Slider label="재생 속도" variant="track" min={0.5} max={2} step={0.05} defaultValue={1} />
```

#### Anatomy

1. **Stack** — 라벨과 컨트롤을 세로로 담는다.
2. **Label** — 시각 라벨. `htmlFor`로 컨트롤에 연결된다.
3. **Control** — 실제 `<input type="range">`. 레일·채움·썸을 전부 이 요소가 그린다.

**값 표시는 이 컴포넌트의 부품이 아니다.** 제품은 값 문구의 자리와 형식이 벌마다 다르고(오른쪽
알약, 라벨 옆, 아래 눈금) 그 배치는 호출부의 격자에 달려 있다. 컴포넌트는 `formatValue`로
스크린 리더용 표현만 소유한다.

#### Properties

| prop | 값 | 기본 | 뜻 |
| --- | --- | --- | --- |
| `label` | ReactNode | 없음 | 시각 라벨. 없으면 `aria-label`이 필수다 |
| `size` | `md` \| `sm` | `md` | 컨트롤 높이. 레일 두께는 바뀌지 않는다 |
| `variant` | `thumb` \| `track` | `thumb` | 아래 Hierarchy와 variants |
| `min` / `max` / `step` | number | `0` / `100` / `1` | 범위와 눈금 |
| `value` | number | 없음 | 주면 controlled가 된다 |
| `defaultValue` | number | `min` | 비제어 초기값 |
| `onValueChange` | `(value: number) => void` | 없음 | 값이 바뀔 때 |
| `formatValue` | `(value: number) => string` | 없음 | `aria-valuetext`. 아래 Accessibility |

나머지는 `<input>`의 네이티브 속성을 그대로 받는다.

#### Hierarchy와 variants

| variant | 모양 | 쓰는 자리 |
| --- | --- | --- |
| `thumb` | 4px 레일 위의 둥근 손잡이 | 기본. 값이 한 점으로 읽히면 된다 |
| `track` | 28/20px 굵은 막대를 채우고 채움 끝에 얇은 표식 | 좁은 인스펙터에서 값이 **양**으로 읽혀야 할 때 |

`track`은 제품 인스펙터 17벌의 형태다. **다른 점이 하나 있다** — 제품은 그 표식을 장식으로
그리고 진짜 손잡이를 `width:0; opacity:0; pointer-events:none`으로 지웠다. 여기서는 표식이 곧
손잡이라 모양은 같고 포커스와 방향키가 살아 있다.

#### States

states 표를 두지 않는다. 칠해지는 면(레일·채움·썸)이 전부 브라우저의 섀도우 pseudo-element라
**계산값을 읽을 수 없고**, 게이트가 확인할 수 없는 표를 두면 "확인했다"는 주장만 남는다. 토큰
배정은 아래 Specification이 갖고 CSSOM 선언 대조가 그것을 고정한다.

| state | 표현 |
| --- | --- |
| Default | 채움 `color-action-primary`, 빈 레일 `color-border-default`, 썸 `color-action-primary` + 표면색 링 |
| Hover | **바뀌지 않는다** |
| Focus | 컨트롤 전체가 공유 링을 받는다 |
| Disabled | 레일 전체 `color-border-subtle`, 썸 `color-foreground-disabled`, `cursor: not-allowed` |

**hover에서 아무것도 바꾸지 않는다.** 제품의 두 레시피는 썸을 1.15배로 키우는데, 커서가 이미
레일 위에 있고 손잡이가 보이므로 어포던스가 부족하지 않다. 크기가 변하면 그 순간 값이 어디인지
읽기가 더 어렵다.

#### Interaction and responsive behavior

- 폭은 호출부가 정한다. 컨트롤은 `inline-size: 100%`이며 스스로 폭을 갖지 않는다.
- 레일 어디를 눌러도 그 지점으로 값이 간다. 네이티브 동작이며 손잡이를 정확히 집을 필요가 없다.
- `touch-action: none`이라 드래그 중에 화면이 따라 스크롤되지 않는다. 스크롤이 따라오면 값이 튄다.
- 세로 방향은 지원하지 않는다. 제품에 세로 슬라이더가 0벌이다.

#### Content

- **Label**은 무엇을 조절하는지를 말한다. "투명도"이지 "투명도를 조절하세요"가 아니다.
- 단위는 라벨이 아니라 값 표시가 갖는다. "속도(배)"가 아니라 "속도"이고 값이 "1.5배"다.
- 최소·최대 눈금 문구를 두려면 호출부가 컨트롤 아래에 놓는다. 컴포넌트의 부품이 아니다.

#### Accessibility

- **네이티브 `<input type="range">`다.** `role="slider"`, `aria-valuenow`/`valuemin`/`valuemax`,
  방향키·Home/End·PageUp/PageDown, 터치, forced-colors, RTL이 전부 브라우저의 것이다. Button이
  활성화를 네이티브 `<button>`에 맡긴 것과 같은 이유로 여기도 직접 만들지 않는다.
- **라벨이 필수다.** 시각 라벨이 없으면 `aria-label`을 준다.
- `formatValue`는 **숫자가 그 자체로 뜻을 갖지 않을 때만** 준다. `0.5`가 아니라 `50%`,
  `1.5`가 아니라 `1.5배`. 늘 붙이면 `aria-valuetext`가 `aria-valuenow`를 덮어 원래 값을 잃는다.
- **포커스 링을 지우지 않는다.** 제품의 세 레시피가 `outline: none`을 직접 선언했고 그것이
  37벌 중 25벌(68%)이다. 키보드 사용자가 지금 어디에 있는지 알 수 없는 상태를 옮기지 않는다.
- id는 컴포넌트가 인스턴스마다 발급한다. 호출부가 만들면 같은 화면에 슬라이더가 여럿일 때 겹친다.

#### Specification

| 축 | md | sm | 토큰 |
| --- | ---: | ---: | --- |
| 컨트롤 높이 | 40px | 32px | `layout-control-height-md` / `-sm` |
| 레일 두께 | 4px | 4px | 리터럴 |
| 레일 반경 | 999px | 999px | `radius-pill` |
| 썸 지름 | 16px | 12px | 리터럴 |
| 썸 테두리 | 2px | 2px | `border-width-ring` |
| `track` 막대 높이 | 28px | 20px | 리터럴 |
| `track` 막대 반경 | 8px | 8px | `radius-control-sm` |
| `track` 표식 | 2×14px | 2×14px | 리터럴 |
| stack 간격 | 4px | 4px | `space-control-xs` |
| 라벨 타이포 | 14/1.5 | 14/1.5 | `typography-body-sm-medium` |

리터럴이 남아 있는 이유는 소비처가 이 컴포넌트 하나뿐이기 때문이다 —
[Spacing & Radius](../foundations/spacing-radius.md)가 "두 개 이상의 사용처"를 승격 조건으로 둔다.
Spinner의 16/12px과 같은 판정이다.

컨트롤 높이가 Button·Text Field와 같은 계단인 이유는 하나다 — 인스펙터에서 나란히 서는 컨트롤이
서로 다른 높이를 가지면 줄이 어긋난다. 제품 슬라이더는 8·12·16·24·28px로 흩어져 있다.

#### Effects

없다. 썸에 그림자를 쓰지 않는다 — 제품의 썸 그림자 넷이 값이 다 다르고(`0 1.5px 3px/24%`,
`0 2px 8px/22%`, `0 1px 2px/30%`) DS의 elevation 넷 중 맞는 것이 없다. 새 elevation 토큰을 만드는
대신 표면색 링으로 분리한다. 어느 배경 위에서도 성립하고 forced-colors에서도 사라지지 않는다.

#### Implementation

- 채움 비율은 컴포넌트가 `--kds-slider-fill`로 내려보낸다. `::-webkit-slider-runnable-track`은
  진행 구간을 따로 갖지 않아 그라디언트 정지점으로 그려야 하고, 그 비율은 값에서만 나온다.
  Firefox는 `::-moz-range-progress`가 있어 비율이 필요 없다.
- 그래서 **비제어일 때도 컴포넌트가 값을 안다.** 그 상태가 채움의 유일한 출처다. controlled면
  `value` prop이 이긴다.
- WebKit과 Firefox의 pseudo-element를 **한 선택자로 합치지 않는다.** 한 브라우저가 모르는
  pseudo-element가 섞이면 규칙 전체가 버려진다.
- WebKit은 썸을 트랙 박스의 위쪽 가장자리에 붙인다. `margin-block-start`로 차이의 절반만큼
  올려야 가운데에 온다. Firefox는 자동으로 가운데 정렬한다.

#### Known deviations

- **레일·채움·썸의 렌더 결과를 게이트가 보지 못한다.** Chromium의
  `getComputedStyle(input, "::-webkit-slider-runnable-track")`은 섀도우 pseudo-element가 아니라
  호스트 input의 값을 돌려준다(2026-08-18 실측: 320×40, 배경 투명, 반경 0). 그래서 테스트는
  CSSOM의 **선언**을 대조한다. 선언과 실제 그림이 갈라지는 경로는 열려 있고, 이것은 visual
  regression(2단계 harness)이 닫아야 한다.
- **Firefox 경로가 미검증이다.** `::-moz-range-*` 규칙을 나란히 적었으나 test harness가
  Chromium 단독이라 실행된 적이 없다.
- **컨트롤 높이 40px은 `layout-control-hit-target-minimum` 44px에 미달한다.** Button은
  `.kds-hit-target`의 `::after`로 44를 채우지만 range input은 `::before`/`::after`가 트랙·썸에
  배정돼 그 유틸리티를 쓸 수 없다. Text Field도 같은 40px이며, 레일이 가로 전체를 차지해 실제
  타깃 면적은 크다.
- **제품과 거의 모든 축이 다르다.** 정본이 없으므로 "다르다"가 결함이 아니다. 각 축의 판정은
  [`product.measured.json`](../../migration/product.measured.json)의 `slider`에 있다.
- **범위(두 손잡이) 선택이 없다.** 제품에 0벌이라 이번 범위가 아니다.

#### Acceptance tests

1. md/sm의 컨트롤 높이·stack 간격·라벨 타이포가 `components.measured.json`과 같다.
2. md/sm의 레일 두께·썸 지름·썸 테두리 토큰 선언이 `components.measured.json`과 같다.
3. `track` 변형의 막대 높이와 표식 크기 선언이 `components.measured.json`과 같다.
4. `track` 변형의 썸이 `width:0`·`height:0`·`opacity`·`pointer-events`로 지워지지 않는다.
5. `--kds-slider-fill`이 값을 따라가고 min에서 `0%`, max에서 `100%`다.
6. 방향키가 `step`만큼 움직이고 `min`·`max`를 넘지 않는다.
7. controlled일 때 호출부의 값이 이기고, 갱신하지 않으면 값이 튀지 않는다.
8. 라벨의 `for`가 컨트롤을 가리키고, 라벨을 누르면 컨트롤이 포커스를 받는다.
9. 슬라이더가 둘 있을 때 두 컨트롤의 id가 다르다.
10. 포커스 링이 **키보드에서만** 나타나고 두께가 `border-width-ring`이다.
11. `disabled`면 키보드로도 값이 바뀌지 않고 `onValueChange`가 불리지 않는다.
12. `formatValue`를 준 것만 `aria-valuetext`를 갖는다.
13. 두 변형 모두 자동 접근성 검사에 위반이 없다.

## Sidebar Nav Item · App Top Bar

- Source: design/components/app-shell-parts.md
- Maturity: experimental

### Sidebar Nav Item · App Top Bar

앱 셸 안에 놓이는 부품 둘이다 — navigation rail의 한 행과 top chrome의 한 줄.

**셸의 레이아웃 계약은 이 문서의 것이 아니다.** 사이드바가 어디에 자리를 예약하는지, 스크롤 루트가
어디인지, compact에서 드로어가 어떻게 열리는지는 [app-shell 패턴](../patterns/app-shell.md)이
소유한다. 여기 있는 것은 그 안에 담기는 조각이다.

#### Availability

| Surface       | 상태           | 근거                                                          |
| ------------- | -------------- | -------------------------------------------------------------- |
| Web           | `partial`      | public export와 실브라우저 acceptance test 10건; 셸 composition은 없다 |
| Figma         | `partial`      | component 둘 — SidebarNavItem 6 variant(State×Collapsed)와 AppTopBar. publish는 DS-F-008 |
| Documentation | `done`         | 이 문서                                                        |
| Maturity      | `experimental` | 규범과 구현이 같은 변경 단위에서 처음 선다                     |

#### When to use

- 앱 셸의 navigation rail에 화면 하나를 대표하는 행을 놓을 때.
- 본문 위에 제목과 액션 한 줄이 필요할 때.

쓰지 않는 자리.

- **셸 전체를 조립하는 것.** 그것은 패턴이며 composition이 아직 없다.
- 목록 안의 선택 가능한 행. 그것은 SelectableListRow이며 다른 컴포넌트다.
- 탭. 가로로 늘어서고 콘텐츠를 바꾸는 것은 다른 축이다.

#### API

```tsx
<SidebarNavItem href="/archive" icon={<IconHouse />} current>
  보관함
</SidebarNavItem>

<SidebarNavItem href="/highlight" icon={<IconGraph />} trailing={<Badge>3</Badge>} collapsed>
  하이라이트
</SidebarNavItem>

<AppTopBar
  leading={<IconButton label="사이드바 접기" onClick={toggle}><IconSidebar /></IconButton>}
  title="보관함"
  trailing={profileTrigger}
/>
```

#### Anatomy

**SidebarNavItem** — Icon · Label · Trailing.
**AppTopBar** — Leading · Title · Trailing.

#### Properties

| 컴포넌트 | prop | 값 | 기본 | 뜻 |
| --- | --- | --- | --- | --- |
| SidebarNavItem | `href` | string | 없음 | 있으면 `<a>`, 없으면 `<button>` |
| | `icon` | ReactNode | 없음 | 행 앞 아이콘 |
| | `trailing` | ReactNode | 없음 | 행 끝 배지·개수. 접힘에서 사라진다 |
| | `current` | boolean | `false` | 현재 화면. `aria-current="page"`가 된다 |
| | `collapsed` | boolean | `false` | rail이 접혔는가 |
| AppTopBar | `leading` / `title` / `trailing` | ReactNode | 없음 | 세 슬롯 |
| | `divider` | boolean | `false` | 아래 경계선 |

#### Hierarchy와 variants

variant 축이 없다. rail 안의 행은 전부 같은 무게이며, 강조는 `current` 하나다.

#### States

| state | SidebarNavItem |
| --- | --- |
| Default | 투명, `color-foreground-secondary` |
| Hover | `color-action-ghost-hover`, `color-foreground-primary` |
| Current | `color-background-inset`, `color-foreground-primary` |
| Focus visible | 공유 focus ring |

AppTopBar는 상태 축이 **없다.** 대화형이 아니고 안의 슬롯이 자기 상태를 갖는다.

#### Interaction and responsive behavior

- 라벨은 한 줄로 잘린다. rail 폭이 고정이라 줄바꿈하면 행 높이가 흔들린다.
- 접힘에서 라벨이 시각에서만 숨고 아이콘이 가운데 정렬된다.
- TopBar의 제목이 남는 자리를 먹고 한 줄로 잘린다. 양옆 슬롯은 자기 크기를 갖는다.

#### Content

- 라벨은 **화면의 이름**이다. "보관함"이지 "보관함으로 이동"이 아니다.
- TopBar의 제목은 현재 위치를 말한다. 브레드크럼이 필요하면 `title` 자리에 넣는다 — 이 컴포넌트가
  브레드크럼 구조를 소유하지 않는다.

#### Accessibility

- **선택을 `aria-current="page"`가 소유한다.** 시각 전용 속성을 따로 두면 화면에는 선택으로 보이는데
  보조기술에는 아무것도 전달되지 않는 상태를 만들 수 있다.
- **접혀도 라벨이 DOM에 남는다.** 지우면 접기/펴기마다 접근성 이름이 사라졌다 나타나고, 스크린 리더
  사용자에게는 접힘이 보이지 않는 상태 변화가 된다. `clip-path`로 시각에서만 숨긴다.
- 아이콘은 `aria-hidden`이다. 라벨이 이름을 소유한다.
- **포커스 링이 실제로 그려진다.** 아래 Known deviations를 본다.

#### Specification

| 축 | 값 | 토큰 |
| --- | ---: | --- |
| 행 높이 | 32px | `layout-control-height-sm` |
| 행 좌우 여백 | 8px | `space-control-sm` |
| 행 간격 | 8px | `space-control-sm` |
| 행 반경 | 10px | `radius-overlay-item` |
| 아이콘 | 20px | `icon-size-md` |
| 상단 바 높이 | 40px | `layout-app-shell-top-bar-height` |
| 상단 바 좌우 여백 | 16px | `layout-app-shell-content-inset` |

**상단 바 높이가 40px인 근거.** 제품에는 세 값이 있고 서로 맞지 않는다 — portal 변종 52px,
fixed 변종 36px, 사이드바 헤더 행 `min-height: 40px`. `globals.css`의 주석이 정렬을 40px 전제로
계산하므로 **정렬의 기준이 40**이고 나머지 둘은 그 안에 담기는 내용의 결과다.
[DS-D-0018](../governance/decisions/DS-D-0018-app-shell-geometry.md)이 이 판정을 소유한다.

`layout-control-height-md`가 같은 40px이지만 쓰지 않는다. 값이 같은 것과 의미가 같은 것은 별개이며,
버튼 높이를 바꾸는 날 상단 바가 같이 움직이면 안 된다.

#### Effects

없다.

#### Implementation

- 선택 면을 **항목이 직접 갖는다.** 제품은 두 메커니즘을 쓴다 — 표준 사이드바는 형제로 놓인
  절대배치 span이 면을 그리고 항목은 투명하며, admin 사이드바는 항목이 직접 갖는다. 결과 색은
  같고 이동 애니메이션 유무만 다르다. 인디케이터를 형제로 두면 항목 하나를 다른 곳에 옮겨 놓을 수
  없고, 이동 애니메이션은 rail composition이 원할 때 얹을 수 있다.
- TopBar의 경계선이 기본이 아닌 이유는 제품의 것이 **스크롤 진행률에 따라 색이 연속으로 변하는
  런타임 계약**이기 때문이다. rAF로 매 프레임 값을 쓰므로 컴포넌트가 소유할 수 없다.

#### Known deviations

- **제품의 사이드바 항목에는 포커스 표시가 없다.** `globals.css`의
  `button:focus, button:focus-visible { outline: none }`이 `@layer base` 블록 **밖**에 있어
  `@layer utilities` 안의 Tailwind 임의 유틸리티를 특이도와 무관하게 이긴다. 항목이 선언한
  `[&:focus-visible]:[outline:2px_...]` 세 줄이 전부 사문이고, 앱 셸 소비처 25곳이 모두 `<button>`
  분기를 타므로 **키보드 사용자가 지금 어디에 있는지 알 수 없다.** 그 구조는 옮기지 않았고
  테스트가 링이 실제로 그려지는지 확인한다.
- **목적지가 있으면 링크다.** 제품의 앱 셸 소비처 25곳이 전부 `onNavigate`를 넘겨 `<button>`
  분기를 타는데, 그 결과 새 탭·링크 복사·미들클릭이 죽는다. 라우터 가로채기는 호출부가 `onClick`에서
  한다.
- **셸 composition이 없다.** rail·drawer·scroll root·safe area는 패턴이 기술하지만 구현이 없다.
  이 둘은 그 안에 놓일 조각이며, 그 자체로는 셸을 만들지 못한다.
- **Figma의 접힘에는 라벨이 없다.** 코드는 `clip-path`로 시각에서만 숨기는데 Figma에 그 표현이
  없어 노드를 뺐다. 접근성 이름이 유지되는지는 코드 테스트가 본다.
- **compact 드로어의 layer 자리가 사다리에 없다.** 제품의 드로어(1400)와 scrim(1399)은 프로필
  popover(1100)보다 위인데 DS 사다리는 `sticky < popover`다. 드로어는 composition의 일부이며 그때
  판정한다.

#### Acceptance tests

1. 행과 상단 바의 높이·여백·간격·반경·아이콘 크기가 `components.measured.json`과 같다.
2. **포커스 링이 실제로 그려지고** 두께와 색이 토큰에서 온다.
3. `current`가 `aria-current="page"`가 되고 면·글자가 states 표와 같다.
4. 접혀도 라벨이 DOM에 남고 `display: none`이 아니며, trailing은 사라진다.
5. `href`가 있으면 `<a>`, 없으면 `<button>`이다.
6. 아이콘이 `aria-hidden="true"`다.
7. TopBar의 제목이 남는 자리를 먹고 한 줄로 잘린다.
8. `divider`는 켤 때만 그려진다.
9. `.kds-layer-sticky`의 `z-index`가 `layer-sticky` 토큰에서 온다.

## Dialog

- Source: design/components/dialog.md
- Maturity: experimental

### Dialog / Modal

현재 맥락 위에서 사용자의 결정을 받거나 짧은 작업을 완료할 때 쓰는 차단형 overlay다. 이 문서는
과거 여러 Modal 구현의 평균이 아니라 이 저장소가 따라야 할 **규범 계약**이다. 특히 독립
비디오 편집 프로젝트는 Dialog가 아니라 page-owned Workspace다.

#### Availability

| Surface       | 상태           | 근거                                           |
| ------------- | -------------- | ---------------------------------------------- |
| Web           | `partial`      | `Dialog` compound public export, 실브라우저 회귀 15건 |
| Figma         | `partial`      | component set 3 variant (Size). fullscreen 제외. publish는 DS-F-008 |
| Documentation | `done`         | 이 문서                                        |
| Maturity      | `experimental` | 시각 회귀와 수동 screen-reader 검토가 아직 없음 |

#### When to use

- 사용자가 현재 작업을 계속하기 전에 확인·취소 중 하나를 선택해야 할 때
- 삭제, 덮어쓰기, 결제처럼 결과가 크고 별도 확인이 필요할 때
- 현재 페이지 맥락을 유지한 채 완료할 수 있는 짧고 유한한 폼을 제공할 때
- 캔버스의 한 노드에서 임시로 영상 편집기를 열고, 닫으면 원래 캔버스로 돌아갈 때

다음에는 사용하지 않는다.

- 지속적으로 사용하는 편집기, 대시보드, 프로젝트 상세는 페이지 또는 Workspace로 만든다.
- 트리거 주변의 짧은 선택은 [Menu / Popover](../components/menu-popover.md)를 사용한다.
- 진행 상황 알림만 필요하면 Toast/Status를 사용한다.
- 내용이 여러 단계이거나 URL·새로고침·뒤로가기를 독립적으로 가져야 하면 route를 사용한다.
- 화면이 좁다는 이유만으로 Workspace를 `aria-modal` Dialog로 바꾸지 않는다.

#### Surface classifier

겉모양이 전체 화면이라고 같은 컴포넌트가 아니다. 아래 질문 중 하나라도 Workspace 쪽이면 Dialog API에
`portalContainer`를 넣어 의미를 바꾸지 말고 별도 셸을 사용한다.

| 질문/계약              | Modal Dialog                         | Docked / Route Workspace                               |
| ---------------------- | ------------------------------------ | ------------------------------------------------------ |
| 사용자 맥락            | 원래 화면 위의 임시 작업             | URL이 소유하는 주 작업                                 |
| Mount owner            | 앱 전용 modal overlay root           | AppShell이 할당한 main/workspace host                  |
| Position               | viewport 기준 fixed inset            | host 기준 flow/grid 또는 absolute inset                |
| Backdrop               | 있음                                 | 없음                                                   |
| Background interaction | inert + pointer 차단                 | sidebar/header 등 허용된 shell chrome은 계속 사용 가능 |
| ARIA                   | `role="dialog"`, `aria-modal="true"` | `main`/`region`; `aria-modal` 없음                     |
| Focus                  | 초기 포커스 + trap + 호출 요소 복귀  | 문서의 정상적인 focus 순서                             |
| Escape                 | dismissible이면 닫고 원래 맥락 복귀  | 페이지 자체를 닫지 않음; 하위 overlay만 닫음           |
| Body scroll            | 잠금                                 | AppShell/Workspace가 자체 scroll owner를 정함          |
| App sidebar relation   | Dialog가 위에서 차단                 | shell grid가 공간을 할당하며 서로 겹치지 않음          |
| 완료/뒤로가기          | `onOpenChange(false, reason)`        | route navigation·dirty guard                           |

#### Variants

| Variant           | 용도                                      | 기본 초기 포커스                     |
| ----------------- | ----------------------------------------- | ------------------------------------ |
| `confirm`         | 되돌릴 수 있는 일반 확인                  | primary 또는 가장 안전한 명시적 액션 |
| `danger-confirm`  | 삭제·초기화 등 파괴적 결과                | 취소/가장 안전한 액션                |
| `task`            | 짧은 폼·설정                              | 첫 유효 필드                         |
| `media-workbench` | 현재 화면 위에서 임시로 여는 큰 편집 작업 | dialog surface(이름이 먼저 읽힌다)   |
| `sheet`           | 작은 화면에서 변환된 modal task           | 닫기 또는 첫 필드                    |

`docked`, `standalone`, `route`는 Dialog variant가 아니다. 공유해야 하는 것은 editor body이며, modal wrapper와
workspace wrapper는 분리한다.

**variant 전환은 소비자가 한다.** Dialog는 뷰포트 폭을 보고 `task`를 `sheet`로, `medium`을 `fullscreen`으로
자동 전환하지 않는다. 폭에 따라 dismiss 정책과 초기 포커스가 바뀌면 같은 컴포넌트가 화면 크기에 따라 다른
계약을 갖게 되고, 그것은 Surface classifier가 금지한 "화면이 좁다는 이유로 의미를 바꾸는 것"의 축소판이다.
`sheet`와 `fullscreen`은 소비자가 자신의 breakpoint 정책으로 선택한다.

`media-workbench`의 초기 포커스가 dialog surface인 이유는, surface가 포커스를 가지면 스크린리더가
`aria-labelledby`가 가리키는 제목을 먼저 읽고 다음 Tab이 내용으로 들어가기 때문이다. 비어 있는 편집
캔버스에서 임의의 첫 컨트롤을 고르는 것보다 신뢰 가능한 경로다.

#### Anatomy

1. **Overlay root** — modal stack과 portal owner를 연결한다.
2. **Backdrop** — 배경을 시각적으로 낮추고 pointer interaction을 차단한다.
3. **Positioner** — viewport, safe area, 작은 화면 배치를 담당한다.
4. **Dialog surface** — role, accessible name/description, focus scope를 소유한다.
5. **Header** — 제목과 선택적 닫기 액션. 제목은 하나만 둔다.
6. **Body** — 설명, 폼, 오류, 스크롤 콘텐츠.
7. **Footer** — 안전한 취소와 primary/danger action.
8. **Nested overlay host** — Select, Popover, Tooltip을 같은 modal branch에 연결한다.

#### Properties

목표 public API는 Dialog의 의미를 바꾸지 않는다. Workspace host를 받는 `portalContainer`는 이 API에
포함하지 않는다. `mode`, `modal`, `layer`, `zIndex`, `role`도 포함하지 않는다 — 그 중 하나라도 열면
Dialog가 Workspace로 변장하는 통로가 된다.

| Property          | 값/형태                                      | 기본값       | 설명                                                      |
| ----------------- | -------------------------------------------- | ------------ | --------------------------------------------------------- |
| `open`             | `boolean`                                    | 필수         | controlled state. uncontrolled 모드는 없다                |
| `onOpenChange`     | `(open, reason) => void`                     | 필수         | **`open === false`일 때만 호출된다.** `confirm`, `cancel`, `escape`, `backdrop`, `programmatic` |
| `variant`          | 위 variant                                   | `task`       | 레이아웃·초기 포커스·dismiss 정책                         |
| 제목               | 하위 컴포넌트                                | 필수         | `aria-labelledby` 대상. id는 인스턴스별로 발급된다        |
| 설명               | 하위 컴포넌트                                | 권장         | `aria-describedby` 대상. 렌더될 때만 연결된다             |
| `initialFocus`     | ref, `surface`, `safe-action`, `first-field` | variant 기반 | 열림 포커스                                               |
| `returnFocus`      | ref 또는 호출 요소 자동 캡처                 | 자동         | 닫힘 포커스                                               |
| `dismissible`      | `boolean`                                    | `true`       | Escape/닫기 버튼 허용                                     |
| `closeOnBackdrop`  | `boolean`                                    | variant 기반 | danger·busy 상태에서는 보통 false                         |
| `busy`             | `boolean`                                    | `false`      | 중복 실행·dismiss 차단, `aria-busy`                       |
| `confirmVariant`   | `primary`, `danger`                          | `primary`    | 액션 의미                                                 |
| `size`             | `compact`, `medium`, `large`, `fullscreen`   | variant 기반 | content 요구에 따른 크기                                  |
| `onDismissBlocked` | `(reason) => void`                           | 없음         | **추가** 훅. 기본 안내는 Dialog가 스스로 제공한다         |

제목과 설명은 prop이 아니라 하위 컴포넌트가 소유한다. 제목은 호출부가 heading level을 정해야 페이지
outline이 깨지지 않고, 설명은 선택이라 prop으로 받으면 존재 여부를 알 수 없어 렌더되지 않았을 때
`aria-describedby`가 없는 id를 가리킨다. dangling reference는 화면상 아무 이상이 없는 접근성 회귀다.

버튼 라벨, loading, disabled, 오류는 명시적인 props/slots로 제공한다. 전역 keydown listener로 confirm을
추론하지 않는다.

`closeOnBackdrop`은 `dismissible`에 종속된다. 실효값은 `closeOnBackdrop && dismissible && !busy`다.
종속시키지 않으면 "Escape로는 못 닫는데 backdrop으로는 닫히는" 상태가 만들어지고, 그것은 States의
Busy 계약과 어긋난다.

dismiss가 차단될 때 Dialog는 **스스로** polite live region에 안내를 낸다. 안내가 선택이면 소비자가
아무것도 넘기지 않았을 때 차단이 완전히 무음이 되고, 사용자는 Escape가 고장난 것으로 인지한다.
`onDismissBlocked`는 소비자가 자기 문구로 덮거나 추가 처리를 하기 위한 훅이지 안내의 유일한 출처가 아니다.

#### States

| 상태    | 계약                                                                           |
| ------- | ------------------------------------------------------------------------------ |
| Closed  | DOM 없음 또는 완전히 inert; 배경 상호작용 정상                                 |
| Opening | root mount → 배경 inert/scroll lock → 위치 확정 → initial focus → enter motion |
| Open    | top modal만 active; focus trap과 nested overlay branch 유지                    |
| Busy    | 중복 confirm과 accidental dismiss 차단; 상태 문구와 spinner, `aria-busy` 제공  |
| Error   | Dialog 유지; 오류를 관련 필드/요약에 연결하고 첫 오류로 이동할 수 있음         |
| Closing | 즉시 action과 focusable child를 inert 처리; exit 후 unmount와 focus return     |

Error의 "첫 오류로 이동"은 소비자가 소유한다. Dialog는 그 이동이 **가능하도록** body만을 scroll owner로
두어 `scrollIntoView`가 Dialog 밖 문서를 움직이지 않게 한다.

Busy는 `aria-busy`를 dialog surface에 붙인다. confirm action은 네이티브 `disabled`가 아니라
`aria-disabled`로 막는다 — 네이티브 disabled는 현재 포커스를 제거하고, busy 중 포커스가 body로 떨어지면
trap이 무의미해진다. 취소는 busy 중에도 기본 활성으로 남는다. Error가 복구 경로를 요구하기 때문이다.

닫힘 타이머는 가장 긴 exit duration과 같은 token에서 계산한다. 카드가 사라진 뒤 투명 root가 pointer를
가로채거나, root가 먼저 사라져 focus return이 실패하면 안 된다.

#### Interaction

##### Open and focus

1. 열기 직전 `document.activeElement` 또는 명시적 Trigger를 저장한다.
2. Modal root를 최상위 stack에 등록하고 뒤 앱 root를 inert 처리한다.
3. body/scroll owner를 잠그되 기존 inline style을 보존한다.
4. Surface가 배치된 뒤 variant에 맞는 initial focus를 보낸다.
5. 닫힐 때 Trigger가 남아 있으면 복귀하고, 없으면 논리적인 다음 owner로 보낸다.

Tab과 Shift+Tab은 최상위 Dialog 내부에서 순환한다. nested Popover에 포커스가 있으면 같은 modal branch로
취급한다. 아래 Dialog나 페이지로 포커스가 빠지지 않는다.

##### Keyboard

- `Escape`: top modal만 닫는다. `dismissible=false` 또는 `busy=true`이면 닫지 않고 필요한 안내를 제공한다.
- `Enter`: 폼의 네이티브 submit 또는 현재 focus된 버튼만 실행한다. document capture 단계에서 전역
  confirm으로 바꾸지 않는다.
- `danger-confirm`: Enter를 누르는 것만으로 danger action을 실행하지 않는다. 사용자가 danger button에
  명시적으로 focus하고 활성화해야 한다.
- IME 조합, textarea 줄바꿈, Select/Listbox key event를 상위 Dialog가 가로채지 않는다.
- 중첩 Dialog가 불가피하면 topmost 하나만 Escape/Tab scope를 소유한다.

##### Pointer

- Backdrop dismiss는 `event.target === event.currentTarget` 또는 overlay branch 외부인지 확인한 뒤 실행한다.
  구현은 backdrop을 dialog surface의 **형제 요소**로 두고 그 요소 자신에 핸들러를 붙인다. surface에서
  시작해 backdrop에서 끝난 드래그의 click target은 두 요소의 공통 조상이므로 backdrop 핸들러에 도달할 수
  없다 — 우발적 dismiss가 선언이 아니라 구조로 사라진다.
- backdrop의 `mousedown` 기본 동작을 취소한다. 취소하지 않으면 backdrop 클릭이 `tabindex="-1"`인 overlay
  root로 포커스를 옮겨, 닫지 않기로 한 경우에도 포커스가 dialog surface 밖으로 조용히 빠져나간다.
- Surface와 nested portaled overlay의 pointerdown/click은 backdrop dismiss로 처리하지 않는다.
- danger-confirm과 데이터 입력 task는 기본적으로 backdrop click을 취소와 동일시하지 않는다. 데이터
  손실 가능성이 있으면 dirty guard를 제공한다.
- closing 상태의 root는 action을 다시 받지 않는다. 다만 exit가 끝날 때까지 배경 클릭이 accidental
  action으로 통과하지 않도록 정책을 일관되게 유지한다.

#### Modal and Workspace separation

Dialog는 modal behavior만 소유한다. route가 주 작업을 소유하면
[Editor Workspace](../patterns/editor-workspace.md)를 사용하고 App Shell geometry는
[App Shell](../patterns/app-shell.md)에 맡긴다.

- 하나의 core를 공유할 수 있지만 Dialog wrapper와 route Workspace wrapper는 별도 public type이다.
- portal target 유무, ref timing, z-index로 mode를 추론하지 않는다.
- route Workspace에는 backdrop, `aria-modal`, focus trap, outside-close를 적용하지 않는다.
- Workspace에서 연 confirm Dialog는 global modal root를 사용하고 topmost modal behavior를 따른다.

#### Portal and layer rules

- 모든 Modal Dialog는 앱의 하나인 modal overlay root로 portal한다. feature tree 안의 임의 div는 허용하지
  않는다.
- raw z-index 대신 `layer-popover < layer-modal < layer-critical` 의미 토큰과 stack manager를 사용한다.
- 새 Dialog가 열리면 이전 Dialog는 stack에 남더라도 inert다. Escape, focus trap, backdrop은 topmost만
  처리한다.
- Dialog에서 연 Popover/Tooltip은 같은 modal branch에 등록한다. 별도 body portal이라는 이유로 Dialog를
  닫거나 inert 처리되지 않는다.
- toast가 modal보다 위에 필요한지 아래에 필요한지는 feedback policy로 정하고, 숫자를 높여 우연히
  해결하지 않는다.
- viewport safe area와 virtual keyboard를 고려한다. `100vh`보다 visual viewport/`100dvh`와 safe-area
  padding을 우선한다.

#### Responsive behavior

- compact confirm: `min(360px, viewport - 40px)` 기준. 320px에서도 좌우 여백을 유지한다.
- task dialog: 최대폭을 두되 body만 스크롤하고 제목과 footer action은 접근 가능하게 유지한다.
- action은 충분한 폭에서는 한 행, 긴 KO/EN/JA 또는 200% 확대에서는 세로 스택으로 전환한다.
- 큰 media workbench는 작은 화면에서 fullscreen modal이 될 수 있지만 여전히 원래 화면 위의 임시 맥락이면
  Dialog 계약을 유지한다.
- route Workspace는 fullscreen으로 보여도 Dialog 모션, backdrop, focus trap을 적용하지 않는다.

#### Content

- 제목은 결정을 구체적으로 설명한다: `프로젝트를 삭제할까요?`, `변경사항을 저장하고 나갈까요?`.
- 설명은 결과와 복구 가능 여부를 말한다. 제목을 반복하지 않는다.
- 버튼은 결과를 나타낸다: `취소` / `삭제`, `계속 편집` / `저장하고 나가기`.
- danger action에 `확인` 같은 모호한 라벨을 쓰지 않는다.
- async action은 `저장 중`, `삭제 중`처럼 상태를 표시하되 말줄임표를 쓰지 않는다.
- 오류 후 Dialog를 닫지 말고 사용자가 복구할 방법을 제공한다.

#### Accessibility

- Surface는 `role="dialog"`와 `aria-modal="true"`를 사용한다. `alertdialog`는 이번 구현 범위가 **아니다.**
  `role`을 prop으로 여는 순간 Workspace 오용 통로가 열리며, 짧은 경고를 위한 별도 recipe가 필요해지면
  그때 독립 컴포넌트로 만든다.
- 보이는 제목을 `aria-labelledby`, 설명을 `aria-describedby`로 연결한다. id는 인스턴스마다 고유하다.
  설명이 렌더되지 않았으면 `aria-describedby`를 **붙이지 않는다.**
- 열림 초기 포커스, focus trap, 닫힘 focus return은 선택 사항이 아니다.
- modal 뒤 앱 root는 pointer뿐 아니라 보조 기술·키보드 접근도 막아야 한다.
- 모든 버튼에 visible `:focus-visible`이 있고 icon-only close에는 locale-aware accessible name이 있다.
  Dialog가 제공하는 버튼은 공용 focus ring 유틸을 직접 부착한다 — 그 유틸이 opt-in이므로 부착하지 않으면
  링이 조용히 사라진다.
- busy, error, status는 [Loading Pattern](../patterns/loading.md)과 live region 계약을 따른다. Dialog는
  인스턴스마다 polite live region을 하나 소유하고 dismiss 차단 안내를 그곳에 쓴다.
- 320px, 200% 확대, light/dark, reduced-motion, KO/EN/JA를 검증한다.

#### Specification

| Part/state      | 목표 token/recipe                                    | 검증                              |
| --------------- | ---------------------------------------------------- | --------------------------------- |
| Compact width   | `min(360px, 100vw - 40px)`                           | 320px viewport와 200% zoom        |
| Task max width  | content tier token                                   | 긴 폼과 locale별 문구             |
| Surface radius  | compact 24px, large `radius-overlay` 16px            | compact/regular visual regression |
| Surface padding | compact 16px, content tier에 따라 증가               | scroll 가능한 content/action 분리 |
| Backdrop        | `surface-scrim-modal` = neutral 50% reference        | light/dark 대비                   |
| Action height   | 44px 이상                                            | pointer/touch target              |
| Action gap      | 8px                                                  | 200% zoom reflow                  |
| Elevation       | `elevation-modal`                                    | overlay hierarchy                 |
| Layer           | `layer-modal`, 숫자 리터럴 금지                      | nested overlay stack              |
| Enter motion    | `motion-modal-enter`: opacity + translate/scale      | reduced-motion 대체               |
| Exit motion     | `motion-modal-exit`, unmount lifecycle과 같은 source | animation completion              |
| Reduced motion  | 비필수 transform/filter 제거, 즉시 또는 짧은 opacity | motion preference                 |

#### Implementation

- Web source: `packages/react/src/dialog/**`
- CSS recipe: `packages/css/src/component/dialog.css`
- Public import: `import { Dialog, OverlayProvider } from "@klipse-design/react"`
- Tests: `packages/react/test/dialog.browser.test.tsx` (실브라우저 15건, 두 motion context에서 각각)
- Storybook: `apps/storybook/stories/dialog.stories.tsx`

소비자는 앱 root에 `OverlayProvider`를 한 번 둔다. Menu와 같은 Provider이며 Dialog가 두 번째 소비자다.

##### 계층 분담

| 계약 | 소유 |
| --- | --- |
| modal 격리 3축, 중첩 형제 격리, scroll lock refcount, Escape 단계별 닫힘, presence, focus 복원 시점, branch lineage, 인스턴스 id | overlay primitive (DS-P3-005) |
| variant → 정책 해석, backdrop 판정, confirm/cancel 어휘, 호출 요소 캡처, aria 배선, 차단 안내 | 이 recipe |
| scrim·surface·header/body/footer의 시각 표현과 responsive geometry | `dialog.css` |

Dialog는 anchored가 아니라 Menu의 `AnchoredRoot`를 재사용하지 않는다. 그것은 `mode: "non-modal"`,
`layer: "popover"`, `anchored: true`를 하드코딩하고 positioner로 children을 감싸며 Trigger를 전제한다.
전부 옵션화하면 남는 것은 `useOverlay`의 얇은 래퍼이고 두 recipe 중 어느 쪽도 그 조합의 절반을 쓰지 않는다.

**backdrop은 dialog surface의 형제이며 같은 portal subtree 안에 있다.** 별도 portal로 렌더하면 modal
host의 두 번째 직속 자식이 되고, primitive의 중첩 격리가 자기 자신의 backdrop에 inert를 걸어 클릭이
조용히 죽는다.

#### Known deviations

- **compact surface radius가 24px이 아니라 20px이다.** 24px 토큰이 소스에 없다. 값 자체는
  `radius-card-lg`(20px)로 자기 이름을 갖는다 — [DS-D-0014](../governance/decisions/DS-D-0014-card-radius.md)
  전까지는 `radius-card`를 빌려 썼고, 제품의 프로젝트 카드가 4벌 전부 16px이라 그 이름이 16으로
  내려갔다. "compact가 large보다 둥글다"는 서열은 유지된다.
- **최대폭과 viewport 여백이 토큰이 아니라 리터럴이다.** content tier 토큰과 20px spacing 토큰이 없다.
  Specification의 `viewport - 40px`을 맞추려면 20px이 필요해 값을 지키고 리터럴을 한 줄에 격리했다.
- **surface padding이 `space-layout-*`에서 온다.** `space-surface-*` tier가 없다. `space-control-*`는
  컨트롤 **내부** 스케일이라 표면 여백에 쓰지 않는다.
- **`surface-scrim-modal` 대신 `color-scrim-modal`을 쓰고 값이 50%가 아니라 56%(light)/72%(dark)다.**
  Specification 표가 대는 이름의 토큰이 없고 실제 값은 두 테마에서 다르다.
- **surface에 hairline border가 있다.** Specification 표에는 없지만 dark에서 `elevation-modal` 그림자만으로
  표면 경계가 서지 않는다. Menu 패널과 같은 판단이다.
- **Anatomy 3번 Positioner가 별도 DOM 노드가 아니다.** Dialog는 anchored가 아니라 positioner를 쓰지
  않는다. 그 역할은 overlay root가 grid 정렬과 padding으로 직접 소유한다.
- **dialog surface가 자손 `position: fixed`의 containing block이다.** enter transform과
  `container-type: inline-size`가 둘 다 그 효과를 낸다. Dialog 안에서 여는 Popover는 non-modal host로
  portal되어 surface의 자손이 아니므로 영향받지 않는다.
- **virtual keyboard가 열렸을 때 surface가 중앙에 남는다.** `100dvh`는 브라우저 chrome은 따라가지만
  소프트 키보드는 따라가지 않는다. visual viewport 추종은 CSS만으로 불가능하며 별도 결정이 필요하다.
- **`env(safe-area-inset-*)`와 `100dvh`의 실효를 자동 검증하지 못한다.** 브라우저 harness의 iframe에서
  `env()`는 0이고 `dvh === lvh === svh`다. 선언의 존재만 고정한다.
- **action의 세로 전환 임계값이 콘텐츠가 아니라 컨테이너 폭이다.** 긴 라벨은 `flex-wrap`이 받고
  좁은 폭·200% 확대는 surface의 container query가 받는다. 두 경로가 하나로 통합되지 않는다.
- **`alertdialog`를 지원하지 않는다.** Accessibility가 "검토한다"고만 쓴 것을 이번 구현은 "하지 않는다"로
  확정했다. `role`을 prop으로 여는 것이 Workspace 오용의 최단 경로다.
- **exit 동안 배경 격리가 먼저 풀린다.** focus 복원 대상이 inert면 `focus()`가 무효가 되므로 격리 해제가
  복원보다 앞선다. 그 결과 exit 모션(200ms) 동안 배경이 다시 조작 가능해진다. scroll lock은 그대로 유지해
  화면이 튀지 않는다.

#### Overlay behavior layer

modal 격리·scroll lock·focus 복원·중첩 stack은 `packages/react/src/overlay/`의 내부 primitive가
구현한다. Dialog recipe는 그 위에 얹히며 순서를 다시 쓰지 않는다. 경계는
[DS-D-0011](../governance/decisions/DS-D-0011-overlay-primitive-boundary.md)이 소유한다.

| 계약 | 구현 | 회귀 테스트 |
| --- | --- | --- |
| 배경을 pointer·keyboard·a11y tree 세 축에서 차단 | `overlay/inert-controller.ts` | `overlay-stacking.browser.test.tsx` |
| Dialog 안 Popover는 inert 면제 | 같은 파일의 포함 관계 판정 | `overlay-stacking.browser.test.tsx` |
| 중첩 Dialog는 topmost만 조작 가능 | modal host 내부 형제 격리 | `overlay-stacking.browser.test.tsx` |

| Escape는 최상위 한 단계만, 잠기면 아래로 넘기지 않음 | `overlay/overlay-store.ts` | `overlay-keyboard`, `overlay-store.node` |
| unmount 전에 focus를 돌려준다 | `overlay/presence.ts` + `overlay/focus-region.tsx` | `overlay-keyboard.browser.test.tsx` |

transition과 같은 CSS 선언을 읽으므로 두 값이 어긋날 수 없다(DS-D-0011 결정 3).

#### Migration

1. ~~focus scope, inert, scroll lock, stack, overlay branch를 가진 headless `Dialog` primitive를 만든다.~~
   **해소(DS-P3-005).**
2. 단일 `Dialog` compound와 `variant` prop으로 confirm·task·media-workbench를 표현한다. 세 개의 별도
   recipe를 만들지 않는다 — 셋의 차이는 초기 포커스 기본값, dismiss 기본값, 크기 tier 세 값뿐이고,
   그 값을 세 컴포넌트에 흩으면 규범이 한 곳에서 읽히지 않는다. 필요하면 소비자가 자기 앱에서
   `variant`를 고정한 얇은 래퍼를 만든다.
3. 단순 confirm 소비처를 먼저 이관하고 danger action의 전역 Enter confirm을 금지한다.
4. form/legal/media modal을 공용 primitive로 옮겨 Escape·focus·scroll 정책을 맞춘다.
5. 영상 편집 UI를 `VideoEditorWorkspaceCore`, `VideoEditorDialog`, `VideoEditorRouteWorkspace`로 분리한다.
6. AppShell grid가 sidebar와 main rect를 유일하게 계산하도록 하고 raw offset/z-index를 제거한다.
7. Figma variant와 interaction/visual/a11y 테스트를 연결한 뒤 기존 Modal adapter를 폐기한다.

#### Migration acceptance tests

##### Dialog behavior

- pointer와 keyboard 각각으로 열었을 때 variant별 initial focus가 맞다.
- Tab/Shift+Tab이 top Dialog와 그 nested overlay branch 안에서만 순환한다.
- Escape는 top dismissible Dialog만 닫고 Trigger로 포커스를 돌린다.
- modal 동안 뒤 앱의 button/link/canvas가 pointer, keyboard, accessibility tree에서 상호작용되지 않는다.
- body/scroll owner가 잠기고 닫힌 뒤 기존 scroll 위치와 inline style이 복원된다.
- backdrop, Surface, nested portaled Popover 클릭이 각각 올바른 dismiss 결과를 만든다.
- busy 중 중복 confirm과 accidental dismiss가 차단되고 상태가 읽힌다.
- danger-confirm은 focus되지 않은 상태의 전역 Enter로 실행되지 않는다.
- 두 Dialog를 쌓아도 topmost 하나만 Escape, focus trap, confirm을 처리한다.

##### Modal editor versus route workspace

- 캔버스에서 여는 영상 편집기는 viewport modal overlay에 있고 backdrop, dialog semantics, focus trap을 가진다.
- route editor는 page main rect 안에 있고 backdrop, `aria-modal`, modal focus trap이 없다.
- desktop sidebar expanded/collapsed 각 상태와 전환 중 `sidebarRect.right <= workspaceRect.left`를 만족한다.
- Workspace가 viewport 기준 `fixed left:0`이 아니며, shell이 할당한 host를 100% 채운다.
- top chrome action portal은 editor body의 layout rect를 바꾸거나 sidebar 위 hit area를 만들지 않는다.
- 719px 경계 전후에서 mobile drawer는 닫혀 있을 때 hit area가 없고, 열리면 backdrop과 닫기 동작이 있다.
- Workspace 안의 ConfirmDialog는 앱 modal root에 떠서 editor와 shell을 모두 차단한다.
- 브라우저 뒤로가기와 dirty guard가 modal close와 혼동되지 않는다.

##### Visual and accessibility

- 320px, 200% 확대, KO/EN/JA 긴 문구, light/dark, reduced-motion에서 내용과 action이 잘리지 않는다.
- focus-visible, 이름·설명 연결, 중복 id, axe smoke를 검증한다.
- sidebar/workspace와 modal stack의 bounding-box·hit-test 회귀를 브라우저 테스트로 고정한다.

이 테스트와 Figma variant가 연결되고 알려진 편차가 닫히기 전에는 `stable`로 승격하지 않는다.
