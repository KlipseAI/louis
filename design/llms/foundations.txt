검토하지 않은 값을 그대로 복사하지 않는다.

[`@klipse-design/tokens`](../../packages/tokens/README.md)에서 관리한다.

#### 공통 품질 기준

- WCAG 2.2 AA를 기본 목표로 한다.
- keyboard와 pointer로 동일한 핵심 기능을 사용할 수 있어야 한다.
- focus-visible은 가려지지 않고 명확해야 한다.
- 200% zoom과 좁은 container에서도 핵심 동작을 잃지 않아야 한다.
- 색만으로 상태를 전달하지 않는다.
- `prefers-reduced-motion`에서 비필수 motion을 줄인다.

AI용 projection은 [Foundations text](foundations.txt)로 생성된다.

### Color & Theme

Color & Theme은 색 값을 나열하는 문서가 아니라, 같은 의미가 light/dark 환경에서 예측 가능한 역할로
해석되게 하는 계약이다. P2 source와 platform projection은 로컬 release-candidate다. Package public
release, 제품 adoption과 published Figma library는 아직 `not-ready`다.

#### Source and artifacts

| 구분           | 계약 경로                                     | 현재 상태               |
| -------------- | --------------------------------------------- | ----------------------- |
| DTCG source    | `packages/tokens/src/klipse.tokens.json`      | local release-candidate |
| Validator      | `scripts/lib/token-model.mjs`                 | local release-candidate |
| CSS            | `packages/tokens/generated/tokens.css`        | done projection         |
| JavaScript     | `packages/tokens/generated/index.js`          | done projection         |
| TypeScript     | `packages/tokens/generated/index.d.ts`        | done projection         |
| Resolved JSON  | `packages/tokens/generated/tokens.json`       | done projection         |
| Figma proposal | `packages/tokens/generated/figma.tokens.json` | done, not published     |
| Manifest       | `packages/tokens/generated/manifest.json`     | done projection         |
| Diff baseline  | `packages/tokens/baseline/manifest.json`      | local release-candidate |

Raw color와 semantic color는 단일 DTCG source 안의 논리적 계층이다. 모든 artifact는 projection이며 직접
수정하지 않는다.

#### Token model

1. **Primitive**는 팔레트 값과 투명도처럼 의미 없는 재료를 소유한다.
2. **Semantic**은 background, foreground, border, accent, feedback, focus 같은 사용 목적을 소유한다.
3. P3의 component token은 semantic token만 참조하며 primitive를 직접 참조하지 않는다.

제품 코드는 semantic color만 소비한다. primitive 이름을 화면 의미로 사용하거나 기존 CSS 변수 이름을
새 정본으로 승격하지 않는다.

#### Theme modes

- `light`와 `dark`를 필수 mode로 둔다.
- theme-dependent semantic token은 두 mode 모두에서 명시적으로 resolve되어야 한다.
- 누락된 dark 값을 light 값으로 암묵 fallback하지 않는다.
- CSS는 기본 theme와 `[data-theme="dark"]` override의 semantic custom property를 결정론적으로 생성한다.
- 생성 CSS는 light/dark selector에 대응하는 `color-scheme`을 선언한다. 소비 제품이 해당 selector를
  document에 적용하고 browser chrome·SSR 초기 mode와 동기화하는 동작은 P3/P5에서 검증한다.
- SSR과 첫 paint에서 사용할 theme 결정은 소비 제품이 소유하지만, 생성 CSS는 theme 전환 중 이름이나
  cascade 순서를 바꾸지 않는다.
- forced-colors/high-contrast 환경은 별도 색 mode로 가장하지 않고 system color와 focus visibility
  대체 규칙을 문서화한다.

#### Alias and naming rules

- alias는 같은 type만 가리키며 cycle과 dangling reference를 허용하지 않는다.
- semantic token이 primitive로 resolve되는 방향만 허용하고 primitive가 semantic token을 참조하지 않는다.
- source ID는 CSS, JavaScript, TypeScript와 Figma 이름이 바뀌어도 추적 가능한 안정 식별자다.
- 플랫폼 이름 변환 충돌은 build error다.
- alpha가 있는 색은 실제 배경과 함께 contrast pair를 선언한다.

#### Accessibility

- 일반 텍스트 foreground/background pair는 4.5:1 이상을 목표로 한다.
- 큰 텍스트와 의미 있는 비텍스트 그래픽·control boundary는 3:1 이상을 목표로 한다.
- success, warning, danger, selected 상태는 색 외의 텍스트·아이콘·형태 신호를 함께 제공한다.
- contrast 검사는 임의의 모든 색 조합이 아니라 source에 선언한 허용 pair를 대상으로 한다.

#### Acceptance tests

이 절은 P2 local RC에서 자동화한 source·생성물 검사다. 실제 component의 forced-colors, 상태별 비색상
신호와 화면 대비는 P3/P5 소비 구현 게이트이며 아직 `not-ready`다.

- schema가 알 수 없는 field, 잘못된 color type과 중복 ID를 거부한다.
- alias graph가 cycle, dangling reference와 type mismatch를 거부한다.
- 모든 semantic color가 light/dark에서 하나의 값으로 resolve된다.
- 선언된 contrast pair가 각 mode에서 기준을 통과한다.
- CSS의 semantic mode/output과 JS·JSON·Figma proposal·manifest의 primitive/semantic color graph가 같은
  normalized model과 일치한다. 생성 CSS의 light/dark `color-scheme` selector도 검사한다.
- alias target, description/deprecation과 source provenance는 JS·JSON·Figma proposal·manifest에서 source와
  일치한다.
- 같은 process에서 동일 source를 두 번 render한 결과가 byte-for-byte 동일하다.
- Figma proposal 생성만으로 manifest의 Figma 상태를 `partial` 또는 `done`으로 올리지 않는다.

### Typography

Typography는 글꼴 크기 목록이 아니라 정보 위계, 읽기 흐름, locale fallback과 확대 수용 조건을 함께
정의한다. P2 source와 projection은 로컬 release-candidate다. Public package API와 제품 adoption은 아직
`not-ready`다.

#### Source and artifacts

| 구분           | 계약 경로                                     | 현재 상태               |
| -------------- | --------------------------------------------- | ----------------------- |
| DTCG source    | `packages/tokens/src/klipse.tokens.json`      | local release-candidate |
| Validator      | `scripts/lib/token-model.mjs`                 | local release-candidate |
| CSS            | `packages/tokens/generated/tokens.css`        | done projection         |
| JavaScript     | `packages/tokens/generated/index.js`          | done projection         |
| TypeScript     | `packages/tokens/generated/index.d.ts`        | done projection         |
| Resolved JSON  | `packages/tokens/generated/tokens.json`       | done projection         |
| Figma proposal | `packages/tokens/generated/figma.tokens.json` | done, not published     |
| Manifest       | `packages/tokens/generated/manifest.json`     | done projection         |
| Diff baseline  | `packages/tokens/baseline/manifest.json`      | local release-candidate |

Primitive와 semantic typography는 단일 DTCG source 안의 논리적 계층이며 별도 정본 파일이 아니다.

#### Token model

- primitive는 font family, weight, size, line-height와 letter-spacing 재료를 소유한다.
- semantic role은 display, title, heading, body, label, caption, code처럼 사용 목적을 소유한다.
- semantic typography는 필요한 primitive field를 묶는 composite contract다.
- 컴포넌트가 임의 size/weight 조합을 새 role처럼 만들지 않는다.
- source의 dimension은 값과 unit을 명시하며 generator가 px/rem을 추측하지 않는다.

#### Locale and font loading

- P2 source는 공용 multi-script fallback 후보를 ordered font-family 배열로 보존한다. Validator는 trim된
  non-empty string 배열과 typography composite 구조를 검사하며 실제 script별 glyph 지원을 증명하지 않는다.
- locale별 font 선택, asset 제공과 실제 glyph coverage 검증은 소비 환경이 소유하며 P3/P5 전에는 완료로
  간주하지 않는다.
- fallback은 weight와 glyph coverage가 없는 font를 무조건 첫 순서에 두지 않는다.
- webfont 로딩 전후에도 button, navigation, card title과 dialog action이 잘리거나 순서가 바뀌지 않아야
  한다.
- 숫자, timestamp, code처럼 정렬 안정성이 필요한 role은 별도 요구를 선언한다.
- 제품별 branding font는 공용 role의 접근성과 fallback 계약을 만족할 때만 alias target으로 제안한다.

#### Responsive and inclusive behavior

- 200% text zoom에서도 핵심 정보와 action이 사라지지 않는다.
- line-height를 고정 box 높이로 상쇄하지 않는다.
- 긴 KO/EN/JA 문구에서 truncation은 정보 우선순위와 대체 접근 경로가 있을 때만 허용한다.
- font size만으로 heading semantics를 대신하지 않는다.
- 사용자가 브라우저 기본 크기를 바꿨을 때 semantic hierarchy가 유지되어야 한다.

#### Platform mapping

- CSS는 font family, size, weight, line-height, letter-spacing을 안정된 semantic custom property로 생성한다.
- JavaScript와 resolved JSON은 composite field와 unit을 보존한다. TypeScript declaration은 안정 token ID,
  type·mode·alias target, `TypographyValue`와 nested dimension value 구조, primitive/semantic container를
  선언한다. Token별 실제 resolved 숫자와 문자열은 runtime data이며 literal value union으로 고정하지 않는다.
- Figma proposal에서 native variable로 표현할 수 없는 composite는 field별 mapping과 loss metadata를
  포함한다. semantic `typography-*`는 text style로, primitive `type-style-*`는 미표현으로 분류한다
  ([DS-D-0007](../governance/decisions/DS-D-0007-figma-library-structure.md)).
- platform 변환이 의미를 잃으면 조용히 근사하지 않고 build warning 또는 error로 분류한다.

#### Acceptance tests

P2 local RC는 아래의 구조·생성 검사를 자동화한다.

- schema가 허용되지 않은 weight, unit과 불완전한 composite를 거부한다.
- 모든 semantic role이 필요한 field를 빠짐없이 resolve한다.
- CSS의 semantic field projection과 JS·JSON·Figma proposal·manifest의 primitive/semantic composite가
  normalized model과 일치하고 TypeScript가 해당 ID/type/value shape를 선언한다.
- Figma가 composite를 직접 표현하지 못하면 field mapping과 loss metadata를 제공한다.
- 같은 process에서 동일 source를 반복 render한 결과가 byte-for-byte 동일하다.

다음은 P3/P5 소비 구현 게이트이며 아직 `not-ready`다.

- KO/EN/JA별 실제 fallback 순서, font asset과 glyph coverage 근거가 준비되어 있다.
- 320px container, 200% zoom과 긴 KO/EN/JA fixture에서 핵심 label/action이 잘리지 않는다.
- font loading 전후의 주요 layout shift가 승인된 기준을 넘지 않는다.

### Spacing & Radius

Spacing & Radius는 모든 픽셀 값을 토큰으로 만드는 체계가 아니다. 반복되는 관계와 surface 계층을 이름
있는 계약으로 만들고, 제품별 scene geometry는 제품에 남긴다. P2 source와 projection은 로컬
release-candidate이며 public package와 제품 adoption은 아직 `not-ready`다.

#### Source and artifacts

| 구분           | 계약 경로                                     | 현재 상태               |
| -------------- | --------------------------------------------- | ----------------------- |
| DTCG source    | `packages/tokens/src/klipse.tokens.json`      | local release-candidate |
| Validator      | `scripts/lib/token-model.mjs`                 | local release-candidate |
| CSS            | `packages/tokens/generated/tokens.css`        | done projection         |
| JavaScript     | `packages/tokens/generated/index.js`          | done projection         |
| TypeScript     | `packages/tokens/generated/index.d.ts`        | done projection         |
| Resolved JSON  | `packages/tokens/generated/tokens.json`       | done projection         |
| Figma proposal | `packages/tokens/generated/figma.tokens.json` | done, not published     |
| Manifest       | `packages/tokens/generated/manifest.json`     | done projection         |
| Diff baseline  | `packages/tokens/baseline/manifest.json`      | local release-candidate |

Dimension primitive, semantic spacing/radius와 responsive profile은 단일 DTCG source 안의 논리적 계층이다.

#### Spacing model

- primitive scale은 반복 가능한 dimension 재료를 제공한다.
- semantic spacing은 control inset, stack gap, section gap, surface inset, shell outer gap처럼 관계를
  설명한다.
- App Shell outer gap, content inset, navigation leading line과 Project Grid gap/card minimum은 source에서
  서로 다른 의미로 유지한다.
- hit target 최소 크기와 시각 padding을 같은 token으로 간주하지 않는다.
- 음수 값으로 Shell ownership 오류를 보정하지 않는다.
- 제품별 scene 좌표나 일회성 media crop 값은 공용 token으로 승격하지 않는다.

#### Radius model

- radius는 control, surface, overlay, overlay-item처럼 계층과 사용 목적을 표현한다.
- `radius-overlay`와 `radius-overlay-item`은 별도 semantic role이며 하나의 숫자를 우연히 공유해도 같은
  token으로 합치지 않는다.
- pill/circle은 고정 숫자보다 shape semantics로 표현한다.
- component가 임의 radius literal을 추가하려면 두 개 이상의 사용처와 시각·접근성 근거가 필요하다.

#### Responsive profile

`packages/tokens/src/klipse.tokens.json`의 Klipse responsive profile metadata는 일반 component breakpoint
묶음이 아니라 [Responsive Layout](../foundations/responsive-layout.md)의 Shell migration compatibility profile을
기계적으로 표현한다.

- component와 grid는 실제 container 크기로 적응한다.
- viewport profile을 component 내부 media query의 기본값으로 사용하지 않는다.
- Project Grid의 `minimumCard`와 `gap`은 각각 안정 semantic ID `layout-project-card-minimum`과
  `layout-project-grid-gap`을 참조한다.
- container 최소 폭 0/720/1200/1800px에서 preferred column은 2/3/4/5다. Preferred 값이 card minimum과
  gap을 만족하지 못하면 capacity 계산으로 1열까지 안전하게 줄인다.
- profile step이나 capacity 결과를 바꾸려면 Responsive Layout, App Shell, Project Grid와 migration evidence를
  함께 갱신한다.
- safe-area inset은 환경 입력이며 고정 spacing primitive가 아니다.

#### Units and platform mapping

- source dimension은 number와 unit을 명시한다.
- CSS는 source unit을 그대로 직렬화하고 JavaScript/resolved JSON은 DTCG `{value, unit}` 구조를 보존한다.
- TypeScript declaration은 안정 token ID, token별 type·mode·alias target과 `{ value, unit }` dimension shape를
  선언한다. Token별 실제 숫자는 runtime data이며 literal value union으로 고정하지 않는다.
- Figma proposal은 원래 dimension value와 unit-loss metadata를 함께 제공한다. P2는 rem/px 변환이나
  platform별 rounding을 수행하지 않는다.

#### Acceptance tests

P2 local RC는 아래의 구조·생성 검사를 자동화한다.

- validator가 malformed `{value, unit}`, 알 수 없는 unit, alias type mismatch와 중복 ID를 거부한다.
  spacing/radius primitive, duration, shadow blur와 responsive minimum width처럼 명시된 field는 음수를 거부한다.
- semantic spacing/radius가 primitive 또는 승인된 semantic alias로 완전히 resolve된다.
- CSS의 semantic resolved value와 JS·JSON·Figma proposal·manifest의 primitive/semantic dimension
  value·unit이 normalized model과 일치하고 TypeScript가 해당 ID/type/value shape를 선언한다.
- Project Grid profile의 container measurement, ordered 0/720/1200/1800px step, 2/3/4/5 preferred column과
  stable minimum-card/gap reference shape를 검증한다.
- 같은 process에서 동일 source를 반복 render한 결과가 byte-for-byte 동일하다.

다음은 P3/P5 소비 구현 게이트이며 아직 `not-ready`다.

- Shell outer gap/content inset/navigation 정렬 관계가 sidebar 상태 전환 중 유지된다.
- Project Grid 구현이 profile과 실제 container capacity를 정확히 따르고 공간이 부족하면 1열까지 안전하게
  fallback한다.
- 320px, 200% zoom과 44px 권장 hit target에서 spacing이 핵심 action을 자르지 않는다.

## Elevation & Layer

- Source: design/foundations/elevation-layer.md
- Maturity: experimental

### Elevation & Layer

Elevation은 surface의 시각적 깊이이고 Layer는 interaction과 stacking 순서다. 그림자가 크다는 이유로 더
높은 z-index를 갖지 않으며 두 체계를 별도 token family로 유지한다. P2 source와 projection은 로컬
release-candidate이며 public package와 제품 adoption은 아직 `not-ready`다.

#### Source and artifacts

| 구분           | 계약 경로                                     | 현재 상태               |
| -------------- | --------------------------------------------- | ----------------------- |
| DTCG source    | `packages/tokens/src/klipse.tokens.json`      | local release-candidate |
| Validator      | `scripts/lib/token-model.mjs`                 | local release-candidate |
| CSS            | `packages/tokens/generated/tokens.css`        | done projection         |
| JavaScript     | `packages/tokens/generated/index.js`          | done projection         |
| TypeScript     | `packages/tokens/generated/index.d.ts`        | done projection         |
| Resolved JSON  | `packages/tokens/generated/tokens.json`       | done projection         |
| Figma proposal | `packages/tokens/generated/figma.tokens.json` | done, not published     |
| Manifest       | `packages/tokens/generated/manifest.json`     | done projection         |
| Diff baseline  | `packages/tokens/baseline/manifest.json`      | local release-candidate |

Elevation primitive, semantic elevation과 semantic layer는 단일 DTCG source 안의 논리적 계층이다.

#### Elevation model

- primitive는 shadow layer, offset, blur, spread와 color 재료를 소유한다.
- semantic role은 surface-raised, popover, modal처럼 사용 목적을 소유한다.
- `elevation-popover`와 `elevation-modal`은 light/dark surface에서 경계가 읽혀야 한다.
- 고대비 환경에서는 shadow만으로 surface 경계를 전달하지 않고 border/system color 대체를 제공한다.
- Figma는 shadow를 native variable로 표현하지 못한다. semantic `elevation-*`는 effect style로,
  primitive `shadow-*`는 미표현으로 분류하고 loss metadata를 남긴다
  ([DS-D-0007](../governance/decisions/DS-D-0007-figma-library-structure.md)).

#### Layer model

공용 상대 순서는 다음과 같다.

`layer-content < layer-sticky < layer-popover < layer-modal < layer-critical`

- source는 semantic 순서와 플랫폼별 numeric projection을 함께 검증한다.
- feature가 공용 순서 사이에 임의 숫자를 끼워 넣지 않는다.
- local floating UI는 자기 surface의 stacking context 안에 머문다.
- global popover와 modal은 App Shell의 승인된 overlay root를 사용한다.
- 투명하거나 closing 중인 layer가 보이는 control의 pointer/focus를 가로채면 실패다.
- `layer-critical`은 session/payment interruption처럼 승인된 system case에만 사용한다.

#### Platform mapping

- CSS는 elevation custom property와 layer custom property를 분리해 생성한다.
- CSS와 JavaScript는 resolved layer number를 노출하고 JS metadata와 JSON/manifest는 명시적인 relative
  order도 제공한다. TypeScript declaration은 token별 number/shadow value shape와 metadata의 semantic
  layer ID 순서를 선언한다.
- Figma proposal은 elevation을 전달하되 runtime stacking layer를 시각 style로 가장하지 않는다.
- layer 순서 변경은 이름이 유지돼도 behavior breaking change로 분류한다.

#### Acceptance tests

P2 local RC는 아래의 구조·생성 검사를 자동화한다.

- schema가 elevation/layer type 혼용과 승인되지 않은 layer 순서를 거부한다.
- CSS의 semantic layer number와 JS·JSON·Figma proposal·manifest의 primitive/semantic graph가 normalized
  model과 일치하고 명시적 relative order가 검증된다. TypeScript가 해당 ID/type/value shape를 선언하며
  Figma proposal은 비지원 항목을 loss metadata로 기록한다.
- 같은 process에서 동일 source를 반복 render한 결과가 byte-for-byte 동일하다.

다음은 P3/P5 소비 구현 게이트이며 아직 `not-ready`다.

- light/dark/high-contrast fixture에서 raised, popover와 modal 경계가 식별된다.
- profile popover, editor local floating UI와 modal을 함께 열어 상대 순서와 hit-test를 검증한다.
- closing layer가 action을 재실행하거나 뒤 control로 pointer event를 통과시키지 않는다.

## Motion

- Source: design/foundations/motion.md
- Maturity: experimental

### Motion

Motion은 장식 효과가 아니라 상태 전환, 공간 변화와 lifecycle 완료 시점을 설명한다. P2의 duration/easing
원본, semantic motion recipe, reduced-motion 대체와 platform projection은 로컬 release-candidate다. 실제
component animation과 public adoption은 P3 이후가 소유한다.

#### Source and artifacts

| 구분           | 계약 경로                                     | 현재 상태               |
| -------------- | --------------------------------------------- | ----------------------- |
| DTCG source    | `packages/tokens/src/klipse.tokens.json`      | local release-candidate |
| Validator      | `scripts/lib/token-model.mjs`                 | local release-candidate |
| CSS            | `packages/tokens/generated/tokens.css`        | done projection         |
| JavaScript     | `packages/tokens/generated/index.js`          | done projection         |
| TypeScript     | `packages/tokens/generated/index.d.ts`        | done projection         |
| Resolved JSON  | `packages/tokens/generated/tokens.json`       | done projection         |
| Figma proposal | `packages/tokens/generated/figma.tokens.json` | done, not published     |
| Manifest       | `packages/tokens/generated/manifest.json`     | done projection         |
| Diff baseline  | `packages/tokens/baseline/manifest.json`      | local release-candidate |

Motion primitive와 semantic recipe는 단일 DTCG source 안의 논리적 계층이며 별도 정본 파일이 아니다.

#### Token model

- primitive는 duration과 easing 재료를 소유한다.
- semantic recipe는 overlay-enter, overlay-exit, modal-enter, modal-exit, layout-change처럼 목적을 소유한다.
- Klipse `motionProperties` extension은 enter/exit lifecycle마다 duration, easing과 함께 허용 CSS property를
  선언한다. 선언되지 않은 property를 component가 임의로 animation하지 않는다.
- unmount timer와 interaction lock은 시각 transition과 같은 resolved recipe를 읽는다.
- loading처럼 지속 시간이 작업 완료에 달린 상태를 고정 animation duration으로 가장하지 않는다.

#### Reduced motion

- semantic recipe마다 `reduce` mode 또는 명시적인 대체가 있어야 한다.
- 위치·크기·scale 기반 비필수 motion은 제거하거나 짧은 opacity/state change로 대체한다.
- motion을 제거해도 open/closed, loading, success, error 의미가 텍스트와 상태로 남아야 한다.
- reduced-motion에서도 focus 이동, scroll lock, inert와 unmount 순서는 동일하다.

#### Platform mapping

- CSS는 duration/easing custom property와 semantic recipe metadata를 생성한다.
- JavaScript는 resolved transition 값과 motion metadata를 제공하고 TypeScript declaration은 token별
  transition value shape, ID·mode·alias target과 runtime container를 선언한다. 실제 animation completion과
  unmount lifecycle 연결은 P3/P5 소비 구현이 소유한다.
- Figma proposal은 지원 가능한 easing/duration을 매핑하고 spring·복합 keyframe처럼 손실되는 정보는
  metadata로 표시한다. semantic `motion-*`는 Figma가 해석하지 않는 문서용 STRING 변수로 격하하고
  primitive `transition-*`와 easing은 미표현으로 둔다
  ([DS-D-0007](../governance/decisions/DS-D-0007-figma-library-structure.md)).
- duration 또는 easing 변경은 사용자 동작·lifecycle에 영향을 주면 behavior change로 분류한다.

#### Acceptance tests

P2 local RC는 아래의 구조·생성 검사를 자동화한다.

- schema가 음수 duration, 알 수 없는 easing, 누락된 reduced-motion 대체를 거부한다.
- 모든 semantic recipe가 duration, easing, property와 reduce 결과로 resolve된다.
- `motionProperties`가 알려진 lifecycle만 참조하고 `opacity`, `transform` 등 validator가 허용한 CSS
  property만 포함한다.
- CSS의 semantic transition output과 JS·JSON·Figma proposal·manifest의 primitive/semantic transition
  graph가 normalized model과 일치하고 TypeScript가 해당 ID/type/value shape를 선언한다. Lossy mapping은
  Figma proposal에 명시된다.
- 같은 process에서 동일 source를 반복 render한 결과가 byte-for-byte 동일하다.

다음은 P3/P5 소비 구현 게이트이며 아직 `not-ready`다.

- Dialog/Popover exit 완료와 unmount 시점이 같은 source를 사용한다.
- `prefers-reduced-motion: reduce`에서 비필수 transform과 무한 shimmer가 제거된다.

## Iconography

- Source: design/foundations/iconography.md
- Maturity: experimental

### Iconography

아이콘은 라벨을 대체하지 않고 보강한다. 이 문서는 정본 위치, 기하 계약, 크기·색 계약, 접근성 기본값과
Web/Figma 표면을 소유한다. 정본 위치와 provenance 규칙은
[DS-D-0008](../governance/decisions/DS-D-0008-icon-source.md)이 결정했다.

#### Source and artifacts

| 역할 | 경로 |
| --- | --- |
| 정본 SVG | `packages/react/src/icons/svg/{name}.svg` |
| provenance | `packages/react/src/icons/provenance.json` |
| upstream 라이선스 원문 | `packages/react/src/icons/licenses/{key}.txt` |
| React 생성물 | `packages/react/src/icons/generated/index.tsx` |
| 아이콘 manifest | `packages/react/src/icons/generated/manifest.json` |
| 고지문 | `packages/react/THIRD-PARTY-NOTICES.md` |

generated 셋은 직접 수정하지 않는다. 정본을 고치고 `pnpm build:icons`를 실행한다.

**모든 글리프는 provenance를 갖는다.** `origin: "original"`이거나, upstream 프로젝트·아이콘 이름·
라이선스·라이선스 파일·출처 URL·취득일·수정 내역을 전부 갖는다. 추정 출처와 `unknown`은 빌드 실패다.
upstream 글리프를 채택하면 그 라이선스 원문이 저장소에 함께 들어오고 고지문이 패키지에 동봉된다.

#### Geometry contract

- `viewBox="0 0 24 24"`.
- **root `<svg>`는 `xmlns`와 `viewBox`만 갖는다.** 표현 속성은 요소마다 둔다 — root에 두면
  선언되지 않은 요소가 그것을 상속해, 보이지 않던 잔재가 갑자기 그려진다.
- `stroke="currentColor"`, `fill="none"`, `stroke-linecap="round"`, `stroke-linejoin="round"`를
  **요소마다** 명시한다.
- `stroke-width`는 **1.5** 하나만 허용한다.
- 요소는 `path` `circle` `rect` `ellipse` `line` `polyline` `polygon` `g`만 허용한다.
- 아무것도 그리지 않는 요소를 남기지 않는다(`g` 제외). upstream의 배경 `rect`가 대표적이다.
- `id`와 `clip-path`는 정본에 남길 수 없다. 인라인 SVG의 `id`는 문서 전역이라 같은 페이지의 다른
  아이콘과 클리핑이 서로 먹는다.
- 속성 따옴표는 `"`와 `'` 모두 유효하다. 두 형태가 다르게 취급되면 같은 문서가 규칙에 따라 다르게
  읽히므로, 파서는 둘을 동등하게 보고 **읽지 못한 태그는 통과가 아니라 실패로 처리한다.**

**1.5의 근거는 임의값이 아니다.** 제품의 정본 두께 공식은 `strokeWidth = screenPx × viewBox / size`이고
표준 `screenPx = size / 16`이므로 viewBox 32에서 stroke-width는 크기와 무관하게 상수 2다. 같은 광학
두께를 24 격자로 옮기면 `2 × 24 / 32 = 1.5`다. Figma 변수·component도 24 기준이 다루기 쉽다.

#### Size model

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--kds-icon-size-sm` | 16px | 조밀한 행, 인라인 |
| `--kds-icon-size-md` | 20px | 기본 |
| `--kds-icon-size-lg` | 24px | 단독 액션, 큰 타깃 |

- 원시 px를 받는 prop은 제공하지 않는다.
- **컨테이너와 글리프를 구분한다.** 컨테이너 크기는 컨트롤이 소유하고 글리프 크기는 아이콘이
  소유한다. 아이콘은 자기 컨테이너를 그리지 않으며 아이콘 래퍼에 배경색을 두지 않는다.
- 히트 영역은 아이콘이 소유하지 않는다. 주요 액션의 44×44 CSS px 계약은 부모 컨트롤이 소유한다
  ([Inclusive Design](../foundations/inclusive-design.md)의 "시각 아이콘 크기와 실제 히트 영역을 분리").

#### 검색

**사람은 아이콘의 이름을 모른 채 찾는다.** "휴지통"을 떠올리지 `trash-simple`을 떠올리지 않는다.
그래서 글리프마다 한국어와 영어 동의어를 함께 선언한다.

- 원천은 [`packages/react/src/icons/keywords.json`](../../packages/react/src/icons/keywords.json)이며
  글리프당 2개 이상, **한국어를 최소 하나** 포함해야 한다. 없으면 빌드가 실패한다.
- 같은 목록이 icon manifest와 Figma component description의 `KEYWORDS:` 블록에 함께 들어간다.
  parity 게이트가 둘이 갈라지지 않는지 매 실행 확인한다.
- 구분자는 ASCII 마커다. 이모지 마커는 파싱과 diff에서 다루기 어렵다.

#### 왜 낱개 component인가

Figma에서 아이콘 26개는 **각각 독립 component**다. component set으로 묶지 않는다.

variant 축은 **값이 2개 이상일 때만** 만든다. Klipse 아이콘은 두께가 `1.5` 하나뿐이라 묶을 축이
없다 — 축이 하나뿐인 set은 드롭다운에 값이 하나만 있는 빈 껍데기가 된다. 나중에 Fill 두께를
그리게 되면 그때 `Weight` 축으로 묶는다.

낱개여도 활용성이 떨어지지 않는 이유는 **소비 방식이 instance swap이기 때문**이다. Button의
`LeftIconGlyph`, IconButton의 `Glyph`가 INSTANCE_SWAP property이므로 컴포넌트 안에서 26개 중
아무거나 고를 수 있다. asset 패널은 `icon/` 접두사로 이미 한 폴더로 묶는다.

#### Color contract

- 아이콘은 `currentColor`만 쓴다. 자기 색을 정하지 않으며 부모의 `color`를 상속한다.
- 상태 색은 부모가 semantic token으로 준다. 색만으로 상태를 구분하지 않고 텍스트·형태 신호를 함께
  제공한다 ([Color & Theme](../foundations/color-theme.md)).
- 다색 글리프는 아이콘이 아니다. 브랜드 로고와 일러스트는 별도 트랙이다.

#### Accessibility

- **아이콘의 기본값은 장식이다.** `label`을 주지 않으면 `aria-hidden="true"`가 부여된다.
- **아이콘은 accessible name을 제공하지 않는 것이 기본이다.** 아이콘 전용 버튼의 이름은 버튼이
  `aria-label`로 소유한다 ([Button](../components/button.md)의 Accessibility). 아이콘에도 `label`을
  주면 이름이 두 겹으로 노출된다.
- `label`은 아이콘이 화면에서 **유일한 정보 전달 수단일 때만** 준다. 텍스트 라벨이 곁에 있으면
  아이콘은 언제나 장식이다.
- 아이콘은 라벨의 의미를 반복 설명하지 않는다 ([Menu & Popover](../components/menu-popover.md)).
- 아이콘은 focus를 받지 않는다. 상호작용은 부모 컨트롤이 소유한다.
- forced-colors 모드에서 아이콘은 시스템 텍스트 색을 따라야 한다. `mask-image` + 배경색 기반 렌더는
  이 요구를 만족하지 못하므로 정본 소비 경로가 아니다.

#### Web surface

`@klipse-design/react/icons`가 글리프당 named export와 `IconName` union을 제공한다. 시그니처는
`IconProps`가 소유하며 `size`와 `label` 두 prop만 노출한다. Button의 `leftIcon`/`rightIcon`은
`ReactNode`로 유지되므로 Button API는 바뀌지 않는다.

서브패스는 첫 글리프 세트가 게이트를 전부 통과한 뒤에 열었다(DS-D-0008 Rollback). **제거는
breaking이므로**(DS-D-0006) 글리프 이름과 심볼은 이제 공개 계약이다.

`packages/react`의 `files`에 `THIRD-PARTY-NOTICES.md`가 포함되므로, 패키지를 받는 쪽은 upstream
라이선스 원문을 함께 받는다. 고지문 없이 아이콘만 배포되는 경로는 존재하지 않는다.

#### Figma mapping

- 이름은 `icon/{kebab-name}`, 개별 component다. component set이 아니다 — 아이콘 이름은 prop이 아니라
  심볼 식별자이므로 `componentPropertyDefinitions` ↔ 코드 prop 대조 규칙(DS-F-006)과 의미가 어긋난다.
- frame은 24×24 하나다. **크기 variant를 두지 않는다.** 두면 코드의 `IconSize`와 Figma variant가 두
  정본이 되어 4px 격자를 누가 소유하는지 모호해진다. 크기는 코드와 이 문서가 소유한다.
- stroke는 색 변수에 바인딩한다. Figma에는 `currentColor`가 없으므로 DS-F-006의 "raw 값 0"을
  만족하려면 변수를 물어야 한다.

#### Naming and lifecycle

- kebab-case, upstream 이름을 우선하되 Klipse 의미가 다르면 우리 이름을 쓴다.
- 글리프 제거와 이름 변경은 named export 제거이므로 breaking이다(DS-D-0006).

#### Not adopted

| 항목 | 사유 |
| --- | --- |
| `mask-image` + 배경색 소비 | npm 패키지가 소유할 수 없는 URL에 의존하고, 아이콘당 요청 1건이며, forced-colors에서 무너지고, stroke 계약을 소비 시점에 게이트할 수 없다 |
| SVG sprite | 외부 sprite는 소비 앱의 public 경로에 의존하고, 인라인 sprite는 전량 DOM 삽입이라 tree-shaking이 불가능하다 |
| 12 / 13 / 14 / 15px | 4px 격자 밖. 제품 실측의 15px 다수는 노드 캔버스 국소값이다. 이관 시 16으로 수렴한다 |
| 32px과 64px | 32는 정본 viewBox와 숫자가 같아 혼동을 만든다. 64는 빈 상태 컴포넌트가 생길 때 사유와 함께 추가한다 |
| `vector-effect: non-scaling-stroke` | 아이콘 규범이 아니라 줌 컨텍스트의 국소 처방이다 |
| 크기 variant를 가진 Figma component set | 정본 이중화 |
| 브랜드 로고·상표를 아이콘 슬롯에 투입 | 다색·고정색이라 `currentColor` 계약을 만족할 수 없고 상표 조건이 다른 축이다 |

#### Known deviations

| 항목 | 상태 | 사유 |
| --- | --- | --- |
| 실루엣 정확성 | 게이트 없음 | 정규화·해시·이름·고지는 기계가 잡지만 "이 글리프가 의도한 그림인가"는 사람의 시각 review다 |
| 출처 미확정 글리프 | 미채택 | provenance를 확인할 수 없는 글리프는 채택하지 않는다(DS-D-0008 결정 3). 재작도 또는 확인이 선행 조건이다 |

#### Acceptance tests

1. 세 크기 토큰의 계산 박스가 브라우저에서 16 / 20 / 24 CSS px다.
2. `label` 없는 아이콘이 accessibility tree에 노출되지 않는다.
3. `label` 있는 아이콘이 `role="img"`와 해당 이름으로 정확히 한 번 노출된다.
4. 아이콘 전용 버튼의 accessible name이 버튼의 `aria-label` 하나이며 중복되지 않는다.
5. 부모 `color` 변경이 light/dark 양쪽에서 아이콘 stroke에 반영된다.
6. forced-colors 모드에서 아이콘이 시스템 텍스트 색을 따른다.
7. 같은 아이콘 두 개를 한 문서에 렌더해도 id 충돌로 클리핑이 깨지지 않는다.
8. 200% zoom에서 아이콘과 라벨의 정렬이 유지된다.
9. 한 아이콘만 import한 production 번들에 다른 글리프의 path 데이터가 포함되지 않는다.
10. `THIRD-PARTY-NOTICES.md`가 provenance의 모든 upstream 라이선스 원문을 포함한다.

## Interaction states

- Source: design/foundations/interaction-states.md
- Maturity: experimental

### Interaction states

컨트롤이 가질 수 있는 상태의 **이름과 그 이름이 가리키는 기술적 사실**을 고정한다. 이 문서가 없던
동안 Button은 `Pressed`를 "누르고 있는 중"으로, Icon Button은 `pressed`를 "토글이 켜짐"으로 썼다.
같은 단어가 두 컴포넌트에서 다른 것을 가리켰고, 그 상태로 Figma component set이 하나 만들어졌다.

#### 이름은 웹 플랫폼에서 가져온다

새 단어를 만들지 않는다. 상태 이름은 CSS pseudo-class 또는 ARIA 속성 이름을 그대로 쓴다. 그러면
"이 이름이 무슨 뜻인가"를 이 문서가 아니라 플랫폼 명세가 답한다.

| 이름       | 출처                    | 가리키는 사실                          | 축              |
| ---------- | ----------------------- | -------------------------------------- | --------------- |
| `default`  | —                       | 아무 상태도 아님                       | —               |
| `hover`    | `:hover`                | 포인터가 위에 있음                     | 일시적          |
| `focus`    | `:focus-visible`        | 키보드 focus가 있음                    | 일시적          |
| `active`   | `:active`               | **누르고 있는 동안**                   | 일시적          |
| `pressed`  | `aria-pressed="true"`   | **토글이 켜져 있음**                   | 지속            |
| `selected` | `aria-selected="true"`  | 목록·탭에서 선택됨                     | 지속            |
| `checked`  | `aria-checked`          | 체크박스·라디오가 켜짐                 | 지속            |
| `expanded` | `aria-expanded="true"`  | 연결된 표면이 열려 있음                | 지속            |
| `disabled` | `:disabled`, `aria-disabled` | 실행되지 않음                     | 지속            |
| `busy`     | `aria-busy="true"`      | 진행 중이며 중복 실행을 막음           | 지속            |

#### `active`와 `pressed`를 절대 섞지 않는다

가장 자주 틀리는 곳이라 따로 적는다.

- `active`는 **손가락이 닿아 있는 동안**이다. 떼면 사라진다. 시각적으로는 눌리는 피드백이다.
- `pressed`는 **토글이 켜진 상태**다. 손을 떼도 남는다. 시각적으로는 켜져 있음의 표시다.

둘을 같은 시각으로 표현하면 사용자는 버튼이 눌린 것인지 켜진 것인지 구분할 수 없다. 이름까지
같으면 **만드는 사람도 구분하지 못한다** — 실제로 그렇게 됐다.

일상 영어에서 "pressed"가 두 뜻을 다 갖는 것이 원인이다. 그래서 일상 영어가 아니라 플랫폼 이름을
정본으로 삼는다: `:active`가 있는 쪽이 `active`, `aria-pressed`가 있는 쪽이 `pressed`다.

#### 어느 상태를 어디가 소유하는가

| 축                    | 소유                          | 이유                                                     |
| --------------------- | ----------------------------- | -------------------------------------------------------- |
| 일시적 상태           | CSS pseudo-class              | 브라우저가 이미 안다. prop으로 받으면 두 진실이 생긴다   |
| 지속 상태             | prop → ARIA 속성 → `[attr]` 선택자 | 보조 기술이 읽어야 하므로 DOM에 남아야 한다      |

**일시적 상태를 prop으로 받지 않는다.** `hovered`, `active` 같은 prop을 두면 호출부가 브라우저와
경쟁하게 되고, 둘이 어긋나는 순간 어느 쪽이 옳은지 판정할 근거가 없다.

지속 상태는 `data-*`가 아니라 **ARIA 속성 자체**를 선택자로 쓴다. `[aria-pressed="true"]`가
`[data-pressed="true"]`보다 나은 이유는 하나뿐인데 결정적이다 — 속성이 없으면 스타일도 없으므로,
**보조 기술에 노출되지 않은 상태는 화면에도 나타날 수 없다.** 둘이 어긋날 방법이 없어진다.

값이 boolean이 아닌 축(`variant`, `size`)은 이 규칙 밖이며 `data-*`를 쓴다 (DS-D-0004).

#### Figma에서의 표현

Figma에는 CSS 상태가 없다. 그래서 일시적 상태도 variant property로 만들어야 하고, 그 property는
**코드에 대응하는 prop이 없다.** parity 게이트는 그런 property를 사유와 함께 계약에 선언해야만
통과시킨다 — 선언되지 않은 property가 생기면 실패한다.

variant option 이름은 이 문서의 이름을 **대문자로 시작해** 그대로 쓴다: `Default`, `Hover`,
`Active`, `Pressed`, `Disabled`, `Loading`. 컴포넌트가 갖지 않는 상태는 option을 만들지 않는다.

#### Accessibility

- 지속 상태는 반드시 ARIA 속성으로 노출된다. 색이나 굵기만으로 표현된 상태는 상태가 아니다.
- 토글이 아닌 컨트롤에 `aria-pressed`를 붙이지 않는다. 한 번 실행되고 끝나는 액션에 붙이면
  스크린리더가 "눌림/안 눌림"을 계속 읽는다.
- `disabled`는 이유를 인접 텍스트로 제공한다. 비활성 자체는 이유를 말하지 않는다.
- 상태 전환에 애니메이션을 쓰는 경우 [Motion](../foundations/motion.md)의 reduced-motion 계약을 따른다.

#### Acceptance tests

1. 컴포넌트 규범의 States 표에 쓰인 이름이 모두 이 문서의 표에 있다.
2. `active`와 `pressed`를 함께 갖는 컴포넌트에서 둘의 시각 표현이 서로 다르다.
3. 지속 상태가 ARIA 속성 없이 시각적으로만 표현되는 경우가 없다.
4. Figma component set의 State option 이름이 이 문서의 이름과 일치한다.

#### Migration and changelog

- 2026-08-15 — 첫 공개. Button의 Figma `State=Pressed`(실제로는 `:active`)와 Icon Button 규범의
  `pressed`(실제로는 `aria-pressed`)가 충돌한 것을 발견해 어휘를 고정했다. Button의 option을
  `Active`로 고치고 component set을 다시 만들었다.

## Inclusive Design

- Source: design/foundations/inclusive-design.md
- Maturity: beta

### Inclusive Design

Klipse의 신규 UI와 수정되는 UI는 WCAG 2.2 AA를 기본 목표로 한다. 이 문서는 과거 구현의 평균이
아니라 **앞으로 지켜야 할 최소 계약**이다. 공용 구현 편차는 manifest blocker로, route 통합 편차는
소비 제품의 debt로 기록한다.

기준 문서: [WCAG 2.2](https://www.w3.org/TR/WCAG22/),
[Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum),
[Focus Appearance](https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance.html).

#### 시각적 명료성

- 색만으로 성공·오류·선택 상태를 구분하지 않는다. 텍스트, 아이콘 또는 형태를 함께 제공한다.
- 일반 텍스트 대비는 4.5:1 이상, 큰 텍스트는 3:1 이상을 목표로 한다.
- 컨트롤 경계·상태·포커스처럼 의미 있는 비텍스트 그래픽은 인접 색과 3:1 이상을 목표로 한다.
- 200% 텍스트 확대와 긴 KO/EN/JA 문구에서 정보나 액션이 잘리지 않아야 한다.

#### 키보드와 포커스

- 포인터로 가능한 주요 동작은 키보드로도 가능해야 한다.
- 모든 인터랙티브 요소에는 인지 가능한 `:focus-visible` 표시가 있어야 한다.
- 포커스 순서는 DOM과 시각 순서가 일치해야 하며, 열린 overlay 뒤의 콘텐츠로 빠지면 안 된다.
- 아이콘 전용 버튼에는 문맥을 설명하는 접근 가능한 이름이 필요하다.
- 드래그가 필수인 기능은 버튼·입력 등 단일 포인터 대체 수단을 제공한다.

#### 타깃 크기

- 주요 컨트롤은 44×44px 이상의 히트 영역을 권장한다.
- WCAG 2.2 AA 최소 기준인 24×24px보다 작은 타깃은 허용하지 않는다. 예외가 필요하면 동일 기능의
  충분히 큰 대체 컨트롤과 근거를 해당 구현의 검증 기록에 남긴다.
- 시각 아이콘 크기와 실제 히트 영역을 분리해 작은 아이콘도 쉽게 누를 수 있게 한다.

#### Dialog와 overlay

- Dialog는 적절한 이름과 설명을 `aria-labelledby`/`aria-describedby`로 연결한다.
- 열릴 때 의도한 첫 요소로 포커스를 보내고, Tab을 내부에 가두며, 닫힐 때 호출 요소로 돌려보낸다.
- Escape로 닫을 수 있어야 한다. 파괴적 확인 Dialog에서 Enter 기본 확인을 허용하려면 별도 결정이
  필요하다.
- modal이면 배경 상호작용과 body 스크롤을 잠근다.
- Popover·Menu·Tooltip은 각각의 ARIA 역할과 키보드 패턴을 사용한다.

#### 비동기 상태와 오류

- 진행 중인 컨트롤은 `aria-busy`와 시각적 로딩 상태를 함께 제공한다.
- 상태 메시지는 `role="status"`/`aria-live="polite"`, 즉시 주의가 필요한 오류는 상황에 맞는 live
  region으로 전달한다.
- 필드 오류는 해당 필드와 프로그램적으로 연결하고, 색 이외의 설명과 해결 방법을 제공한다.
- 로딩·성공·실패·취소 흐름은 [Loading Pattern](../patterns/loading.md)을 따른다.

#### 모션과 미디어

- `prefers-reduced-motion: reduce`에서 위치·크기 기반의 비필수 모션을 제거하거나 즉시 전환으로 바꾼다.
- 무한 애니메이션은 로딩·상태 전달처럼 필요한 경우에만 사용한다.
- 장식 이미지는 보조 기술에서 숨기고, 기능성 이미지와 아이콘에는 목적 중심 대체 텍스트를 제공한다.
- 영상은 키보드로 제어할 수 있어야 하며 자동재생·소리·자막 정책을 화면별로 명시한다.

#### 완료 조건

컴포넌트를 `stable`로 올리려면 최소한 다음을 확인한다.

- 키보드 탐색과 포커스 표시
- 접근 가능한 이름·역할·상태
- light/dark 및 app-shell 배경에서 대비
- 320px 폭, 200% 확대, KO/EN/JA 긴 문구
- reduced-motion
- 오류·로딩·빈 상태
- axe smoke와 핵심 상호작용 테스트

기존 제품의 outline, Dialog focus, Toast live region 편차는 이 규범의 예외가 아니다. 소비 제품이
새 package를 도입할 때 제품 레포에서 검증하고, 공용 구현 결함이면 이 저장소의 blocker로 올린다.

## Responsive Layout

- Source: design/foundations/responsive-layout.md
- Maturity: beta

### Responsive Layout

Klipse의 반응형 레이아웃은 화면 폭별 시안을 모아 놓은 규칙이 아니라, **사용 가능한 공간이 바뀌어도
기능의 소유권과 정보 우선순위가 유지되는 계약**이다. 아래 rule과 compatibility profile은 이 저장소가
소유하는 규범이다.

#### 용어

| 용어                | 의미                                                                | 판단에 사용한다                          |
| ------------------- | ------------------------------------------------------------------- | ---------------------------------------- |
| Viewport            | 브라우저가 현재 제공하는 가시 영역                                  | 앱 셸 모드, safe area, 모바일 내비게이션 |
| Shell content box   | 내비게이션과 바깥 인셋을 제외한 실제 제품 영역                      | 페이지 그리드, 에디터 호스트             |
| Component container | 재사용 컴포넌트가 실제로 받은 영역                                  | 카드 열 수, 패널 재배치, 내부 밀도       |
| Compact mode        | 지속 사이드바를 둘 수 없어 overlay navigation으로 전환한 상태       | 셸·내비게이션 동작                       |
| Constrained mode    | 데스크톱 입력은 유지하지만 모든 보조 패널을 동시에 놓기 어려운 상태 | 에디터 패널 축소·접기                    |

Viewport 폭과 content box 폭은 같지 않다. 사이드바가 펼쳐지거나 접히면 같은 viewport에서도 content
box가 달라진다. 따라서 페이지와 컴포넌트의 열 수를 viewport만 보고 결정하지 않는다.

#### Target rules

##### 1. 소유자가 맞는 공간을 측정한다

- App Shell만 viewport와 persistent/overlay navigation 전환을 소유한다.
- 페이지 패턴은 shell content box를 기준으로 배치한다.
- 재사용 컴포넌트와 프로젝트 그리드는 component container를 기준으로 적응한다.
- 기능 컴포넌트가 전역 사이드바 폭이나 `window.innerWidth`를 직접 조합해 자기 폭을 만들지 않는다.
- 하나의 상태에서 sidebar width, main offset, main width는 같은 레이아웃 원천을 읽어야 한다.

Container query를 쓰는지 ResizeObserver를 쓰는지는 구현 선택이다. 계약은 **실제 받은 공간으로 결과를
결정한다**는 데 있다.

##### 2. 폭이 줄면 정보 우선순위대로 변한다

1. 장식과 낮은 우선순위 메타를 축소한다.
2. 보조 액션을 menu 또는 sheet로 옮긴다.
3. 보조 패널을 접거나 순차 탐색 구조로 바꾼다.
4. persistent navigation을 overlay drawer로 바꾼다.
5. 핵심 작업 영역은 마지막까지 유지한다.

콘텐츠를 겹치게 두거나 잘라서 맞추는 것은 반응형 단계가 아니다. 지원 가능한 최소 공간보다 작으면
compact 구조 또는 명시적인 지원 범위 안내로 전환한다. 문서 전체에 `min-width`를 걸어 우연히 충돌을
피하는 방식은 목표 계약이 아니다.

##### 3. 레이아웃 안전 규칙

- 가변 grid/flex 자식은 `min-width: 0`과 필요한 경우 `min-height: 0`을 가져야 한다.
- `100vw`와 persistent sidebar offset을 같은 축에 더하지 않는다.
- viewport 고정 요소는 safe-area inset을 포함하고, 동적 브라우저 UI가 있는 환경에서는 검증된 가시
  높이 원천을 사용한다.
- 페이지에는 한 개의 primary scroll root만 둔다. 내부 편집기는 패널별 scroll을 가질 수 있지만 문서
  스크롤과 경쟁하지 않아야 한다.
- 숨긴 영역은 시각적으로만 감추지 않고 focus 순서와 접근성 트리에서도 제거한다.
- 긴 KO/EN/JA 문구와 200% 확대에서 액션이 잘리면 다음 레이아웃 단계로 전환한다.

##### 4. breakpoint는 행동 경계다

새 breakpoint는 “이 폭에서 보기 좋다”가 아니라 다음 중 하나가 바뀔 때만 추가한다.

- navigation이 persistent에서 overlay로 바뀐다.
- 프로젝트 카드의 유효 열 수가 바뀐다.
- 핵심 패널을 동시에 표시할 수 없어 접기 또는 순차 구조로 바뀐다.
- 컨트롤의 hit area나 번역 문구가 더 이상 보장되지 않는다.

경계값 변경은 App Shell, Project Grid, Editor Workspace의 기준 화면을 함께 검증하고 결정 기록을 남긴다.

#### Compatibility matrix

아래 구간은 monolith 결과를 검토해 **공식 migration compatibility profile**로 채택했다. 구현은
container 기반이어야 하지만 기준 viewport와 기본 shell 상태에서는 같은 기능 밀도를 제공한다.

| 기준 viewport 구간 | Required shell/grid outcome                                          |
| ------------------ | -------------------------------------------------------------------- |
| `≤719px`           | compact shell, reserve 0, overlay drawer, 프로젝트 grid profile 2열  |
| `720–959px`        | constrained shell/workspace, 전역 가로 scroll 금지, grid profile 3열 |
| `960–1199px`       | regular persistent navigation, grid profile 3열                      |
| `1200–1799px`      | wide content, grid profile 4열                                       |
| `≥1800px`          | extra-wide content, grid profile 5열                                 |

이 호환 기준의 비규범 provenance는
[`KP-LAYOUT-001`](../../migration/product-baseline.md)과
[`KP-GRID-001`](../../migration/product-baseline.md)에 있다.

#### Viewport height and safe area

- App Shell이 가시 높이와 safe area를 한 번 계산해 페이지와 workspace에 제공한다.
- 각 Scene이 `100dvh`, `100svh`, JS 주입 높이를 제각각 선택하지 않는다.
- 화면 회전, 모바일 주소창 변화, 소프트 키보드 표시 시 현재 입력과 주요 완료 액션이 가려지지 않아야
  한다.
- 높이가 제한되면 세로 패널의 최소 높이를 서로 경쟁시키지 말고 보조 영역을 접거나 자체 scroll로
  전환한다.

#### Accessibility

- DOM 순서와 compact에서 보이는 순서가 일치해야 한다. CSS `order`만으로 읽기 순서를 바꾸지 않는다.
- reflow 후 현재 focus가 제거되는 경우 논리적으로 가장 가까운 컨트롤로 이동한다.
- drawer와 modal은 뒤 콘텐츠를 inert 처리하고, 닫을 때 호출 컨트롤로 focus를 돌려준다.
- hover에서만 나타나는 필수 액션은 touch·keyboard에서 항상 도달 가능한 대안을 제공한다.
- reduced-motion에서는 sidebar, grid, panel 재배치가 즉시 또는 비공간적 전환으로 바뀌어야 한다.

#### Extraction decisions

- `720–959px` 전역 horizontal scroll은 목표 동작이 아니라 제거할 호환 편차다.
- sidebar geometry는 App Shell이 제공하는 단일 상태에서 계산한다.
- 프로젝트 열 수와 요청 개수의 동기화는 보존하되 viewport가 아니라 실제 content container를 측정한다.
- compact editor가 viewport를 점유하려면 sidebar reserve 0, drawer closed, safe-area 처리를 함께 검증한다.

제품 관측은 [migration baseline](../../migration/product-baseline.md)에만 남으며 이 규범보다 우선하지
않는다.

#### Acceptance tests

- compact 경계의 바로 아래·위에서 sidebar와 main surface 사이에 겹침이나 빈 reserve가 없다.
- expanded/collapsed sidebar 전환 중 main width, 프로젝트 열 수, header 위치가 같은 프레임에서 맞는다.
- 프로젝트 grid 경계의 바로 아래·위에서 기대 열 수가 나오고 카드가 최소 사용성을 잃지 않는다.
- 320px 폭, 200% 확대, KO/EN/JA 긴 문구에서 핵심 탐색·생성·저장·완료 액션을 사용할 수 있다.
- 세로가 짧은 viewport, 화면 회전, 모바일 주소창 변화에서 이중 문서 스크롤이나 잘린 완료 액션이 없다.
- keyboard만으로 drawer, grid card, overflow menu, editor panel을 순서대로 탐색할 수 있다.
- `prefers-reduced-motion: reduce`에서 레이아웃 변화가 의미 손실 없이 동작한다.
- 주요 기준 화면을 light/dark와 sidebar expanded/collapsed 조합으로 시각 회귀 비교한다.
