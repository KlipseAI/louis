# Landing Shell

Landing Shell은 로그인 전 마케팅 화면의 껍데기다 — 홈 · 모델 · 가격 · 문의 · 블로그 · 템플릿 ·
법적 고지가 이 하나를 공유한다. 껍데기는 **위의 헤더(GNB)와 아래의 타임라인 푸터** 둘이다.

이 문서의 제품 근거는 2026-10-07 기준 제품 작업 브랜치 `feat/landing-hero-scroll` ·
`feat/ambassador-links` 의 `landing/navigation/Gnb.tsx` 와 `landing/sections/TimelineFooter.tsx` 다.
`origin/dev` 에는 아직 없는 변경(전폭 시트 · 푸터 · 모바일 2단계)이 많다 — 아래 각 절이 어느 판인지
적는다.

**App Shell과 정반대 모델이다.** 앱 셸은 레일이 자리를 예약하고 본문이 그만큼 밀리지만, 랜딩
헤더는 **자리를 예약하지 않고 콘텐츠 위에 뜬다.** 두 셸을 같은 규칙으로 그리면 랜딩 첫 화면의
윗부분이 헤더에 가려지거나, 반대로 없는 여백이 생긴다.

값은 배포본 인용이며 아직 DS 토큰이 아니다. 간격 환산 기준은 제품의 `--spacing: 2px`다 —
`h-14`는 56px이 아니라 **28px**이다.

## Anatomy

| 부품 | 역할 |
| --- | --- |
| Blur plate | 헤더 뒤에 깔리는 흐림 판. 기본 **고정 120px**이고 스크림이 없다. **메가 시트가 열린 동안만** 시트 바닥까지 늘어나며 틴트를 깐다(아래 Mega sheet) |
| Header wrapper | `position: fixed` 투명 껍데기. 패딩만 갖는다 |
| Nav rail | 3열 그리드 — 로고 / 가운데 메뉴 / 우측 액션 |
| Menu list | 가운데 메뉴 다섯 — 모델 · 문서 · 가격 · 문의 · 리소스. 모델 · 문서 · 리소스가 메가 시트를 연다. **720px 미만에서 사라진다** |
| Mega sheet | 모델 · 문서 · 리소스가 여는 전폭 시트. body portal이고 면이 없다 |
| Actions | 언어 글로브 · 테마 · 상단 CTA · 햄버거. 상단 CTA는 페이지가 바꿔 끼울 수 있다(아래 Actions) |
| Fullscreen menu | 720px 미만 전용. `<nav>`의 자식이며 `z-index: -1`이다. 2단계(모델 · 문서 · 리소스)를 갖는다 |
| Timeline footer | 헤더와 별개인 `<footer>`. 공개 화면 전부의 공용 푸터이고 늘 다크다(아래 Footer) |

**스크림이 없다.** 헤더는 배경이 `transparent`이고 가독성은 전적으로 blur plate가 만든다.
헤더에 반투명 면을 깔면 배포본과 다르다. **예외는 하나다** — 메가 시트가 열려 있는 동안 blur plate
가 56% 틴트를 깐다(아래 Mega sheet). 헤더 자신에는 여전히 면이 없다.

## Layout contract

| 축 | 값 |
| --- | --- |
| 헤더 | `position: fixed` · `top: 0` · `left: 0` · `width: 100%` · `background: transparent` |
| 헤더 패딩 | `12px 12px 12px 20px` · **≤450px** `12px 16px` |
| 레일 | `display: grid` · `grid-template-columns: 1fr auto 1fr` · `align-items: center` · `min-height: 24px` |
| 레일 전환 | `color 320ms ease` |
| 레일 (≤719px) | `grid-template-columns: 1fr auto` — **가운데 열이 소멸한다** |
| 레일 행 높이 | `min-height`는 하한일 뿐이고 실제 높이는 **최장 액션 컨트롤**이 정한다 — 32px(Button md · LanguageSelector compact) · **≤719px 38px**(햄버거) |
| 1열 로고 | `justify-self: start` · 높이 24px · 폭 `calc(24px × 291 / 85)` = 82.16px |
| 2열 메뉴 | `justify-self: center` · `flex` · `gap: 16px` · **≤959px `gap: 4px`**(메뉴가 다섯이 되자 720~959 폭의 영어 · 일본어에서 메뉴가 로고에 붙었다) · **≤719px `display: none`** |
| 3열 액션 | `justify-self: end` · `inline-flex` · `gap: 8px` |
| 3열 액션 · LanguageSelector compact | `36×32` · `padding: 0 8px` · `border-radius: 12px` · globe **20 단독**(라벨도 셰브런도 없다) |
| 메뉴 링크 | 높이 `28px` · `padding-inline: 12px`(**≤959px 8px**) · `border-radius: 999px` · 면 `transparent` |
| 메뉴 링크 전환 | `color 320ms ease, opacity 200ms ease` |

**헤더가 점유하는 높이는 56px이지만(12 + 32 + 12) 본문에서 예약되지 않는다.** 첫 섹션은 헤더
아래에서 시작하지 않고 **헤더 밑을 지나간다.** 앱 셸의 「레일이 자리를 예약한다」를 여기 적용하면
첫 화면의 구도가 통째로 달라진다.

**가운데 32px은 레일의 `min-height: 24px`가 아니다.** 24px은 하한이고, 행 높이는 액션 열에서
가장 큰 컨트롤이 정한다 — LOUIS Button md 32px(`packages/css/src/component/button.css:67-68` →
`packages/css/generated/tokens.css:467`)와 LanguageSelector compact 32px이 나란히 선다.
**≤719px에서는 상단 CTA가 숨고(`:337`) 햄버거 38px(`:347`)이 최장이 되어 점유 높이가 62px이다.**

**≤959px 의 좁은 간격은 2026-10-07 실측에서 나왔다** — 메뉴가 넷에서 다섯으로 늘자 720~959 폭에서 영어
「Get started」가 두 줄로 꺾였다. `MENU` · `MENU_LINK` 의 `max-width:959px` 변형이 갖는다
(제품 `feat/landing-hero-scroll` `b0d4777f2`).

근거: `landing/navigation/Gnb.tsx:109-114`(헤더) · `:115-119`(레일) · `:148-151`(로고) ·
`:159-162`(메뉴) · `:164-172`(메뉴 링크) · `:325`(3열 액션) · `:334-338`(상단 CTA) ·
`:346-352`(햄버거) · `tailwind.css:162`(간격 기준). LanguageSelector compact 의 기하는 제품
`LanguageSelector` 의 `TRIGGER`(높이 32) + `TRIGGER_COMPACT`(`padding: 0 8px` · `rounded-12`) +
`ICON_COMPACT`(20)가 갖는다 — 그 파일은 아직 evidence lock 밖이라 줄 좌표로 인용하지 않는다.

## Blur plate

랜딩 헤더가 가독성을 얻는 **유일한** 장치다. 헤더의 형제이고 한 층 아래에 깔린다.

| 축 | 값 |
| --- | --- |
| 배치 | `position: fixed` · `top/left/right: 0` · `height: 120px` (**시트가 닫혀 있을 때 고정**) |
| 층 | `z-index: 999` — 시트(1000)와 헤더(1001) **아래**. 시트 글자가 흐려지지 않으려면 판이 시트 밑이어야 한다 |
| 포인터 | `pointer-events: none` |
| 흐림 | `var(--louis-progressive-blur-header)` = `blur(12px)` |
| 마스크 | `var(--louis-progressive-blur-mask-header)` = `linear-gradient(to bottom, black 40%, transparent 100%)` — **2스톱** |
| 접두사 | 표준과 `-webkit-`를 **둘 다** 내보낸다 |
| DOM | `<div aria-hidden="true">` 하나. 자식이 없다 |

**값은 LOUIS 가 갖는다**(2026-08-30). 그전에는 흐림 반경과 곡선을 제품이 숫자와 리터럴로
적고 있었다 — 같은 곡선이 제품 다섯 군데에 베껴져 있었고, 그중 `CreativeMediaClient` 는 이
띠와 바이트 동일한 2스톱을 따로 들고 있었다. 반경은 카드 쪽 `blur-surface`(10px)와 **다른 것이
계약**이라 `blur-header`(12px)로 이름을 따로 냈다 — 카드 것을 재사용하면 헤더가 2px 옅어진다.

**120px은 시트가 닫혀 있을 때의 고정값이며 헤더 높이에서 유도되지 않는다.** 헤더 점유 높이(56px)의 배수도 아니고
뷰포트에도 비례하지 않는다 — 어디에서도 계산되지 않는 숫자이므로 바꿀 때 따라 움직일 값이 없다.
마스크는 위에서 40%까지 완전 불투명이고 거기서 아래로 선형 감쇠한다.

**배너 캐러셀의 값을 여기 쓰지 마라.** 그쪽은 `blur(22px) saturate(125%)`에 5스톱 마스크라 흐림이
두 배 가깝게 짙고 감쇠 곡선이 다르다.

근거: `landing/navigation/Gnb.tsx:102-107`(상수) · `:737`(소비처) · LOUIS `packages/css/src/base.css`(두 토큰).
**z-index 999는 작업 브랜치의 값이다**(`:118-124` `HEADER_BLUR`). `origin/dev` 판은 1000이었고 시트가 없었다.

**한때 스크림이 깔려 있었다.** 제품 `66baeb6f`(2026-08-27)가 대비를 벌려고 페이지 바닥색 88%
베일을 이 판에 깔았다 — 위 「스크림이 없다」를 어긴 상태였고, 88% 불투명 판이 흐림을 덮어
progressive blur 가 보이지 않았다. 2026-08-30 소유자 결정으로 걷어내 규범으로 돌아왔다.
그 베일이 풀던 문제(어두운 사진 위 메뉴 글자 1.52:1)는 **닫히지 않았다** — 아래
Tone inversion 이 그 자리다.

## Mega sheet

모델 · 문서 · 리소스 셋이 여는 **전폭 시트**다. 카드가 아니라 헤더 밑을 가로지르는 **면 없는** 띠이고, 뒤를
받치는 것은 헤더의 blur plate 하나다. 값의 출처는 토스 상단 내비의 세부 메뉴 실측이며(제품 주석이
프레임 단위로 잰 값을 적는다) 그것을 우리 헤더 위에 옮긴 것이다 — 우리 패널은 헤더 **아래**에서
시작하므로 토스의 상단 패딩 104는 쓰지 않고 헤더 높이를 뺀 40을 쓴다.

출처: 2026-10-07, 제품 `feat/landing-hero-scroll` `Gnb.tsx:352-411`(@`26d093f6a` 시트 구조 · @`45f0ffad6`
항목 간격 · @`d2c5f8dd0` blur plate 연장).

### 구조

| 축 | 값 |
| --- | --- |
| 부모 | body portal. `position: fixed` · `top`은 열린 메뉴 항목의 바닥 · `left/right: 0` · `z-index: 1000`(인라인) |
| 면 · 그림자 · 라운드 | **없다.** 패널 · 열 어디에도 없다 |
| 내용 그리드 | 가운데 정렬 · `max-width: 1920px` · `gap: 24px` |
| 패딩 (위 / 좌우 / 아래) | **40 / 160 / 48** · **≤1440px 40 / 128 / 48** · **≤1024px 32 / 40 / 40** |
| 열 | 최대 네 칸. 폭 `calc((100% − 72px) / 4)` — 「네 열 + 간격 셋(24 × 3)」이 내용 폭에 꼭 차는 값이다. 열이 둘 · 셋인 시트(문서 · 리소스)도 같은 폭으로 **가운데**에 선다 |
| 열 제목 | `caption-12-medium` · `padding-inline: 12`(항목 `padding 8 12` 의 글자 시작점에 맞춘다) · 잉크는 `--gray-400` 채널 |
| 열 안 목록 | `flex column` · **`gap: 4px`**(소유자 2026-10-07 「세부 메뉴들 위아래 간격을 좀 좁혀줘」, 12 → 4. 항목 자체가 위아래 8 패딩을 가져 **줄 간격은 52 → 44** 다) |
| 항목 | LOUIS `.louis-menu__item` 이 패딩 · 곡률 · 색 · hover · transition 을 소유한다. 이름은 `body-16-medium`. 제품 쪽에는 드래그 · 선택 억제만 남는다 |
| 항목 hover · 현재 면 | 시트 잉크 6% 알파(`rgb(--gray-000-rgb / 0.06)`) |

**열 제목의 12는 항목 패딩을 따라간 값이다.** 제목엔 패딩이 없고 항목만 있어 글자 시작점이 12px
어긋나 있었다(제품 실측: 제목 310 · 항목 글자 322). 항목의 패딩은 hover 알약의 모양이라 지울 수 없어 제목을 맞춘다.

**열 수가 시트마다 다르다.** 모델 4열(영상 · 이미지 · 오디오 · 둘러보기) · 문서 2열 · 리소스 2열이다. 시트는
**하나**이고 내용만 갈아 끼운다 — 내용이 바뀌면 새로 마운트해 항목 등장이 처음부터 다시 돈다.
모델 열은 25%로 두었다가 네 열 + 간격이 72px 넘쳐 양옆 36px씩 밀려난 뒤 위 식으로 고쳤다(2026-10-08 리뷰).

### 잉크는 헤더 톤을 따른다

시트는 body 포털이라 페이지의 테마 범위 밖에 있어 램프만으로는 그 톤을 알 수 없다. 그래서 **시트 루트가
`SHEET_INK_LIGHT` / `SHEET_INK_DARK` 를 직접 달고** `data-sheet-ink="light|dark"` 를 단다 — 흰 잉크(`light`)는
어두운 것이 비칠 때(홈 히어로의 어두운 영상 위)이고 어두운 잉크(`dark`)는 밝은 면 위다. 세 변수를 한 묶음으로 재지정한다.

| 변수 | 흰 잉크 | 검은 잉크 |
| --- | --- | --- |
| `--louis-color-gray-000`(항목 이름) | `palette-gray-000` | `static-black` |
| `--gray-000-rgb`(hover 면 · 흐린 행) | `palette-gray-000-rgb` | `palette-gray-1000-rgb` |
| `--gray-400-rgb`(열 제목) | `palette-gray-400-rgb` | `palette-gray-600-rgb` |

문서 전체를 보는 `walkthrough-*` 범위를 시트에 붙이지 않는다 — 늘 마운트된 포털에 붙이면 페이지 전체의 라이트
노드 변수가 풀린다.

### 열고 닫는 모션

| 대상 | 열 때 | 닫을 때 |
| --- | --- | --- |
| 패널 | `opacity` 0 → 1 · **300ms** `ease-in-out` · transform 없음 | **130ms** `ease-in` |
| blur plate | 높이와 틴트 **300ms** `ease-in-out` | **130ms** `ease-in` |
| 항목 | `landingMenuItemDrop` **400ms** `cubic-bezier(0, 0, 0.2, 1)` · 거리 `-10px` · 흐림 `10px` · 지연 `(열 + 행) × 45ms` 의 **대각선 웨이브** | — |
| 호버 의도 | 닫기를 **120ms** 미룬다 | |

닫힌 시트는 투명할 뿐 DOM에 남으므로 `inert` 로 막아 탭이 보이지 않는 링크에 들어가지 않게 한다.
`prefers-reduced-motion` 에서는 항목 등장과 transform 이 꺼지고 패널은 `opacity 120ms` 만 남는다.

### 시트가 열리면 blur plate가 늘어난다

소유자 지시(2026-09-21): 「가운데 하얀 효과 대신 프로그레시브 블러가 아래로 늘어나게」, 「컬러 기반도, 펼칠 때 한해서」.
토스는 패널 뒤에 흰 타원 글로우를 깔지만 우리는 그것을 걷고 **헤더의 유리가 시트까지 내려와 덮게** 했다.

| 축 | 닫힘 | 열림 |
| --- | --- | --- |
| 높이 | `120px` | `max(120px, 시트 바닥 ÷ 0.4)` — 마스크가 위 40%를 불투명으로 두므로 **시트 바닥이 그 40% 안에 들도록** 나눈다 |
| 곡선 | `--louis-progressive-blur-mask-header` | **그대로** — 높이만 바뀐다 |
| 틴트 | 없음 | **56%** 알파. 색은 **헤더 톤의 반대**다 — 흰 글씨 헤더면 `palette-gray-1000` 56%, 검은 글씨면 `palette-gray-000` 56% |
| 전환 | | 위 모션 표(300ms / 130ms) |

**이것이 「120px 고정 · 스크림 없음」 계약의 유일한 예외다.** 56%인 이유: 88% 판은 유리를 덮어 흐림이 보이지 않았다
(2026-08-30 베일을 걷은 까닭, 위 Blur plate). 흐림이 비쳐 보이는 선에서 멈춘 값이다. 틴트 색이 헤더 톤의 반대인 이유:
틴트가 헤더 자리부터 시작하므로 헤더 글자와 같은 색을 깔면 글자가 묻힌다.

**판정 필요 — 56%와 `÷ 0.4` 를 토큰으로 둘지.** 지금은 제품 상수(`HEADER_BLUR_SHEET_TINT_*` ·
`SHEET_BLUR_SOLID`)다. 마스크의 `40%` 와 짝이므로 둘이 따로 움직이면 시트 글자가 흐린 구간에 들어간다 —
토큰으로 올린다면 마스크 토큰과 한 묶음이어야 한다. 이 문서는 값을 제품 인용으로만 적는다.

## Tone inversion

랜딩 헤더의 잉크는 **테마가 아니라 「내 밑에 깔린 면」** 이 정하고, 정해지면 **다섯 부품이 한 덩어리로** 뒤집힌다.
이것을 모르면 밝은 면 위에서 헤더 글자가 사라지고 어두운 면 위에서 아이콘만 검게 남는다.

**이 절의 앞선 판은 폐기됐다.** 그때는 `IntersectionObserver` 가 뷰포트 상단 3~4% 띠에 닿은 밝은 섹션
일곱 곳(`overview` · `capabilities` · … · `final-cta`)을 감지해 스크롤마다 뒤집었다. 랜딩이 밝은 페이지였고 그
안에 다크 섹션이 섞여 있던 시절의 장치인데, 페이지가 테마를 따르게 되면서 근거가 사라졌고 목록 일곱 중
다섯은 이제 없는 섹션이다(제품 주석). **지금은 아래 입력 넷이 정한다.** 스크롤 위치로 추측하지 않는다.

### 입력

| 입력 | 누가 주나 | 뜻 |
| --- | --- | --- |
| 테마 | `ThemeProvider` (`useTheme()`) | 기본. 라이트면 어두운 글씨(`navBlack`), 다크면 밝은 글씨. **`document` 를 읽지 않는다** — 서버는 항상 false 로 그려 하이드레이션 불일치가 DOM을 안 고쳤고 다크에서 메뉴 글자가 검은 바닥 위 1.12:1 이 됐다 |
| `lightSurface` | prop. 밝은 배경 페이지(docs 등) · 흰 톤으로 고정한 랜딩 홈 | 테마와 무관하게 **어두운 글씨가 기본 톤**으로 고정된다. 기본일 뿐이라 아래 섹션 톤이 이긴다 |
| `darkSurface` | prop. **앰배서더 브랜치**. 페이지가 스크롤 위치로 켜고 끈다 | 라이트 테마인데 GNB 아래가 **늘 어두운 면**(제품 캔버스 장면 · 어두운 밴드)일 때 **밝은 글씨**로 바꾼다. **반대 방향**이다 |
| `pageTheme` | prop. **앰배서더 브랜치** | 페이지가 제 루트에 `data-theme="light"` 를 달아 테마를 고정했다는 사실. GNB 가 그 루트 안에 그려져 LOUIS 토큰은 고정된 테마를 따르지만, **모바일 메뉴 패널과 리소스 시트는 `html[data-theme]`(사용자 테마)를 읽는다** — 톤을 그 둘로 나눠 고른다 |
| 섹션 톤 | `setLandingNavTone(tone, owner)` · `useSyncExternalStore`. **히어로 스크롤 브랜치** | **자기 배경을 아는 섹션이 값으로 알린다.** `"light"`(밝은 글씨) · `"dark"`(어두운 글씨) · `null`(기본 규칙). 알려 온 톤이 `lightSurface` 와 테마를 **모두 이긴다** |

**섹션 톤은 주인별로 든다.** 한 전역 값에 여럿이 쓰면 한 프레임에 멀리 뛸 때 떠나는 쪽의 `null` 이 들어오는
쪽의 톤을 지운다. 그래서 `null` 은 자기 요청만 거두고, 살아 있는 요청이 여럿이면 **가장 늦게 들어온 것**이 이긴다.
주인은 히어로(`"page"`) · 크리에이터 장면(`"creator"`) · 끝 장면(`"ending"`)이다. 값으로 넘기는 이유는 CSS 가
못 이기기 때문이다 — 톤이 `!` 유틸리티로 붙어 중요 선언끼리는 레이어 순서가 뒤집히고, 진행도를 상위 상태로 올리면
랜딩 전체가 매 프레임 리렌더된다.

### 결정식

| 판 | 어두운 글씨(`navBlackActive`)가 켜지는 조건 |
| --- | --- |
| `origin/dev` | `lightSurface \|\| 테마가 라이트` |
| `feat/landing-hero-scroll` | 섹션 톤이 없거나 **전체 화면 메뉴가 열려 있으면** `lightSurface \|\| 테마가 라이트`, 아니면 섹션 톤이 `"dark"` |
| `feat/ambassador-links` · `pageTheme` 없음 | `lightSurface \|\| (테마가 라이트 && (!darkSurface \|\| 메뉴나 시트가 열림))` |
| `feat/ambassador-links` · `pageTheme="light"` | 메뉴나 시트가 열려 있으면 `테마가 라이트`(그 패널의 테마), 아니면 `!darkSurface` |

**열린 메뉴에서는 강제 톤을 푼다 — 세 판이 같은 이유로 같은 일을 한다.** 알려 온 톤이나 `darkSurface` 는
「내 밑에 깔린 면이 이렇다」는 뜻인데, 메뉴가 열리면 그 면이 더는 히어로가 아니라 **메뉴 패널**(또는 시트)이다.
풀지 않으면 밝은 회색 패널 위에 흰 아이콘이 얹혀 글로브 · 테마 · 닫기가 전부 사라진다(제품 실측: 모바일 390 라이트).
홈의 패널은 `data-menu-theme="light"` 로 밝은 면에 고정이라 풀면 `lightSurface` 가 정한 검은 아이콘이 선다.

**`feat/landing-hero-scroll` 과 `feat/ambassador-links` 는 서로 합쳐지지 않았다.** 둘이 같은 `navBlackActive` 를
다른 식으로 고쳤으므로 합칠 때 한 식으로 모아야 한다. **판정 필요** — 우선순위를 섹션 톤 > `darkSurface` >
`lightSurface` > 테마로 둘지, `pageTheme` 고정 페이지에서 섹션 톤이 오면 어느 쪽이 이길지. 정하지 않으면 합치는 사람이
다시 발명한다. 이 문서는 아직 어느 한 식도 DS 계약으로 올리지 않는다.

### 뒤집히는 다섯

| 부품 | 밝은 글씨 (어두운 면 위) | 어두운 글씨 (밝은 면 위, `navBlack`) |
| --- | --- | --- |
| 레일 전경 | `--gray-000` — 헤더 안에서 `#fafafa`로 복구 | `--gray-900` |
| 로고 자산 | `klipse-dark.svg` | `klipse-light.svg` |
| 메뉴 링크 | `palette-gray-000` · 비활성 `opacity .7` / hover `.9` | `palette-gray-900` · 비활성 `.65` / hover `.8` |
| 상단 CTA | 면 `palette-gray-000` · 글자 `palette-gray-900` | 면 `palette-gray-900` · 글자 `palette-gray-000` |
| 햄버거 | `gray-000` | `gray-900` |
| **언어 · 테마 트리거** | `--louis-color-fg-primary` 를 `palette-gray-000` 으로 재지정 · hover · focus-visible `0.88` | 같은 변수를 `palette-gray-900` 으로 · hover `0.88` · hover 에 `opacity .7` |
| **메가 시트 잉크 · blur plate 틴트** | 흰 잉크(`data-sheet-ink="light"`) · 틴트 `palette-gray-1000` 56% | 검은 잉크 · 틴트 `palette-gray-000` 56% |

**「다섯」은 본체 다섯이고, 같은 톤 입력을 받아 함께 뒤집히는 부품이 둘 더 있다**(굵게 적은 두 줄) — 앞선 판은
언어 · 테마 트리거를 몰랐고 시트가 없었다. 활성 링크는 **양쪽 모두 불투명 1**이다. 전환은 레일 · 햄버거가
`color 320ms ease`, 로고가 `filter 320ms ease`다.

**밝은 면 위 비활성 링크는 `.65` 아래로 내려갈 수 없다.** 시안 값 `.50`으로 그리면 `palette-gray-900`이 랜딩
바닥(#fafafa)에서 약 **3.3:1**(제품 주석 3.27 · 이 문서의 계산 3.31)이라 14px 본문 기준 AA(4.5)에 못 미친다 —
비활성 컨트롤이 아니라 **누를 수 있는 내비게이션 링크**라 면제 대상이 아니다. `.65`는 **5.28:1**이고 활성(1.00)과의
간격도 남는다. 어두운 면 위(흰 잉크)는 `.70`에서 이미 9.57:1이라 손대지 않는다 — **두 톤의 불투명도가 다른 것이
맞다.** 근거: `landing/navigation/Gnb.tsx:190-199`. (이 절의 앞선 판이 적은 3.23 · 5.11 은 바닥이 #f1f1f3 이던
시절의 값이다 — 결론은 같다.)

**헤더 안에서 `--gray-000`을 팔레트 값으로 되돌린다.** 시맨틱 램프는 테마에서 뒤집히는데 랜딩 헤더는
면의 밝기로 판정하므로, 두 축이 겹치면 어두운 면 위에서 글자가 검게 나온다. 같은 이유로 `-rgb` 채널
(`--gray-000-rgb`)도 함께 고정한다 — `LanguageSelector` 가 램프를 `rgb(var(--gray-000-rgb)/…)` 로 직접 읽는다.

### 언어 · 테마 트리거 잉크 — 토큰 재지정 계약

LOUIS `.louis-menu-trigger` 는 자기 색을 `color: var(--louis-color-fg-primary)` 로 **직접** 정한다. 시맨틱이라
라이트에서 검정이고, nav 가 상속으로 내려보내는 흰색은 그 규칙에 진다(제품 실측: 라이트 첫 화면에서 아이콘만
검정, 소유자 지적 2026-09-20). 그래서 **색을 덮지 않고 그 변수를 트리거 자신에게 넘긴다.**

1. **`!important` 로 덮지 않는다.** 소유자 판정(2026-09-21): 「`!important` 가 있으면 스파게티가 된다」. LOUIS 는 이
   변수를 테마 범위에서만 선언하고 트리거 자신에는 선언하지 않으므로 겨룰 규칙이 없다.
2. **nav 가 아니라 트리거에 건다.** nav 에 걸면 그 안의 다른 LOUIS 요소(언어 드롭다운 항목 등)까지 같은 색을
   물려받는다. 드롭다운은 트리거의 형제라 트리거에 건 값은 내려가지 않는다. 앰배서더 브랜치는 아직 nav 에 건다
   (`NAV_ON_DARK_SURFACE`, `Gnb.tsx:142`) — 두 브랜치가 갈라져 있다.
3. **셀렉터는 클래스(`.louis-menu-trigger`)로 집는다.** 오른쪽 버튼 둘이 모두 그 클래스인데 **테마 버튼에는
   `aria-haspopup` 이 없다**(언어 선택기만 목록을 연다). 속성으로 집으면 언어만 밝아지고 테마 아이콘은 검정으로 남는다.
4. **어두운 면 톤은 라이트 테마에서만 의미가 있다.** 다크 테마에서는 그 변수의 값이 이미 그 톤이므로 붙이지 않는다
   (`darkSurface && !isDarkTheme`). 고정 라이트 페이지(`pageTheme="light"`)는 늘 붙인다.
5. **메뉴나 시트가 열리면 푼다.** 열린 패널은 테마 면이라 어두운 면 톤이 남으면 그 위에서 아이콘이 사라진다.

**판정 필요 — LOUIS 에 입력을 열지.** 이 계약은 **시맨틱 변수를 지역에서 바꿔 쳐서** 이름이 거짓이 된다
(`fg-primary` 가 라이트에서 흰색이다). 대안은 `.louis-menu-trigger` 에 「면의 밝기」 입력(`data-surface` 또는 전용 변수)을
열어 시맨틱 변수를 덮지 않아도 되게 하는 것이다. 정하기 전까지 위 다섯 규칙이 계약이다.

근거: 2026-10-07, 제품 `feat/ambassador-links` `Gnb.tsx:142,527-590`(@`77522e3c1` · `6a106db62` · `cbc5b4cb9`) ·
`feat/landing-hero-scroll` `Gnb.tsx:186-207`(@`79425db2d`) · `:831-835`(톤 결정) · `landing/system/navTone.ts`
(@`ab8f0bca1` · `d1136262d` · `5bc42e986`) · 이 절의 폐기된 앞선 판은 `Gnb.tsx:88-105` · `:653-657`(옛 줄 좌표).

## Actions

3열 액션은 `inline-flex` · `gap: 8px` 로 **언어 글로브 · 테마 · 상단 CTA · 햄버거**를 순서대로 둔다. 상단 CTA는 720px 미만에서
숨고(`display: none`) 햄버거가 그 자리를 이어받는다.

### 상단 CTA

LOUIS Button `primary` `md`(높이 32 · 안쪽 12)를 그대로 쓰되 **헤더 톤에 맞춘 반전 중립 알약**으로 덮는다.

| 축 | 값 |
| --- | --- |
| 면 | 밝은 글씨 헤더 → `palette-gray-000` 면 · `palette-gray-900` 글자. 어두운 글씨 헤더 → `palette-gray-900` 면 · `palette-gray-000` 글자. **고정 팔레트**다 — 테마를 따라 뒤집히는 시맨틱이 아니다 |
| 빛 | **끈다**(`::before { display: none }`). primary 의 안쪽 광이 중립 알약에는 없다 |
| 그림자 | `--louis-hairline-inset` |
| 줄바꿈 | 라벨 `white-space: nowrap` — 720~800 폭의 영어 「Get started」가 두 줄로 꺾였다(2026-10-07 실측). 줄바꿈은 정본 라벨(`.louis-button__label`)이 따로 켜고 있어 그 `span` 에 건다 |
| 라벨 | 로그인 전 「시작하기」 · 로그인 후 「보관함으로」(`/archive`) — 같은 버튼을 쓰는 최종 CTA 와 같은 규칙 |

**이것은 Button 의 레이어를 `!` 로 이기는 덮개다.** 정본이 바뀌면 바로 깨진다. **판정 필요** — 헤더 톤에 따라 뒤집히는
고정 팔레트 변형을 Button 에 둘지. 지금 있는 `variant="inverse"`(인증 플로우 제출 CTA)는 **테마를 따라** 뒤집히는
다른 축이라 그 자리를 대신하지 못한다 — 헤더의 톤은 테마와 무관하게 정해진다(위 Tone inversion).

출처: 2026-10-07, 제품 `feat/landing-hero-scroll` `Gnb.tsx:496-509`.

### 페이지별 주 행동 슬롯 — `primaryAction`

페이지가 상단 CTA 의 **라벨과 행동을 바꿔 끼운다.** 서비스 내비게이션(시작하기 / 보관함으로)이 기본이고, 슬롯이 있으면
슬롯이 이긴다.

```ts
primaryAction?: { label: string; onClick: () => void }
```

- 상단 CTA 와 **풀스크린 메뉴 안 CTA 둘 다** 같은 슬롯을 쓴다. 메뉴 안에서는 행동을 하기 전에 메뉴를 닫는다.
- **슬롯이 있으면 `loading` 중에도 활성이다.** 기본 CTA 는 로그인 상태를 모르는 동안 비활성이지만, 슬롯의 행동은
  인증 상태와 무관하다(앰배서더는 「지원하기」로 지원서를 연다).
- 슬롯은 행동만 바꾼다 — 면 · 크기 · 톤 반전은 위 표 그대로다.

출처: 2026-10-07, 제품 `feat/ambassador-links` `Gnb.tsx:539-541,1066-1078,1221-1228`(@`6dcf59011` 계열).

### 언어 · 테마 트리거

LOUIS `.louis-menu-trigger` 둘이다. 잉크는 위 Tone inversion 의 **토큰 재지정 계약**이 정한다. 언어 선택기는 compact
(`36 × 32` · globe 20 단독)이고 테마 버튼에는 `aria-haspopup` 이 없다.

## Layer order

**랜딩 GNB는 semantic layer를 쓰지 않고 실수를 직접 쓴다.** [Elevation & Layer](../foundations/elevation-layer.md)가
금지한 「공용 순서 사이의 임의 숫자」에 해당하므로 **부채로 기록한다.** 다만 화면을 그리려면 실제
순서를 알아야 한다.

| 층 | 값 | 비고 |
| --- | ---: | --- |
| 헤더 | 1001 | 시트 위. 헤더 글자가 시트와 blur plate 에 가려지지 않는다 |
| 메가 시트 (body portal) | **1000** | **인라인 style**이 클래스의 `z-20`을 이긴다. 시트 글자가 흐려지지 않으려면 blur plate **위**여야 한다 |
| Blur plate | **999** | 시트 아래 — 시트까지 늘어난 판이 시트 글자를 흐리지 않는다 |
| `<nav>` | 2 | `position: relative` — 여기서 stacking context가 생긴다 |
| 풀스크린 모바일 메뉴 | **−1** | `<nav>`의 **자식**이다 |

### 음수 오버레이 관용구

모바일 메뉴는 `position: fixed; inset: 0; z-index: -1`이면서 `<nav>`의 자식이다. `<nav>`가
`relative` + `z-index: 2`로 자체 stacking context를 만들기 때문에 **`z: -1`이 밖으로 새지 않고
nav의 배경 층에 갇힌다.**

그 결과 **nav의 다른 자식인 로고와 햄버거가 메뉴 위에 남아 계속 눌린다** — 그것이 유일한 닫기
수단이다. 오버레이가 포인터를 가로채지 않는다는 점에서 규범을 만족시키지만, **방식이 규범이
기술한 것과 다르다.**

**판정이 필요하다.** 이 관용구를 `layer-*`의 대응 항목으로 인정할지, 부채로 보고 오버레이를 위로
올린 뒤 별도 닫기 버튼을 두게 할지. 정하지 않으면 화면을 조립할 때마다 다시 발명된다.

**작업 브랜치에서 층이 옮겨졌다**(2026-09-21, `d2c5f8dd0`). `origin/dev` 판은 드롭다운 패널이 인라인 **2000**,
blur plate 가 **1000** 이었다 — 패널이 헤더 위에 떴다. 시트가 헤더 유리 위로 오면서 순서가
**헤더 1001 > 시트 1000 > blur plate 999** 로 바뀌었다. 아래 근거 줄 좌표는 옛 판이다.

근거: `landing/navigation/Gnb.tsx:882`(드롭다운 패널의 인라인 `zIndex: 2000` — 옛 판) · `:223`(같은 패널의
클래스 `z-20` — 인라인이 이긴다) · `:108`(헤더 1001) · `:101`(blur plate 1000 — 옛 판) · `:116`(`<nav>`의

## Fullscreen menu

720px 미만에서만 나타난다. `<nav>` 의 자식이고 `z-index: -1` 이다(위 음수 오버레이 관용구).

| 축 | 값 |
| --- | --- |
| 표면 | 기본 `display: none` → **≤719px `display: block`** |
| 닫힘 · 열림 | `pointer-events: none` ↔ `auto`. 불투명도가 아니라 **`clip-path`** 가 연다 |
| 패널 | `clip-path: inset(0 0 100% 0)` → `inset(0)` — **위에서 아래로 자란다.** 내용이 제자리에 있고 드러나는 창만 커져 매 프레임 레이아웃이 없다 |
| 패널 시간 | `min(480, max(240, 창 높이 / 2))` ms — **열 때 재어** `--gnb-menu-rate` 로 넘긴다(Apple 의 `_setFlyoutHeight` 와 같은 식). 닫을 때는 80ms 뒤 같은 속도로 접힌다 |
| 곡선 | **전부 `cubic-bezier(0.4, 0, 0.6, 1)` 하나**다(`<nav>` 의 `--gnb-menu-ease`) |
| 안쪽 | `height: 100%` · `flex column` |
| 안쪽 패딩 | `78px 18px calc(28px + env(safe-area-inset-bottom, 0px))` — 상단 78px 이 헤더 자리를 비운다 |
| 스크롤 | `overflow-y: auto` · `overscroll-behavior: contain` |
| 면 | `palette-gray-100` · **`data-menu-theme="follow"` 인 페이지에서 다크이면 `palette-gray-950`** |
| 테두리 · 곡률 | `none` · `0` |
| 흐림 | **패널 자신은 없다.** 불투명 100%다. 커튼만 흐린다(아래) |

**메뉴의 테마는 뿌리의 `data-menu-theme` 하나가 정한다.** 값은 `light`(홈 · 테마를 고정한 페이지) 또는
`follow`(문의 · 가격 · 블로그처럼 테마를 따르는 페이지)다. 다크 변형은 `html[data-theme=dark]` 만이 아니라
**`[data-menu-theme=follow]` 안에서만** 걸린다 — 홈의 라이트 고정을 뚫고 다크 패널이 서고 그 위에 어두운 아이콘이
얹히던 결함(소유자 지적 2026-09-21)의 처방이다.

**구조와 움직임은 Apple 모바일 글로벌 내비(apple.com, 833px 이하)를 옮겼다**(소유자 지시 2026-09-21, 헤더 CSS · JS 에서
값을 뽑아 줄 단위로 검증했다). 앞선 판은 「슬라이드하지 않고 불투명도만 바뀐다」였으나 **지금은 자라는 패널이다.**

### 2단계 드릴

1단계는 모델 · 문서 · 가격 · 문의 · 리소스 다섯이 **같은 단계**이고, **모델 · 문서 · 리소스**가 2단계를 갖는다.
2단계는 열 제목 없이 **한 열**이다(시트의 열을 이어 붙인다). 두 단계를 **같은 칸**에 겹쳐 둔다(`grid-area: 1/1`) —
Apple 도 2단계를 1단계와 같은 원점에 `absolute` 로 겹친다. 높이는 긴 쪽을 따르고 쉬는 단계는 `invisible` 로 빠지며
탭은 `inert` 로 막는다.

| 이동 | 나가는 쪽 | 들어오는 쪽 |
| --- | --- | --- |
| 앞으로(1단계 → 2단계) | 1단계가 **왼쪽 8px** 밀리며 사라진다 · **0ms 지연 · 240ms** (`gnbDrillForwardOut`) | 2단계가 **오른쪽 8px** 에서 들어온다 · **160ms 지연 · 240ms** (`gnbDrillForwardIn`) |
| 뒤로 | 2단계가 오른쪽 8px 로 나간다(`gnbDrillBackOut`) | 1단계가 왼쪽 8px 에서 들어온다(`gnbDrillBackIn`) |

**화면 폭만큼 밀어내지 않는다.** 8px 이동과 80ms 겹침(240 − 160)이 「다음 페이지」의 전부다. 값은 Apple 의
`globalnav-flyout-slide-*` 네 키프레임과 같다(제품 `keyframes.css`). 움직이는 동안 들어온 단계 이동은 무시한다(Apple 도 같다).

**뒤로 버튼이 로고 자리를 쓴다.** 2단계에서는 로고가 240ms 동안 사라지고 `ChevronLeft`(24 · 획 1.75 · 이름은 `aria-label`)가
같은 자리에 선다 — 들어올 때는 **160ms 뒤 오른쪽 4px 에서 240ms**, 나갈 때(뒤로 · 메뉴 닫기)는 **제자리에서 0.8배로 줄며
240ms**. 들어오고 나가는 모양이 다르다. 돌아올 때 로고는 뒤로 버튼이 줄어드는 것과 겹치도록 160ms 뒤에 나타난다.

- Esc 는 어느 단계에서든 **한 단계 뒤가 아니라 메뉴 전체**를 닫고 포커스를 햄버거로 돌려준다. 2단계에서 X 를 눌러도 전체가 닫힌다.
- 단계를 옮긴 뒤 포커스는 들어가면 2단계 첫 링크, 돌아오면 그 단계로 들어간 행이다.
- `prefers-reduced-motion` 에서는 **전부 즉시 바뀐다.** Apple 은 이를 보지 않지만 우리는 본다.

**판정 필요 — 이 값들을 모션 토큰으로 둘지.** 거리 8 · 지연 160 · 길이 240 · 곡선 `0.4, 0, 0.6, 1` 이 제품 상수(`MOBILE_MENU_*`)와
키프레임에 흩어져 있다. 지금은 제품 인용으로만 적는다.

### 재생헤드의 움직임

- 쉴 때 레인의 40.5% 에 선다. **마우스가 타임라인 위를 지나면 그 가로 자리로 따라온다**(소유자 2026-10-07). 벗어나면 쉬는 자리로 돌아간다.
- **시상수 0.12초**의 지수 접근이다(`1 − exp(−dt / 0.12)`). 끝 장면 클립의 감보다 조금 빠르다.
- **`(hover: hover) and (pointer: fine)` 이고 터치가 아닐 때만** 따라온다. 터치는 쉬는 자리에 둔다.
- 창 크기가 바뀌면 쉬는 자리로 다시 둔다. 서버 그림과 첫 그림은 클래스의 자리이고 마운트 뒤에는 스크립트가 `left` 를 px 로 적는다.
- 눈금 · 재생헤드 · 시각은 **장식**이라 `aria-hidden` 이다.

### 접근성

- 타임라인은 `<nav aria-label>`(문구 키 `footer.columns.product`)이고 트랙 이름은 `<h2>` 다. 폰에서 이름이 `sr-only` 로 남으므로 이름은 보조기기에 계속 읽힌다.
- 트랙 아이콘은 `aria-hidden` 이다.
- 공개 예정 클립은 링크가 아니라 `<span aria-disabled="true" title>` 이다 — 「공개 예정 = 툴팁」이 이 자리에서는 사실이다
  ([GNB Menu Item](../components/gnb-menu-item.md) 과 달리).
- 푸터의 폰 축약은 720px 에서 갈린다 — 헤더의 메뉴가 사라지는 선(719px)과 같다.

**Figma 변형은 아직 없다.** Figma 에는 옛 판 푸터(`Product/Public Footer`)가 있고 타임라인 푸터는 없다 — 판 푸터는 제품에서 걷혔다.

## Accessibility

- blur plate는 `aria-hidden="true"`이며 포인터를 받지 않는다.
- 가운데 메뉴는 720px 미만에서 DOM에서 사라진다(`display: none`) — 접힘이 아니라 **소거**다.
  앱 셸이 「이름은 남긴다」로 처리하는 것과 다르다.
- **메가 시트**는 `role="menu"` 이고 이름은 열린 메뉴의 라벨이다. 열 목록은 `role="group"`(이름 = 열 제목)이고 항목은
  `role="menuitem"` 이다 — 메뉴 안에는 메뉴 항목과 그 묶음만 둘 수 있어서 열 제목 `<p>` 는 `aria-hidden` 이고
  목록과 칸은 역할을 지운다(`role="none"`). 전에는 `li` 가 항목과 메뉴 사이를 끊어 스크린리더가 항목을 메뉴 밖 링크로
  읽었다(Lighthouse 접근성).
- 시트를 여는 트리거는 `aria-haspopup` · `aria-expanded` 를 갖는다. **문서**는 호버로 시트를 펼치지만 누르면 그대로 문서
  첫 쪽으로 가는 링크다.
- **닫힌 시트는 `inert` 다** — 투명할 뿐 DOM 에 남아 있어, 막지 않으면 탭이 보이지 않는 링크로 들어간다. 시트 안에
  초점이 있을 때 Esc 로 닫으면 **초점이 트리거로 돌아간다.**
- 모바일 메뉴가 열려 있을 때 로고와 햄버거가 계속 도달 가능하다. **닫기 버튼이 따로 없다** — 햄버거가 X 로 바뀌어 그 일을 한다.
  2단계에서는 로고 자리에 **뒤로 버튼**이 서고(이름은 `aria-label`), 숨은 단계는 `inert` 라 탭이 들어가지 않는다.
- 푸터의 눈금 · 재생헤드 · 시각은 장식이라 `aria-hidden` 이다. 폰에서 트랙 이름은 `sr-only` 로 남는다.

## Acceptance tests

1. 헤더가 본문 자리를 예약하지 않는다 — 첫 섹션이 헤더 밑을 지나간다.
2. blur plate가 **시트가 닫혀 있을 때** 120px 고정이고 뷰포트 높이에 비례하지 않는다. 시트가 열리면 `시트 바닥 ÷ 0.4` 로 늘어나고
   닫으면 120px 로 돌아온다.
3. 같은 톤 입력이 오면 다섯 부품(레일 전경 · 로고 · 메뉴 링크 · 상단 CTA · 햄버거)과 언어 · 테마 트리거가 **함께** 뒤집힌다. 하나만
   뒤집히지 않는다.
4. `lightSurface` 페이지에서는 스크롤과 무관하게 어두운 글씨가 기본 톤으로 고정된다. 섹션이 톤을 알려 오면 그쪽이 이긴다.
5. 라이트 테마에서 `darkSurface` 가 켜지면 밝은 글씨가 서고 **언어 · 테마 트리거 아이콘도 흰색**이다. 메뉴나 시트가 열리면 풀린다.
6. 720px 미만에서 가운데 메뉴가 DOM에서 사라지고 레일이 2열이 된다.
7. 모바일 메뉴가 열려도 로고·햄버거가 눌린다. 2단계에서는 로고 대신 뒤로 버튼이 눌린다.
8. 메가 시트가 헤더 blur plate **위**, 헤더 래퍼 **아래**에 그려진다 — 인라인 층이 클래스를 이긴다.
9. 메가 시트 열 안 항목 간격이 4px 이고 줄 간격이 44px 이다.
10. 푸터가 라이트 테마에서도 `palette-gray-950` 면이다. 720px 미만에서 트랙 이름이 `sr-only` 가 되고 레인이 줄바꿈한다.
11. 가격 카드 · 크레딧 팩 · FAQ 행의 면이 같은 값(`bg-raised`)이다.

## Pre-implementation blockers

- **음수 오버레이 관용구의 판정**(위 Layer order). 인정할지 부채로 볼지 정해야 한다.
- **blur plate가 `backdrop-filter` 축인지 표면 흐림 축인지.** DS의 blur primitive와 같은 축이면
  토큰을 공유하고, 아니면 별도 축을 세운다. **시트 틴트(56%)와 높이 식(`÷ 0.4`)도 같은 판정에 묶인다.**
- **톤 반전을 mode로 볼 것인가.** 라이트/다크 mode와 직교하는 **세 번째 축**이다 —
  [Color & Theme](../foundations/color-theme.md)의 mode 계약은 이 축을 모른다. 입력이 이제 넷(`lightSurface` · `darkSurface` ·
  `pageTheme` · 섹션 톤)이고 두 작업 브랜치가 서로 다른 식을 갖고 있어 **합친 식**이 먼저 정해져야 한다(위 Tone inversion).
- **언어 · 테마 트리거의 잉크 입력을 LOUIS 가 열지**(위 Tone inversion 끝).
- **상단 CTA 의 헤더 톤 변형을 Button 이 가질지**(위 Actions).

## 승격 조건

- 위 blocker가 닫힌다.
- blur plate · 헤더 패딩 · 톤 전환 길이 · 시트 틴트가 semantic token으로 선다.
- 푸터 값이 컴포넌트 문서(트랙 · 클립 · 재생헤드)로 올라가고 Figma 변형이 선다.
- 그 전까지 이 문서의 값은 **제품 인용**이며 DS 계약이 아니다.
