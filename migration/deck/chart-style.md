# 차트 스타일

## 먼저 알아야 할 것

**제품 코드에 차트 라이브러리가 없다.** `apps/web` 의존성에 recharts · d3 · visx · nivo 계열이
하나도 없고, 차트 구현 흔적도 없다(2026-08 확인). 즉 아래 규칙은 **문서·장표·이미지용**이며,
제품에 차트를 도입할 때는 라이브러리 선택부터 사용자와 합의해야 한다.

## 색

차트용 팔레트를 새로 만들지 않는다. 디자인 시스템 토큰에서 고른다.

**계열 색 순서** — 이 순서대로 쓰고, 필요한 만큼만 쓴다:

1. `primary-500` (브랜드 블루)
2. `accent-mint-500`
3. `accent-yellow-500`
4. `accent-violet-500`
5. `accent-pink-500`
6. `accent-sky-500`

- 계열이 6개를 넘으면 **차트를 나누는 게 맞다.** 색을 더 만들지 않는다.
- 계열이 **하나뿐이면 `primary-500`** 만 쓴다. 무지개로 칠하지 않는다.
- **상태를 뜻하는 색은 고정이다** — 성공 `status/success`, 경고 `status/warning`, 위험 `status/danger`.
  이 색을 상태가 아닌 계열 구분에 쓰지 않는다.
- 강조할 계열 하나만 색을 주고 나머지는 `content/tertiary` 로 낮추는 방식을 우선 고려한다.
  계열이 많을수록 이쪽이 읽힌다.

## 축 · 격자 · 라벨

| 요소 | 토큰 |
| --- | --- |
| 격자선 | `border/subtle` — 가로선만, 세로 격자는 생략 |
| 축선 | `border/default` |
| 축 라벨 | `content/tertiary` · `caption-12` |
| 값 라벨 | `content/secondary` · `caption-12` |
| 제목 | `content/primary` · `body-16-semibold` 이상 |

- 선 두께는 아이콘 규칙과 같은 감각으로 얇게 — 격자 0.5px, 데이터 선 2px.
- 범례는 차트 위쪽에 가로로 둔다. 항목이 3개 이하면 범례 대신 **계열에 직접 라벨**을 붙인다.

## 하지 않는 것

- 3D · 그림자 · 그라디언트 채움을 쓰지 않는다.
- 원형 차트로 5개 이상을 나누지 않는다. 그럴 땐 가로 막대를 쓴다.
- 축을 0 에서 시작하지 않은 막대 차트를 만들지 않는다.
- 팔레트에 없는 색을 만들지 않는다. 필요하면 역할을 먼저 추가한다.

## 라이트 · 다크

문서·장표는 보통 한 테마로 고정된다. 그래도 **면 위 전경은 고정 토큰**(`content/on-light`)을 쓰고,
테마를 따르는 화면에 얹을 차트라면 축·격자·라벨을 역할 토큰으로 잡아 양쪽에서 확인한다.
