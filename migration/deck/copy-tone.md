# 카피와 문서 표현 원칙

원천: `apps/web/components/landing/system/messages/{ko,en,ja*}.ts`.
아래는 그 문구들에서 관찰된 규칙이다. 새 문구를 쓸 때 여기에 맞춘다.

## 언어

- 제품 UI 문구는 **KOR / ENG / JPN 세 언어**를 함께 넣는다. 한 언어만 추가하지 않는다.
- 파일: `ko.ts` · `en.ts` · `ja-overrides-surface.ts`.
- 하드코딩 금지 — 에러·모달·토스트·확인/취소 라벨·버튼 문구는 전부 `messages` 를 거친다.

## 톤

- **평서형 종결.** "~합니다" 를 기본으로 하고, 버튼·메뉴 라벨은 명사형으로 끊는다
  (`업그레이드`, `새 캔버스 프로젝트`, `비디오 에디터`).
- **과장하지 않는다.** 슬로건도 기능을 그대로 말한다 —
  `AI 영상 제작의 모든 순간을 하나의 워크스페이스로.` (`footer.tagline`)
- **사용자를 탓하지 않는다.** 에러는 상태를 말하고 다음 행동을 준다.
  `생성 중 오류가 발생했습니다.` 처럼 무엇이 일어났는지 먼저 쓴다.
- **기능 이름은 한국어로.** `노드 캔버스` · `비디오 에디터` · `하이라이트` · `분석`.
  제품명(`Klipse`)과 플랫폼명(`YouTube` · `Instagram`)만 원문을 유지한다.
- **아직 없는 기능은 숨기지 말고 표시한다.** `탐색 · 업데이트 예정`, `베타` 배지.

## 표기

- 로마자 제품명은 첫 글자만 대문자 — `Klipse`. 전부 대문자로 쓰지 않는다.
- **UI 라벨·아이브로우를 전부 대문자로 쓰지 않는다.** 문장형을 쓴다.
- 숫자와 단위는 붙여 쓴다 — `6s`, `4K`, `21:9`.
- 가운뎃점(`·`)으로 나열을 구분한다. 쉼표 나열보다 이쪽을 쓴다.

## 문서·장표에서

- 제목은 명사구로 끊고, 부제에서 문장으로 설명한다.
- 한 장표에 주장 하나. 근거는 그 아래.
- 수치를 쓸 때는 기준 시점과 출처를 같은 장표에 남긴다.
