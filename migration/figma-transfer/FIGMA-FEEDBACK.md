### `전역`/`앱셸` 모드 추가 여부 — 의견

**문서 쪽 세션의 「추가하지 않는다」에 동의한다.** 이유를 하나 덧붙인다.

Figma 모드는 **프레임에 수동으로 지정**하는 것이라, 잘못 지정해도 아무 경고가 없다. 실제로 이번 작업 전에
`Semantic` 컬렉션 모드를 프레임에 걸어 두고도 컴포넌트가 고정 팔레트에 묶여 있어 테마가 전혀 반응하지
않는 상태를 한동안 못 알아챘다. 모드가 하나 더 늘면 「모드는 맞는데 값이 틀린」 조합이 두 배가 된다.

대신 **해결값 직접 입력 + 문서가 정본**이 낫다. 다만 그러면 Figma 쪽 값이 문서와 어긋나도 잡히지 않으므로,
**Figma 덤프 대 문서 3자 대조**(`build-design-tokens.mjs --figma` 가 이미 하는 일)를 앱 화면 색까지
확장하는 것을 제안한다.

## 4차 — 되먹임을 문서에 직접 반영 (2026-08-08)

보고만 하지 않고 **확인한 것은 내가 문서에 넣었다.** 넣은 것은 전부 코드에서 대조한 값이다.

| 문서 | 넣은 것 | 근거 |
| --- | --- | --- |
| `10.1.md` 배너 절 | 슬라이드 설명문 **EN 2줄 × 3장** 표 + 화살표 `aria-label` KO/EN | `messages/en.ts:3008-3026` |
| `10.1.md` 기계 추출 증거 | **`#### 아이콘 원본 ② — 마스크로 쓰는 파일`** 신설 | 파일 6개 직접 판독 |

| `10.6.md` 브랜드 패널 | 슬로건이 **`auth` 가 아니라 `footer` 트리**라는 경고 | 위와 같음 |

새 절 「아이콘 원본 ②」가 필요했던 이유 — 기존 `#### 아이콘 원본` 은 **인라인 SVG 만** 담는데,
사이드바 아이콘은 `mask-image: url(...)` 파일 참조라 코드 안에 path 가 없다. 그래서 「아이콘 원본이
없다」로 보였다. 절 제목이 범위를 정확히 말하고 있었는데 내가 못 읽은 것이다.

그 절에 **마스크는 색을 갖지 않는다**는 경고도 넣었다 — `MagicWand.svg` 는 `stroke="white"`,
`youtube.svg` 는 `stroke="black"` 인데 둘 다 마스크라 무의미하다. 그대로 옮기면 틀린다.
`MagicWand.svg` 만 `stroke-width: 2`(나머지 2.4)라는 것도 적었다.

### 남긴 것 (내가 못 채움)

- **`--gray-800` 라이트 값** — 문서에 직접 없어 `--gray-N`(라이트) = `palette-gray-(1000−N)` 로
  유도했고 `style-evidence --var gray-800` 로 **전역 `#e3e4e8`** 확인. 앱 셸에서는 시프트로
  **`#eeeef1`** 이 된다. 이 유도 규칙 자체를 §4.0.1 에 한 줄로 적어 두면 매번 유도하지 않아도 된다.
- **워크플로우 항목 아이콘** — 문서·코드 어디에서도 확인하지 못해 「확인되지 않았다」로 적었다.

### 반응형 — 지적받고 고침

프레임을 절대 좌표 + 고정 크기로 놓아 **폭을 바꾸면 그대로 남았다.** 코드 구조대로 바꿨다:

| 화면 | 구조 |
| --- | --- |
| `/archive` | 루트 HORIZONTAL 오토레이아웃 → 사이드바 280 고정 + `sceneAppSidebarRail`(패딩 상12·우12·하12·좌**0**) FILL. 카드 FILL/FILL |

### 블루 버튼 — 지적받고 고침 (내 누락)

### 11차 — 비율 잠금

프로젝트 카드가 `aspect-ratio: 1/1` 인데 Figma 에서 390×270 직사각형으로 나왔다.

**원인**: `node.targetAspectRatio = {...}` 로 대입했는데 이 프로퍼티는 **읽기 전용**이다
(`TypeError: read-only property on FRAME node`). 내가 `try/catch` 로 감싸 두어 **실패를 못 봤다.**
카드 4장 전부 `ar: null` 인 채로 지나갔다.

**해결**: 전용 메서드 **`node.lockAspectRatio()`** 가 있다. 정사각으로 맞춘 뒤 호출한다.
프레임을 2400 으로 넓혀 **510×510**, 1920 으로 되돌려 390×390 을 확인했다 — 진짜 잠금이다.

같은 방식으로 커버에도 걸었다 — `/templates` **4/3** · `/blog` **16/9** (총 12개).

> **`try/catch` 로 감싼 Figma API 호출은 실패를 숨긴다.** 이번 세션에서 이걸로 놓친 게 두 번째다
> (첫 번째는 `components.json` 이름 불일치로 설명 갱신이 no-op 된 것). 감쌀 거면 **에러를 반환값에
> 담아 확인**해야 한다.

### 15차 — 그림자 z-order 와 백드롭 블러

**① `::before` 를 프레임 효과로 대신할지, 실제 레이어로 만들지는 `z-index` 가 정한다.**

Figma 의 `INNER_SHADOW` 는 **불투명한 자식 아래**에 그려진다. CSS 의 inset box-shadow 도 같다.
그래서 카드의 흰 림이 `archivePreview` 에 통째로 가려져 있었다.

- 버튼 `::before` — `z-index` 없음 → 콘텐츠 아래 → **프레임에 직접** 건다
- 카드 `::before` — **`z-index: 5`** → 콘텐츠 위 → **실제 레이어**가 필요하다

앞서 「대용 박스를 만들지 말 것」으로 규약을 적었는데 **기준이 틀렸다.** 판단 기준은
「박스를 만들지 마라」가 아니라 **「z-index 가 콘텐츠 위인가」** 다. §3 을 그렇게 고쳤다.

**② `backdrop-filter` → `BACKGROUND_BLUR` 1:1 대응.** 「재현 불가」로 미뤘던 자리에 전부 적용했다(18곳).

| 자리 | 값 |
| --- | --- |
| 배너 컨트롤 알약 | `blur(12px) saturate(130%)` → BACKGROUND_BLUR 12 |
| 배너 `::before` | `blur(22px) saturate(125%)` → BACKGROUND_BLUR 22 |
| 카드 타이틀 오버레이 | `blur(10px)` → BACKGROUND_BLUR 10 |
| 마케팅 GNB 블러 밴드 | 높이 120 · `blur(12px)` → BACKGROUND_BLUR 12 |

**남는 재현 불가는 「블러」가 아니라 「블러에 씌운 그라디언트 마스크」**다. `saturate()` 도 대응이 없다.
이 구분을 §3 에 명시했다 — 이전 기록이 「백드롭 블러 = 재현 불가」로 되어 있어 오해를 낳았다.

### 16차 — 글래스 프레임 단순화 (갈래 A · 코드까지 변경)

「글래스 섀도우 싹 다 제거하고 0.5px 그레이스케일 스트로크로」 요청.
`SYNC.md` §2 의 **갈래 A** 절차대로 **코드를 먼저** 고쳤다.

**호출부 40여 곳을 고치지 않고 토큰 하나만 바꿨다** — `--glass-dropdown-frame` 은 111곳이 공유하는
SSOT 라서, 정의를 바꾸면 전부 따라온다. (CLAUDE.md 「가장 작은 변경」 원칙)

```css
/* 다크(:root) */  --glass-dropdown-frame: 0 0 0 0.5px var(--palette-gray-700);  /* #575d68 */
/* 라이트      */  --glass-dropdown-frame: 0 0 0 0.5px var(--palette-gray-300);  /* 전역 #d5d7dd */
```

- **`border` 가 아니라 spread-only `box-shadow`** 로 그렸다. border 는 박스 크기를 바꿔 111곳의
  레이아웃을 민다. spread-only 는 밀지 않는다.
- **라이트를 팔레트 토큰으로 둔 것이 핵심**이다. §4.0.1 앱 셸 램프에서 `palette-gray-300` 이
  자동으로 한 칸 이동해 **앱 화면 #e4e5e9 · 랜딩 #d5d7dd** 가 된다 — 두 면 모두에서
  「요소·부모와 겹치지 않는 톤」 조건을 만족한다. hex 를 박았으면 한쪽이 틀렸을 것이다.
- `--glass-dropdown-frame-on-dark` 도 같은 값으로 통일했다. 분리 이유였던 「흰 림이 라이트에서
  뒤집힌다」가 림이 사라져 없어졌다. 이름만 호환용으로 남겼다.

**갱신한 것**: `globals.css` → `tokens.yaml` · `llms/{foundations,patterns}.txt` ·
`DESIGN_SYSTEM.md` 토큰 표(생성) · **§6.1.1 산문(손으로 재작성)**.
§6.1.1 은 제목부터 「5겹」이었다 — 생성 구간이 아니라 게이트가 못 잡는 자리다.

**검증**: `verify-gates` 10개 + 카나리아 4종 · `check-types` · `lint`(오류 0) 통과.
Figma 26 프레임의 스트로크도 앱 셸/랜딩에 맞춰 재조정했다(11곳).

> **남은 판단**: `--glass-bevel-highlight/shade`(베벨)는 **손대지 않았다.** 프레임과 다른 계열이고
> 블루 버튼·업그레이드 CTA 등 입체감 표현에 쓰인다. 이것도 걷어낼지는 별도 결정이 필요하다.

`minmax(0,1.2fr) minmax(320px,0.8fr)` 라 1.2:0.8 을 못 넣어, 컨테이너 폭에서 계산한 고정값으로 넣었다.
→ `SYNC.md` §3 에 넣을 항목.

**재현 불가로 남긴 것**
- 기간 세그먼티드 **썸** — `left`/`width` 를 `getBoundingClientRect` 로 JS 가 잰다. 정적 마크업으로 재현 불가.

**§10.9 — 다크에서는 경계가 없다**

페이지 바닥·스테이지·캔버스가 **셋 다 #171b22** 다. 라이트에서만 캔버스/스테이지(#e3e4e8)가
페이지 바닥(#f1f1f3)보다 어둡다. 「캔버스가 더 어두운 면」이라는 인상은 **라이트에만 성립**한다.

**같은 값인데 토큰 이름이 셋 다 다르다** — 라이트 캔버스는 `--gray-800`, 스테이지는
`--palette-gray-200`, 페이지는 `--gray-900`. 이름만 옮기면 어긋난다.

**툴바·줌 알약은 두 테마 모두 캔버스 바닥보다 밝다**(다크 #313640 vs #171b22).
「다크니까 더 어두운 크롬」으로 그리면 틀린다. 헤더도 면이 없다 — 48px 블러 + 캔버스색 45% 틴트
띠뿐이라 **사각 바로 그리면 배포와 다르다.**

**§10.10 — 도킹 모달은 아무것도 그리지 않는다**

`modalShellDocked` 가 셸의 면·그림자·곡률을 전부 무력화한다. 뒤 카드 면(라이트 #f8f8f9 /
다크 #313640)이 그대로 배경이 된다. **모달을 「어두운 라운드 판」으로 옮기면 틀린다.**
모달 헤더 액션은 상단 크롬 바의 `mainChromeProfileLeading` 슬롯으로 portal 되므로
**모달 자체 헤더 행은 렌더되지 않는다.**

**§10.11 — 고정 업로드 카드는 패널 밖에 있다**

`position: fixed` · `left: 사이드바 폭` · `right: 0` · `margin: 0 auto` · 400×140 · bottom 20.
페이지 루트의 마지막 자식이라 패널의 `overflow:hidden` 에 클립되지 않는다.
Figma 에서 오토레이아웃 흐름에 넣었더니 우측으로 밀려 나갔다 — **`layoutPositioning: ABSOLUTE` + constraints
가 필수**다. 빈 상태에서는 같은 카드가 인플로우 960×240 으로 바뀐다(변형이 두 개다).
