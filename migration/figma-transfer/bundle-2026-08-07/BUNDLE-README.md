## 지난번에 틀린 5가지 — 전부 문서에 들어갔다 (2026-08-07)

Figma 이관 중 보고된 5건은 **문서의 결함이 맞았다.** 고쳤고, 전부 `foundations.txt` 끝의
생성 절에 있다. 다시 시작하기 전에 이 5절부터 본다.

| 지난번 문제 | 어디에 |
| --- | --- |
| 토큰 **이름만** 있고 해결된 최종값이 없어 `surface/inset` 다크 색을 틀림 | 이제 모든 테마 값이 `별칭 → 최종값` 으로 나온다. 예: `surface-inset: light=var(--palette-gray-100) → #f1f1f3 dark=var(--palette-gray-600) → #777d89` |
| **오버라이드된 기본값** — 업그레이드 버튼이 정의는 민트, 실제는 검정/흰색 | `## ⚠ 오버라이드된 기본값` (베이스 정의와 실제 값을 나란히 적었다) |
| **토큰 이름이 종류를 뜻하지 않음** — `--glass-dropdown-frame` 은 드롭섀도우가 아니라 헤어라인 링 | `## ⚠ 토큰 이름이 종류를 뜻하지 않는다` (값에서 종류를 뽑아 적는다) |
| **화면별 레이어 순서·관계**가 없어 카드가 통째로 빠짐 | `## 화면 레이어 사다리` (라이트에서 페이지 바닥 = 카드 면 = `#f1f1f3` 로 **같은 색**이다. 경계는 색이 아니라 테두리·여백으로 난다) |
| **Figma 로 표현 불가한 것** 미명시 | `## Figma 등 다른 도구로 그대로 옮길 수 없는 것` (뒤 배경 블러 66파일 · 그라디언트 마스크 23파일 · 테마를 따라가지 않는 그림자 · `@layer` 우선순위) |

전부 `globals.css` 와 소스에서 **생성**된다 — 손으로 쓴 게 아니라 재생성하면 갱신된다.

Figma 쪽 `Home — 로그인 후 (시스템 검증)` 의 미검증 부분(토글 아이콘 · 구분선 진행도 ·
상태 배지 · 빈/로딩 상태)은 **아직 문서 근거가 없다.** 위 5절로 해결되는 항목이 아니므로
그대로 신뢰하지 말 것 — 필요하면 알려주면 해당 화면의 사양을 뽑아 문서에 넣는다.

## 작업 전에 반드시 알아야 할 3가지

### 1. 역할 토큰은 아직 코드에 없다 — Figma 의 계획이다

`foundations.txt` 의 `## Color — roles` 절을 보면 이름마다 표시가 붙어 있다.

```
surface/: page[코드] · raised[코드] · … · overlay[Figma 전용] · inverse[Figma 전용] · brand[Figma 전용]
content/: primary[Figma 전용] · …   ← 그룹 전체가 Figma 전용
구현 현황: 35개 중 9개만 CSS 변수로 존재한다.
```

- **Figma 작업에서는** 역할 이름을 그대로 써도 된다. 그게 Figma 쪽 어휘다.
- **다만 그 이름이 코드에 있다고 가정하지 말 것.** 9개만 실재하고, 그 9개조차 현재 소비처가 0이다.
- 역할 층을 실제로 코드에 착지시킬지는 **미결정**이다 (`DESIGN_SYSTEM.md` §7.5).

이 표시가 없던 시절, 문서가 "신규 작업 기준" 이라며 존재하지 않는 토큰을 쓰라고 지시하는 상태가 됐었다.
같은 일이 반복되지 않도록 표시를 확인하고 작업할 것.

### 2. 토큰은 코드가 원천이다 — Figma 에서 새로 저작하지 말 것

`foundations.txt` · `tokens.yaml` 은 `apps/web/app/globals.css` 에서 **생성**된다.
Figma Variables 는 이 값을 **가져오는** 쪽이지 만드는 쪽이 아니다.

Figma 에서 값을 새로 정하면 코드와 갈리고, 그 갈림을 잡아주는 장치가 없다.
필요한 값이 없으면 임의로 만들지 말고 **없다는 사실을 보고**할 것 — 그게 시스템에 추가될 항목이다.

### 3. `components.txt` 만 방향이 반대다

다른 문서는 전부 `globals.css` → 문서인데, 이 파일만 Figma 보드 → 문서다. 그래서:

- **코드에는 있는데 Figma 보드에 없는 컴포넌트는 이 목록에 안 나온다.** 목록에 없다고 없는 게 아니다.
- 반대로 Figma 에만 있고 코드에 없는 항목이 섞여 있다 (예: 코드 검색 결과 0회인 이름들).

컴포넌트를 Figma 에 만들 때는 `DESIGN_SYSTEM.md` 의 해부 절(§6.9 노드 · §6.10 Button ·
§6.11 모달 · §6.12 툴팁/피드백 · §6.13 앱 셸 · §6.14 상태 화면 · §6.15 Auth 폼 · §6.16 페이지 피드백)을
같이 보는 편이 정확하다. 그쪽은 코드에서 뽑은 것이다.

## 결정이 필요한 4건 — Figma 가 임의로 굳히면 안 되는 것

`DESIGN_SYSTEM.md` §7.5 에 미결정 **69건**이 있다. 대부분은 Figma 가 안 그리는 영역이지만,
아래 4건은 **Figma 가 그리면서 한쪽을 기정사실로 만들어 버린다.** 그리기 전에 확인할 것.

| 결정 | 상황 |
| --- | --- |
| 역할 토큰 층 착지 여부 | 위 1번. Figma 35개 vs 코드 9개 |
| 앱 셸 형태 A/B | 카드를 `<main>` 에 거는 계열과 별도 패널 div 에 거는 계열이 공존한다. 한쪽만 그리면 나머지 절반이 시스템 밖이 된다 |
| 토스트 글래스/솔리드 | 두 스타일이 병존하고 radius·elevation·blur 가 양립 불가 |
| 포커스 링 | **코드 결정이다.** `globals.css` 가 레이어 밖에서 outline 을 죽이고 있어, 어떤 토큰을 만들어도 호출부마다 `!` 가 필요하다 |

이 4건은 답이 정해지면 알려주면 문서와 토큰에 반영한다.

## 이 스냅샷이 낡았을 때

```bash
./refresh.sh                      # 기본 레포 ~/klipse
REPO=~/klipse-aws ./refresh.sh    # 이사한 뒤
```

**손으로 복사하지 말 것.** 한 번 손으로 만들었더니 `skill-references/` 가 통째로 빠졌고,
그 안에 장표 그리드가 들어 있어서 팩만 본 세션은 컴포넌트가 있다는 건 알아도
어디에 놓을지 몰랐다. 파일 목록은 `refresh.sh` 안에 있다 — 새 참조 파일이 생기면 거기에 추가한다.

스크립트가 하는 일:

- 레포의 생성 문서가 `globals.css` 와 어긋나 있으면 **복사하지 않고 중단**한다.
  어긋난 상태를 팩에 옮기면 팩이 조용히 틀린 값을 퍼뜨린다.
- 9개 문서 + `skill-references/` 를 복사한다.
- `KLIPSE-DESIGN-SKILL.md` 가 §6 에서 가리키는 참조 파일이 **전부 왔는지 대조**하고,
  하나라도 없으면 실패한다. 지난번 누락이 이 검사에 걸린다.
- `_SNAPSHOT.txt` 에 커밋·미커밋 변경 건수·시각을 남긴다.
  이 팩은 커밋이 아니라 **작업 트리 상태**를 담는다는 점에 주의.
