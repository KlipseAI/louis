### 10.3 템플릿 (`/templates` · `/templates/[slug]`)

**6.13(앱 페이지 셸)은 이 두 라우트에 적용되지 않는다.** 좌측 사이드바도, 라운드 메인 카드도 없다. 두 라우트는 랜딩과 같은 **마케팅 셸**(상단 fixed GNB + 하단 푸터)을 `TemplateShell` 로 두르고, 그 위에 **테마를 따르지 않는 고정 라이트 서피스**를 강제한다. 다크 테마로 바꿔도 이 두 페이지의 콘텐츠 영역은 픽셀이 바뀌지 않는다.

**§6.10 공용 Button 은 본문에서 쓰지 않는다.** 본문에 나오는 버튼 3종(프롬프트 복사 · 캐러셀 좌우 · 캐러셀 점)은 전부 `components/ui/Button.tsx` 를 거치지 않는 전용 구현이다. `ui/Button` 이 쓰이는 자리는 **GNB 상단 CTA 와 모바일 오버레이 CTA 둘뿐**이고, 그 둘은 같은 컴포넌트를 쓰면서도 서로 다른 화면을 만든다(아래 GNB 절). **모달은 이 그룹에 없다** — §6.11 은 해당 없음.

> **§6.2(GNB Landing)는 이 라우트에 대해 틀린 문서다.** 그래서 **이 절이 GNB 와 Footer 를 자체 기술한다.** §6.2 는 navBlack 을 "scroll trigger 로 pricing/final-cta 라이트 섹션 위에서만 활성"이라 적지만 이 두 라우트는 `<Gnb lightSurface />` 라 **스크롤과 무관하게 상시 navBlack** 이다. 수치도 어긋난다 — Wrapper padding 문서 `16px 20px` vs 코드 `12px 12px 12px 20px`(`Gnb.tsx:70-75`), "상단 블러 그라디언트 8-step" vs 코드 `backdrop-filter: blur(12px)` + 마스크 1개(`Gnb.tsx:63-68`). 일치하는 것은 로고 높이 24px 과 메뉴 버튼 높이 28px 둘뿐이다. **DESIGN_SYSTEM.md 에는 Footer 절 자체가 없다**(실질 언급은 §6.15 Auth brandPanel 의 `#0093ff` 한 줄인데 푸터의 `#007aff` 와 다른 값이다).

├─ <PastDueBanner />                       ← fixed z-index 9999. SITE_ROOT 바깥·위 (조건부)
└─ SITE_ROOT   (min-h-svh flex flex-col)   ← 이 화면에서 테마가 보이는 유일한 면

`TemplateShell` 의 자식 순서는 **고정 4개**이며 분기가 없다(`TemplateShell.tsx:44-49`). 두 라우트가 넘기는 `children` 은 최상위 요소 **하나**뿐이다 — 목록은 `<section>`, 상세는 `<article>`.

GNB 의 커뮤니티 드롭다운과 LanguageSelector 메뉴는 **`document.body` 로 포털**되므로 이 트리 밖에 있다. **`[data-page-root]` 램프를 받지 않는다** — 두 메뉴의 색은 `html[data-theme]` 값으로 해석된다.

#### 셸이 강제하는 라이트 서피스 (`LIGHT_SURFACE_CLASS`, `TemplateShell.tsx:25-33`)

`<main data-page-root>` 한 요소에 걸리는 **7개 유틸리티 전부가 중요 선언(`!`)** 이다. 같은 요소를 겨냥하는 레이어 **밖** `[data-page-root]` 블록(`globals.css:1649-1685`)을 이기기 위한 것이고, 레이어 **안**의 중요 선언은 레이어 밖 일반 선언을 이긴다.

| 선언 | 별칭 | 해결된 최종값 (라이트 = 다크) | `[data-page-root]` 기본값 |
| --- | --- | --- | --- |
| `--page-bg` | `var(--palette-gray-100)` | **`#f1f1f3`** | `var(--gray-1000)` = **`#000000`** |
| `--gray-000` | `var(--palette-gray-1000)` | **`#000000`** | `var(--palette-gray-000)` = `#fafafa` |
| `--gray-000-rgb` | `var(--palette-gray-1000-rgb)` | **`0 0 0`** | `250 250 250` |

| `--text-muted` | `rgb(var(--palette-gray-1000-rgb) / 0.52)` | **`rgb(0 0 0 / 0.52)`** | `rgb(var(--gray-000-rgb) / 56%)` |

`palette-*` 는 테마 불변이므로 **다섯 토큰 모두 라이트/다크에서 값이 같다.** 이 오버라이드가 없으면 랜딩 기본값대로 페이지가 **검정 바탕에 흰 글씨**가 된다.

#### 스크롤 모델

**스크롤 컨테이너는 문서(`body`) 하나뿐이다.** §6.13 의 "문서는 스크롤하지 않는다" 와 정반대다. 페이지 내부에 별도 스크롤 영역도, `sticky` 요소도 없다. 고정 요소는 GNB 와(조건부) 배너뿐이다.

- `globals.css:912-925` 의 `html, body { max-width: 100vw; overflow-x: clip; scrollbar-width: none }` + `html/body::-webkit-scrollbar { width:0; height:0; display:none }` → **문서 스크롤바는 완전히 숨겨진다.** (전역 `*` 커스텀 스크롤바 규칙은 html/body 를 제외한 스크롤 영역용이고, 이 화면에는 그런 영역이 없다.)
- 섹션의 `scroll-mt-60`(= `scroll-margin-top: 120px`)이 fixed GNB 블러 밴드 높이(120px)를 보정한다.

#### 반응형 타입 램프 (`[data-page-root]` 스코프 — `globals.css:873-910`)

| 토큰 | 기본 | ≤1023px | ≤767px | ≤479px |
| --- | --- | --- | --- | --- |
| `--type-heading-48-size` | 48px | 36px | 32px | **28px** |
| `--type-heading-36-size` | 36px | 32px | 28px | **20px** |
| `--type-body-20-size` | 20px | 18px | 16px | 16px |

`heading-48` 은 전 구간 `letter-spacing: -0.02em`. `heading-36` 은 ≤479px 에서만 **`-0.01em`** 으로 바뀐다. 기본값: `heading-48` 48/1.35/−0.02em · `heading-36` 36/1.35/−0.02em · `body-20` 20/1.5/−0.01em · `body-16` 16/1.5/−0.01em · `body-14` 14/1.5/−0.01em · `caption-12` 12/1.5/−0.01em. 굵기 `regular` 400 / `medium` 500 / `semibold` 600. `type-*` 클래스는 `font-family: var(--type-font-family)`(Pretendard) 와 `font-feature-settings: "ss07" 1` 도 함께 싣는다(`globals.css:1048-1071`).

**별개의 전역 규칙 하나가 더 있다** — `:root` 에 걸리는 `@media (max-width: 450px) { --type-body-16-size: var(--type-body-14-size) }`(`globals.css:860-864`). 이 스코프 램프와 무관하게 450px 이하에서 eyebrow · 목록 설명 · 빈 상태 · 프롬프트 본문이 전부 **14px** 이 된다.

**이 램프는 푸터·GNB 오버레이에도 적용된다** — 둘 다 `<main data-page-root>` 안이다. 푸터 태그라인(`type-heading-36-medium`)은 고정 36px 이 아니라 36→32→28→**20px**, 모바일 오버레이 항목(`type-body-20-medium`)은 오버레이가 보이는 ≤719px 구간에서 항상 **16px** 이다.

#### 레이아웃에 영향을 주는 레이어 밖 전역 규칙

`globals.css` 맨 끝(레이어 **밖**, 1632-1743)과 상단 리셋 뒤(1017-1032)에 있는 규칙들이고, 이 그룹의 `!` 는 전부 그것을 되받는 자리다.

| 규칙 | 내용 | 이 그룹의 대응 |
| --- | --- | --- |
| `[data-page-root] :where(h1..h6, p, li, dt, dd, figcaption, blockquote, a, button, label, legend, span, strong, em, small, td, th)` | `text-wrap: balance` · `word-break: keep-all` · `overflow-wrap: break-word` · `line-break: strict` (**`div` 는 목록에 없다**) | 제목 `[text-wrap:balance]!` · 부제/프롬프트 `whitespace-pre-wrap!` `[word-break:break-word]!` · **Button 의 `white-space:nowrap` 은 여기에 진다**(`Button.tsx:14-20` 이 "`!` 를 붙였다가 헤더/푸터 높이가 어긋난 실제 사고" 를 기록) |
| `[data-page-root] [data-reveal]` | `opacity: 1` · `transform: none` · `filter: none` (0,2,0) | 목록 카드 hover lift 가 여기에 **진다** — 「놓치기 쉬운 것」 참조 |
| `a { color: inherit; text-decoration: none }` | 링크 색·밑줄 제거 | 카드 `[text-decoration:none]!` · 뒤로가기 `text-[var(--text-soft)]!` `[text-decoration:none]!` · 푸터 링크 전부 `!` |
| `button:focus, button:focus-visible, button:active { outline: none }` | **`button` 과 `input[type=button|submit|reset]` 만** 대상 | 복사 버튼·캐러셀 버튼·햄버거·CTA 의 포커스 링이 사라진다. **`<a>` 는 대상이 아니다** → 푸터 소셜 링크만 포커스 링이 살아 있다 |
| `@layer base { * { box-sizing:border-box; padding:0; margin:0 } }` | 전역 리셋 | 프롬프트 `<h2>` 등이 margin 0 인 근거 |

`--spacing: 2px` 격자이므로 유틸 숫자 × 2px 다.

| --- | --- | --- |

| `py-56 px-10` | `padding: 112px 20px` | 항상 |

## 결과 캐러셀 (`TemplateResultCarousel`)

라이브러리 없이 CSS 3D 트랜스폼만 쓴 커버플로우다. `items` 는 `template.media` 전량 + `workflow_video_url` 이 있으면 마지막에 `{ type: "video", url, label: copy.workflowTitle }` 1장. **워크플로 영상은 별도 섹션이 아니라 캐러셀의 마지막 카드**이고 라벨 배지로만 구분된다.

#### 스테이지 · 카드 기하

| 요소 | 값 | ≤640px |
| --- | --- | --- |
| 바깥 래퍼 | `margin-top: 8px`(`mt-4`) | — |
| 스테이지 | `position: relative` · `height: 540px` · `perspective: 1400px` · `transform-style: preserve-3d` · `outline: none` · `touch-action: pan-y` · `overflow: hidden` | `height: 440px` |
| 스테이지 접근성 | `tabIndex={0}` · `role="group"` · `aria-roledescription="carousel"` · `aria-label="결과 미디어"` | — |
| 카드 | `position: absolute` · `top: 50%` · `left: 50%` · `height: 500px` · `aspect-ratio: 4/5` · `border-radius: 16px` · `overflow: hidden` · `background: #000` · `will-change: transform, opacity` | `height: 400px` |
| 카드 트랜지션 | `transform 520ms cubic-bezier(0.22,1,0.36,1), opacity 400ms ease, box-shadow 400ms ease` | — |
| 미디어 `MEDIA_CLASS` | `width: 100%` · `height: 100%` · `object-fit: cover` · `display: block` · `user-select: none` | — |

카드 **폭은 높이에서 파생**된다 — `aspect-ratio: 4/5` 이므로 500px → **400px**, 모바일 400px → **320px**. 상세 본문 래퍼가 860px 이어도 카드 폭은 그와 무관하다.

#### 미디어 요소 속성 (`TemplateResultCarousel.tsx:179-197`)

| 태그 | 속성 |
| --- | --- |
| `<video>` | `src={m.url}` · **`controls={isActive}`** · **`muted={!isActive}`** · `playsInline` · `preload="metadata"` — **`autoPlay` 없음 · `loop` 없음 · `poster` 없음** |
| `<img>` | `src={m.url}` · `alt=""` · **`draggable={false}`**(스와이프 제스처 충돌 방지) · `loading="lazy"` |

**캐러셀 영상도 자동 재생되지 않는다.** 사용자가 활성 카드의 네이티브 컨트롤을 직접 누르기 전까지 아무것도 재생되지 않는다.

#### 3D 배치 — 클래스가 아니라 JS 인라인 `style`

각 카드는 `offset = i − active`, `abs = |offset|` 로 매 렌더 인라인 계산된다.

```
transform: translate(-50%, -50%)
           translateX(offset × 52%)      ← 카드 자기 폭 기준
           translateZ(abs × −140px)
           rotateY(offset × −34deg)
           scale(max(0.7, 1 − abs × 0.08))
z-index:   100 − abs
opacity / pointer-events:  abs > 3 이면 0 / none, 아니면 1 / auto
```

**클래스만 읽으면 카드가 전부 한 점에 겹쳐 보인다.** 배치를 재현하려면 이 식이 필요하다.

#### 라벨 배지 · 컨트롤

| 요소 | 값 |
| --- | --- |
| 라벨 배지 | `type-caption-12-medium` · `position: absolute` · `left: 12px` · `bottom: 12px` · `padding: 4px 10px`(`py-2 px-5`) · `border-radius: 8px` · `background: rgb(0 0 0 / 58%)` · `color: #fafafa` · `pointer-events: none`. `m.label` 이 있는 카드(= 워크플로 영상)에만 |
| 컨트롤 줄 | `display: flex` · `align-items: center` · `justify-content: center` · `gap: 16px`(`gap-8`) · `margin-top: 20px`(`mt-10`). **`count > 1` 일 때만 렌더** |
| 좌우 버튼 | `inline-flex` 중앙정렬 · **`40 × 40px`**(`w-20 h-20`) · **`border-radius: 50%`**(`rounded-[50%]` — `rounded-full` 의 999px 아님) · `border: 1px solid rgb(0 0 0 / 16%)` · `background: rgb(0 0 0 / 6%)` · `color: #000000` · `cursor: pointer` · `transition: background 160ms ease, border-color 160ms ease, opacity 160ms ease` |
| 좌우 버튼 hover | `[&:hover:not(:disabled)]` — `background: rgb(0 0 0 / 12%)` · `border-color: rgb(0 0 0 / 26%)` |
| 좌우 버튼 disabled | `opacity: 0.3` · `cursor: default` |
| 글리프 · 라벨 | `‹`(U+2039) / `›`(U+203A), `aria-label="이전"` / `"다음"` |
| 점 컨테이너 | `display: flex` · `align-items: center` · `gap: 8px`(`gap-4`) · `role="tablist"` |
| 점 공통 `DOT_CLASS` | **`8 × 8px`**(`w-4 h-4`) · `padding: 0` · **`border: none`**(`[border:none]` — `border-0` 아님) · `border-radius: 50%` · `cursor: pointer` · `transition: background 160ms ease, transform 160ms ease` · **`[&:hover]:background: rgb(0 0 0 / 40%)`** · `role="tab"` · `aria-selected` · `aria-label="{i+1}번째 미디어"` |

#### 점(dot) 4상태 — **활성 점은 hover 하면 파랑을 잃는다**

| 상태 | background | transform |
| --- | --- | --- |
| 비활성 | `rgb(0 0 0 / 22%)` | — |
| 비활성 + hover | `rgb(0 0 0 / 40%)` | — |
| 활성 | `var(--primary-500)` = **`#0088ff`** | `scale(1.35)` |
| **활성 + hover** | **`rgb(0 0 0 / 40%)`** | `scale(1.35)` |

전 상태 160ms. 근거는 파일 상단 주석(`TemplateResultCarousel.tsx:21-24`)에 명시돼 있다 — 원본 모듈 CSS 에서 `.carouselDot:hover`(0,2,0) 가 `.carouselDotActive`(0,1,0) 를 이겨 활성 점도 호버 시 회색 40% 가 됐고, Tailwind 에서도 hover 변형이 무접두 `bg-primary-500` 보다 뒤에 출력되므로 **같은 결과를 의도적으로 보존**했다. '활성이면 파랑 유지' 로 만들면 배포와 갈린다.

## 놓치기 쉬운 것

- **§6.2 를 따라 GNB 를 만들면 틀린 화면이 나온다.** navBlack 활성 조건(스크롤 트리거 vs 상시) · Wrapper padding · 블러 레이어 구성이 전부 어긋난다. **이 절의 GNB 표를 원본으로 삼을 것.**
- **`PastDueBanner` 가 z 9999 로 GNB(1001)·블러(1000) 위를 덮는다.** '적층 최상단은 GNB' 라고 적으면 틀린다. 배너는 `[data-page-root]` 밖이라 램프도 다르게 해석된다(라이트 테마에서 `--gray-000` = `#000000` → 빨간 면에 검은 글씨).
- **≤719px 에서 GNB 는 다른 화면이 된다.** 반응형 표를 '섹션 패딩 20→16px' 한 줄로 적으면 없는 것을 있다고 잘못 말한다. header wrapper 패딩이 바뀌는 임계는 **≤450px** 로 따로 있다.
- **모바일 오버레이 CTA 와 상단 CTA 는 같은 버튼이 아니다.** 상단은 높이 32px · padding-inline 12px · `::before` 제거 · 블루 그라디언트를 `#171b22` 뉴트럴 면으로 대체한 형태이고, 오버레이 안 CTA 는 `w-full mt-auto` 만 얹어 **§6.10 primary 원형(40px · 블루 그라디언트 · `::before` 오버레이 유지)** 그대로다.
- **'회색 알파는 전부 검정' 규칙이 푸터 안에서만 뒤집힌다.** 셸이 `--gray-000-rgb: 0 0 0` 을 **중요 선언**으로 세워도 footer 요소 자신의 무중요 선언이 이긴다(중요도는 같은 요소 안에서만 겨루고, 상속값은 자식의 자기 선언에 진다). 규칙을 그대로 적용하면 `#171b22` 위에 검은 글씨가 된다.
- **푸터는 뷰포트 미디어쿼리와 컨테이너 쿼리를 섞어 쓴다.** 패딩·min-height 분기는 `@media (max-width:720px)`, 3컬럼→1열과 소셜 `justify-self` 는 `@container (max-width:720px)`. 두 임계는 스크롤바 폭 때문에 정확히 같지 않을 수 있는데 `min-height` 식은 padding 이 이미 16px 로 줄었다고 **가정**한다(`100cqi − 72px`).
- **푸터 태그라인은 고정 36px 이 아니다.** `[data-page-root]` 램프 안이라 36 → 32 → 28 → **20px** 로 내려간다.
- **활성 캐러셀 점은 hover 하면 파랑을 잃는다**(회색 40% + scale 1.35 유지). 원본의 명시도 사고를 Tailwind 출력 순서로 의도적으로 보존한 것이라고 파일 주석이 명시한다.
- **캐러셀·목록 커버 영상은 어느 쪽도 자동 재생되지 않는다.** `autoPlay`·`loop`·`poster` 가 전부 없고, 캐러셀은 활성 카드에만 `controls` 가 붙는다. 캐러셀 이미지는 `draggable={false}`(스와이프 충돌 방지).
- **목록 카드의 hover lift 가 죽어 있다.** `[&:hover]:[transform:translateY(-4px)]` 에 `!` 가 없어 레이어 밖 `[data-page-root] [data-reveal] { transform: none }` 이 **명시도와 무관하게** 이긴다. 형제 파일(`app/blog/page.tsx`, `BlogTeaser.tsx`, `FeatureGrid.tsx`)은 전부 `!` 를 달았다. 배포 화면에서 카드는 hover 시 **테두리·배경색만** 바뀐다. (→ 결정 필요)
- **포커스 링은 이 화면에 딱 한 종류만 살아 있다.** 레이어 밖 `button:focus, button:focus-visible, button:active { outline: none }` 은 **`button` 과 `input[type=button|submit|reset]` 만** 대상이라 복사 버튼·캐러셀 버튼·햄버거·CTA 의 링을 전부 지우지만, `<a>` 는 대상이 아니다 → **푸터 소셜 링크의 `outline: 2px solid #fafafa`(offset 2px)만 실제로 보인다.** 캐러셀 스테이지는 `tabIndex={0}` 인데도 `outline-none` 을 직접 달고 있다.
- **드롭다운 항목의 '공개 예정' 55% 색은 렌더되는 텍스트에 닿지 않는다.** 행에 `color: rgb(0 0 0/0.55)!` 가 있지만 라벨 span(`#000000`)과 칩 span(`#777d89`)이 각자 색을 세운다. 반대로 **모바일 오버레이**의 공개 예정 행은 라벨이 raw 텍스트라 행의 idle 색을 그대로 받는다 — 두 곳의 결과가 다르다.
- **드롭다운 패널은 다크 테마에서 배경만 라이트로 고정되고 프레임은 다크 변형이 남는다.** `[html[data-theme=dark]_&]:[background:rgb(241 241 243)]` 는 배경만 덮고, `--glass-dropdown-frame` 은 다크 값(검정 링 50% + 흰 림 50%)이 그대로 적용된다. **LanguageSelector 메뉴에는 그 고정이 없어** 다크에서 표면이 `#313640` 이 된다.
- **`LanguageSelector` 트리거 색에는 `!` 를 붙이면 안 된다**(컴포넌트 주석이 근거를 적어 둠). 색은 Gnb `NAV_BLACK` 의 중요 선언이 공급한다.
- **로고 폭이 두 값이다.** CSS 는 `calc(24px * 291 / 85)` ≈ **82.164px**, `<Image width>` 는 `logoWordmarkWidthForHeight(24)` = **82**(반올림). 실제 렌더 폭은 CSS 쪽이 이긴다.
- **`nav` 의 `min-h-12`(24px)는 바닥값이지 헤더 높이가 아니다.** 실제 행 높이는 가장 큰 자식이 정한다 — 데스크톱 32px(액션), ≤719px 38px(햄버거).
- **커뮤니티 패널의 중앙 정렬이 `transform` 에 실려 있다.** `motion-reduce:[transform:none]` 이 열림/닫힘 분기보다 뒤에 출력되므로 `prefers-reduced-motion: reduce` 에서는 `translateX(-50%)` 까지 함께 사라진다.

#### 언어 메뉴 옵션 — 선택 상태와 hover/focus 가 겹칠 때

「비선택 / hover / focus-visible / 선택」 네 칸으로는 부족하다. 옵션의 `className` 은 `type-caption-12-regular` + 공통 `OPTION` + (`OPTION_ACTIVE` | `OPTION_INACTIVE`) 세 덩어리를 잇는 것이고(`LanguageSelector.tsx:329-331`), **hover·focus-visible 선언은 선택/비선택과 배타가 아니라 공통 `OPTION` 쪽에 있다**(`:146-161`). 그래서 선택된 옵션에 포인터를 올리면 상태가 겹친다.

| 조합 | `background` (라이트 = 다크) | `color` | 근거 |
| --- | --- | --- | --- |
| 선택, 유휴 | `var(--palette-gray-200)` = **`#e3e4e8`** | `#000000` | `OPTION_ACTIVE` `:168-171` · `globals.css:28` |
| **선택 + hover** | `rgb(0 0 0 / 6%)` — 선택 배경이 **덮인다** | `#000000` (변화 없음) | `:155` + `globals.css:52` |
| **선택 + focus-visible** | `rgb(0 0 0 / 8%)` — 선택 배경이 **덮인다** | `#000000`, `outline: none` | `:158-160` |
| 선택 + hover + focus-visible | `rgb(0 0 0 / 8%)` (hover 쪽이 `:not(:focus-visible)` 로 배제됨) | `#000000` | `:155` vs `:158` |

승자는 출력 순서가 아니라 **특이도**로 정해진다. hover 유틸리티가 만드는 선택자는 `.…:hover:not(:focus-visible)` = (0,3,0), `OPTION_ACTIVE` 의 `[background:var(--palette-gray-200)]` 는 (0,1,0) 이다. 파일 주석 `:33-35` 가 원본 모듈 CSS 에서도 `.option:hover`(0,2,0) 가 `.optionActive`(0,1,0) 를 이겼고 그 결과를 보존하려 상호배타로 갈랐다고 적는다.

전환은 어느 조합이든 `transition: color 120ms ease-in-out, background-color 120ms ease-in-out`(`:152`) 하나로 처리된다.

`--palette-gray-200`(`#e3e4e8`)·`--palette-gray-1000`(`#000000`, rgb `0 0 0`)은 고정 팔레트라 **옵션 배경·글자는 라이트/다크가 같다**(`globals.css:28, 38, 52`). 테마로 바뀌는 것은 그 아래 표면(`--dropdown-surface-bg`)뿐이다.

> **선택 + hover 는 선택 표시를 사실상 지운다.** 라이트 표면 `#f1f1f3` 위에서 `rgb(0 0 0/6%)` 의 합성 계산값은 `rgb(227 227 228)` 로, 선택 배경 `#e3e4e8`(`rgb(227 228 232)`)과 거의 구분되지 않는다(합성은 위 두 읽은 값에서 계산한 것이고, 브라우저로 확인하지는 않았다). 다크 표면 `#313640` 위에서는 반대로 `rgb(0 0 0/6%)` 가 더 어두워져 선택 배경보다 **어둡게** 뒤집힌다.

#### 언어 메뉴는 스크롤에도 위치를 다시 잡는다 (커뮤니티 패널과 다름)

`useLayoutEffect` 는 `open` 이 false 면 즉시 반환하고(`:242`), 열릴 때 `updateMenuPosition()` 을 한 번 직접 호출한 뒤 두 리스너를 붙이며, 닫힘·언마운트에서 **같은 캡처 플래그로** 해제한다(`:246-249`). 트리거 클릭 핸들러도 여는 경로에서만 `updateMenuPosition()` 을 먼저 부른다(`:286-292`) — 첫 프레임 위치 튐 방지.

`scroll` 을 캡처 단계로 등록했다는 것은 **`window` 가 아닌 중첩 스크롤 컨테이너의 스크롤도 잡는다**는 뜻이다(스크롤 이벤트는 버블링하지 않으므로 캡처가 아니면 놓친다).

| 분기 | 조건 | `style` |
| --- | --- | --- |
| `below` | `rect.top < window.innerHeight / 2` | `{ position: "fixed", top: rect.bottom + 8, right, bottom: "auto", left: "auto" }` |
| `above` | 그 외 | `{ position: "fixed", top: "auto", right, bottom: window.innerHeight - rect.top + 10, left: "auto" }` |

`right` 는 두 분기 공통으로 `Math.max(8, window.innerWidth - rect.right)`(`:224`) — 뷰포트 우측 최소 8px 을 보장한다. **아래로 펼칠 때의 간격 8px 과 위로 펼칠 때의 간격 10px 은 서로 다르다**(`:229` vs `:235`). `bottom: "auto"` / `left: "auto"` 는 공통 클래스 `MENU` 의 `fixed top-0 left-0`(`:110`) 을 되돌리기 위한 것이다.

> **이 라우트에서 `above` 분기는 실행되지 않고, `scroll` 재계산도 값을 바꾸지 않는다.** 트리거가 `position: fixed` 헤더 안에 있어 스크롤해도 `getBoundingClientRect()` 가 변하지 않기 때문이다 — `rect.top` 은 항상 뷰포트 상반부이므로 `below` 로 고정된다. 다만 `updateMenuPosition` 은 매 스크롤 이벤트마다 **새 객체 리터럴**을 `setMenuPos` 에 넣으므로(`:227-238`) 값이 같아도 참조가 달라 리렌더가 발생한다. 실제 프레임 비용은 측정하지 않았다.

#### 접근성 — 캐러셀 카드 `aria-hidden` 과 드롭다운 항목 `role`

**캐러셀: 보조기술에 노출되는 카드는 항상 1장뿐이다.** 카드 루트 `<div>` 에 `aria-hidden={!isActive}` 가 붙는다(`TemplateResultCarousel.tsx:173`). React 가 boolean 을 문자열로 출력하므로 활성 카드에는 속성이 생략되는 게 아니라 **`aria-hidden="false"`** 가, 나머지 전부에는 `aria-hidden="true"` 가 실제로 찍힌다.

| 카드 | `aria-hidden` | `opacity` / `pointer-events` (인라인) |
| --- | --- | --- |
| 활성 (`offset === 0`) | `"false"` | `1` / `auto` |
| 비활성 · 창 안 (`abs ≤ 3`) | `"true"` | `1` / `auto` |
| 창 밖 (`abs > 3`, `TemplateResultCarousel.tsx:161`) | `"true"` | `0` / `none` |

창 밖 카드에도 **별도의 숨김 수단이 없다** — `hidden` 도 `inert` 도 `tabIndex={-1}` 도 선언되지 않고, 카드 루트가 갖는 속성은 `key` · `className` · `style` · `aria-hidden` · `onClick` 다섯뿐이다(`TemplateResultCarousel.tsx:169-178`). 즉 **창 안 비활성 카드와 창 밖 카드는 접근성 트리에서 구분되지 않는다.**

그 결과 "비활성 카드 클릭으로 이동" 경로는 **`aria-hidden="true"` 인 `<div>` 위에만 존재한다.** 카드에는 `tabIndex` 도 `role` 도 없어 포커스가 가지 않으므로, 키보드·스크린리더 쪽 이동 수단은 스테이지의 `←`/`→` 와 점 버튼(`role="tab"`)뿐이다.

**드롭다운: `role="menu"` 안에 `role` 없는 행 2개가 섞인다.** `role="menu"` 는 포털된 패널 최상위 `<div>`(= `PRODUCTS_PANEL`, 12px 호버 브리지를 포함하는 요소)에 있다(`Gnb.tsx:790`). 그 아래 5행의 태그와 role 은 다음과 같다.

| # | 라벨 키 | 태그 | `role` | 근거 |
| --- | --- | --- | --- | --- |
| ① | `nav.templates` | `<Link href="/templates">` | `menuitem` | `Gnb.tsx:844-847` |
| ② | `nav.blog` | `<span>` | **없음** | `Gnb.tsx:806-820` |
| ③ | `nav.ambassador` | `<span>` | **없음** | 〃 |
| ④ | `nav.officialYoutube` | `<a target="_blank">` | `menuitem` | `Gnb.tsx:825-830` |
| ⑤ | `nav.officialInstagram` | `<a target="_blank">` | `menuitem` | 〃 |

`Gnb.tsx` 전체에서 `role` 속성은 **이 세 자리(`:790` · `:830` · `:847`)뿐**이다. 따라서 ≤719px 모바일 오버레이의 같은 5개 항목에는 `menu`/`menuitem` 계열 속성이 **하나도 없다** — 오버레이는 평범한 링크 목록이다.

또한 파일 안에 `aria-controls` 도 `id` 도 없다. 트리거의 `aria-haspopup="true"` + `aria-expanded` 와 패널의 `role="menu"` 사이에 참조 연결이 없고, 패널은 `document.body` 포털이라 DOM 상 트리거의 자손도 아니다.

#### 일본어 로케일에서 폰트 스택이 바뀐다 — 그리고 그 교체는 `<body>` 규칙이 한다

「반응형 타입 램프」가 적은 `font-family: var(--type-font-family)`(Pretendard)는 **ko/en 기준값**이다. `html[lang="ja"]` 에서는 앞에 PretendardJP 가 붙는다.

| 선언 | 값 | 위치 |
| --- | --- | --- |
| 기본 | `--type-font-family: var(--font-pretendard)` | `globals.css:341` |
| 기본 | `--type-feature-settings: "ss07" 1` (ja 에서도 **불변**) | `globals.css:342` |
| ja 토큰 | `html[lang="ja"] { --type-font-family: var(--font-pretendard-jp), var(--font-pretendard) }` | `globals.css:399-401` |
| ja 본문 | `html[lang="ja"] body { font-family: var(--font-pretendard-jp), var(--font-pretendard) }` | `globals.css:403-405` |

`<html lang>` 은 `getServerLocale()` 결과가 그대로 들어간다(`layout.tsx:78`) — 「로케일 결정」 절의 쿠키 → `Accept-Language` → 기본값 순서를 그대로 따른다. 두 ja 규칙은 **레이어 밖**이다(파일 안 유일한 `@layer` 는 `globals.css:993` 의 `@layer base`).

**폰트 등록** (`next/font/local`):

| | KR | JP |
| --- | --- | --- |
| 선언 | `layout.tsx:41-48` | `layout.tsx:52-59` |
| 파일 | `./fonts/PretendardVariable.woff2` | `./fonts/PretendardJPVariable.woff2` |
| CSS 변수 | `--font-pretendard` | `--font-pretendard-jp` |
| `display` | `block` | `block` |
| `preload` | `true` | **`false`** (주석 `layout.tsx:50-51` — 5.3MB, ja 사용자에게만 지연 로드) |
| `weight` / `adjustFontFallback` | `45 920` / `false` | `45 920` / `false` |

빌드 산출물의 `@font-face` 는 세 개뿐이고 실제 패밀리명은 해시 없는 `pretendard` · `pretendardJP` 다. `adjustFontFallback: false` 이므로 **next/font 가 만드는 size-adjust 폴백 페이스가 없고**, 최종 `font-family` 값에 폴백 패밀리도 붙지 않는다(`font-family: pretendard`). JP 는 `font-display: block` 이라 로드 완료 전에는 폴백으로 즉시 스왑하지 않는다.

**변수가 붙는 요소가 `<body>` 라는 점이 중요하다.** `<body className={`${pretendard.variable} ${pretendardJP.variable} ${pretendard.className}`}>`(`layout.tsx:92`) — 즉 `--font-pretendard` / `--font-pretendard-jp` 는 **`<body>` 에서만 정의된다**(빌드 CSS 에서도 이 두 변수의 선언은 `.variable` 클래스 하나씩뿐). 반면 `--type-font-family` 는 `<html>` 에서 선언된다(`globals.css:341` `:root`, `:400` `html[lang="ja"]`). 그러므로 **html 레벨 토큰 교체(`:399-401`)만으로는 글꼴이 바뀌지 않고, 실제로 바꾸는 것은 body 규칙(`:403-405`)이다.** 코드가 두 규칙을 나란히 둔 이유가 이것이다. `pretendardJP.className` 은 어디에도 적용되지 않는다.

가시적 결과는 두 경로가 같다 — 페이지의 모든 텍스트가 ko/en 은 `pretendard`, ja 는 `pretendardJP, pretendard` 를 쓴다. `type-*` 클래스의 `font-family: var(--type-font-family)`(`globals.css:1048-1071`)를 거치든 `body`(`globals.css:970-984` + `.__className_*`)에서 상속되든 최종 패밀리는 동일하다. (선언 위치는 소스와 빌드 CSS 양쪽에서 확인했다. 브라우저 계산값 측정은 하지 않았다.)

별개로 `globals.css:6-12` 가 같은 KR woff2 를 **리터럴 `"Pretendard"`** 이름으로 한 번 더 등록한다. 주석(`:1-5`)에 따르면 `ctx.font` 같은 캔버스 코드가 해시된 이름을 못 찾는 문제 때문이고, `--type-font-family` 체인과는 별개의 등록이다 — ja 분기도 이 리터럴 이름에는 적용되지 않는다.
