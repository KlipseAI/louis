### 10.4 블로그·문서 (`/blog` · `/blog/[slug]` · `/docs` · `/docs/nodecanvas` · `/docs/videoeditor` · `/docs/highlight`)

#### ⚠ 다크 변형 — "이 그룹엔 없다"는 **틀렸다**. 본문엔 없고 GNB 오버레이 3곳엔 있다

**본문(페이지 면)은 테마 무관 단일값이다.** 두 셸 모두 루트에 `data-page-root` 를 달고, `globals.css:1649`(레이어 **밖**)의 `[data-page-root]` 블록이 시맨틱 `--gray-000 … --gray-1000` 을 **고정 램프** `--palette-gray-*` 로 통째로 재매핑한다. `--palette-gray-*` 는 `:root` 에만 정의되고 `html[data-theme="dark"]` 어디에서도 재정의되지 않는다. 이 그룹의 본문 소스 파일에 `dark:` 변형은 0건이다.

#### 셸 A — `BlogShell` (`/blog` · `/blog/[slug]`)

```

├─ <SectionInteractions/>       ← DOM 을 만들지 않는다 (IntersectionObserver 만)
```

#### 공통 — 타입 스케일이 이 6개 라우트에서 반응형으로 바뀐다

`type-*` 유틸리티는 `font-size`/`line-height`/`letter-spacing`/`font-weight` 를 토큰으로 참조하고, `font-family: var(--type-font-family)` 와 `font-feature-settings: var(--type-feature-settings)`(= `"ss07" 1`)을 함께 싣는다(**5.3절**). 그 토큰을 `[data-page-root]` 스코프의 레이어 밖 미디어 블록(`globals.css:874-910`)이 다시 세우므로 **이 그룹 전체가 영향을 받는다.**

| 토큰 | 기본 | ≤1023px | ≤767px | ≤479px |
| --- | --- | --- | --- | --- |
| `heading-48` | 48px / 1.35 / −0.02em | 36px | 32px | 28px |
| `heading-36` | 36px / 1.35 / −0.02em | 32px | 28px | **20px** (ls −0.01em) |
| `heading-28` | 28px / 1.35 / −0.02em | `= body-20` → **18px** | 18px (ls −0.01em) | — |
| `body-20` | 20px / 1.5 / −0.01em | 18px | 16px | — |
| `body-16` | 16px / 1.5 / −0.01em | — | — | ≤450px `= body-14`(14px, `:root` 전역, `globals.css:860-864`) |
| `body-14` | 14px / 1.5 / −0.01em | — | — | — |
| `caption-12` | 12px / 1.5 / −0.01em | — | — | — |

weight: regular 400 · medium 500 · semibold 600. 기본 `--type-font-family: var(--font-pretendard)`.

⇒ **`/docs` 와 제품 문서의 h1(`heading-36`)은 479px 이하에서 20px 이 되고, 본문 h2(`heading-28`)는 767px 이하에서 18px 이 되어 본문(16px)과 거의 붙는다.**

#### 공통 — 줄바꿈은 개별 컴포넌트가 아니라 전역에서 온다

`globals.css:1694-1723` 의 레이어 밖 규칙:

```
[data-page-root] :where(h1,h2,h3,h4,h5,h6,p,li,dt,dd,figcaption,blockquote,
                        a,button,label,legend,span,strong,em,small,td,th) {
  text-wrap: balance;
  word-break: keep-all;
  overflow-wrap: break-word;
  line-break: strict;
}
```

목록에 `div` 는 없다. 이 그룹에 흩어진 `text-balance!` · `whitespace-pre-wrap!` · `[word-break:break-word]!` 는 전부 이 규칙과의 승부를 되돌리려는 것이다.

#### 공통 — 리빌 애니메이션은 실제로 일어나지 않는다

`SectionInteractions` 가 `[data-reveal]` 을 IntersectionObserver(threshold 0.2, rootMargin `0% 0% -8% 0%`)로 관찰해 `is-visible` 클래스를 붙이고 unobserve 한다. 그런데 **`.is-visible` 을 스타일하는 CSS 도, `--reveal-delay` 를 소비하는 CSS 도 이 그룹 스코프에 없다**(전 저장소에서 `app/(highlight-standalone)/hl-landing/page.module.css:166,170` 한 곳뿐 — 범위 밖). 게다가 레이어 밖 `[data-page-root] [data-reveal] { opacity:1; transform:none; filter:none }`(`globals.css:1729-1733`)이 초기 상태를 이미 최종 상태로 고정한다.

⇒ **`/blog` 진입 시 페이드/슬라이드 인은 없다.** `data-reveal` 이 하는 실질적인 일은 blog 카드 hover `transform` 을 이겨서 `!` 를 강제하는 것뿐이다. `SectionInteractions` 는 그 외에 `--footer-reveal-height` 를 푸터 높이로 갱신하지만 **그 변수를 읽는 CSS 규칙이 저장소에 없다.**

### 스크롤 · 쌓임 순서

페이지 스크롤은 문서 본문 하나다. 그 위에 **fixed 2개**와 **sticky 2개**가 얹힌다.

| 쌓임 (낮은 쪽부터) | 요소 |
| --- | --- |
| −1 | GNB 모바일 메뉴 (`MOBILE_MENU`, ≤719px 에서만 존재) |
| auto | docs 콘텐츠 (`SHELL_CLASS`·`CONTENT_CLASS` 에 z-index 없음) |
| 2 | blog 콘텐츠 레이어 `SURFACE_LAYER` (`relative z-2`) |
| 3 | docs 좌측 사이드바 (`z-3`) |
| 4 | 푸터 (`relative isolate z-4` — 자체 스태킹 컨텍스트, 내부 자식은 `z-1`) |
| 1000 | GNB 상단 블러 스크림 (`HEADER_BLUR`) |
| 1001 | GNB 래퍼 (`WRAPPER`, 내부 `NAV` 는 `relative z-2`) |
| 2000 | 리소스 드롭다운 패널 · 언어 선택기 메뉴 (둘 다 `document.body` 로 portal, 인라인 `zIndex: 2000`) |

- **독립 스크롤 영역은 sticky 두 곳뿐이다** — docs 좌측 사이드바와 제품 문서 우측 aside, 둘 다 `max-height: calc(100svh − 140px)` + `overflow: auto`. (언어 메뉴는 스크롤 영역이 아니다.)
- **blog 2개 라우트에는 sticky 가 하나도 없다.**
- 제품 문서 우측 aside 에는 z-index 선언이 없다.
- docs 셸에는 blog 의 `z-2` 표면 레이어에 해당하는 래퍼가 **없다**.

### 이 그룹을 만들 때 놓치기 쉬운 것

- **`--spacing: 2px` 이므로 유틸 숫자 × 2 다.** 자주 틀리는 값: `pt-60`=120px · `pb-48`=96px · `gap-24`=48px · `gap-18`=36px · `gap-8`=16px · `w-120`=240px · `w-124`=248px · `pt-56`=112px · `pt-41`=82px · `scroll-mt-60`=120px · `scroll-mt-56`=112px · `min-h-48`=96px · `min-h-20`=40px · `min-h-19`=38px · `min-h-14`=28px · `min-h-12`=24px · `w-14 h-14`=28×28px · `w-16 h-16`=32×32px · `w-19 h-19`=38×38px · `w-10 h-7`=20×14px · `py-9`=18px · `mb-24`=48px. 곡률(`rounded-2/6/8/10/12/14/16`)과 `rounded-full`(999px)은 **px 스케일**이라 이 배수가 적용되지 않는다.
- **`--dropdown-surface-bg` 의 `:root` 기본값이 다크(#313640)이고 라이트가 `html[data-theme="light"]:not(:has([data-landing-walkthrough-dark]))` 스코프에서 덮는다.** '기본 = 라이트' 로 가정하면 반대가 된다.
- **리소스 드롭다운 패널은 배경만 라이트로 못 박혀 있다.** `html[data-theme="dark"] &` 가 `background: rgb(241 241 243)` 을 세우지만 `box-shadow` 의 `--glass-dropdown-frame` 은 그대로 테마를 따라간다. '배경 고정 = 완전 고정' 으로 읽으면 틀린다.
- **`/klipse-light.svg` 는 검정 잉크 워드마크이고 `/klipse-dark.svg` 가 흰 잉크다**(파일 tail `fill="black"` / `fill="white"` 로 확인). 이름은 '어느 테마용인가'를 뜻하지 '잉크 색'이 아니다. 이 6개 라우트는 항상 `/klipse-light.svg`(검정)를 쓴다.
- **GNB 드롭다운 라벨은 '리소스'다.** 코드 상수명·주석(`communityItems`, `PRODUCTS_*`, "커뮤니티", "제품")을 그대로 옮기면 배포와 다른 라벨이 된다.
- **`nav.getStarted` 는 ja 오버라이드가 없다.** `ja-overrides-landing.ts` 의 nav 블록에 키 자체가 부재하고 deepMerge 베이스가 en 이라 일본어 화면의 GNB CTA 는 **"Get started"** 로 나간다. ja 에 있는 `tryKlipse`("Klipseを試す")와 혼동하지 말 것.
- **docs 셸에는 `max-width` 가 없다.** `SHELL_CLASS` 에 `mx-auto` 는 있지만 폭 캡이 없어 무효이고, 셸은 뷰포트 폭에서 좌우 20px 만 뺀 만큼 늘어난다. blog 는 반대로 1120px/760px 캡이 있다.
- **GNB 는 `fixed` 라 어떤 셸에서도 공간을 차지하지 않는다.** 그래서 docs 는 셸에 `padding-top: 120px`, blog 는 섹션에 `padding-top: 112px` 로 각각 직접 상단 여백을 만든다. sticky 요소의 `top: 120px` 과 `max-height: calc(100svh − 140px)` 도 그 120px 고정 헤더를 전제로 한 숫자다(140 = 120 + 20 여유).
- **`--palette-gray-950` 는 저장소 어디에도 정의돼 있지 않다**(전체 grep 결과 `DocArticle.tsx` 3줄 = 주석 2 + 선언 1). `DocArticle` 의 요약 값이 `color: var(--palette-gray-950)` 를 쓰므로 선언이 계산 시점에 무효가 되고 상속색 **#171b22** 로 렌더된다. 코드 주석이 "토큰 이름을 고치면 렌더가 바뀐다"고 명시한 **의도된 유지**다 — 오탈자로 보고 "고치면" 배포 화면과 달라진다.
- **레이어 밖 규칙이 레이어 안 유틸리티를 특이도와 무관하게 이긴다 — 이 그룹의 `!` 는 전부 그 승부를 되돌리는 것이다.** 상대는 넷이다: (a) `a { color: inherit; text-decoration: none }`(`globals.css:1029`, `@layer base` **밖**) → 모든 링크의 `color`·`no-underline`; (b) `[data-page-root] :where(h1..h6, p, li, a, button, span, td, th, …)` 의 `text-wrap: balance` · `word-break: keep-all` → `text-balance!` · `whitespace-pre-wrap!` · `[word-break:break-word]!` · 푸터의 `whitespace-nowrap!`; (c) `[data-page-root] [data-reveal] { transform: none }`(0,2,0) → blog 카드 hover 의 `translateY(-4px)!`; (d) `[data-page-root] { background; color }` → 두 셸의 배경·글자색. **`!` 를 떨어뜨리면 렌더가 바뀐다.**
- **공용 `Button` 의 `whitespace-nowrap` 은 `[data-page-root]` 안에서 적용되지 않는다.** `text-wrap` 은 `text-wrap-mode` 롱핸드를 `white-space` 와 공유하므로 위 (b) 가 이긴다. 이건 의도된 상태이고, 여기에 `!` 를 붙였다가 랜딩/GNB 높이가 61px 어긋난 사고 기록이 `Button.tsx:14-20` 과 `app/docs/layout.tsx:12-21` 에 남아 있다. **GNB CTA 와 댓글 등록 버튼의 텍스트는 nowrap 이 아니다.**
- **이 그룹의 hover 는 거의 전부 `[&:hover]:` 다.** Tailwind 의 `hover:` 는 `@media (hover: hover)` 로 감싸지지만 원본 모듈 CSS 의 `:hover` 는 아니었다 — **터치 기기에서도 hover 규칙이 매칭된다.** 예외는 댓글 입력의 `focus:` 하나뿐(표준 변형, 가드 없음).
- **Tailwind v4 의 `col-1`/`col-2` 는 `grid-column: 1`/`2` 이지 `col-span-*` 이 아니다.** docs 사이드바(`col-1`)·콘텐츠(`col-2`)가 이걸로 명시 배치되고 ≤900px 에서 `col-auto` 로 풀린다.
- **docs 의 두 2열 그리드가 서로 다른 트랙 함수를 쓴다.** `DocsOverview` 는 `repeat(2, 1fr)`(임의값), `DocArticle` 요약은 `grid-cols-2` = `repeat(2, minmax(0,1fr))`. 두 파일 모두 "원본 그대로"라고 주석하고 있다 — 긴 비분절 문자열에서 넘침 거동이 갈린다. **같은 것으로 적으면 안 된다.**
- **blog 카드 배경은 '흰 카드'가 아니라 검정 4% 오버레이다.** `--gray-000-rgb` 가 `BlogShell` 에서 `0 0 0` 으로 뒤집혔으므로 카드가 페이지 바닥(#f1f1f3)보다 **어둡다**.
- **알파는 `/N` 단축이 아니라 `rgb(var(--…-rgb) / N%)` 임의값으로 쓴다.** 단축은 `color-mix()` 로 컴파일돼 값이 달라진다. 커버 플레이스홀더도 `bg-[linear-gradient(...)]` 가 아니라 `[background:linear-gradient(...)]` 단축 그대로여야 한다.
- **docs 사이드바 배경(#f1f1f3)은 페이지 바닥과 같은 색이다.** 시각적 패널이 아니라 sticky 스크롤 시 본문이 비치는 것을 막는 불투명 마스크다. 문서에 '패널'로 적으면 다른 톤을 칠하게 된다. **docs 에는 카드 배경이 하나도 없다** — 모든 카드는 위/아래 1px `#e3e4e8` 선으로만 구분되고, 유일하게 채워진 면은 aside CTA 버튼(#000000)이다.
- **앵커 오프셋이 8px 어긋나 있다.** docs 본문 섹션은 `scroll-margin-top: 112px` 인데 sticky 요소와 GNB 블러 스크림은 120px 다 — 목차 클릭 시 제목이 스크림 경계 안쪽 8px 에 걸린다. blog 섹션은 120px 로 맞다.
- **`border: 0` 은 `border-0` 이 아니라 `[border:0]` 이다.** `border-0` 은 폭만 0 으로 두고 `--tw-border-style` 을 solid 로 남긴다. 같은 이유로 `outline: none` 도 `outline-none`(= `outline-style` 만)이 아니라 `[outline:none]` 이다.
- **불릿 점의 반경은 `rounded-full`(999px)이 아니라 `border-radius: 50%` 이고 크기는 5×5px** — 2px 격자에서 떨어지지 않는 임의값이다. `top` 은 `0.62em`.
- **날짜 포맷이 세 군데에서 다르다.** 인덱스 카드 `YYYY.MM.DD`(zero-pad) · 상세 헤더 `YYYY년 M월 D일`(zero-pad 없음) · 댓글 `YYYY.MM.DD`(ISO 앞 10자 slice). 앞 둘은 `new Date()` 기반이라 클라이언트 타임존 영향을 받고, 댓글만 타임존 무관이다. **날짜 알파도 두 값이다** — 카드·글 메타 **42%**, 댓글 **40%**.
- **포커스 링:** `globals.css:1017-1026` 의 레이어 밖 규칙이 `button` 과 `input[type=button|submit|reset]` 의 `:focus`·`:focus-visible`·`:active` `outline` 을 지운다. 이 그룹의 링크·`<summary>` 는 그 목록에 없으므로 **브라우저 기본 포커스 링이 그대로 뜬다.** 반대로 댓글 입력 2종은 자체 `outline: none` 이라 테두리 색만이 포커스 표식이다. 푸터 소셜 링크만 자체 `:focus-visible outline: 2px solid #fafafa` 을 갖는다.
- **푸터 메타 행은 `justify-content: space-between` 인데 자식이 하나뿐이다.** 두 덩어리로 그리면 배포와 달라진다.
- **푸터 사업자정보의 라벨/값 분리는 런타임에 첫 `:` 기준으로 일어난다.** 카피 원문에 콜론이 들어 있다 — 문서에 라벨과 값을 따로 적으면 원천을 잘못 기술하는 것이다.

#### GNB 모바일 메뉴의 DOM 위치와 실제 페인트 층

`≤719px 풀스크린 모바일 메뉴` 절(패널·라벨·항목 값)은 이미 있으므로 여기서는 **DOM 위치와 쌓임만** 확정한다.

`Gnb` 가 그리는 최상위는 형제 둘이다 — `<div className={HEADER_BLUR} aria-hidden="true" />`(`Gnb.tsx:700`) 와 `<header className={WRAPPER}>`(`Gnb.tsx:701`). 모바일 메뉴는 그 header 안에 **2단 더 들어가 있다.**

```
<div HEADER_BLUR>            Gnb.tsx:700   fixed · z-index 1000        (Gnb.tsx:64)
<header WRAPPER>             Gnb.tsx:701   fixed · z-index 1001        (Gnb.tsx:71)
  <nav aria-label="Global navigation">   Gnb.tsx:702   relative · z-index 2   (Gnb.tsx:79)
    <Link LOGO_LINK> … 가운데 메뉴 … 우측 CTA · 햄버거
    <div aria-hidden={!mobileOpen}>      Gnb.tsx:906   fixed inset-0 · z-index -1  (Gnb.tsx:288)
      <div MOBILE_MENU_INNER>            Gnb.tsx:914
  </nav>                     Gnb.tsx:1006
</header>                    Gnb.tsx:1007
```

`<header>` 는 `fixed` + `z-index: 1001`(`Gnb.tsx:71`), `<nav>` 는 `relative` + `z-index: 2`(`Gnb.tsx:79`) — **둘 다 스태킹 컨텍스트를 만든다.** 그래서 메뉴의 `z-index: -1`(`Gnb.tsx:288`)은 **`<nav>` 내부의 순서일 뿐**이고, 페이지 전체에 대한 층이 아니다. CSS 페인팅 순서상 음수 z 자식은 nav 자신의 배경 다음·nav 의 인플로우 자손보다 먼저 칠해지므로, 결과는 **로고·햄버거·CTA 는 메뉴 위, 메뉴는 그 아래, 그리고 header 통째로 1001 층**이다. header·nav 배경은 둘 다 투명(`[background:transparent]` `Gnb.tsx:72`)이라 메뉴를 가리지 않는다.

바깥 층이 1001 인 근거: 두 셸의 루트 `<main data-page-root>` 가 스태킹 컨텍스트를 만들지 않는다. docs 는 `DOCS_ROOT_CLASS = relative`(z-index 없음, `app/docs/layout.tsx:30-36`)이고 `<Gnb lightSurface />` 는 그 main 의 직계 자식(`app/docs/layout.tsx:63-64`), blog 는 `LIGHT_SURFACE_CLASS` 에 `position`·`z-index`·`isolation` 이 없고(`components/blog/BlogShell.tsx:26-34`) `<Gnb lightSurface />` 가 직계 자식이다(`BlogShell.tsx:45,47`). header·nav 어디에도 `transform`·`filter`·`backdrop-filter` 가 없으므로 메뉴의 `fixed inset-0` 도 뷰포트 기준으로 남는다(`backdrop-filter` 는 형제인 `HEADER_BLUR` 에만 있다 — `Gnb.tsx:64-65`).

**「스크롤 · 쌓임 순서」표의 `−1 | GNB 모바일 메뉴` 행은 삭제한다.** 그 자리는 `1001 | GNB <header>` 행의 내부 순서로 대체된다:

| 층 | 요소 |
| --- | --- |
| 1001 · header 내부 상위 | `<nav>` 의 인플로우 자손 — 로고 · 가운데 메뉴 · 우측 CTA · 햄거거 버튼 |
| 1001 · header 내부 하위 | 모바일 메뉴 `<div>`(nav 스코프 `z-index: -1`) |

즉 모바일 메뉴는 푸터(`z-4`) · docs 사이드바(`z-3`) · blog 서피스 레이어(`z-2`) · `HEADER_BLUR` 스크림(`z-1000`)보다 **위**에 뜬다. 초안 표대로 사다리 맨 아래에 두면 열려도 페이지 뒤에 깔린다.

#### 워크플로우 · FAQ 섹션의 `<section>` 래퍼

둘 다 ④ 본문 섹션과 **완전히 같은** `SECTION_CLASS` 를 쓴다. 값이 다른 것은 `<h2>` 하나뿐이다.

| 래퍼 | 여는 태그 | `id` | `className` | `<h2>` |
| --- | --- | --- | --- | --- |
| ⑤ 워크플로우 | `DocArticle.tsx:394` | `` `${docKey}-workflow` ``(`:331`) | `SECTION_CLASS` | `SECTION_HEADING_CLASS`(`:395`) |
| ⑦ FAQ | `DocArticle.tsx:415` | `` `${docKey}-faq` ``(`:332-335`) | `SECTION_CLASS` | `FAQ_HEADING_CLASS`(`:416`) |

`SECTION_CLASS`(`DocArticle.tsx:102-107`) 해결값 — `margin-bottom: 40px`(`mb-20`) · `scroll-margin-top: 112px`(`scroll-mt-56`) · `padding-top: 28px`(`pt-14`) · `border-top: 1px solid #e3e4e8`(`border-t border-t-palette-gray-200`, `globals.css:28`). 나머지 세 변에는 테두리가 없다.

두 `<h2>` 는 margin·color 가 같고 타입 스케일만 갈린다 — 공통 `margin: 0 0 14px`(`mt-0 mx-0 mb-7`) · `color: #000000`(`text-palette-gray-1000`, `globals.css:38`). 워크플로우는 `type-heading-28-medium`(`DocArticle.tsx:109-113`), **FAQ 만** `type-body-20-medium`(`:116-120`)이다. 파일 주석이 `:115` 에서 "FAQ 제목만 `type-body-20-medium` 을 쓴다(원본 그대로)"로 못 박고 있으니 heading-28 로 맞추면 안 된다.

`--palette-gray-*` 는 `:root` 한 곳에서만 선언되고 `html[data-theme="dark"]`(`globals.css:664`)에서 재정의되지 않는다 — **라이트·다크 모두 `#e3e4e8` / `#000000`** 로 같다.

두 섹션 사이의 tip 콜아웃은 `<div className={CALLOUT_CLASS}>`(`DocArticle.tsx:409`)로, `<section>` 도 아니고 `SECTION_CLASS` 도 쓰지 않는다 — 상단 1px 선과 28px 패딩이 붙지 않는다. FAQ 섹션은 `doc.faq.length > 0` 일 때만 렌더되고 0건이면 래퍼째 사라진다(`DocArticle.tsx:414`, `:426` 뒤 `: null`); 같은 조건이 `faqLink` 를 `null` 로 만들어 「이 페이지에서」 목록에서도 빠진다(`:332-338`). 현재 3종 모두 FAQ 가 있으므로(7 / 7 / 4) 실제로는 항상 렌더된다.
