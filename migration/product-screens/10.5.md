#### 1행 — 뒤로가기 버튼

`<button type="button" aria-label={messages.footer.legalBack}>` 안에 20×20 인라인 SVG + `<span>{label}</span>`. 라벨이 aria-label 과 본문에 **둘 다** 들어간다.

| 항목 | 값 |
| --- | --- |
| 타이포 | `type-body-14-medium` → 14px / 1.5 / -0.01em / 500 + `font-family: var(--type-font-family)` + `font-feature-settings: var(--type-feature-settings)` |
| 박스 | `inline-flex items-center` · `gap: 6px`(`gap-3`) · `align-self: start` · `margin: 0` · `padding: 8px 10px 8px 6px`(`py-4 pr-5 pl-3`) |
| 면·곡률 | `border: none` · `border-radius: 10px`(`rounded-10`) · `background: transparent` · `cursor: pointer` |
| 색 | `rgb(var(--gray-000-rgb)/72%)` → 라이트 `rgb(0 0 0/72%)` · 다크 `rgb(250 250 250/72%)` |
| 전환 | `background-color 140ms ease, color 140ms ease` |
| 아이콘 | 인라인 SVG `width="20" height="20" viewBox="0 0 24 24" fill="none"` · 클래스 `shrink-0 block` · 단일 `<path d="M15 18l-6-6 6-6" stroke="currentColor" strokeWidth="1.5" strokeLinecap="round" strokeLinejoin="round" />` — 외부 아이콘 라이브러리가 아니다 |

**높이 선언이 없다.** 라벨 행이 14×1.5 = 21px 이고 아이콘이 20px 이므로 콘텐츠 21px + 상하 8px = **37px** 이 된다.

| 상태 | 선언 |
| --- | --- |
| hover | `background: rgb(var(--gray-000-rgb)/8%)` + `color: rgb(var(--gray-000-rgb)/92%)` |
| active | `background: rgb(var(--gray-000-rgb)/12%)` **`!`** — hover 와 동시에 걸릴 때 active 가 이기도록 고정(임의 변형끼리는 Tailwind 출력 순서가 관계를 보장하지 않는다) |
| focus-visible | `outline: 1px solid rgb(var(--gray-000-rgb)/28%)` **`!`** + `outline-offset: 2px` |
| 클릭 | `typeof window !== "undefined" && window.history.length > 1` → `router.back()`, 아니면 `router.push("/")` |

> hover/active 는 `hover:` 가 아니라 **`[&:hover]:` / `[&:active]:` 임의 변형**이다 —
> `@media (hover: hover)` 가드가 없어 터치 기기에서도 걸린다(원본 모듈 CSS 동작 보존).
> focus 아웃라인의 `!` 는 레이어 밖 전역
> `button:focus, button:focus-visible, button:active { outline: none }` 을 이기기 위한 것이다.

스타일 `TITLE = "type-body-20-semibold m-0 text-[rgb(var(--gray-000-rgb)/96%)]"` → **20px / 1.5(=30px) / -0.01em / 600** + `--type-font-family` + `--type-feature-settings`, 색 라이트 `rgb(0 0 0/96%)` · 다크 `rgb(250 250 250/96%)`.

> **문서 제목은 heading 스케일이 아니라 body-20 이다.** 법적 문서라고 `heading-36`/`heading-48` 을 쓰면 배포와 다르다.
>
> **`[data-page-root]` 의 body-20 반응형 축소(≤1023px 18px · ≤767px 16px)는 이 화면에 걸리지 않는다** —
> `LegalDocumentPage` 루트에 `data-page-root` 가 없다. 따라서 **모든 폭에서 20px 고정**이다.
>
> **한 화면에 h1 이 두 개 렌더된다.** 이 i18n 제목(20px/600/96%)과, 바로 아래 md 본문 첫 줄의
> `# Klipse 서비스 이용약관` / `# Klipse 개인정보처리방침`(`[&_h1]` 규칙 → **16px**/600/96%)이다.
> "md 첫 h1 을 제목으로 쓴다"고 오해하면 제목이 하나만 남거나 문자열이 달라진다.

#### 4행 — 마크다운 본문

3. `position: relative` · `background: var(--page-bg)` · `color: var(--gray-000)` (뒤 둘은 위 `!` 에 진다).
4. 자손 `:where(h1..h6, p, li, dt, dd, figcaption, blockquote, a, button, label, legend, span, strong, em, small, td, th)` 에 `text-wrap: balance; word-break: keep-all; overflow-wrap: break-word; line-break: strict` — 폼의 h1·p·button·span 이 전부 대상이다.

#### ⚠ 랜딩 GNB · Footer 위임 경고 — **§10.2 는 레벨 3 이 아니다**

#### 토스트

문서 흐름 안의 알약 배너다(고정 오버레이가 아니다). 위치는 HEADER 와 `<form>` 사이.

> gap 만 보고 「아이콘 + 텍스트」 2슬롯을 그리면 배포와 달라진다.
> 퇴장은 **오직 타이머로만** 일어나고 사용자가 닫을 수단이 없다.

#### 업로드 제약과 오류 분기

`MAX_FILE_SIZE = 4.5 * 1024 * 1024`(4,718,592 bytes) · `MAX_FILES = 5` · `ALLOWED_TYPES = ["image/png","image/jpeg","image/webp"]` · `CATEGORIES = ["bug","account","payment","other"]`.

| 조건 | 결과 |
| --- | --- |
| `remaining <= 0` | 즉시 `t.maxImagesError` 토스트 후 return |
| `fileList.length > remaining` | `slice(0, remaining)` 으로 잘라 넣고 **추가로** `maxImagesError` 토스트 |
| `file.size > 4,718,592` | `t.fileSizeError` 토스트 후 그 파일만 `continue` |
| `!ALLOWED_TYPES.includes(file.type)` | `t.fileTypeError` 토스트 후 `continue` |

#### 제출 파이프라인

1. 이미지가 있으면 `crypto.randomUUID()` 로 `inquiryId` 를 만들고 Supabase Storage 버킷 `inquiry_images` 에 `{inquiryId}/{i}.{ext}` 로 `upsert: false` **순차** 업로드 → `getPublicUrl` 수집. 업로드 에러는 throw → catch 에서 `t.errorGeneric` 토스트.
2. `POST /api/inquiry` 에 `{ title, description, category, email: user?.email ?? email, _hp: "", imageUrls }`.
3. `json.ok` 면 `gaEvent("inquiry_submitted", { category, has_attachments, attachment_count, authenticated })` 후 `setSubmitted(true)`.
4. 아니면 `showToast(json.error || t.errorGeneric, "error")`. `finally` 에서 항상 `setSubmitting(false)`.

**진행률 표시는 없다** — 이미지 N장이면 N번 순차 업로드 동안 버튼만 disabled 상태로 머문다.

**서버(`app/api/inquiry/route.ts`)** — 응답은 `{ ok: true, data: { id } }` 또는 `{ ok: false, error }`. `MAX_IMAGE_URLS = 5`(초과분 `slice(0,5)` 로 조용히 잘림) · `EMAIL_REGEX = /^[^\s@]+@[^\s@]+\.[^\s@]+$/` · `body._hp` 가 truthy 면 DB 저장 없이 `{ ok: true, data: { id: "ok" } }`. 오류 문구 6종은 **i18n 을 거치지 않은 한국어 리터럴**이고 그대로 토스트에 노출된다:

| 상황 | status | error |
| --- | --- | --- |
| JSON 파싱 실패 | 400 | `Invalid request body.` |
| 제목 없음 | 400 | 「제목을 입력해 주세요.」 |
| 설명 없음 | 400 | 「설명을 입력해 주세요.」 |
| 카테고리 무효 | 400 | 「유효한 카테고리를 선택해 주세요.」 |
| 이메일 형식 오류 | 400 | 「유효한 이메일을 입력해 주세요.」 |
| DB insert 실패 | 500 | 「문의 제출에 실패했습니다.」 |

- **`PastDueBanner` 는 이 그룹 문서에서 빠지기 가장 쉬운 요소다.** 라우트 파일 어디에도 나오지 않고 `app/layout.tsx` 가 형제로 렌더한다. 라이트 테마에서 `--gray-000` 은 **#000000** 이라 #b72431 빨강 밴드 위에 **검정 글자**가 올라간다 — 「빨강 배경 + 흰 글자」로 그리면 라이트에서 틀린다.
- **`--background` 는 이름과 달리 라이트에서 밝다.** `var(--gray-900)` 인데 라이트가 `--gray-900` 을 `--palette-gray-100`(#f1f1f3)으로 재매핑한다. 팔레트 900(#171b22)을 그대로 쓰면 라이트에서 새까만 페이지가 된다. 그리고 `--background` 와 `--app-page-bg` 는 **네 스코프 전부에서 같은 값**이다 — §4.4 의 구분은 소비처 규약이지 색 차이가 아니다.
- **`/privacy`·`/terms` 는 heading 스케일을 전혀 쓰지 않는다.** 페이지 h1 은 body-20(20px), 마크다운 h1/h2 는 body-16(16px), h3 는 caption-12(12px)로 **본문보다 작다.** 그리고 화면에 **h1 이 두 개** 렌더된다(i18n 제목 + md 첫 줄).
- **본문 md 는 표가 지배적인 문서다** — privacy 표 11개(본문 53행) · terms 표 7개(32행). 12px 스케일 블록이 페이지 세로 리듬의 큰 부분을 차지한다. 반대로 `[&_blockquote]` 는 **terms 세 로케일 전부에서 한 번도 발동하지 않는다.**
- **마크다운 링크 `rgb(130 200 255/95%)` 와 로드 에러 `rgb(255 130 130/92%)` 는 테마 분기가 없는 고정 리터럴이다.** 라이트(#f1f1f3 바탕)에서 대비가 약해지지만 그것이 현재 배포 동작이다.
- **`/inquiry` 는 한 URL 에 두 개의 완전히 다른 셸이다.** 스크린샷 한 장으로 문서화하면 반드시 절반이 틀린다.
- **랜딩 브랜치 안에서는 `--gray-*` 램프가 테마 토글을 무시하고 팔레트로 고정된다**(`--gray-000` = #fafafa). 폼이 읽히는 유일한 이유는 `[[data-inquiry-root]_&]` 오버라이드가 거의 모든 요소에 잉크색을 다시 얹기 때문이다. 오버라이드가 없는 요소(토스트, 썸네일 삭제 버튼, 제출 버튼)는 팔레트 고정색 그대로다. **새 요소를 추가하면서 오버라이드를 빠뜨리면 그 요소만 흰 글자로 사라진다.**
- **랜딩 브랜치에서 드래그오버 테두리 강조가 나타나지 않는다.** `[[data-inquiry-root]_&]`(0,2,0)가 `COMPOSE_BORDER_DRAG`(0,1,0)를 특이도로 이긴다. 코드 주석이 "원본 모듈 CSS 시절 동작이므로 보존"이라고 명시한다.
- **앱 셸이 켜지면 라이트 팔레트 전체가 바뀐다.** `palette-gray-200` 은 이 화면에서 #e3e4e8 이 아니라 **#eeeef1**, `palette-gray-100` 은 #f1f1f3 이 아니라 **#f8f8f9** 다. 크롬 바 배경(#f8f8f9)과 구분선(#eeeef1)도 이 재매핑을 거친 값이다.
- **상단 크롬 바 배경은 두 테마 모두 메인 카드와 정확히 같은 색이다.** 보이는 것은 하단 1px 구분선뿐이다. 별도 톤으로 그리면 배포와 다르다.
- **`--header-progress` 는 이 화면에서 절대 세워지지 않는다**(훅 미import) → 카드 상단 72px 페이드가 항상 0px. 반면 `--mainchrome-divider-progress` 의 폴백은 `1` 이라 **크롬 바 하단 구분선은 항상 100% 로 그려진다.** MyPage·VideoEdit 등 다른 앱 화면과 이 두 가지가 다르다.
- **`gap` 세 곳이 죽어 있다** — `mainChromeLeadingCluster gap:4px`(자식 = 토글 하나), `mainChromeProfileCluster gap:8px`(자식 = 트리거 하나), 토스트 `gap-4`(자식 = 문자열 하나). gap 만 보고 2슬롯을 그리면 세 곳 모두 틀린다.
- **토스트에는 아이콘도 닫기 버튼도 `role`/`aria-live` 도 없다.** 2400ms 뒤 자동 퇴장이 유일한 소멸 경로다.
- **토스트 성공색과 완료 아이콘 원은 `rgba(0,222,192,·)`(#00DEC0) 리터럴인데 글자와 체크 스트로크는 `--accent-mint-500`(#00c68e)이다.** 두 초록이 섞여 있으니 한쪽으로 통일해 옮기면 배포와 달라진다.
- **§10.2 위임은 미검증 문서로의 위임이다.** 랜딩 GNB·Footer 값을 §10.2 에서 그대로 옮기면 안 된다 — 그 절은 레벨 3 이 아니고 §6.2 와 값이 어긋난다고 스스로 신고한다. 확정된 것은 `lightSurface` → 항상 navBlack 하나뿐이다.
- **BrandLogo 의 파일명이 반대로 읽힌다.** `/klipse-light.svg` 는 **라이트 UI 용(어두운 잉크)** 자산이고 다크 테마에서 숨겨진다. 랜딩 GNB 도 `navBlackActive ? "/klipse-light.svg" : "/klipse-dark.svg"` 로 같은 규약이다.
- **이 그룹의 hover 는 전부 `[&:hover]:` 임의 변형이다** — Tailwind 의 `hover:` 와 달리 `@media (hover: hover)` 가드가 없어 터치 기기에서도 걸린다(뒤로가기 버튼 · 로고 · 마크다운 링크 · 카테고리 칩 · 첨부 버튼 · 완료 보조 버튼 · 사이드바 토글 · 프로필 트리거).
- **focus 아웃라인은 어디서든 `!` 가 필요하다.** 레이어 밖 `button:focus, button:focus-visible, button:active { outline: none }` 이 특이도와 무관하게 `@layer utilities` 를 이긴다.
- **`LANDING_MAIN` 의 `flex-1` 은 무효 선언이다.** 부모 `<main>` 은 flex 컨테이너가 아니다(`[data-page-root]` 는 `position: relative` 만 준다). 세로 높이는 `SITE_ROOT min-h-svh flex flex-col` + `SITE_CONTENT flex-1` 이 만든다. Figma 로 옮길 때 이 flex 를 실제 레이아웃으로 착각하지 말 것.
- **크롬 바의 `z-index: 1002` 는 실제로는 5 처럼 동작한다.** `SHELL_HEADER_SLOT`(sticky + z-5)이 스택 컨텍스트를 만들어 그 안에 갇힌다. 그래서 카드 `::before`(z-10)·`::after`(z-11)가 크롬 바 위에 그려진다.
- **타이포 브레이크포인트가 두 브랜치에서 다르다.** 랜딩 h1 은 48 → 36 → 32 → 28px 로 줄지만 `?shell=app` 에서는 **모든 폭에서 48px** 다(`data-page-root` 부재). 반면 ≤450px 의 body-16 → 14px 는 양쪽 다 걸리고, 크롬 바 제목 라벨도 함께 줄어든다.
- **`/data-deletion-status` 에 이 저장소의 규약을 투영하지 말 것.** 인라인 style · `system-ui` 폰트 · #e0e0e0/#aaa 고정색 · `fontSize: 24`/`14` 리터럴 · 영문 하드코딩 · 테마 분기 없음. 문서에는 "토큰을 쓰지 않는 예외 화면"으로 명시해야 한다.
- **감소 모션 대응이 거의 없다.** `globals.css` 의 `@media (prefers-reduced-motion: reduce)` 는 툴팁 토큰 3개만 건드리고, `keyframes.css`·`tailwind.css` 에는 해당 미디어 쿼리가 없다. `inquiryFadeUp`·`inquiryToastIn/Out` 3개에는 `motion-reduce:` 변형이 붙어 있지 않다. **예외는 GNB 쪽 둘뿐** — 사이드바 토글 선 이동(`transition-duration: 0.01ms!`)과 ≤719px 드로어 전환(`transition: none!`).
- **Tailwind spacing base 는 2px 이다.** 이 절의 유틸리티는 전부 ×2 로 읽는다 — `pt-12`=24px · `px-10`=20px · `pb-20`=40px · `gap-10`=20px · `gap-9`=18px · `mb-16`=32px · `py-40`=80px · `px-16`=32px · `w-28`=56px · `w-16`=32px · `w-14`=28px · `w-9`=18px. 곡률(`rounded-4`=4px · `rounded-8`=8px · `rounded-10`=10px · `rounded-12`=12px)만 px 스케일이라 예외다. **단, Gnb 의 크롬 바 상수들은 유틸리티가 아니라 임의 프로퍼티(`[padding:8px_8px]` 등)라 ×2 가 아니라 리터럴 px 다** — 같은 파일 안에서 두 읽는 법이 섞여 있다.

위임 대상이 스스로 무효화되므로 이 절이 값을 직접 들고 간다. 원천은

#### 앱 셸 브랜치 — 프로필 트리거의 면색·backdrop-filter 충돌

같은 `<button>` 이 `gnb-rightControls` 와 `gnb-profileTrigger` 를 **동시에** 받는다
(`Gnb.tsx:5313-5318`; 열린 상태에는 `gnb-rightControlsOpen` 이 추가된다). 두 클래스가 같은 속성을
반대로 세우는데, `rightControls` 쪽에는 다른 선언들과 달리 `:not(.gnb-profileTrigger)` 가드가 없다.

| 속성 | `rightControls` | `profileTrigger` | 가드 |
| --- | --- | --- | --- |
| 배경 | :1731 `[background-color:rgb(var(--gray-000-rgb)_/_10%)]` | :1386 `[background:transparent]` | **없음** (같은 규칙의 `gap`:1727 · `padding`:1728 · `border-radius`:1729 · `box-shadow`:1732 에는 `[&:not(.gnb-profileTrigger)]` 가 붙어 있다) |
| backdrop-filter | :1733 `[backdrop-filter:blur(10px)]` | :1388 `[backdrop-filter:none]` | **없음** |

둘 다 `@layer utilities` 안의 단일 클래스 임의-속성 유틸리티라 **특이도가 완전히 동일**하고,
JSX 의 className 나열 순서는 CSS 승부에 영향을 주지 않는다. 승자는 Tailwind 가 유틸리티를 어떤
순서로 방출하느냐로만 정해지므로 **소스만 읽어서는 확정할 수 없다.** 게다가 배경 쪽은 단축
(`background`) 대 롱핸드(`background-color`) 싸움이라, `background` 가 뒤에 오면 색까지 초기화하고
앞에 오면 `background-color` 만 덮인다 — 승자에 따라 결과가 "완전 투명" 과 "gray-000 10%" 로 갈린다.

로컬 프로덕션 빌드 산출물(`apps/web/.next/static/css/*.css`, 커밋 대상 아님)에서 확인하면
`@layer utilities` 안 방출 순서가 `[background-color:rgb(var(--gray-000-rgb)/10%)]` →
`[backdrop-filter:blur(10px)]` → `[backdrop-filter:none]` → `[background:transparent]` 였고,
따라서 **트리거는 `background: 0 0`(= 투명) · `backdrop-filter: none`, 즉 `profileTrigger` 가 양쪽 다
이긴다.** 다만 이는 빌드 산출물 관측이지 소스에 적힌 계약이 아니다.

**문서 결론:** 트리거는 **면 없음 · 블러 없음**으로 그린다(§10.5 의 프로필 트리거 표에 이미 적힌
`background: transparent` · `backdrop-filter: none` 과 일치). 동시에 이것은 *가드 누락으로 우연히
성립한 상태*이며, `Gnb.tsx:1731`·`:1733` 에 `[&:not(.gnb-profileTrigger)]` 를 붙여 의도를 코드에
고정할지 여부는 미결 결정 항목이다. 초안의 「→ needsDecision 참조」가 가리키던 항목이 이것이다.

## 보강 5차

#### 보강 — 드로어 **내부 메뉴 열**의 ≤719px 규칙, 그리고 「접힘 속성은 모바일에서 아예 붙지 않는다」

위 「드로어 패널 + 스크림」 절은 패널 **껍데기**(폭·면색·변환·z)까지만 규정하고 내용물을 §6.3 / C-2 로 위임했다. 그런데 `Gnb.tsx` 안에는 껍데기 밖에도 `@media(max-width:719px)` 선언이 **15개** 더 있고 전부 메뉴 열을 겨눈다. 그 15개의 전제가 되는 사실이 먼저 필요하다.

**≤719px 에서 `<html>` 에 `data-app-gnb-sidebar-collapsed` 는 붙지 않는다.** 속성을 세우는 이펙트의 조건이 `sidebarCollapsed && !isCompactViewport` 이고, 아니면 `removeAttribute` 다(`apps/web/components/navigation/Gnb.tsx:3763-3774`). 코드 주석(`:3764`)이 의도를 못박는다 — 「모바일 드로어는 항상 펼침 사이드바 레이아웃 — 접힘 CSS 가 라벨·간격을 깨뜨리지 않게」. ⇒ **정상 상태의 드로어는 언제나 펼침 레이아웃**(라벨 보임 · 행 전폭)이고, 데스크톱 접힘의 아이콘 스트립은 모바일로 새지 않는다. 위 드로어 표가 같은 결론을 CSS 재선언(`:2010-2012`)으로 적었는데, **1차 방어선은 이 JS 쪽**이고 CSS 는 2차다.

**그럼에도 그 CSS 가 죽은 코드가 아닌 이유 — 마운트 직후 한 틱.** `isCompactViewport` 초기값은 `false`(`Gnb.tsx:2506-2507`)이고 `matchMedia("(max-width: 719px)")` 갱신은 마운트 **후** 이펙트(`:3788-3797`)다. 접힘 선호는 `localStorage["klipse-app-gnb-sidebar-collapsed"] === "1"` 이면 마운트 직후 `true` 가 된다(`:3722-3730`, 키 `:2269`). 그래서 **접힘을 저장해 둔 사용자가 ≤719px 로 들어오면 속성이 잠깐 붙는다.** 아래 되돌림 규칙이 그 구간의 화면을 정한다.
