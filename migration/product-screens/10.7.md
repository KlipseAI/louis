#### ⚠ 이 두 화면의 라이트 색은 팔레트 기본값이 아니다 — 먼저 읽을 것

사이드바가 DOM 에 있으므로 **6.13절** "라이트 앱 셸은 회색 램프를 통째로 다시 매핑한다" 가 여기에 적용된다. 재매핑은 `globals.css` 가 아니라 `Gnb.tsx` 의 사이드바 래퍼 클래스 목록에 `[html[data-theme=light]_body:has(&)]:[--palette-gray-N:…]` 형태로 들어 있어, 팔레트 표(**4.1절**)만 보고 옮기면 **라이트에서 전부 틀린다.**

#### 셸 — 6.13 형태 B 에서 달라지는 것만

두 씬이 만드는 4겹은 동일하다(클래스 조립 코드가 복붙 수준으로 같다).

```
div.page                       ← 페이지 루트 (1층)
├─ <Gnb …/>                    ← position: fixed, 문서 흐름 밖
└─ div.contentWithAppSidebarPanel   ← 메인 카드 (2층, appMainCardChromeSurface)
   └─ <main>.content.contentWithAppSidebar   ← 유일한 스크롤 영역 (3층)
      ├─ div.mainChromeHeaderSlot   ← sticky, Gnb 가 portal 로 채운다
      └─ div  container + settingsSection + subscriptionSettingsInner + appSidebarMainLenisContent  (4층)
```

- **1층 `page`**: `position:relative` · `flex column` · `overflow:hidden` · `min-height:100dvh` · `color:var(--gray-000)`. `:has(.tw-mp-006)`(= 앱 셸 본문 존재, 이 두 화면은 항상 참)이면 `height/max-height:100dvh` + `box-sizing:border-box` + `padding-top:var(--app-gnb-safe-top)`(데스크톱 **12px**) + `padding-bottom:var(--app-gnb-rail-padding-bottom)`(**12px**). `::before` 는 `display:none`.
- **2층 패널**: `margin-left:var(--app-gnb-sidebar-width)` · `margin-right:var(--app-gnb-main-inline-padding-end)`(12px) · `margin-top/bottom:0` · `flex:1 1 auto` · `min-height/min-width:0` · `transition: margin-left 320ms cubic-bezier(0.4,0,0.2,1)`. 크롬은 전역 `appMainCardChromeSurface`(**6.13절**).
- **3층 `<main>`**: `position:relative z-index:1 flex:1 justify-content:center`, 그리고 `.tw-mp-006` 동반 시 `flex:1 1 auto · flex-direction:column · align-items:stretch · min-height/min-width:0 · overflow-x:hidden · overflow-y:auto · overscroll-behavior:none`. 패딩 `0 var(--app-gnb-main-inline-padding-end) 20px var(--app-gnb-main-inline-padding)` = 데스크톱 **상 0 / 우 12 / 하 20 / 좌 16px**. (`.tw-mp-006` 이 없을 때만 쓰는 `padding:116px 24px 56px` 은 이 두 화면에서 발화하지 않는다.)
- **4층 컨테이너**: 네 클래스가 한 요소에 함께 붙어 `flex column · align-items:stretch · width:100% · box-sizing:border-box · min-height:100% · **max-width:1400px · margin-inline:auto · gap:0**`. `container` 단독의 `max-width:none`·`gap:32px` 와 `settingsSection` 단독의 `1200px` 는 2클래스 규칙 `.tw-mp-108.tw-mp-136` 에 특정도로 진다. `subscriptionSettingsInner` 는 선언 0개짜리 순수 마커다.

**6.13절과 다른 점 두 가지:**

1. **상단 페이드가 없다.** 패널 `::before` 의 상단 겹 높이는 `calc(72px * min(1, var(--header-progress, 0) * 1000))` 인데, `--header-progress` 를 세팅하는 `useMainChromeHeaderScrollProgress` 를 호출하는 씬은 `NodeCanvasHomeScene` · `AppHomeScene` · `HighlightScene` **셋뿐**이다. 두 씬은 `appSidebarMainScrollRef` 를 만들어 `<main>` 에 붙여 놓고도 어떤 훅에도 넘기지 않는다 ⇒ 변수 미정의 ⇒ **상단 페이드 0px**. 실제로 보이는 것은 하단 20px 한 겹뿐이고, 그 색은 각 테마의 카드 표면색이다 — 라이트 `rgb(248 248 249 / 100→53%@50%→19%@80%→0%)`, 다크 `rgb(49 54 64 / …)`, 둘 다 `bottom / 100% 20px no-repeat`.
2. **상단 바 구분선이 항상 완전 불투명이다.** 같은 이유로 `--mainchrome-divider-progress` 도 세팅되지 않아 fallback `1` 이 쓰인다. 스크롤 여부와 무관하다.

**transition 전량:** 카드 `margin-left` 320ms `cubic-bezier(0.4,0,0.2,1)` · 토글 썸 `transform`+`width` 220ms 같은 커브 · 토글 버튼 `color` 160ms ease · 행/플랜 버튼 `filter`+`transform` 150ms ease · dangerButton·모달 버튼 180ms ease · 툴팁 170ms ease · 크레딧 pane 교차 250ms ease · 게이지 `width` 600ms ease · 이력 행 `background`+`padding-inline` 140ms ease · 드롭다운 트리거 `background` 140ms ease · 모달 인풋 `border-color`+`box-shadow` 180ms ease · 플로팅 라벨 `all` 180ms ease · 철회 칩 `background .15s, color .15s` · 팩 카드 160ms ease · 페이저 `border-color`+`background` 150ms ease · 상단 바 `border-bottom-color` 120ms ease.

> **`prefers-reduced-motion: reduce` 는 이 화면의 모션을 하나도 끄지 않는다.** `globals.css` 의 해당 블록은
> 선언이 3개뿐이고 전부 툴팁 토큰이다. 유일한 예외는 정렬 드롭다운 메뉴로, `CustomDropdown` 자체가
> `motion-reduce:` 변형을 들고 있다(**6.5절**). "접근성 설정 시 애니메이션 없음"으로 문서화하면 틀린다.

### 스크롤 모델

스크롤하는 요소는 `<main>` **하나뿐**이다(`overflow-y:auto` · `overscroll-behavior:none`). `page` 는 `height:100dvh` + `overflow:hidden` 이라 문서 스크롤이 없다. sticky 는 카드 안 상단 크롬 슬롯(`top:0`) 하나뿐이고, 카드 자체가 `overflow:hidden` 이므로 스크롤바는 카드 안쪽에 생긴다.

### 새 계정·설정 화면을 만들 때 놓치기 쉬운 것

- **라이트 색을 팔레트 표에서 그대로 가져오면 전부 틀린다.** 사이드바가 있는 화면은 회색 램프가 재매핑된다(위 표). 특히 페이지 바닥 `#eeeef1` · 카드 `#f8f8f9` · `--gray-500` `#bcc0c9`.
- **상단 페이드가 없다.** 같은 CSS 를 쓰는 AppHome/Highlight/NodeCanvas 와 여기서 동작이 갈린다. 하단 20px 한 겹만 그린다.
- **`.appMainCardChromeSurface` 는 `@layer` 밖 전역 클래스**이고 같은 요소에 레이어 안 유틸리티가 얹힌다. `border-radius` · `overflow` · `box-shadow` · `background-color` 는 전역이 이기므로, 유틸리티에서 같은 프로퍼티를 쓰려면 `!` 나 더 높은 특정도가 필요하다. ≤719px 블록이 `background:transparent` 를 걸고 다시 테마 후손 셀렉터로 `background-color` 를 되돌리는 것도 이 때문이다.
- **`settingsRow::before` 는 상단 선, `creditHistoryListItem::after` 는 하단 선이다.** 두 리스트의 구분선 방향이 반대이므로 한쪽 규칙을 다른 쪽에 복사하면 첫/마지막 항목이 어긋난다.
- **높이가 셋 다 다르다** — `settingsRowButton` `min-height:32px`, 스켈레톤 버튼 34px, `settingsRowNameInput` `min-height:34px`.
- **`--spacing: 2px` 계약은 `ConfirmModal` 에만 적용된다.** `p-8`=16px · `h-22`=44px · `gap-4`=8px · `mt-12`=24px · `-mr-4`=−8px. `myPageSceneStyles.ts` 쪽은 전부 임의 프로퍼티라 px 그대로 읽는다.
- **토큰 표에 없는 raw 색이 넷이다** — `settingsInlineError` 의 `rgb(255 116 109 / 92%)`, 팩 카드 `::after` 의 브론즈/실버/골드 3색. 넷 다 테마 분기가 없다.
- **탭 제목이 i18n 을 타지 않는다.** `useDocumentTitle` 호출부가 `page.tsx` 안의 한국어 리터럴이라 EN/JA 로케일에서도 탭은 `설정 | Klipse` · `구독 | Klipse` 다(`useDocumentTitle` 이 ` | Klipse` 를 붙인다). 화면 제목·상단 바 nav 만 메시지 키를 쓴다.

- `intlLocale` 매핑은 `lib/localeFormat.ts:3-12` — `en→en-US` · `ko→ko-KR` · `ja→ja-JP`.
- 두 날짜 모두 `timeZone` 을 지정하지 않아 **브라우저 로컬 타임존**으로 렌더된다. 서버가 내려주는 `occurred_at` · `current_period_end` 는 ISO 문자열이므로, 자정 근처 항목은 사용자 타임존에 따라 하루 어긋나 보일 수 있다.

#### 잔여(balance) 열 — 서버 플래그로 통째로 사라진다

이력 행 우측의 잔여 표기가 사라지는 경로가 **둘이고 서로 독립**이다. 하나는 DOM 자체가 없어지고, 하나는 DOM 은 있고 CSS 로만 감춘다. 둘 중 하나를 정본으로 고를 수 없어 둘 다 적는다.

| 경로 | 판정 | 결과 |
| --- | --- | --- |
| API 플래그 | `SubscriptionScene.tsx:161-162` `const creditHistoryBalanceVisible = billing?.credit_history_meta?.balance_visible ?? true;` → `:1117-1127` `{creditHistoryBalanceVisible ? (<span …creditHistoryListBalance>…) : null}` | **`<span>` 이 DOM 에 존재하지 않는다.** `creditHistoryListValue` 의 자식이 증감 1개(+ 조건부 철회 칩)뿐이 된다 |
| 반응형 | `myPageSceneStyles.ts` 의 `creditHistoryListBalance` `@media (max-width:560px) { display:none }` | DOM 에는 있고 그리지만 않는다 |

- 필드가 **미정의일 때의 기본은 `true`**(`?? true`)다. 플래그를 내려주지 않는 응답에서는 잔여가 보인다.
- 잔여 span 의 내용은 `{pt.colBalance} {…}` 로 **접두 라벨이 붙는다** — ko `잔여`(`messages/ko.ts:3448`) / en `Balance`(`messages/en.ts:3483`). 값은 `entry.balance_after !== null && Number.isFinite(entry.balance_after) ? entry.balance_after.toLocaleString() : "—"` 이라, 결측이면 em dash `—`(U+2014) 한 글자다(`SubscriptionScene.tsx:1121-1125`).

#### 충전팩 3장의 실제 내용

정의는 `apps/web/app/lib/payments/toss/topup-packs.ts:12-37` 의 `TOPUP_PACKS` 이고, 씬은 `SubscriptionScene.tsx:230` `Object.values(TOPUP_PACKS)` 로 **객체 선언 순서 그대로**(bronze → silver → gold) 3장을 렌더한다. 팩은 이 세 개가 전부다.

| 순번 | `code` | 카드 1행 `pack.name` | 카드 2행 (KO / EN) | 카드 3행 (KO / EN) |
| --- | --- | --- | --- | --- |
| ① | `bronze` | `Bronze` | `250 크레딧` / `250 credits` | `4,900원` / `KRW 4,900` |
| ② | `silver` | `Silver` | `550 크레딧` / `550 credits` | `9,900원` / `KRW 9,900` |
| ③ | `gold` | `Gold` | `1,800 크레딧` / `1,800 credits` | `29,900원` / `KRW 29,900` |

- **팩 이름은 번역되지 않는다.** `name` 이 `"Bronze" | "Silver" | "Gold"` 리터럴 유니온이라 로케일과 무관하게 영문 그대로다(`topup-packs.ts:5`).
- 2행 문자열은 `pt.chargeCreditsPackCredits(pack.creditAmount)` — ko `` `${n.toLocaleString()} 크레딧` ``(`ko.ts:3410`) / en `` `${n.toLocaleString()} credits` ``(`en.ts:3445`). **ko 는 숫자와 「크레딧」 사이에 공백이 있다.**
- 3행 금액은 `formatSubscriptionAmount(pack.amount, sub.upgradeSuccess.amountPrefix, sub.upgradeSuccess.amountSuffix)`(`SubscriptionScene.tsx:937-941`). 포매터는 `` `${prefix}${value.toLocaleString()}${suffix}`.trim() ``(`app/mypage/upgrade/copy.ts:5-11`)이고, 접두/접미는 ko `""` / `"원"`(`ko.ts:3876-3877`) · en `"KRW "` / `""`(`en.ts:3919-3920`)다. ⇒ **금액 서식이 로케일마다 자리(앞/뒤)까지 다르다.** `toLocaleString()` 에 로케일 인자를 넘기지 않으므로 자릿수 구분자는 앱 로케일이 아니라 브라우저 기본 로케일을 따른다.
- **팩 pane 의 첫 자식은 팩 그리드가 아니라 eyebrow 다.** `SubscriptionScene.tsx:904-908` `<span class="type-caption-12-medium planTabEyebrow">{pt.chargeCreditsTitle}</span>` — ko `추가 크레딧팩`(`ko.ts:3409`) / en `Additional credit packs`(`en.ts:3444`). 클래스가 플랜 카드 eyebrow 와 같은 `planTabEyebrow` 이므로 색·타입도 같다.
- 카드는 `<button type="button">` 이고 `aria-label` 이 없다 — 접근성 이름은 세 줄 텍스트의 합이다(`:911-943`).

#### 만료 예정 배지·툴팁의 문구 · 날짜 · 접근성 라벨

문구는 함수 키 2개다. `${a}` 는 **금액이 아니라 잔여 크레딧 수**이고, `${localizedDate}` 는 갱신일이다.

| 키 | KO | EN | JA |
| --- | --- | --- | --- |
| `planTab.expiringCreditsBadge(a)` | `만료 예정: ${a}` | `Expiring: ${a}` | `失効予定: ${a}` |
| `planTab.expiringCreditsRenewalHover(d)` | `${d} (갱신일)에 만료 예정` | `Expires on ${d} (renewal date)` | `${d}（更新日）に失効予定` |

근거: `ko.ts:3462-3464` · `en.ts:3497-3499` · `ja-overrides-surface.ts:583-585`. **JA 만 전각 괄호 `（）` 이고 앞뒤 공백이 없다.**

- **`${a}` 생성**: `SubscriptionScene.tsx:534-537` `planPool.remaining.toLocaleString(intlLocale(locale))`. `intlLocale` 은 `lib/localeFormat.ts:3-12` 의 `ko→ko-KR · en→en-US · ja→ja-JP`. 세 로케일 모두 세 자리마다 `,` 라 출력이 같다(예 `12,345`). 통화 기호·단위는 붙지 않는다.
- **`${d}` 생성**: `SubscriptionScene.tsx:524-532` `new Date(billing.current_period_end).toLocaleDateString(intlLocale(locale), locale === "en" ? {year:"numeric", month:"short", day:"numeric"} : {year:"numeric", month:"long", day:"numeric"})` — **en 만 `short`, ko·ja 는 `long`**. 이력 날짜(`month:"numeric"`)와도, 갱신일 meta(`Intl.DateTimeFormat`, en 만 `short`)와도 옵션이 다르다. 2026-08-08 기준 출력: ko `2026년 8월 8일` · en `Aug 8, 2026` · ja `2026年8月8日`. **`timeZone` 을 지정하지 않아 뷰어의 로컬 타임존으로 렌더된다** — UTC 자정 근처 값이면 날짜가 하루 밀릴 수 있다.
- **툴팁 문장은 툴팁에만 있는 것이 아니다.** 래퍼 `<span class="planTabExpiringCreditsWrap">` 이 `aria-label={`${expiringCreditsBadge(a)}. ${expiringCreditsRenewalHover(d)}`}` 를 들고(`SubscriptionScene.tsx:740-746`), 배지 텍스트와 툴팁 문장을 **마침표 + 공백**으로 이어 붙인다. 예(ko): `만료 예정: 12,345. 2026년 8월 8일 (갱신일)에 만료 예정`. 이 래퍼에는 `role` 이 없다.
- 툴팁 `<span>` 에는 `role="tooltip"` 이 붙고(`:754-761`), `aria-describedby` 로 연결되는 곳은 없다. 배지·툴팁 모두 hover 로만 열리며(**포커스 가능한 요소가 아니다** — `tabIndex` 없음) 키보드로는 툴팁을 띄울 수 없다.
- 렌더 조건은 `planPool.remaining > 0 && billing?.current_period_end && planCreditExpiryHoverDate`(`:736-738`) — 셋 다 참이어야 배지·툴팁·`aria-label` 이 통째로 DOM 에 들어간다.

#### 이력 항목 — 키보드 활성화와 칩의 이벤트 차단

행의 상호작용은 전적으로 `href` 하나로 갈린다. `href` 는 `getCreditHistoryHref`(`SubscriptionScene.tsx:287-304`)가 만든다.

| `entry.receipt_url` 있음 | `receipt_url` 그대로 |
| `receipt_url` 없고 `project_id` 없음 | `null` |

> `usage_kind === "image_generation"` 분기(`:297-299`)와 default(`:301`)가 **완전히 같은 문자열을 반환한다.** 갈래가 있는 것처럼 보이지만 결과는 하나다.

`href` 유무가 한 요소의 role·tabIndex·핸들러·클래스를 동시에 결정한다(`SubscriptionScene.tsx:1071-1092`).

| | `href` 있음 | `href` 없음 |
| --- | --- | --- |
| `role` | `"button"` | `"listitem"` |
| `tabIndex` | `0` | `undefined`(속성 없음 → 포커스 불가) |
| `onClick` / `onKeyDown` | `activate` / 키 필터 핸들러 | 둘 다 `undefined` |
| 클래스 | `creditHistoryListItem` + `creditHistoryListItemClickable` | `creditHistoryListItem` 만 |

**활성화 키는 Enter 와 Space 둘뿐이다.** `onKeyDown` 은 `event.key === "Enter" || event.key === " "` 일 때만 `event.preventDefault()` 후 `activate()` 를 부른다(`:1079-1087`). `Spacebar` 같은 레거시 키 이름 분기는 없고, `keyup`·`keypress` 핸들러도 없다.

`activate`(`:1060-1068`)는 클릭과 키보드가 공유한다 — `receipt_url` 이 있으면 `window.open(href, "_blank", "noopener,noreferrer")` 로 **새 탭**, 아니면 `navigate(href)`(`onNavigate` 가 있으면 그쪽, 없으면 `router.push`, `:125-134`)로 같은 탭이다. `if (!href) return` 가드가 앞에 있지만 핸들러 자체가 `href` 있을 때만 붙으므로 실행되지 않는 방어선이다.

**청약철회 칩이 행 클릭을 막는 방식은 `onClick` 한 곳뿐이다.** 버튼은 `onClick={(e) => { e.stopPropagation(); setWithdrawalTarget(entry); }}`(`:1128-1138`)를 갖는다. **`onKeyDown` 에는 stopPropagation 이 없고, 행의 `onKeyDown` 에도 `event.target` 가드가 없다** — 두 사실 모두 위 라인에서 그대로 읽힌다. 마우스로는 칩만 눌리지만 키보드 경로는 그 보호를 받지 않는 구조다.

- 행이 클릭 가능하면 **탭 정지점이 둘**이다 — 행 div(`tabIndex 0`)와 칩 `<button>`. 행에는 `role="button"` 이 붙어 있는데 그 안에 실제 `<button>` 이 중첩된다.
- 칩 3종은 **배타 분기**다(`:1128-1151`): `topup_refund_eligible` → `<button class="withdrawalButton">` · 아니면 `topup_refund_completed` → `<span class="withdrawalCompleted">` · 아니면 `topup_refund_pending` → `<span class="withdrawalPending">` · 아니면 `null`. 뒤 두 개는 `<span>` 이라 포커스도 클릭 핸들러도 없다.

##### 스피너 링 (`InlineLoadingLabel.tsx:36-48`)

`::before` 와 `::after` 두 겹이 `inset-0 rounded-[inherit] box-border` 로 겹쳐 있다.

- `::before` = 4면 전체 링, `border-solid border-current` + `opacity: 0.22` (:40)
- `::after` = `border-transparent` 위에 `border-t-current` (:41) → **위쪽 1/4 호만 불투명**
- 회전: `animation: inlineLoadingSpin 700ms linear infinite` (:37). `@keyframes inlineLoadingSpin` 은 `app/keyframes.css:50-54`, 본문은 `to { transform: rotate(360deg) }` **하나뿐**이다(`from` 없음).
- 비로딩 시 `[animation-play-state:paused]`, 로딩 시 `running` (:51-52, 적용 :84).

**⚠ 링 굵기는 `sm` 에서도 2px 다 — 코드 의도와 결과가 어긋난다.**
`SPINNER_BASE` 가 `before:border-2 after:border-2`(2px)를 깔고, `SPINNER_SM`(:48)이 `before:border after:border`(1px)를 **`!` 없이** 덧붙여 되돌리려 한다. 두 유틸은 명시도가 같고(클래스+의사요소), Tailwind 가 내보내는 순서가 `border`(1px) → `border-2`(2px) 라 **뒤에 오는 2px 가 이긴다.** 즉 `sm` 은 12px 원에 2px 링(안쪽 구멍 8px), `md` 는 16px 원에 2px 링(구멍 12px)이다. 확인 방법: 빌드된 스타일시트에서 `.before\:border:before`(1px)가 `.before\:border-2:before`(2px)보다 앞에 나오고, `.after\:border` 도 마찬가지다. **`sm` 을 1px 로 그리면 배포와 다르다.** (같은 파일 `:34-35` 주석은 `border-top-color` 를 `!` 로 고정했다고 적혀 있으나 `:41` 코드에는 `!` 가 없다. 이쪽은 순서가 우연히 맞아 — `after:border-transparent` 다음에 `after:border-t-current` 가 나온다 — 위쪽 호가 정상 표시된다. 주석과 코드가 어긋난 상태 그대로 적는다.)

## 보강 3차 — 재구현 검증 「치명」 항목

#### 만료 예정 배지의 절대 배치 앵커 — 좌 플랜 카드가 아니다 (정정)

앞의 ⑤ 좌 카드 내용 순서 ④번과 「만료 예정 배지 + 툴팁 (카드 우상단 absolute 오버레이)」 표, 그리고 z-index 사다리의 「만료 배지 wrap (카드 로컬) 5」는 **배치 기준을 잘못 적었다.** 마크업 위치와 렌더 위치가 다르다.

**마크업상 위치**: `<span class="planTabExpiringCreditsWrap">` 는 확실히 좌 플랜 카드 안이다 — `section.panel` → `planSplitGrid` → `planSummaryGrid` → 첫 번째 `planMergedCard` → `planMergedSection` 의 직계 자식 (`apps/web/components/scenes/SubscriptionScene.tsx:713-761`). (로딩 스켈레톤 분기 `:587-626` 에는 배지가 없다.)

**포함 블록(containing block)**: `position:absolute` 는 가장 가까운 *positioned* 조상을 기준으로 한다. 조상 사슬을 위로 훑으면 —

| 조상 | `position` 선언 | 근거 |
| --- | --- | --- |
| `planMergedSection` | **없음** (display/flex-direction/align-items/gap/width 뿐) | `apps/web/components/scenes/myPageSceneStyles.ts:598-605` |
| `planMergedCard` | **없음** (display/flex-direction/gap/padding/border-radius/border/background/미디어/테마 뿐) | `myPageSceneStyles.ts:582-594` |
| `planSummaryGrid` | **없음** — grid 컨테이너일 뿐, grid 는 포함 블록을 만들지 않는다 | `myPageSceneStyles.ts:624-631` |
| `planSplitGrid` | **없음** — 위와 같음 | `myPageSceneStyles.ts:616-622` |
| `section.panel.tabPanel.planPanel` | **`position:relative`** ← 여기가 앵커 | `myPageSceneStyles.ts:572-580` (`tabPanel` `:1276-1283`, `planPanel` `:614` 은 position 무선언) |

`transform` / `filter` / `contain` / `will-change` / `perspective` 로 포함 블록을 만드는 선언은 이 사슬 어디에도 없다(위 다섯 클래스 전수 확인). `position:relative` 를 가진 `planMergedSectionCredit`(`:607-614`)은 **우측 크레딧 카드**의 섹션이라 좌 카드 배지의 조상이 아니다.

**따라서 실제 렌더 위치** — 래퍼는 `[position:absolute][top:12px][right:14px]`(`myPageSceneStyles.ts:726-735`)이므로 **좌 카드가 아니라 `section` 전체의 우상단**에 그려진다.

- **가로**: `panel` 은 `padding:0`(`:572-580`), `planSplitGrid` 는 `grid-template-columns:1fr` 단일 열이라 `planSummaryGrid` 가 섹션 전폭을 차지하고, 데스크톱에서 `planSummaryGrid` 는 `repeat(2, minmax(0,1fr))` 2열이다. 즉 **섹션 오른쪽 모서리 = 우측 크레딧 카드의 오른쪽 모서리**. `right:14px` 는 크레딧 카드 안쪽 14px 지점이 된다 — 문서가 말한 좌 플랜 카드 반대쪽 절반이다.
- **`@media (max-width:760px)`**: `planSummaryGrid` 가 `1fr` 로 접히면(`:624-631`) 두 카드가 세로로 쌓이고 섹션 폭 = 카드 폭이므로, 이때만 배지가 (첫 카드인) 플랜 카드 우상단과 겹쳐 보인다. **문서의 기존 서술은 좁은 폭에서만 맞는다.**
- **세로 — 확정할 수 없다.** `tabPanel` 이 `flex:1 · display:flex · flex-direction:column · justify-content:center`(`:1276-1283`)이고 바깥 래퍼는 `min-height:100%` 인 flex column(`container` `:21-33`, `settingsSection` `:1050`, `appSidebarMainLenisContent` `:9-17`)이다. 섹션에 여유 높이가 있으면 `planSplitGrid` 가 **세로 가운데**로 밀리므로 섹션 상단은 카드 상단보다 위에 있고, `top:12px` 는 카드 밖(헤더와 카드 사이 여백)에 놓인다. 내용이 여유 높이를 넘기면 섹션 상단 = 카드 상단이 되어 `top:12px` 가 카드 안쪽 12px 이 된다. **어느 쪽인지는 뷰포트 높이와 크레딧 이력 길이에 달려 있어 선언만으로는 정할 수 없다.**

**레이아웃 점유 없음**: 절대 배치라 `planMergedSection` 의 flex 라인을 소비하지 않는다. 배지가 떠도 좌 카드의 ①②③⑤ 항목 간격(`gap:8px`)과 `planTabCardActions` 의 `margin-top:auto` 바닥 고정은 영향을 받지 않는다.

**툴팁은 이 정정의 영향을 받지 않는다.** 래퍼 자신이 positioned 이므로 `planTabExpiringCreditsTip` 의 `top:calc(100% + 10px) · right:0`(`myPageSceneStyles.ts:696-724`)은 배지 래퍼 기준 그대로다. 원본 모듈 CSS 에는 아래로 여는 이유가 주석으로 남아 있다 — 위쪽은 `.page` / `.contentWithAppSidebar` 의 `overflow` 에 잘린다(`90d8ada5^:apps/web/components/scenes/MyPageScene.module.css:1352-1353`).

**회귀가 아니다.** Tailwind 이전 원본에도 `.planMergedCard` 에 `position` 선언이 없고(`90d8ada5^:apps/web/components/scenes/MyPageScene.module.css:1145-1153`), `.panel` 만 `position:relative` 였으며(`:754-760`, `padding:0` 은 `:2349-2351`), `.planTabExpiringCreditsWrap` 의 `absolute/top:12px/right:14px/z-index:5` 도 동일하다(`:1331-1339`). 마이그레이션이 만든 문제가 아니라 지속 상태다.

**z-index 사다리 정정**: 「만료 배지 wrap (카드 로컬) 5」 → **`5` (스태킹 컨텍스트는 카드가 아니라 `section.panel` 로컬)**. 같은 섹션 안의 `planTabCardActions` 는 `position:relative · z-index:1`(`myPageSceneStyles.ts:632-641`)이므로 배지가 그 위다.

> 이 판정은 CSS 선언으로부터의 도출이며 브라우저 실측이 아니다. 배포 화면에서 배지가 어느 카드 위에 보이는지, 세로로 카드 안인지 밖인지는 실측으로 확정해야 한다. 이것이 의도된 디자인인지 결함인지도 여기서는 판정하지 않는다.

**최종 색 (라이트/다크 양쪽).** 이 화면은 사이드바(`gnb-wrapperSidebar`)가 있는 **앱 셸**이지만, 앱 셸 재매핑(`Gnb.tsx:1972-2000`)은 `--palette-gray-100~600` 과 `--gray-400~900` 만 건드리고 **`--gray-000-rgb` 는 건드리지 않는다.** 따라서 아래 값은 전역 스코프와 앱 셸 스코프가 동일하다. 다크 `--gray-000-rgb: var(--palette-gray-000-rgb)` = `250 250 250`(`globals.css:677` · `:40`), 라이트 `--gray-000-rgb: var(--palette-gray-1000-rgb)` = `0 0 0`(`globals.css:832` · `:52`).

| 대상 | 다크 | 라이트 |
| --- | --- | --- |
| 표 래퍼 배경 `/4%` | `rgb(250 250 250 / 4%)` | `rgb(0 0 0 / 4%)` |
| 헤더 행 배경 `/4%` | `rgb(250 250 250 / 4%)` | `rgb(0 0 0 / 4%)` |
| 헤더 하단 보더 `/12%` | `rgb(250 250 250 / 12%)` | `rgb(0 0 0 / 12%)` |
| 데이터 행 하단 보더 `/8%` | `rgb(250 250 250 / 8%)` | `rgb(0 0 0 / 8%)` |
| 셀 채움 `/8%` | `rgb(250 250 250 / 8%)` | `rgb(0 0 0 / 8%)` |

> **헤더 행 배경은 래퍼 배경 위에 겹쳐 칠해진다.** 둘 다 `/4%` 라 헤더 영역만 두 겹이 되어, 계산상 `1-(0.96)^2 = 7.84%` 에 해당하는 톤이 나온다(선언값이 아니라 합성 결과다). 데이터 영역은 래퍼의 한 겹 4% 뿐이므로 **헤더가 본문보다 한 단계 진하다.**

**높이 — 스켈레톤 표에는 `min-height` 가 없다.** 행 높이는 선언에서 그대로 나온다(`box-sizing:border-box`(`globals.css:995`)이지만 높이가 auto 라 결과는 같다).

- 헤더 행 = `9 + 14 + 9 + 1(보더)` = **33px**
- 데이터 행 = 33px × 2 + 마지막 행 32px(보더 0) = **98px**
- 표 래퍼 = **131px** · `creditHistoryBlock` 전체 = `24(제목) + 8(gap) + 131` = **163px**

> 로드 후의 `creditHistoryList` 는 `min-height:430px`(`myPageSceneStyles.ts:117-124`)이고 그 위에 h2 + 툴바가 더 붙는다. **스켈레톤 이력 블록은 163px 뿐이라 로드 완료 시 이 영역이 267px 이상 세로로 늘어난다.** 스켈레톤 쪽에는 430px 에 해당하는 선언이 없다 — 시안에서 로딩 상태를 로드 후와 같은 높이로 그리면 배포와 다르다.

**접근성.** 스켈레톤 블록 각각에는 `aria-hidden="true"` 가 붙지만(`SubscriptionScene.tsx:39-46`), `/subscription` 로딩 분기(`:559-680`)에는 `role` 도 `aria-busy` 도 `aria-hidden` 도 루트에 없다 — `grep` 상 이 범위의 `role=`/`aria-*` 는 SkeletonBlock 내부 것 외에 0건이다. `/settings` 스켈레톤이 루트에 `aria-hidden="true"` 를 두는 것과 다르다.

#### 프로필 팝오버 안쪽 — `renderPopoverMenuContent()` (§6.4 가 비워 둔 자리)

§6.4 는 팝오버 껍데기만 적고 내용물을 적지 않는다. 내용물은 `Gnb.tsx:2997-3432` 의 `renderPopoverMenuContent()` 한 함수가 전부 만들고, `profilePopoverContent`(`Gnb.tsx:1337-1345` — `flex-direction:column · gap:0 · position:relative · z-index:1`) 아래에 **붙여서** 놓인다. 행 사이 간격은 0 이고, 유일한 여백은 크레딧 카드의 `margin-bottom:4px` 와 구분선의 `margin:4px 10px` 다.

> **아바타도 이메일도 이름도 없다.** 최상단이 크레딧 카드이고, 사용자 식별 정보를 보여 주는 행은 없다.
