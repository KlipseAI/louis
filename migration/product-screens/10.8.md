### 10.8 결제·충전

**6.13절**이 앱 페이지 셸을, **6.14절**이 결제 결과 7종의 카드 *안쪽*을 다룬다면, 이 절은 그 앞단 — **플랜 선택(`/mypage/upgrade`)과 결제 확인(`/mypage/upgrade/checkout`)** — 을 다루고, 9개 라우트가 셸·사이드바·크롬 바를 어떻게 나눠 쓰는지를 정리한다. 결과 7종의 부품·리듬·카피는 **6.14절이 정본**이므로 여기서 다시 쓰지 않고, **라우트별 차이**와 **6.14절을 정정해야 하는 지점**만 적는다. 셸은 **6.13절**, 공용 버튼은 **6.10절**, 토큰 인벤토리는 **6.0절**을 참조한다.

> **이 절의 색 값은 전부 "라이트 앱 셸 재매핑이 적용된 뒤"의 값이다.** 9개 라우트 모두 `Gnb` 가 사이드바를 그리므로 `.gnb-wrapperSidebar` 가 DOM 에 존재하고, `html[data-theme=light] body:has(.gnb-wrapperSidebar)` 스코프가 발동한다. **이 스코프는 두 가지를 동시에 한다** — (a) `--palette-gray-100…600` 원시값을 한 칸 밝게 갈아끼우고, (b) **시맨틱 램프 `--gray-400 … --gray-900` 과 그 `-rgb` 미러까지 다시 선언한다**(`Gnb.tsx:1972-2000`). **4.1절 팔레트 표의 기본값으로도, `globals.css` 의 `html[data-theme=light]` 블록만으로도 라이트를 그리면 틀린다.**

| --- | --- | --- |

#### 상단 크롬 바 — 이 그룹에서만 참인 것

바 자체의 치수·구조는 **6.3절**이 정본이다. 이 그룹 고유 사실만 적는다.

- **9개 전부** 빈 `HEADER_SLOT` 의 ref 를 state 에 담아 `Gnb` 에 `mainChromeSlot` 으로 넘긴다 → 바가 `createPortal` 로 카드 안에 들어간다(`gnb-mainChromeTopBarInPanel`: `position: static`, `padding: 8px var(--mainchrome-pad-x)`(8px), 좌우 음수 마진 + `width: calc(100% + bleed-left + bleed-right)` 로 카드 안쪽 패딩을 뚫고 풀블리드). 토글 32×32 + 상하 8px = **바 높이 48px**.
- **뒤로가기 버튼(`mainChromeTrailing`)은 `upgrade` 와 `checkout` 2개만 넘긴다.** 나머지 7개는 사이드바 토글만 있다.

- **구분선은 이 9개 라우트에서 페이드하지 않는다.** `--mainchrome-divider-progress` 를 세팅하는 것은 `useMainChromeHeaderScrollProgress` 뿐이고 그 소비자는 `AppHomeScene` · `NodeCanvasHomeScene` · `HighlightScene` 셋이다. 이 그룹은 아무도 쓰지 않으므로 변수 미정의 → 폴백 `1` → **항상 100% 불투명**.

##### `TIER_CARD_CURRENT` — 선언은 있으나 **렌더되지 않는다**

```
TIER_CARD_CURRENT = "[outline:2px_solid_rgb(var(--accent-ultra-400-rgb)/42%)] [outline-offset:-2px]"
```

`className` 조립은 `[TIER_CARD, gradientClass, isCurrentPlan ? TIER_CARD_CURRENT : ""].filter(Boolean).join(" ")` — **현재 플랜 카드에만 붙는다.**

**왜 안 보이나**: `--accent-ultra-400-rgb` 미러 토큰이 **레포 어디에도 정의돼 있지 않다.** `globals.css:336` 에 `--accent-ultra-400: #b9e1f7` (hex) 만 있고, 레포 전체 grep 결과 `accent-ultra-400-rgb` 의 유일한 출현이 이 사용처(`page.tsx:212`)뿐이다. 따라서 `rgb(var(--accent-ultra-400-rgb)/42%)` 가 무효값이 되어 `outline` 선언 전체가 버려지고, **양 테마 모두 파란 링이 나오지 않는다.** `outline-offset:-2px` 는 유효하지만 outline 이 없어 시각 효과가 없다.

⇒ 현재 플랜 카드에서 **실제로 보이는 변화는 버튼 쪽뿐**이다: 라벨이 `messages.profile.currentPlan`(ko **"현재 이용 중"** / en **"Current plan"**)로 바뀌고 `cursor-default opacity-92` + `disabled`.

> ⚠ **회귀 위험** — 누군가 `globals.css` 에 `--accent-ultra-400-rgb: 185 225 247;` 을 추가하는 순간, 이 코드는 손대지 않아도 현재 플랜 카드에 `rgb(185 225 247 / 42%)` 2px 안쪽 아웃라인이 **의도치 않게 살아난다.**

##### 페이지 레벨 오류 배너 (`CHECKOUT_ERROR`)

헤더와 덱 **사이**에 삽입된다. 마크업은 정확히:

```jsx
{checkoutError ? (
  <div className={CHECKOUT_ERROR} role="alert"><strong>{checkoutError}</strong></div>
) : null}
```

**`role="alert"` 가 실제로 붙어 있다** — §6.14 결과 템플릿이 "`role=status`/`aria-live` 도 없다"로 부재를 명시한 것과 대비된다. 자식은 `<strong>` 하나뿐이라 이 문자열이 배너의 전부이고, **닫기 버튼이 없다**(업그레이드 경고 모달을 다시 열 때만 `null` 로 지워진다).

| 항목 | 값 (해결값) |
| --- | --- |
| 마진 | `margin: 0 0 24px` |
| 패딩 | `py-8 px-9` = **16px 18px** |
| 테두리 | `1px solid rgb(var(--accent-red-500-rgb)/24%)` = **`rgb(255 75 89 / 24%)`** |
| 곡률 | `rounded-20` |
| 배경 | `rgb(var(--accent-red-500-rgb)/12%)` = **`rgb(255 75 89 / 12%)`** |
| 글자색 | `text-accent-red-100` = **#ffe5e8** |
| 타이포 | `font-size: var(--type-body-14-size)` **14px** / `line-height` **1.5** |

`--accent-red-*` 는 `:root` 단일 정의라 **테마 불변**이다(`--accent-red-500: #ff4b59` = `255 75 89`, `--accent-red-100: #ffe5e8`, `--accent-red-400: #ff6f7c`).

**결과 7종의 `STATUS_ALERT_ERROR`(rounded-12 · 12/16px · 테두리 16% · 면 8% · 글자 #ff4b59)와 완전히 다른 스펙이다.** 하나로 뭉뚱그리면 안 된다.

##### ⚠ `ConfirmModal` 의 키보드·포커스·ARIA 계약 — 전부 부재

파일 전체(203줄)에 `Escape|role=|aria-|focus|addEventListener|keydown|tabIndex|autoFocus` **매치 0건**이다. §6.11 `GlassConfirmModal` 관행대로 채워 넣으면 배포 동작과 갈린다.

- 루트는 오버레이 `<div>` 이며 **`role="dialog"` · `aria-modal` · `aria-labelledby` · `aria-describedby` 없음.**
- **`keydown` 리스너 없음 → Escape 로 닫히지 않는다.**
- **포커스 트랩 없음.** 열릴 때 오토포커스 없음, 닫힐 때 포커스 복원 없음, `tabIndex` 지정 없음 ⇒ 탭 순서는 DOM 순서(취소 → 확인)이고 탭이 모달 밖 요소로 빠져나간다.
- **`aria-live` / `role="status"` 없음** — 처리 중 라벨(「해지 예약 중...」 등)이 스크린리더에 알림되지 않는다.
- 닫히는 경로는 정확히 2개: (a) 오버레이 `onClick`(`isLocked` 면 무시), (b) 취소 버튼 `onClick`. 확인 버튼은 `disabled={confirmDisabled}` 와 **별개로** `if (isLocked) return;` 이중 가드를 갖는다.

#### 결과 화면 7종 — **6.14절** 참조

부품·리듬·상태·카피는 **6.14절이 정본**이다. 이 절이 더하는 것은 아래 세 가지뿐이다.

**(나) 6.14절을 정정해야 하는 지점 2건.**

- **`?code` 기본값은 리터럴이 아니다.** 실제 소스는 `searchParams.get("code")?.trim() ?? messages.subscription.upgradeFail.unknownErrorCode` 로 i18n 키를 경유한다. ko·en 모두 값이 `"UNKNOWN_ERROR"` 라 지금은 화면 결과가 같지만, 로케일이 바뀌면 달라질 수 있는 자리다.

#### 놓치기 쉬운 것

- **라이트 앱 셸 스코프는 팔레트만 바꾸는 게 아니다.** `--gray-400 … --gray-900` 과 `-rgb` 미러까지 다시 선언한다. `globals.css` 의 `html[data-theme=light]` 블록만 보고 라이트 값을 계산하면 **비교표·상태 색이 전부 한 칸씩 어긋난다.**
- **`/mypage/upgrade` 와 `/checkout` 은 6.14절의 화면이 아니다.** 셸부터 다르다 — `PAGE_SHELL` 에 `h-[100dvh] + overflow-hidden` 이 붙어 카드 안쪽만 스크롤하고, 카드 안에 `SCROLL_AREA` · `PRICING_CONTAINER` 두 겹이 더 있으며, 카드 그림자도 다르다.
- **카드 그림자를 베이스 선언만 보고 옮기면 틀린다.** 형태 A 는 테마 규칙이 이겨 **베벨 2줄만** 나오고, 형태 B 는 `--glass-dropdown-frame` 5줄이 그대로 나온다.
- **덱은 다크모드를 없애지 않는다.** 카드 면(#fafafa)·잉크(#313640)·CTA(#171b22)만 고정되고, `--gray-100…600` 은 라이트 앱 셸 재매핑을 그대로 받아 한 칸 밝아진다. 그리고 `--glass-dropdown-frame`·`--app-tooltip-*` 는 회색 토큰이 아니라 **여전히 테마를 따른다.**
- **비교표는 덱의 형제라 팔레트 주입을 못 받는다.** 랜딩 `/pricing` 에서는 `SECTION`(`bg-gray-100 text-gray-900`)이 대비면을 깔아 주므로 **같은 컴포넌트가 두 화면에서 다르게 보인다.**
- **비교표는 행 테이블이 아니라 완전 피벗된 4개 열-카드다.** 29개 행 라벨이 열마다 반복되어 총 116개 `<li>`. `<table>` 로 재구현하면 DOM 구조가 달라진다.
- **비교표 대시는 하이픈이 아니라 EN DASH `–`(U+2013)** 이고, `role="img" aria-label="not included"` 를 갖는다. 체크는 16×16 뷰포트 / `viewBox="0 0 24 24"` / `role="img" aria-label="included"`.
- **브레드크럼 구분자는 `/`(U+002F)** 이고 타이포는 **body-16 medium** 이다. `design/llms/components.txt:413` 의 "body-14-medium" 은 틀렸다.
- **티어 카드가 `overflow: hidden` 이다.** 기능 툴팁은 `li`(relative) 기준 절대배치인데 그 `li` 가 카드 안에 있으므로, **카드 경계를 넘는 부분은 잘린다.** 카드 하단 가까운 기능(특히 6개짜리 Trial 의 마지막 항목)의 팁은 온전히 보이지 않는다.

#### 미결정 (코드가 스스로 모순되는 지점)

1. **비교표가 양 테마 모두 배경과 사실상 같은 색으로 렌더된다.** 라이트에서 제목·열 헤드·값 텍스트 `text-gray-900` = **#f8f8f9** 인데 카드 면도 **#f8f8f9** 로 완전히 같고, 다크에서는 #171b22 텍스트가 #313640 카드 위에 얹혀 거의 안 보인다. 이를 고치려던 `COMPARISON_BLOCK` 의 `[&_[class*=comparisonTitle]]:text-gray-000!` / `[html[data-theme=light]_&_[class*=comparisonTitle]]:text-palette-gray-900!` 훅은 대상 클래스가 DOM 에서 사라져 무효다. **문서에 (a) 현재 렌더 그대로(사실상 안 보임)를 적을지, (b) 훅이 의도했던 값(다크 #fafafa / 라이트 #171b22)을 적을지 결정 필요.** 이 절은 "배포 화면과 정확히 일치" 기준에 따라 **(a) 로 썼다.**
2. **같은 이유로 비교표 상단 여백이 `clamp(40px,5vw,64px) + 64px` 로 누적된다**(`[&_[class*=comparisonWrap]]:mt-0!` 무효). 위와 마찬가지로 실제 배포 기준인 **누적값으로 썼다.** 의도값(`clamp` 만)을 정본으로 삼을지 결정 필요.
3. **`--accent-ultra-400-rgb` 미러 토큰 부재를 '고칠 버그'로 문서화할지, '현재 상태(링 없음)를 정본으로' 문서화할지.** 토큰을 추가하면 코드 변경 없이 현재 플랜 카드에 파란 링이 살아나므로 두 문서화가 서로 다른 화면을 낳는다. 이 절은 **현재 상태(링 없음)를 정본으로 썼고, 회귀 위험을 함께 적었다.**
4. **`design/llms/components.txt:413` 의 브레드크럼 "body-14-medium" 과 소스의 `--type-body-16-*` 가 모순이다.** 소스가 승자이므로 이 절은 body-16 으로 썼다 — **components.txt 를 정정해야 한다.**

카드를 밖에서 건드릴 수 있는 규칙도 없다 — `PRICING_DECK`(`page.tsx:171-197`)은 토큰 재선언과 그리드뿐이고, `globals.css` 에 `article` 선택자는 0건이다. **호버 리프트를 얹으면 배포와 갈린다.**
