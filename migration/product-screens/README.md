# 제품 화면 사양 — 라우트별 (비규범)

배포 화면을 **문서만 보고 재구현할 수 있는지**를 기준으로 쓰인 라우트별 사양이다. 46개 인스코프
라우트, 22,522줄. `design/`의 규범 문서가 아니라 **근거**이며, package API나 새 UI의 정본이 아니다.

## 왜 여기 있나

이 22,522줄은 제품 저장소의 **추적되지 않는 작업 트리에만** 있었다. 커밋된 적이 없고 사본도
없었다 — 그 저장소를 정리하면 사라진다. `design/`에 넣지 않은 이유는 두 가지다.

1. **범위.** 라우트별 화면 사양은 제품 scene이고, 이 저장소의 규범 카탈로그는 배포 가능한
   component 계약을 소유한다. 섞으면 `llms/*` 가 라우트 산문으로 덮인다.
2. **권위.** 아래 「신뢰도」대로 이 문서들은 정적 분석 산물이며 브라우저 실측을 거치지 않았다.
   실측을 거친 `migration/product.measured.json` 계열과 같은 무게로 읽으면 안 된다.

`design/`으로 올라가는 경로는 **절 단위 증류**다 — 값을 실측 하네스로 다시 재고, 규범 문서에
계약으로 적고, 게이트를 붙인다. [App Shell](../../design/patterns/app-shell.md)의 「해결된 치수」가
그렇게 올라간 첫 사례다.

## 신뢰도 — 반드시 읽을 것

**이 문서들은 코드를 읽어서 쓴 것이고 브라우저 실측을 거치지 않았다.** 원본 작업 기록이 스스로
「computed style·스크린샷 비교는 한 번도 안 했다」고 적어 두었다. 캐스케이드가 실제로 어떻게
합성되는지는 담기지 않는다 — 그것이 이 저장소의 실측 하네스가 하는 일이다.

값이 어긋나면 **실측이 이긴다.** 순서는 `figma/components.measured.json` · `migration/product.*.json`
→ 이 문서 → 없으면 코드.

## 문서화 수준

원본 작업에서 「문서만 보고 재구현」 검증을 9라운드 돌린 결과다. 53개 라우트 기준
**레벨 3(전체) 30 · 레벨 2(셸까지) 16 · 범위 밖 7**. 레벨 3은 최근 2라운드 연속 통과한 그룹에만
주어졌다.

`§10.10 비디오 에디터`는 **9라운드 내내 한 번도 통과하지 못했다.** 가장 얇은 문서로 취급한다.

## 알아 둘 함정

읽기 전에 [제품을 읽을 때 틀리는 자리](../../design/foundations/product-reading-traps.md)를 본다.
특히 **라이트 회색 램프가 두 벌**이라는 것 — 사이드바가 있는 화면은 `--palette-gray-*`가 통째로
재매핑되므로, 모르면 앱 화면 색이 전부 한 칸 밀린 오류로 보인다.

`app/(highlight-standalone)/`(hl-*) 7개 라우트는 범위 밖이다. 이름이 비슷한 `/highlight` 제품
화면은 범위 안이다.

## 커버리지 등급 — `route-coverage-levels.json`

라우트별 문서화 수준이다. **레벨 3은 「문서만 보고 재구현」 검증을 최근 2라운드 연속 통과한
그룹에만 준다** — 1회 통과는 판정 흔들림과 구분되지 않는다(실제로 §10.2·10.8·10.11·10.12가
통과→불통과로 뒤집혔다).

| 레벨 | 뜻 | 라우트 수 |
| ---: | --- | ---: |
| 3 | 전체 | 30 |
| 2 | 셸까지 — 문서는 두껍지만 보증하지 않는다 | 16 |
| 0 | 범위 밖 (`(highlight-standalone)` 7개) | 7 |

`§10.10 비디오 에디터`는 **9라운드 내내 한 번도 통과하지 못했다.** 이 파일이 그 판정의 유일한 근거다.

**출처**: 구 저장소 `~/klipse/apps/web/scripts/route-coverage-levels.json` (2026-08-08). 그 저장소는
정리될 예정이고 사본이 없어 여기로 옮겼다 — 바이트 그대로다. `10.N.md` 문서들과 짝이라 같은
디렉터리에 둔다.

### ⚠ 한계 — 이 등급은 klipse-web 기준이 아니다

**등급을 매긴 대상은 구 저장소의 2026-08-08 코드다.** 정본인 `klipse-web` `design` 브랜치와
대조하면 두 방향으로 어긋난다.

| 어긋남 | 내용 |
| --- | --- |
| 낡음 7개 | `(highlight-standalone)/hl*` 7개를 `level 0`(범위 밖)으로 싣고 있는데, `klipse-web` 에는 그 경로가 **0건**이다 — 삭제됐다. 「범위 밖」이 아니라 「없음」이다 |
| 미등재 3개 | `/admin/coupons/[id]/print` · `/creative-media` · `/creative-media-admin` 은 `klipse-web` 에 실재하는데 등급이 없다 |

그래서 `L3`/`L2` 는 **「구 코드 기준으로 문서가 얼마나 두꺼웠나」의 기록**이지 `klipse-web` 현재
상태의 보증이 아니다. 재측정 전까지 참고값으로만 쓴다. 등급을 손으로 고치지 않는다 — 고칠
것은 이 파일이 아니라 **`klipse-web` 기준으로 다시 돌린 측정 결과**다.

### klipse-web 대조 (2026-08-22)

`git ls-tree design` 로 센 실제 화면은 **52개**다 — `page.tsx` 49 + `not-found`·`error`·`global-error` 3.
Figma 이식 보드의 항목 48개와의 차이는 아래가 전부다.

```
52 − /explore · /mypage                              (redirect 한 줄 · 렌더 DOM 0)   −2
   − /docs/{nodecanvas,videoeditor,highlight}        (정본이 klipse-docs 레포)       −3
   + /nodecanvas?project=                            (라우트가 아니라 에디터 상태)     +1
 = 48
```

즉 **보드는 `klipse-web` 에서 화면을 그리는 라우트를 하나도 빠뜨리지 않았다.**

Figma 이식 보드(`OlYKERKOkgbxBEEoXGZW2c`)의 섹션 이름이 이 등급을 인용한다. 등급이 바뀌면
보드를 손으로 고치는 것이 아니라 이 파일에서 다시 찍는다.

## 원본 데이터

`_raw-extracts.json`(36건)과 `_verify-gaps.json`(14건)은 이 사양들을 쓸 때 쓴 추출 원본과
검증 격차 데이터다. 사양이 그 산물이므로 평소에는 읽을 일이 없지만, **어떤 값이 어디서 왔는지를
되짚어야 할 때** 유일한 경로다. 다른 사본이 없어 함께 보존한다.
